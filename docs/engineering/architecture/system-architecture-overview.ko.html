한눈에 보는 현재 구조

CLAiR EMR은 동물병원 외래 흐름을 중심으로 만든 Next.js App Router 기반 EMR SaaS 프로토타입입니다. 화면은 workspace shell과 feature module로 나뉘고, 일부 핵심 흐름은 Next.js API route, server core, Supabase local/dev/test 경계를 통해 검증되고 있습니다. 아직 production/live, 원격 Supabase 검증 완료, 외부 provider 연동 완료, 실데이터 준비 완료 상태는 아닙니다.

앱 프레임

src/app/, src/shell/, src/modules/registry.ts가 workspace 진입, 탭, 패널, 모듈 슬롯을 구성합니다.

기능 모듈

접수, 차트, 검사, 처치/조제, 수납, 고객관리, 병원관리 등은 src/features/* 아래에서 UI와 상태를 소유합니다.

서버 경계

선택된 경로는 API route, server core, permission resolver, mock/Supabase gateway로 나뉘어 서버 권한과 persistence 경계를 분리합니다.

중요한 해석 기준: 화면에서 버튼을 숨기거나 mock role을 쓰는 것은 보안 완료가 아닙니다. 보안, 권한, workspace isolation, billing amount, clinical state transition은 server/API/DB/RLS 경계에서 검증되어야 합니다.

코드 레이어 맵

App routes

공개 페이지, workspace entry, docs viewer, auth page, API route를 정의합니다. 위치는 src/app/입니다.

Workspace shell

navigation, module slot, top menu, workspace tab, panel/drawer 상태와 화면 프레임을 담당합니다.

Module registry

module ID를 label, icon, side panel, content, drawer, optional panel로 연결합니다.

Feature UI and state

접수, 차트, 수납, 검사, 처치/조제, 고객관리 등 화면별 UI 상태와 route consumer를 관리합니다.

Server feature cores

route-safe operation, typed result, permission check, mock gateway, Supabase adapter를 묶는 서버 측 핵심입니다.

Shared domain helpers

demo workspace ID, status label, audit helper, service catalog helper, read-model selector 같은 공통 도메인 유틸리티를 둡니다.

이 문서만으로 주장하면 안 되는 것

  • client-only permission gate, hidden action, mock role label을 보안 완료로 보지 않습니다.
  • local-first 또는 docs-only 근거만으로 remote Supabase, production deployment, provider integration, payment integration, real email, compliance readiness를 주장하지 않습니다.
  • Next.js, Supabase, feature module, route/API, design-system 방향을 별도 architecture decision 없이 starter kit로 대체하지 않습니다.
  • synthetic/demo data와 실제 환자, 보호자, 병원, 결제, identity, clinical data는 분리해야 합니다.
  • Next.js application code를 바꾸는 새 작업은 관련 node_modules/next/dist/docs/ 가이드를 먼저 읽어야 합니다.

아키텍처 관련 작업 전 체크리스트

1. 경계 선언

mock/session-only, local-first, remote staging, production/live 중 어느 범위인지 먼저 말합니다.

2. 영향 범위 명명

module, route, server core, gateway, migration/RLS, test scope를 구체적으로 적습니다.

3. source doc 연결

계약을 복붙하지 말고 실제 source-of-truth 문서로 링크합니다.

4. 서버 권한 보존

permission, workspace isolation, billing amount, clinical state, audit evidence는 서버 기준으로 검증합니다.
