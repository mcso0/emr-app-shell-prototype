결론

현재 프리셋은 오더 선택에는 쓸 수 있지만, 검사 결과를 안전하게 입력·판정·재현하는 임상 프리셋으로는 부족하다.

측정값은 프리셋이 아니다

프리셋에는 입력 형식, 단위, 참고 규칙만 둔다. 실제 측정값은 환자 검사 결과에 저장한다.

하나의 ‘정상값’으로 해결되지 않는다

종뿐 아니라 장비, 검사법, 검체, 연령, 채취법, 프로토콜에 따라 적용 규칙이 달라진다.

참고구간과 결정한계는 다르다

건강 개체 분포와 UPC 같은 임상 행동 기준은 의미가 다르므로 별도 모델이 필요하다.

근거가 없으면 ‘미판정’이 정답이다

조건이 맞는 승인 rule이 없을 때 숫자를 추측해 정상/이상 판정을 만들면 안 된다.

안전선

현재 Airtable의 유일한 source는 synthetic 운영 fixture이며 ‘임상 사용 불가’다. 레코드의 approved/published 상태를 임상 승인으로 해석하면 안 된다.

현재 상태와 끊어진 연결

현재 시스템에는 결과값·단위·문자열 범위·판정 저장 공간이 일부 있지만, 어떤 기준을 왜 적용했는지 결정하는 계층이 없다.

Rule 선택 우선순위

  1. 병원에서 검증·승인한 장비/외부 검사실 rule
  2. 설치 장비 모델·소프트웨어 버전의 제조사 rule
  3. 계약 외부 검사실의 공식 rule
  4. 교육용 일반 수의 reference는 참고 표시만, 자동 판정 금지
  5. 일치 없음: 참고구간 없음 · 미판정

실행 순서

현재 보고서는 조사와 설계 제안까지다. 실제 데이터·앱 변경은 다음 승인 범위에서 진행한다.

임상 안전 기반

source/clinical review 상태 분리, unit vocabulary 교정, CBC analyte 확장, interval set/rule authoring 설계.

병원별 활성화

장비·외부 검사실 프로필과 승인된 revision을 선택. 일치하지 않으면 미판정.

런타임 연결

API가 적용 rule을 반환하고 서버가 판정. 결과에는 rule/context snapshot을 저장.

임상 검토 후 제한 배포

실제 샘플 결과지 대조와 임상병리 수의사 검토 후 승인된 subset부터 활성화.

승인 차단 조건

공식 source locator, 장비/방법/검체, species, 단위·환산, RI/결정한계 의미, 임상 검토자, revision, 병원 활성화 기록 중 하나라도 없으면 자동 판정용 clinical preset을 배포하지 않는다.
