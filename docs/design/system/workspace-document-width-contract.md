## Width and state

- All opted-in document layouts (임상검사, 차트, 조제/처치, 영상, 수납) start wide on first entry and full reload. Wide uses available document space. A manual narrow/wide choice remains respected during module navigation in the current session.
- For 차트, 임상검사, 조제/처치 and 수납, show the width button only when unrestricted document space exceeds the cap. 영상 keeps the same button visible when space is insufficient; it is disabled but keyboard-focusable and explains `현재 공간에서는 두 보기의 폭이 같습니다.` in a hover/focus tooltip. Disabled activation does not change the retained width preference. Measure the center container after shell, profile, inline panels, padding and scrollbar; never use viewport 1600 as the threshold or the restricted document width as the measurement.
- Keep the preference when the button hides. UI preference is scoped by workspace and module in the session store; no database or new durable storage is introduced.
- Keep the Content component and its fields mounted across width and panel presentation changes. Keep existing panel URL states separate from width preference.
- Opt-in layout-only URL updates use Next.js-integrated native `history.replaceState` so panel changes do not trigger server navigation or race a later close. Feature navigation and non-opt-in modules retain their existing routing.
- Center the document within the actual work area beneath patient context, excluding the outer queue/profile. Reserve only requested inline panel columns. Target `(areaWidth - documentWidth) / 2`, clamped between `leftColumn + 16` and `areaWidth - rightColumn - 16 - documentWidth`. A closed side does not reserve a matching blank column. Wide mode fills this available space; narrow mode respects the module cap. Overlaid drawers reserve no columns. Locked chart-start surfaces retain their existing full-center width.
- Explicit width toggles use actual numeric width/position endpoints, 180ms ease-out and no scale/fade. Continuous resize follows dimensions immediately; an inline/drawer boundary settles document position in 180ms without replaying panel entry. History and Lab receipt pointer toggles use the slide contract below. Reduced motion removes movement transitions.

## Panels and accessibility

- Patient header spans the work surface. History starts directly beneath it, beside the document title. Lab equipment receipt shares this hierarchy at the right edge and occupies the full work-surface height. The title/actions and body share one mounted document column and adjust together when history or Lab receipt opens or closes. Imaging and billing reference panels retain their below-title position; their top follows the actual toolbar height, including wrapped actions.
- All five opted-in modules use a borderless document toolbar. The common center owns the single 16px horizontal inset; document content adds no second outer inset. Wide clinical panels, result sections, execution tables and billing cards align with their document and the toolbar when internal panels are closed. Narrow visible content uses the full module cap: 차트 1040px, 임상검사/조제·처치/영상/수납 1120px. Card inner padding, existing minimum panel tracks and contained scrolling remain unchanged.
- Profile remains in the outer slot and does not replace the receipt panel.
- If requested inline panels would leave less than 880px for the center, overlay both requested panels as non-modal drawers at their existing edges. Return inline only when the requested center reaches 912px; the 32px buffer prevents repeated boundary switching. Never automatically close a panel, collapse the queue, or change `aside`/`right` URL state during resize.
- Both presentations use `complementary` semantics with no backdrop, background inert, focus trap or scroll lock. Opening/resizing does not steal current document focus. Outside clicks/focus do not dismiss the panels. Escape closes only the panel containing focus; ignored Escape propagates so central controls keep their existing behavior. Nested receipt/financial dialogs retain their own modal/Escape contracts and raise their owning portal above outer drawers.
- Below 576px of work-area width, show one selected surface (`left`, `right`, `body`) through the bottom work-area selector. Never stack histories. Preserve requested open flags, mounted nodes and input/list state when a panel is concealed; hide and inert its popup, portal and outside focus guards. Sample active focus/nested-dialog ownership before concealment and retain that surface when entering compact mode. Focusing document controls reveals the body. Toolbar buttons reflect actual visibility: activating a concealed panel shows it first; activating the visible panel closes it. Clamp both panels to `min(280, areaWidth - 16)` on sub-280px surfaces, overriding the history minimum width only in this layout.
- If a focused width button becomes unavailable, return focus to the right panel trigger when available, otherwise the history trigger.
- Pointer history toggles slide in from the left in 180ms and back out in 140ms using the existing panel ease-out token. Lab receipt mirrors this motion from/to the right. The document uses translation from its previous visible position to the final layout, without scaling, fading, blurring or animating its width. Reversing a toggle retargets the current visible position.
- Keyboard panel toggles, reduced motion and initial URL restoration settle immediately. Resize never replays a panel slide; only the inline/drawer document boundary has the position settlement above. Explicit narrow/wide mode remains a separate 180ms width/position transition.
- Drawer history has 0px top/bottom left corners and 12px right corners; the right drawer mirrors this with 0px right corners and 12px left corners. Both use a 1px `--emr-border-default` (`neutral-200`, `#E5E5E5`) outer border: top/bottom/right on history and top/bottom/left on the right drawer. Shadow geometry matches each surface. Both drawer sides use `--clair-shadow-lg` on a non-interactive decorative layer: opacity enters in 150ms and exits in 140ms with `cubic-bezier(.2,0,0,1)`. Header, tools and list contents stay opaque. Ordinary inline/drawer resize fades elevation without replaying entry; initial restoration, keyboard changes, compact selection and reduced motion settle elevation immediately. Preserve imaging/billing right-panel immediate close/reset; their elevation disappears with that existing close. The visual slide mask must exclude nested modal/popover portals so their controls remain unclipped.
- Closing history or Lab receipt becomes inert and leaves the accessibility tree immediately; its visible slide completes before Base UI hides the popup. History's stable mounted portal retains group/filter state. Actual close returns focus only if it was inside the closing panel: to the title trigger, or to the persistent body selector if compact mode remains. Lab receipt retains its existing unmount/reset lifecycle after actual exit; imaging and billing reference panels keep their immediate closing and draft lifecycle. Concealment and presentation changes do not run that lifecycle.
- Preserve table columns and font/density. Contain necessary horizontal scrolling inside tables.
- 차트 clinical panel tracks use the actual workspace container width. At 1180px or below, expanded tracks retain their existing 360px minimum and scroll inside the group; wide documents preserve the original panel proportions. Existing independent collapse, editor autosave and Order pinned-column behavior remain intact.
- 조제/처치 preserves instruction/table mount identity, row selection, columns/density and contained horizontal/vertical scrolling. Existing drawer input survives width and history presentation changes; this verifies local input retention, not a new persisted prescription-edit workflow. Execution history and lifecycle actions retain their existing persistence/permission contracts.
- 영상 keeps reading textareas and summary comment mounted across width/panel presentation changes. Summary dismissal returns focus to its toolbar trigger. The Order detail table memoizes its one-row data array to avoid repeated table-state resets after width, panel or density changes. Reading/comment/attachment persistence and PACS behavior retain their existing boundaries.

- 수납 preserves controlled quantities, calculated/excluded totals, assignment, ledger selection/filters and summary memo/adjustment input across width and presentation changes. Memo/adjustment retention is local screen state, not a new persisted financial-edit workflow. Summary close/reopen retains the existing lifecycle; no new draft persistence is introduced. Checkout preparation uses stable selected invoice IDs and refreshes when amounts/status, selection, payment method or memo change rather than on layout-only renders. Nested financial preflight keeps its own focus/Escape and server permission/amount contracts.

## Verification and extension

Lab receipt chrome (title, collapse control, date region and list tools) renders with the popup. The mounted Lab slot provider owns its current-detail read and shares it with the receipt, so opening/reopening does not remount a queue subscription or trigger another read. Only unresolved list content shows pending feedback; known empty/results remain available during refresh. Read errors and permission denial replace list rows, and unknown counts do not imply zero. Permission denial also withholds the previous receipt date. Existing right-popup unmount/reset, card/dialog state and 180/140ms motion contracts remain unchanged. This does not add live equipment integration; the current live mapper still returns an empty receipt list.

Layout-only changes must not add receipt reads or checkout preparation requests. Run focused browser regression, lint, typecheck and build.
