Plan/Order 빠른 추가 기획

검색하고 연속으로 추가합니다.

확정한 방향

오더가 1개 이상일 때 마지막 오더 아래에 + Order 추가를 표시합니다. 클릭하면 검색으로 전환하고, 하나를 추가해도 입력창과 포커스를 유지합니다.

이번 단계

기획과 클릭 가능한 시안까지. 실제 앱 구현·데이터 연결·배포는 다음 단계입니다.

첫 오더와 표시 조건

오더가 0개면 하단 빠른 추가를 숨기고 기존 빈 상태의 + Order 버튼으로 첫 오더를 추가합니다. 첫 추가 뒤 하단 빠른 추가가 나타나고, 마지막 오더를 삭제하면 다시 숨깁니다. 현재 분류만 비어 있고 다른 분류에 오더가 있으면 빠른 추가를 유지합니다.

세 가지 동작 원칙

  1. 전체에서 찾기 — 분류를 먼저 고르지 않고 오더명·청구명으로 검색합니다.
  2. 선택은 미확정 추가 — 단일 오더는 바로 추가하고 세트는 구성 확인을 거칩니다.
  3. 다음 검색으로 이어가기 — 검색어는 비우고 포커스는 유지합니다. 저장은 별도 상태로 표시합니다.

위치와 밀도

분류 제목과 값을 왼쪽 정렬하고, 추가 버튼은 보조 문구 없이 + Order 추가로 표시합니다. 40px 추가행과 36px 입력창을 기준으로 잡았습니다. 버튼·입력창·결과창의 너비는 분류 열 시작부터 고정된 Order 명 열의 오른쪽 경계까지 맞춥니다(현재 332px). 긴 목록에서는 같은 추가행을 청구 요약 위에 고정하고, 좁은 패널에서도 같은 열 기준으로 정렬하고 사용 가능한 너비 안에 맞춥니다. 결과창은 남는 공간에 따라 위·아래로 열립니다.

검색창과 결과 표시

  • 입력창 플레이스홀더는 ‘오더명·청구명 검색’입니다.
  • 입력 전에는 제목·건수·예시 검색어를 숨기고 ‘오더명 또는 청구명을 입력해 주세요.’만 안내합니다.
  • 검색 후 ‘검색 결과 3건’처럼 제목과 건수를 6px 간격으로 붙입니다. 결과 없음은 0건, 검색 실패는 제목과 건수를 숨깁니다.
  • 결과 항목은 분류·오더명·가격만 표시하고 이름 아래 보조 설명을 넣지 않습니다.
  • 입력 전·결과 없음·오류 안내에는 결과 스크롤바를 표시하지 않습니다. 실제 결과 목록이 넘칠 때만 스크롤합니다.
  • 검색 닫기는 CDS X 아이콘이며 접근성 이름은 ‘빠른 검색 닫기’입니다. ‘상세 오더 검색’ 뒤에는 CDS 오른쪽 꺾쇠를 표시합니다.

실수와 실패를 다루는 방법

  • 이미 추가한 오더와 저장 중인 오더는 다시 넣지 않습니다.
  • 저장 실패 시 행을 남기고 ‘다시 저장’을 제공합니다. 성공 안내는 저장이 끝난 뒤 표시합니다.
  • 현재 분류에 안 보이는 항목을 추가하면 ‘전체에서 보기’로 안내합니다.
  • 검색 결과 없음·검색 실패·읽기 전용을 다른 상태로 표시합니다.
  • 한글 조합 중 Enter는 오더 추가로 처리하지 않습니다.

현재 앱과 연결할 부분

‘상세 오더 검색’은 상단·빈 상태의 + Order와 동일한 기존 오더 추가 다이얼로그로 연결하고 검색어를 이어받습니다. 기존 카탈로그 조회, 미확정 오더 추가·저장, 세트 구성창을 재사용합니다. 기존 전체 선택창의 목록 교체 로직과 빠른 추가 로직을 구분해, 기존 오더가 사라지지 않게 합니다.

다음으로 검토할 것

추가행의 위치와 검색창 크기, 연속 추가 시 시선 이동, 긴 목록 고정 방식이 편한지 확인합니다. 이후 실제 사용자에게 익숙한 오더 3개를 추가하게 해 시간과 수정 횟수를 비교합니다.

최근 사용·즐겨찾기·AI 추천·새 오더 생성은 첫 구현에서 제외합니다. 정렬·동시 저장 충돌·환자 전환·실제 가격 계산은 시안 검증 범위 밖이며 앱 구현 단계에서 검증합니다.
