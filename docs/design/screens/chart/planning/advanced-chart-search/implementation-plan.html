최종 시안 반영 계획 · 2026.11.23

로컬 앱 구현 및 합성 자료 검증 완료. CHART-PR-042 후속이다. 수의사가 병원 차트 검색에서 목록과 카드형을 오가며 환자·방문 목적·임상 근거를 확인하고, 필요한 기록의 원본과 기존 복사 절차에 진입하는 것이 목표다. 화면 명세와 데이터 대응표를 기준으로 구현한다.

조사 기준

GitHub main과 로컬 origin/main이 가리키는 fdd72b35810ad4f366a3469cfcfc92dd3541440d에서 코드를 확인했다. 아래의 기존 검수 이력은 당시 릴리스 기록이다. 이번 후속 검수는 별도로 진행한다. 최종 시안은 같은 폴더의 로컬 figma-list-preview.html이다. 이 파일은 조사 기준 커밋에 포함되지 않아 새 작업 환경에는 시안도 함께 전달해야 한다. 시안 SHA-256은 db88d226e26368987dd876c0efcab88581f6c2087d7c9608290fd2538cc3b4c6이다.

  • 검색 작업 화면은 검색·정렬·선택·내보내기·열린 원본을 관리한다. ChartRow가 두 보기의 결과를 그리고 환자 이력 서랍도 ChartStaff를 사용한다. 목록의 Task 상태 교체가 서랍 표시까지 바꾸지 않도록 호출부로 범위를 제한한다.
  • 검색 근거와 정렬과 복사 대상·항목·검토가 구현돼 있다. 시안의 가상 복사창과 메모리 내 선택 로직을 서비스에 이식하지 않는다.
  • 검색 API는 최근 목록의 전용 경로와 검색 색인→현재 페이지 상세 조회 경로를 쓴다. 결과 타입과 실제 조회 SQL을 함께 대조했다. 새 카드 정보는 현재 페이지 단위로 읽는다. 전체 검색 색인 또는 카드마다 별도 요청에 붙이지 않는다.

구현 순서와 완료 기준

단계변경 지점과 선행 조건종료 기준
1. 기준 화면 고정main 후보에서 기존 검색 테스트를 실행하고 같은 합성 차트를 두 진입점에서 읽는다. 기존 검색 결과 Storybook에 첨부·복수 진단·긴 소견·빈 정보 사례를 준비한다.기존 실패를 분리하고 목록·카드·원본 열림·체크 상태의 비교 화면을 확보한다. 시안의 가상 필드와 서비스 응답 필드를 구분한다.
2. 결과 화면 이식workspace.tsx는 상태와 액션을 소유하고 result-card.tsx·presentation.tsx·workspace.module.css에서 썸네일, 네 정보 그룹, 전문 보기와 푸터를 조합한다. 기존 헤더, Button, Checkbox, Badge, EmrStatusBadge, Popover, Sheet, Tooltip을 재사용한다. 검색 입력은 기존 필터·복구 로직에 연결한다.실제 응답만 가진 차트가 두 보기에서 정상 표시된다. 클릭·Tab·Escape·터치로 상세를 확인하고 원위치로 돌아온다. 필터가 스크롤바를 바꿔도 남은 카드 폭과 위치가 흔들리지 않는다.
3. 표시 데이터 연결기존 환자 ID로 공통 프로필을 연결한다. 보호자 ID·최근 내용 수정 시각·확정된 부가 정보는 서버 읽기 계약부터 보강한다. 기존 프로필 진입과 권한 경계를 따른다. 새 필드는 구형 응답을 읽을 수 있게 하고 기존 복사용 버전의 계산 범위를 보존한다. 집계·공동 진료의 정책이 미결인 부분은 별도 작업으로 표시한다.최근 목록·검색 결과·단건 재조회가 같은 필드값을 돌려준다. 같은 방문의 다른 차트나 다른 병원의 결과가 섞이지 않는다. 소스가 불명확한 건수·이름·날짜가 임의 값으로 나타나지 않는다.
4. 실사용 동선 회귀레일에서 독립 검색, 작성 중 차트에서 검색 후 복귀, 검색→원본→기존 차트에 복사, 검색→선택→PDF/CSV를 기존 진입점에서 시험한다. 시안과 서비스가 다른 부분은 현행 계약 기준으로 판정한다.환자·차트·커서·선택 범위가 올바르다. 복사 전 대상과 항목을 확인하고, 실패 후 재시도와 취소가 가능하다. 내보낸 행 수와 선택 범위가 일치한다.

적용한 기준과 남은 결정

  • 이름 검색. 첫 적용은 현행 동물명·보호자명 필터를 유지한다. 이름을 기본 검색에 넣는다면 동일 이름 환자, 임상 단어와의 혼합 검색, 일치 근거와 우선순위를 먼저 합의한다.
  • 오더 명칭. 초음파·검사·처치까지 포함하므로 카드 라벨은 ‘오더 내역’을 권장한다. 라벨 결정은 검색·복사 대상 데이터에 영향을 주지 않는다.
  • 복수 진료의. 이 방문을 진료한 수의사를 판별할 임상 원천을 확인한다. 접수 담당자 목록은 여러 직종을 포함한다. 확인 전에는 방문 담당의 한 명만 제공한다. 배정 테이블 정의
  • 수정일·검사 건수. SOAP·진단·오더 내용이 변경된 시각을 사용한다. 업무 상태 변경은 수정일에서 제외한다. 검사 배지는 임상·원외로 나누고, 이 차트에 귀속된 최종 결과 ID별로 한 건을 센다. 정정은 같은 건이고 취소·격리 결과는 제외한다. 입원·영상·백신의 운영 연동은 차트 귀속과 결과 원천을 확인한 뒤 진행한다.
  • 즐겨찾기 전용 필터, 두 열 카드 썸네일의 최대 높이, 작은 화면의 별도 내보내기 위치는 후보로 둔다. 기존 화면을 이식한 뒤 같은 화면 크기로 재현해서 채택 여부를 판단한다.

11월 21일 검수와 논의

수의사가 과거 차트를 찾아 다른 환자의 작성 중 차트에 복사하고, 첫 차트에서 작업을 이어가는 과정을 합성 사례로 확인했다. 검수 화면 주소는 PR #1105에 있다. 검수 화면을 새로 고치면 해당 탭의 변경 사항이 초기화된다.

확인한 과제관찰한 결과
사례 구별완료 7건, 작성 중 포함 11건을 확인했다. 검색어에 맞는 대표 영상, 첨부 없음, 동물종 필터와 부정 표현의 순서를 확인했다. 1366px에서 목록은 1120px까지 줄고 원본은 오른쪽 끝에 유지됐다. 1024px에서도 복사 버튼 두 개를 사용할 수 있었다.
기존 차트 재사용내 차트와 수정 가능한 동료 차트를 구분했다. 대상의 S/O에 문단을 추가하고 A/P에서 지정한 문단만 교체했다. 검수 화면에서도 복사한 문진을 수정해 저장하고 모카의 원문이 유지되는 것을 확인했다. 이미 있는 진단, 중복 오더 동의, 기존 주진단 유지와 미확정 처방값을 확인했다.
접수 후 첫 차트진료 중인 두부의 추가 차트와 새로 접수한 별이의 첫 차트를 구별했다. 대기 건을 다시 열어 선택한 문단을 한 번 적용했다.
대량 검색격리한 로컬 DB에 본문이 짧은 합성 완료 차트 1만 건을 생성했다. 기존 첫 화면은 조회 한 번에 25건을 반환했다. 단어 검색은 검색용 필드를 500건씩 읽고 표시할 최대 25건의 상세만 가져온다. 검색 API와 로컬 DB를 연결한 시험에서 10건이 일치한 검색은 약 1.7초, 9,990건이 일치한 검색과 그 다음 페이지는 약 1.7~1.8초였다. 이 측정에는 로컬 DB 호출 도구의 시간도 포함된다. 긴 계통별 SOAP와 병원 네트워크에서의 응답 시간은 별도로 확인할 항목이다.

브라우저진료 차트와 통합 검색에서 같은 화면을 열었다. 기본 7건, 작성 중 포함 11건인 합성 자료에서 ‘구토 초음파’로 모카 한 건을 찾았다. 원본과 영상 확대, 좁게·넓게 보기, 기존 차트 복사 후 검색어 유지, 새 차트와 대기 후 재개를 확인했다. 적용한 차트로 이동했다가 검색으로 돌아왔을 때 ‘구토’ 검색어, 모카·탄이·보리 순서, 열어 둔 모카 원본까지 유지됐다.
인증부터 저장까지격리한 로컬 인증 서버에 합성 수의사로 로그인했다. 실제 API로 원본을 읽고, 용량·횟수·기간을 1정·하루 1회·2일에서 2정·하루 2회·4일로 수정했다. 대상에서 새 미확정 오더를 다시 읽었다. 원본 값과 대상의 기존 S 문장은 유지됐다. 같은 요청을 두 번 보냈을 때 요청 이력은 한 건이었다.
DB 회귀 검사다른 환자에게 가져온 S 문단을 기존 차트 저장 기능으로 수정하고 원본이 유지되는지 확인했다. 이전 텍스트·블록 문서와 계통별 SOAP, A/P 문단 교체, 원래 주진단과 새 주진단의 공존, 대상 작성자와 복사자 구분, 원본 첨부 제외, 현재 카탈로그와 처방 단위, 쓰기 권한·오래된 버전 거부를 검사했다. 마지막 오더에서 실패하면 앞서 고른 SOAP도 저장되지 않았다. 수행 작업·청구·수납 생성 수는 0건이었다. 실행한 SQL
오더 조회·복사 권한격리한 합성 DB에서 일반 오더 입력과 같은 권한을 확인했다. 오더 목록 조회 권한이 있는 역할은 현재 단가를 확인하고 미확정 오더를 추가했다. 해당 권한이 없는 차트 편집자는 과거 오더명을 읽고 SOAP 문단을 복사했다. 서버는 현재 단가와 사용 가능 여부를 숨기고 오더가 포함된 적용·대기 요청을 거절했다. 대기 중 권한이 해제된 경우에도 선택했던 오더 단가를 반환하지 않았다.
복사 직전 환자 삭제격리한 합성 DB에서 대상 선택 후 환자가 삭제되면 기존 차트 적용, 새 차트 생성, 복사 대기, 첫 차트 재개가 모두 거절됐다. 새 차트·오더·대기·복사 이력 건수는 그대로였다. 두 DB 연결에서 삭제와 복사를 동시에 실행해 먼저 잠근 작업의 결과를 다음 작업이 확인하는 것도 검증했다. 브라우저에서는 네 경로에 삭제 응답을 주고 원본을 유지한 채 다른 대상에 다시 적용하는 흐름을 확인했다.
검색과 페이지단어 순서·부정 표현·날짜 경계·작성자·담당의·대표 첨부를 비교했다. 같은 진료 시각의 완료 차트 27건을 두 페이지에서 중복 없이 읽었다. 검색 회귀 검사
프로젝트 검증타입 검사, 변경 파일 린트, 실제 DB 환경 변수를 제외한 로컬 빌드가 통과했다. 검색·SOAP·다중 차트 테스트 24개를 통과했다. Storybook에서 완료·작성 중 결과 행 두 개의 상태, 검색어 강조, 첨부 없음과 복사 메뉴를 확인했다. 기존 개발용 모의 서버를 처음 기동하면 첫 오더 저장 검사 한 건이 실패할 수 있었다. 변경 전 main에서도 같은 현상을 재현했다. 두 조회 경로를 먼저 연 뒤 24개를 다시 실행했다.

위 미리보기는 실제 화면 컴포넌트에 브라우저별 합성 기록을 연결한다. 로그인부터 저장까지의 검사는 별도로 격리한 실제 인증 서버·DB에서 실행했다. 복잡한 검색은 병원별 후보를 묶음으로 읽어 관련도를 계산한다. 대형 병원 기록량에서의 응답 시간과 여러 기기의 동시 편집은 배포 전 검토 항목이다.

목표와 범위

두 진입점에서 같은 검색을 열고 사례를 비교한 뒤 선택한 한 차트에 내용을 복사한다. 새 접수의 첫 차트에서도 작업을 이어간다. 이번 범위는 로컬 코드, 마이그레이션 파일, 격리된 합성 데이터 시험, 브라우저 확인이다. PR 검수 배포에는 탭 안에서만 저장되는 합성 차트를 제공한다. 새로 고치면 초기화된다. 검수 후 승인된 두 마이그레이션을 적용하고 운영 앱을 배포한다.

작업 순서

단계작업완료를 확인하는 방법
1 · 화면과 계약확정 PRD 및 피그마 30~32번과 서비스 업무 탭·문서 제목·서랍을 대조한다. 자료 귀속, 읽기·쓰기 요청과 충돌 응답을 고정한다.1440px·넓은 데스크톱·작은 화면에서 검색 조건, 결과 스캔, 원본 읽기, 복사 동선을 확인한다.
2 · 읽기병원과 열람 권한을 검증하는 읽기 경로를 만든다. 같은 방문에 차트 둘, 계통별 소견, 출처 불명 오더, 부정 표현과 여러 첨부가 포함된 합성 자료를 준비한다.초기 완료 목록, AND/OR 필터, 모든 단어 일치, 부정 순위, 첨부 선택, 페이지 경계의 동일 시각 결과를 검사한다. 권한 밖 건수와 자료가 나오지 않아야 한다.
3 · 서비스 화면차트 이력 옆과 통합 검색에 진입점을 둔다. 서비스 컴포넌트로 검색·목록·서랍·복사 대화상자를 연결한다.양쪽 진입, 좁게/넓게 전환, 서랍 닫기, 첨부 확대, 키보드 포커스 복귀, 입력을 바꾼 뒤 늦게 돌아온 이전 응답 처리를 확인한다.
4 · 기존 차트 적용원본과 대상의 버전을 확인하고 S/O·A/P·진단·미확정 오더를 한 번에 기록한다. 항목별 미리보기와 변경 이력을 연결한다.기본 추가·선택 교체·주진단 복수 유지·처방 수정·중복·사용 중지 항목을 검증한다. 부분 실패·재시도·동시 적용 결과를 격리 DB에서 대조한다.
5 · 새 차트와 재개진료 중 방문의 추가 초안과 대기 방문의 첫 차트를 구분한다. 접수로 넘긴 복사를 사용자·방문에 연결하고 첫 차트에 이어가기 동작을 둔다.검색 닫기 → 다른 방문 → 대상 호출 → 첫 차트에서 재검토 → 적용을 확인한다. 선택된 값, 생성 차트 수, 복사 이력 수를 전후 비교한다.
6 · 통합 검토로컬 서버에서 두 진입점을 직접 사용한다. 발견된 화면·상태 문제를 고치고 해당 시나리오를 다시 실행한다.사용자가 같은 URL에서 재현할 수 있는 검토 경로, 실제 실행한 검사, 남은 제한을 기록한다.

수의사가 할 일확인할 결과
‘구토 초음파’ 검색같은 차트에서 두 단어가 일치한다. 대표 첨부는 해당 차트의 초음파이고, 다른 방문 자료가 섞이지 않는다.
좁게 보기에서 원본 열기목록은 가운데, 서랍은 오른쪽에 있다. 첨부 없는 행에도 같은 크기의 없음 영역이 있다.
주진단이 있는 대상에 다른 진단 복사기본 해제와 직접 체크 두 경우를 시험한다. 기존 진단 구분·주진단 표시가 유지된다.
접수한 뒤 검색 닫기새 검색은 최근 완료 차트로 시작한다. 같은 방문 첫 차트에서 복사 이어가기를 누르면 앞서 고른 원본·선택값이 보인다.
재시도와 권한 변경저장 실패 후 같은 요청을 반복하거나 대상이 이미 변경된 상태를 만든다. 성공 이력은 한 번이며 권한이 없으면 대상 기록에 변화가 없어야 한다.

전달 기준

실행한 검증과 예정된 검증은 구분한다. 배포 전에는 후보 커밋, 데이터 귀속·권한·충돌 회귀, 배포 환경과 롤백 절차를 해당 릴리스에서 확인한다. 로컬 검토 결과는 이 문서에 연결한다.
