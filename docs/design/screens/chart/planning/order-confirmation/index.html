CHART / ORDER CONFIRMATION

무엇을, 몇 건 확정하는지 먼저.

루멘의 추천은 목록형 다이얼로그야. 제목에서 건수를 확인하고, 오더 이름과 금액을 검토한 뒤 확정해. 기술 설명은 걷어내고, 이번 행동에 필요한 정보만 남겨.

구조 비교
상태별 시안

버튼은 시안 안에서만 반응해.
실제 확정·저장·결제는 일어나지 않아.

560px 폭으로 오더명과 금액을 나눠 읽고, 합계와 확정 버튼을 하단에 모아.

검토용 시안 · 서비스에 연결되지 않음

현재 화면에서 확인한 문제

  1. 대상을 식별할 수 없음. 운영 화면의 다이얼로그는 1건과 5,000만 표시하고 오더 이름을 보여주지 않아.
  2. 설명이 대상을 앞섬. ‘원자적으로’, ‘공유 Draft’, ‘transaction’이 제목 직후 가장 큰 면적을 차지해.
  3. 시각적 위계가 평평함. 환자·차트번호·건수·금액·재요청 없음이 하나의 작은 설명 상자에 섞여 있어.
  4. 버튼이 판단을 돕지 못함. ‘다시 확인’은 어디로 돌아가는지, ‘Order 확정’은 몇 건을 확정하는지 알려주지 않아.

유지할 점: 확정 전 재검토 기회와 분리된 보조/주요 행동은 이미 있어. 환자·보호자·차트번호는 승욱의 피드백에 따라 이 확인창에서 제외했어. 분류·수량 서브 텍스트, 미선택 안내, 수행 기록 입력도 제외하고 보조 버튼은 ‘취소’로 정리했어. 오더 타입은 이름 앞 작은 배지로 표시해.

판단 근거와 적용

NN/g · Confirmation Dialogs는 확인창에 대상과 행동의 결과를 구체적으로 쓰고, 버튼 자체가 행동을 설명하도록 권고해. 그래서 오더명 목록 + N건 확정을 중심으로 제안해.

NN/g · Progressive Disclosure에 따라 보조 정보만 접어. 오더명·타입 배지·건수·금액·재요청 표시는 기본 노출하고, 세트 상세 구성만 펼쳐 보게 해.

W3C · Modal Dialog Pattern에 맞춰 실제 구현에서는 초기 초점, Tab 이동 범위, Escape 닫기, 닫힌 뒤 초점 복귀를 검증해야 해.

근거 수준: 현재 화면 관찰 + 로컬 코드 확인 + 공개 UX 지침. 실제 사용자 테스트로 개선 효과를 입증한 결과는 아님.

문구와 정보 우선순위

위치제안 문구 / 정보노출 규칙
1. 제목오더 N건을 확정할까요?이번 요청의 선택 오더 수. 수량 합계와 구분.
2. 선택 목록타입 배지 / 오더명 / 행 금액선택한 오더만 원래 순서로 표시. 재요청 표시는 해당 행에만.
3. 금액선택 오더 합계 35,000원현재 선택의 금액. 수납 완료·최종 결제 금액으로 표현하지 않음.
4. 행동취소 / N건 확정‘취소’는 창을 닫고 선택을 유지. 처리 중 ‘확정 중…’.

시각·상호작용 기준

  • 기존 CLAiR 흰색 표면, 중립색 경계, 검정 주요 버튼을 유지. 새로운 강조색이나 중첩 카드 추가는 불필요.
  • 추천 폭 560px, 좁은 화면에서는 좌우 16px 여백. 패딩 24px, 제목 18px, 오더명·본문 14px를 기준으로 기존 의미 토큰 사용.
  • 오더명은 잘라 숨기지 않고 줄바꿈. 오더 수가 많으면 본문만 스크롤하고 제목·행동은 유지.
  • 세트는 선택한 상위 오더 1건으로 표시하고 펼침 버튼의 ‘구성 N항목’으로 구분. 하위 구성과 부모 금액을 중복 합산하지 않음.
  • 목록에서 체크박스를 또 제공하지 않음. 수정하려면 취소 후 기존 선택 화면에서 변경.

반드시 보존할 예외

  • 확정창은 오더 검토와 확정에 집중. 수행 기록 입력 화면과 해당 상태 시안은 이번 제안에서 제외.
  • 재요청은 해당 행에만 표시. ‘재요청 없음’은 삭제.
  • 구현은 기존 선택 범위 금액 계산을 유지하고, 세트는 포함된 구성 오더의 청구 금액을 합산해. 금액 확인 불가 상태는 검토용 시안이며, 별도의 금액 검증 정책 변경은 이번 구현 범위에 포함하지 않아.
  • 충돌·처리 결과 불명확 상태는 ‘실패했으니 다시 확정’으로 단정하지 않고 최신 상태 확인과 기존 재시도 보호를 유지.

구현 계획

01 / 데이터의 의미 고정표시와 확정 대상을 같은 집합으로

confirmationOrderIds/Rows에서 목록·건수·합계를 파생. 세트·제외 구성·재요청·0원·금액 미확인 케이스를 먼저 점검. 로컬 WIP와 배포본 차이도 확인.

02 / 화면 구성 교체오더 전용 본문으로 좁게 변경

module.tsx의 확정창에 이름 목록과 합계를 배치. 기존 Dialog·Button과 의미 토큰 재사용. 공유 확인창 전체의 폭을 바꾸지 말고 이 화면에만 560px 적용. 확정창에 수행 기록 입력은 배치하지 않음. 구버전 V1 오더에 필수인 수행 기록은 별도 선행 단계에서 입력한 후 이 확인창으로 진행. V2·일반 오더는 바로 확인창 표시.

03 / 회귀·사용성 확인보기 쉬운지, 같은 항목이 확정되는지

행 단독 확정/다중 선택/세트/재요청/충돌/재시도 검증. 키보드·작은 화면·긴 목록 점검. 사용자가 대상·건수·동작 결과를 정확히 설명하는지 짧은 과업 테스트.

수용 기준

  • 제목 건수 = 목록 상위 오더 수 = 버튼 건수 = 실제 전송 대상 수.
  • 전체 오더 이름과 금액을 확인할 수 있고, 타입은 작은 중립색 배지로 표시하며 분류·수량 서브 텍스트는 표시하지 않음.
  • 선택하지 않은 오더는 기존대로 미확정 상태를 유지하되, 확인창에서 이를 반복 안내하지 않음.
  • 권한·충돌·중복 요청 방지와 기존 확정 API 계약 유지. 구버전 V1의 필수 수행 기록은 별도 선행 단계로 보존.
  • 목록을 긴 DialogDescription 한 덩어리에 넣지 않고 의미 있는 본문으로 분리. 스크린리더 순서와 레이블 검사.

확인 범위와 남은 검증

초기 조사는 운영 확인창을 읽기 전용으로 진행했어. 2026-09-22 승욱이 최종 타입 배지 시안과 문서 반영, 구현·검증·PR·main 머지·배포를 승인했어. 구현과 배포 증거는 연결된 작업 문서에서 별도로 기록해.

로컬 소스에는 운영 캡처와 문구가 다르고, 조건부 수행 입력도 있어. 모든 로컬 코드가 현재 배포됐다고 가정하지 않았어.

이 페이지는 UI 검토용 샘플이야. 7개 상태와 버튼 피드백은 가상 데이터로 동작하며, 실제 저장·포커스 트랩·서버 오류 회복을 구현한 화면은 아니야.
