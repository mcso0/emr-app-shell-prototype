최신 제품 결정과 구현 현황

이전 추천안을 아래 결정으로 대체했다. 컬럼명은 할인/할증과 %이며, 로컬 구현·집중 테스트·빌드와 승인된 DB 변경 검증이 완료됐다. 앱 배포와 사용자 검수는 아직 완료로 표시하지 않는다.

PR·배포 검증 단계

DEC-01 · 명칭 정정 / 기존 부호 유지

컬럼명은 할인/할증 및 %. 금액·비율은 같은 조정값으로 양방향 연동한다. 음수는 할인, 양수는 할증이며 한 번만 적용한다. 캡처는 명칭만 참고하고 기존 디자인과 폭114/72px은 유지한다.

기준100,000원: -10,000원 ↔ -10% → 90,000원
+10,000원 ↔ +10% → 110,000원
0원 ↔ 0% → 100,000원

DEC-02 · 확정

할인/할증 사유는 자유 입력·optional. 할인/할증이 있어도 빈 사유 허용. 설정 목록 선택과 필수 검증을 제거하는 서버·SQL 변경도 준비 범위에 포함.

DEC-03 · 반영 방향

별도 단위 컬럼 삭제 → 목표26개(고정4+스크롤22). 필요한 값과 인풋에 해당 데이터의 단위를 표시. 임의 변환·dose/strength/dispense fallback 금지.

DEC-04 · 확정

업무 담당:24px avatar trigger + picker; 이름은 hover/focus로 제공. 미지정 기본 아이콘, 로딩/저장 상태, 실패 시 기존값, readonly에서는 picker 없음.

DEC-05 · 확정

known ON/OFF만 switch; unknown은 Neutral400 `-` 및 데이터 없음 설명. 과세 readonly, 청구반영은 기존 편집 가능 조건 유지; saving 잠금/실패 복원.

DEC-06 · 확정

Order 명 기본180 / 최소160 / 최대400px. 오른쪽 최소240px 확보, 불가능하면 전체 가로 스크롤로 전환(고정 해제). 너비는 화면 수명 동안 유지, 초기화180; 영구 저장 없음.

DEC-07 · 확정

현재 확정 여부 오름차순과 정렬 기능·아이콘 유지(시안 차이 기록). 총횟수 숫자 정렬 추가. 실제 정렬 가능한 헤더만 아이콘. resize는 sort로 전파하지 않음.

진행 역할: 루멘이 범위·통합·검증 감독, gpt-5.6-luna / xhigh가 구현 담당. 원본 WIP와 분리한 작업 사본에서 구현 중이다. Jev는 자료 우선순위와 마지막 누락 점검에만 사용하며 테스트를 대체하지 않는다.
구현 순서: A 레이아웃·단위·정렬 → B 상태·아바타·공유 컨트롤 → C 연동 계산·optional 사유의 UI/API/SQL → D 통합 검증.
승인 범위: TDD 통과 후 커밋·푸시·PR·origin/main 머지·배포. 별도로 설명한 원격 사유 제약/RPC 변경과 합성 데이터 검증도 승인되었다. 정확한 대상과 migration 검증 후 적용하며, 구 DB가 빈 사유를 거부하는 상태로 새 UI를 배포하지 않는다. 오래된 migration은 수정하지 않는다.

이번 구현에 반영한 UI 수정사항
  • 고정/스크롤 경계: 헤더와 body에 1px 세로 라인이 보이고, `Order 명` 리사이즈는 같은 8px 영역의 투명 hit area로 유지한다. body에는 Grab 없이 투명 8px gap만 둔다.
  • 스크롤 헤더: 스크롤 컬럼의 Grab은 헤더에만 있고 body에는 없다. 업무 상태는 88px 이상으로 onChange 리사이즈할 수 있다.
  • 빈 값: 데이터가 없는 셀은 Neutral400 ASCII `-`로 통일하고, `계산 불가`처럼 의미가 있는 도메인 표기는 보존한다.
  • 입력 폭: 청구서명·수량·상세 필드·실제 조제량·할인/할증·사유 입력은 컬럼 폭에 따라 늘어난다. 시안의 6px trailing 및 10px leading inset은 보존한다.
  • 토글 정렬: `청구반영`과 `과세`의 헤더·row switch는 가로/세로 중앙 정렬이다. 과세는 read-only, 청구반영의 기존 저장 조건은 유지한다.
  • 고정 영역 스크롤바: terminal 8px gap까지 포함한 고정 폭 뒤에서 horizontal scrollbar가 시작해 checkbox/fixed cells 위에 나타나지 않는다.

SQL은 percent source에서 round(base×percent/100)로 KRW 정수 금액을 만들고 amount source에서 역산 비율을 만든다. allowlist 검사는 nonzero 조정일 때 적용된다. 현재 UI는 설정된 사유만 선택하지만 최신 목표는 자유 입력·optional이다. 서버와 SQL 검증도 함께 변경해야 한다.

단위 DEC-03 예시는 임상 용량 지시가 아닌 합성 표시 예시다: dose=2 tablet, productStrength=10 mg/1 tablet, dispense=6 tablet이면 현재 1회당=2 tablet / 성분량=10 mg/tablet / 조제량=6 tablet로 서로 다른 의미가 섞여 있다. 주사형 dose=1 mL, strength=20 mg/mL, dispense=3 mL도 같다. 단위 컬럼은 삭제하고 각 값에 자체 단위를 유지한다. 값이 없는 비약품 행에는 임의 단위를 만들지 않는다.
