Hospital Admin Order Catalog Sort / Filter Behavior

이번 작업은 수납, 차트, 고객관리에서 검증한 정렬/필터 정책을 병원관리 오더 카탈로그 테이블에 제한 적용한 것이다. 기존 카테고리 탐색, 검색, 상태/청구/작업유형 필터, row action, 상세 drawer는 유지하면서 테이블 값이 안정적인 컬럼만 정렬/필터 대상으로 삼았다.

무엇이 바뀌었나

  • 병원관리 오더 카탈로그 테이블 헤더에서 단일 컬럼 정렬을 실제 row 순서에 적용한다.
  • 정렬은 없음 → 오름차순 → 내림차순 → 없음 순서로 바뀐다.
  • 정렬은 표준 오더명, 원내 오더명, 청구명, 판매금액 컬럼에 제한했다.
  • 필터는 테이블 헤더가 아니라 오더 카탈로그 섹션 오른쪽의 Filter 버튼에서 연다.
  • 필터는 상태, 대상, 서비스 항목 유형, 청구 연동, 판매금액 조건을 지원한다.
  • 조건이 여러 개면 기존 카테고리/검색/상태/청구/작업유형 결과 위에서 AND로 적용된다.
  • 필터 조건이 있으면 버튼이 Filter N으로 조건 수를 보여준다.
  • Save view, saved filters, active chip row, multi-sort는 넣지 않았다.

보존한 것

  • 기존 카테고리 내비게이션과 검색, 상태/청구/작업유형 필터를 유지했다.
  • 오더 선택, row action 메뉴, 상세 drawer 열기와 편집 흐름을 유지했다.
  • column visibility, density 설정, mock auth/session, local-first workflow를 유지했다.
  • Supabase, DB/RLS, 서버 정렬/필터, URL/localStorage persistence, 가격 정책 변경은 이번 범위에서 제외했다.

Evidence

Mock auth storage state로 실제 병원관리 오더 카탈로그 화면을 열고, 로그인 화면이 아닌 테이블을 캡처했다.
