Focus in.
Focus out.

네비 레일의 사이드 패널 버튼이 갑자기 생기고 사라지는 대신, 짧은 이동과 초점 전환을 통해 자연스럽게 나타나고 퇴장하는 세 가지 구현 방안을 비교한다.

Executive decision

현재 앱에 이미 설치된 framer-motion 12.38.0을 유지하고, 토글 래퍼에만 3px 이하 blur + opacity + 4px 이동을 속성별 tween으로 추가하는 A안을 권장한다.

대상NavRail 사이드 패널 토글
현재 소유 파일src/shell/nav-rail.tsx
현재 런타임React 19.2.4 · Framer Motion 12.38
이번 범위리서치·시안만, 앱 코드 변경 없음

먼저 결론

버튼 하나의 자연스러운 등장에는 새 애니메이션 스택보다 기존 Motion의 속성별 제어가 더 적합하다.

A안 권장

A. Motion Focus Fade

현재 AnimatePresence와 useReducedMotion을 그대로 사용한다. 버튼 래퍼만 blur(3px) → blur(0), opacity 0 → 1, y 4px → 0로 조정한다.

  • 새 의존성 없음
  • 기존 exit/unmount 계약 유지
  • 한 파일 안에서 진입·퇴장·reduced motion 관리

디자인 판단

blur는 “흐릿한 물체가 선명해진다”는 인상을 주지만, 24px 아이콘에서는 값이 조금만 커도 번져 보인다. CLAiR에는 2–3px, 120–180ms가 적당하고 6px 이상의 cinematic blur는 피하는 편이 안전하다.

추천 방안 3가지

시각적 결과와 코드 소유권을 함께 비교했다. 각 버튼은 위 인터랙티브 시안으로 연결된다.

OPTION 01 · RECOMMENDED

Motion Focus Fade

기존 Motion 컴포넌트에 filter, opacity, y의 속성별 transition을 추가한다.

  • 가장 작은 변경 범위
  • React unmount와 exit가 이미 해결됨
  • 현재 reduced-motion 분기 재사용
적합성9.6
제어력9.0
복잡도낮음
OPTION 02 · LIGHTEST

CSS Soft Dissolve

CSS keyframes 또는 transition으로 blur와 opacity를 표현한다.

  • 런타임 의존성은 가장 적음
  • 스타일 토큰화가 쉬움
  • React exit 완료 시점 관리는 별도 필요
적합성7.2
제어력6.8
복잡도중간
OPTION 03 · REVERSIBLE

WAAPI Reversible Focus

Element.animate()와 Animation.reverse()로 빠른 재클릭을 직접 제어한다.

  • 중단·반전·재생 속도 제어 우수
  • 추가 패키지 없음
  • ref, cleanup, DOM lifecycle 코드가 늘어남
적합성6.3
제어력9.8
복잡도높음

“가능한가”가 아니라 현재 CLAiR 코드에 얼마나 정직하게 들어가는지를 기준으로 비교했다.

Motion Focus Fade · 기본값

  • Enter: 180ms, [0.16, 1, 0.3, 1], blur 3px, y +4px
  • Exit: 120ms, [0.4, 0, 1, 1], blur 2px, y -3px
  • Blur 대상: 버튼과 첫 divider를 감싸는 현재 motion.div만
  • Layout: 기존 네비 아이템의 spring은 우선 유지하고, 이중 움직임이 보이면 후속 조정
  • Reduced motion: transform·blur 제거, opacity만 80–100ms 또는 즉시 표시

접근성·성능·검증

blur를 추가해도 버튼의 의미, 키보드 접근, 레이아웃 안정성이 약해지면 안 된다.

필수 안전선

  • aria-label과 tooltip 계약은 그대로 유지한다.
  • blur는 최대 3px로 제한하고 전체 nav rail이나 side panel에 걸지 않는다.
  • prefers-reduced-motion에서는 y·blur를 제거한다.
  • 지속적인 will-change는 추가하지 않는다.
  • 패널 접기 후 키보드 focus가 사라지는지 별도 확인한다.

구현 시 검증

  1. 열기·접기 URL 및 상태 회귀 Playwright
  2. 60fps trace 또는 브라우저 performance inspection
  3. 빠른 더블 클릭·반대 방향 재클릭
  4. OS reduced motion 켜짐/꺼짐
  5. 390px 좁은 화면과 200% zoom

라이브러리·플러그인·스킬 조사

런타임 라이브러리와 에이전트 스킬은 역할이 다르다. 스킬은 구현 가이드이며 앱 의존성이 아니다.

런타임 판단

  • Framer Motion: 현재 설치되어 있어 A안에 추가 비용이 없다.
  • CSS: 단순 효과에는 충분하지만 현재 React exit 계약을 다시 풀 이유가 없다.
  • WAAPI: 반전 제어는 강하지만 버튼 하나에는 imperative code가 과하다.
  • GSAP: 복합 timeline에는 훌륭하지만 이번 24px 토글에는 새 의존성이 과하다.

스킬 후보

  • wshobson/agents@interaction-design: 11K installs, 37.9K GitHub stars. microinteraction·easing·reduced motion을 폭넓게 다룬다.
  • jezweb/claude-skills@motion: Motion 전용이지만 788 installs로 품질 확인을 더 거쳐야 한다.
  • 현재 작업에는 이미 설치된 frontend-design으로 시안을 만들기에 충분해 추가 설치는 권장하지 않는다.
