Iconly 사용 방식

Iconly Pro는 Animated/Motion icon을 Figma plugin과 Web App으로 제공하고, 공식 설명상 JSON 기반의 60fps animation asset을 제공한다. Iconly API는 별도 iconly.ai 생성 API로 확인되며 API key가 필요하므로 이번 산출물에서는 실제 호출을 하지 않았다.

API 제한 메모 공식 API 문서 기준으로 모든 요청은 X-API-Key가 필요하다. 현재 세션에는 Iconly API key가 제공되지 않았고, 비용/토큰이 발생할 수 있어 실제 생성 호출은 하지 않았다. 아래 시안의 아이콘은 Iconly Motion asset 검색 키워드와 API fallback subject로 지정한다.

Figma 기준

기준 노드는 emptyPlaceholder이며 세 변형은 style=Default, style=1 action, style=2 action이다. 이번 제안은 그 구조를 상태별로 확장한다.

Figma 스타일 이번 보고서의 대응 권장 용도
Default 액션 없음 사용자 행동이 필요 없거나, 상위 화면의 기본 액션이 이미 충분히 보이는 상황
1 action primary action 1개 가장 명확한 다음 행동이 하나 있는 상황
2 action primary + secondary action 주 행동과 우회 또는 보조 행동을 함께 제공해야 하는 상황

18개 시안

추천 우선안

State 먼저 채택할 시안 이유
no-data B. 첫 업무 생성 실제 empty state의 가장 흔한 해소 행동이 생성 흐름이기 때문이다.
no-search-results B. 검색어 초기화 검색 상태의 가장 빠른 복구 행동은 현재 query를 지우는 것이다.
no-filter-results B. 필터 초기화 필터로 가려진 항목을 복구하는 대표 행동이 명확하다.
no-scope-result C. 날짜/범위 변경 날짜, 환자, encounter, workspace처럼 scope가 원인인 상태를 가장 잘 설명한다.
no-permission B. 권한 확인 단순 빈 화면처럼 보이지 않게 하고 다음 확인 경로를 제공한다.
upstream-pending B. 상위 workflow 이동 데이터가 생기는 원천 화면으로 연결해 사용자가 기다릴지 이동할지 판단할 수 있다.

구현 전 체크

  • 실제 Iconly Pro Motion 자산을 쓰려면 구독/라이선스와 Figma plugin 또는 Web App 접근 권한을 확인한다.
  • Iconly API를 통해 직접 생성하려면 API key, 토큰 비용, rate limit을 먼저 확인한다.
  • no-permission이 실제 차단/복구 상태라면 EmrInlineAlert가 더 적합할 수 있다.
  • 좁은 side panel에서 한국어 버튼이 줄바꿈 또는 overflow 없이 동작하는지 Playwright로 확인한다.
  • Motion 아이콘은 장식용이면 aria-hidden, 의미용이면 제목/설명과 중복되지 않는 대체 텍스트를 정한다.

사용한 스킬과 플러그인

  • frontend-design: 최종 HTML 보고서의 정보 구조와 시각 표현에 사용.
  • context-hub-docs-router: 외부 API 문서 확인 방식과 API key/비용 제한 판단에 사용. 로컬 chub CLI는 사용할 수 없었다.
  • Figma plugin: 사용자가 준 Figma 노드의 세 변형 구조를 재확인하는 데 사용.
  • Web search: Iconly Pro Motion icon, Iconly API, 라이선스 안내를 현재 기준으로 확인하는 데 사용.
