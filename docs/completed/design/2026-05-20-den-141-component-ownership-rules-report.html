컴포넌트 추출 및 소유권 기준

요약

화면 리팩토링 때 UI 코드를 어디에 둘지 판단하는 기준을 만들었다. 핵심은 “가장 작은 안정적인 소유자”를 선택하는 것이다. shadcn/ui는 일반 UI 동작, EMR 컴포넌트는 반복되는 업무 화면 패턴, feature-local 컴포넌트는 아직 한 화면의 workflow 의미가 강한 블록을 맡는다.

정책

  • 기본 primitive는 src/components/ui/*를 우선 사용한다.
  • EMR 화면 전반에 반복되는 안정된 업무 패턴은 src/components/emr/*로 둔다.
  • SOAP, 진단 검색, 접수 등록, 수납 invoice, hospital admin drawer field처럼 workflow 의미가 강하면 먼저 feature-local로 분리한다.
  • 두 개 이상의 화면군에서 같은 UI 역할이 안정적으로 반복될 때만 새 EMR 공통 컴포넌트를 만든다.
  • 컴포넌트 추출 중 route, drawer, tab, keyboard/focus, test id, session-only behavior는 유지한다.

검증 결과

  • components.json에서 shadcn 설정이 base-nova, Base UI, @/components/ui alias임을 확인했다.
  • Button, Dialog, Field, Select, DropdownMenu 등 주요 shadcn/ui primitive와 EmrIconButton, EmrTableCheckbox 등 EMR wrapper를 확인했다.
  • ui-debt-inventory.md와 기존 DESIGN.md 방향에 맞춰 규칙을 정리했다.
  • 구현 추출, DB, Supabase, RLS, live persistence, server enforcement 변경은 하지 않았다.
  • npm run docs:check 검증 대상이다.
