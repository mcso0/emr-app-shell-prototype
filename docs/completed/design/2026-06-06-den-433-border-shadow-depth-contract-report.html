DEN-433 Border/Shadow Depth Contract Report

2026-06-06 · 공통 UX/UI 기준 정리 및 화면 적용

요약

CLAiR EMR의 border, radius, shadow depth 사용 기준을 공통 디자인시스템 contract로 정리했다. 후속 대기열, 환자정보바, SOAP, tab/table density, empty/info box 적용 이슈가 같은 기준을 참조할 수 있는 상태다.

승욱이 지금 확인할 것

이 이슈는 화면 구현 결과물이 아니라 후속 UI 작업을 판단할 기준 승인이야. 지금 볼 것은 "이 기준으로 다음 화면들을 고쳐도 되는가"야.

  • 정보만 담는 카드/패널/테이블은 shadow 없이 flat하게 두는 방향이 CLAiR 화면에 맞는지
  • 클릭해서 열기/이동/추가/생성/삭제/조회/메뉴 실행이 가능한 요소에는 가장 낮은 E1 shadow를 주는 기준이 맞는지
  • 더 강한 shadow는 popover, drawer, dialog 같은 떠 있는 UI에만 쓰는 제한이 괜찮은지
  • 선택/경고/focus 상태를 shadow가 아니라 border, surface, status token으로 표현하는 기준이 납득되는지
승인하면 다음 화면 이슈에서 이 기준을 적용

주요 결정

  • 정보만 담는 화면 안쪽 UI는 flat이 기본이고, 구조 구분은 surface와 1px border가 담당한다.
  • 액션 가능한 요소는 가장 낮은 E1 shadow를 써서 클릭 가능성을 미리 알려준다.
  • 중간 이상 shadow는 실제 depth가 있는 floating surface, drawer, dialog, command overlay에만 제한한다.
  • 선택, focus, dirty, warning, danger, disabled 상태는 generic shadow가 아니라 state/status token으로 표현한다.
  • 새 elevation token은 이번 이슈에서 만들지 않고, 반복 역할이 증명된 구현 이슈에서만 제안한다.

기준 요약

구분 기준 후속 화면에서 확인할 것
일반 패널/카드 1px hairline border + flat surface 정보-only 카드가 여러 겹으로 떠 보이지 않고, 내용 위계가 border/간격/타이포로 읽히는지
액션 가능한 요소 E1 lowest shadow + hairline border 열기/이동/추가/생성/삭제/조회/메뉴 트리거가 눌러도 되는 요소로 미리 보이는지
선택 상태 selected surface + selected border 선택된 row/card가 hover와 구분되지만 과하게 튀지 않는지
상태 안내 info/warning/danger/success status border와 surface 경고나 오류가 단순 shadow가 아니라 의미 있는 색/문구/액션으로 보이는지
Floating UI popover/dropdown/menu는 medium shadow 허용 떠 있는 메뉴가 아래 화면과 분리되어 보이고 닫힘/접근성 동작이 유지되는지
Overlay UI drawer/dialog/command palette는 strong shadow 허용 사용자가 현재 작업 레이어가 바뀐 것을 즉시 이해하는지

시각 샘플

실제 화면 구현은 아직 아니지만, 후속 화면에서 지향해야 하는 depth 차이는 아래처럼 본다.

E0 Flat · 기본 화면 안쪽 UI

정보-only 패널, 테이블, 정보박스는 shadow 없이 얇은 border로만 구분한다.

E1 Action · 클릭 가능한 요소

열기, 이동, 추가, 생성, 삭제, 조회, 메뉴 실행 요소는 가장 낮은 shadow로 클릭 가능성을 알린다.

Selected · 선택/활성 상태

선택은 옆 띠 없이 selected surface와 전체 border로만 표현한다.

E2/E3 · 떠 있는 UI

popover, menu, drawer, dialog처럼 실제로 위에 뜨는 UI만 shadow를 쓴다.

적용 예시와 금지 예시

좋은 방향

  • 대기열 카드: flat + hairline border + selected surface/border
  • 추가/생성/삭제/조회/더보기 버튼: E1 shadow + hairline border
  • 카드 전체가 상세를 여는 경우: 카드 자체에 E1 shadow 적용
  • SOAP 섹션: 패널 border와 섹션 간격으로 구분
  • 정보박스: status tone과 action hierarchy로 의미 전달
  • 더보기 메뉴: popover shadow로 떠 있는 레이어 표현

피해야 할 방향

  • 정보-only 카드까지 모두 shadow를 넣어서 화면 전체가 떠 보이는 것
  • read-only table row 전체에 shadow를 넣어서 모든 행이 버튼처럼 보이는 것
  • 선택/경고/focus를 shadow 강도만으로 표현하는 것
  • 선택/활성 row나 card 옆에 띠처럼 보이는 side rail을 넣는 것
  • 패널 안에 또 장식 카드들을 중첩하는 것
  • feature 코드에 raw rgba shadow stack을 추가하는 것

제외 범위

  • 앱 코드 변경, 화면 리팩토링, 새 token 구현은 하지 않았다.
  • generated token 파일인 clair.css, shadcn.css는 수정하지 않았다.
  • live Supabase, migration, RLS, server enforcement, production deploy, real data는 건드리지 않았다.
