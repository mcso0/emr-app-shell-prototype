재사용 Popover 컴포넌트 조사 및 시안

Figma의 바이탈 입력 popover를 바로 도메인 전용으로 만들기보다, 환자 인포바와 여러 업무 화면에서 반복 가능한 조회·입력·선택·액션 popover 패턴으로 승격하는 방향을 검토했다.

Figma reference 280×279 header / content / footer 구조
Current primitive Base UI src/components/ui/popover.tsx
Direct popover use 검색/선택 품종, 보호자, 멀티 선택
Recommendation EMR shell generic popover 위에 업무용 wrapper

결론

새 엔진을 만들지 말고 기존 Popover primitive를 유지한 채, src/components/emr에 EmrPopoverShell 계열을 추가하는 것이 가장 안전하다. 이 shell은 헤더, 설명, body scroll, footer action, width, density, dirty/disabled 상태를 표준화하고, 바이탈·메모·간단 편집·검색 결과 선택 같은 도메인 내용은 호출부가 소유한다.

Popover 변형 제안

form 바이탈, 간단 메모, 수치 입력. header + compact fields + footer actions.
picker 보호자, 품종, 간단 항목 선택. search/input anchor + listbox body.
single-select 접수 등록 유형, 빠른 상태 전환. radio/card option + optional confirm footer.
multi-select 업무 필터, 표시 옵션, 다중 선택. checkbox list + apply/reset footer.
action-list 짧은 옵션/액션. 단순 row action은 menu, 값 조정은 popover로 제한.

의도

  • 상단 환자 인포바에서 환자 문맥을 잃지 않고 빠르게 입력한다.
  • 필수 수치 입력과 저장 액션이 있어 tooltip이나 menu가 아니라 form popover로 분류한다.
  • 저장 전 dirty 상태, validation, 저장 중 disabled 상태를 shell이 받을 수 있어야 한다.

시안 B · 검색/선택 Popover

보호자 검색
김보호 또는 010 검색 ⌘K
김보호010-1234-5678 · 연결 환자 2마리 선택됨
김보호자010-2234-5678 · 연결 환자 1마리 기존

의도

  • 현재 profile drawer의 보호자/품종 popover를 공통 row density로 정렬한다.
  • 입력 anchor 폭을 기본값으로 쓰되, 넓은 결과는 width="wide"로 확장한다.
  • 결과 선택 후 닫기, 빈 결과 안내, 직접 입력 fallback을 호출부가 결정한다.

  • Figma에서는 selection=radio, showFooter=true, showClose=true 조합으로 만든다.

옵션 및 상태 계약

허용 옵션

  • side, align, sideOffset: 기존 Base UI positioner props 전달
  • width: anchor, sm 236, md 280, lg 360
  • initialFocus: 검색/입력 anchor 유지가 필요한 경우 false 허용
  • footer: save/cancel, apply/reset, secondary action slot
  • bodyScroll: 목록/긴 폼에서 max-height와 overflow 표준화
  • selectionMode: single은 radio semantics, multiple은 checkbox semantics
  • closeOnSelect: single은 기본 true, multiple은 기본 false

금지할 패턴

  • interactive form을 tooltip에 넣지 않기
  • 단순 row action menu를 popover로 재작성하지 않기
  • popover shell이 환자/오더/수납 데이터 타입을 직접 받지 않기
  • 각 화면에서 임의 width, shadow, radius를 반복 정의하지 않기
  • 저장 mutation, 서버 검증, Supabase 범위를 이 컴포넌트 작업에 포함하지 않기

구현 이슈로 넘길 때의 권장 범위

  • 1차: EmrPopoverShell, EmrPopoverHeader, EmrPopoverFooter, EmrPopoverFieldRow 추가
  • 2차: EmrPopoverOption, EmrPopoverOptionGroup, RadioGroup 추가
  • 3차: 환자 인포바의 바이탈 버튼에 feature-local PatientVitalPopover 연결
  • 4차: 접수 등록 mode selection을 shared single-select option/card primitive로 정렬
  • 검증: lint, typecheck, 환자 인포바 browser QA, 접수 single-select keyboard 회귀 확인
