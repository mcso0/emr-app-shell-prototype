Customer Table Sort / Filter Behavior

이번 작업은 수납과 차트에서 검증한 정렬/필터 정책을 고객관리 테이블에 제한 적용한 것이다. 고객 검색, 프로필 drawer, 행 작업, 컬럼 표시 설정은 유지하면서 테이블 안의 의미가 안정적인 값만 정렬/필터 대상으로 삼았다.

무엇이 바뀌었나

  • 고객관리 동물/보호자 테이블 헤더에서 단일 컬럼 정렬을 실제 row 순서에 적용한다.
  • 정렬은 없음 → 오름차순 → 내림차순 → 없음 순서로 바뀐다.
  • 동물 테이블은 환자코드, 동물명, 나이/생년월일, 등록일시 정렬을 지원한다.
  • 보호자 테이블은 보호자명과 등록일시 정렬을 지원한다.
  • 필터는 테이블 헤더가 아니라 테이블 섹션 오른쪽의 Filter 버튼에서 연다.
  • 동물 테이블 필터는 품종, 성별, 상태, 수신 여부를 지원한다.
  • 보호자 테이블 필터는 동의 상태를 지원한다.
  • 필터 조건이 있으면 버튼이 Filter N으로 조건 수를 보여준다.
  • Save view, saved filters, active chip row, multi-sort는 넣지 않았다.

보존한 것

  • 기존 고객 검색은 유지되고, 검색 결과 위에서 추가 필터가 AND로 적용된다.
  • 동물/보호자 프로필 drawer 열기와 URL drawer 상태를 유지했다.
  • 행 선택, 행 작업 메뉴, 컬럼 표시 메뉴, density 설정을 유지했다.
  • mock auth/session, local-first customer workflow는 유지했다.
  • Supabase, DB/RLS, 서버 정렬/필터, URL/localStorage persistence, 실제 고객 데이터 import는 이번 범위에서 제외했다.

Evidence

Mock auth storage state로 실제 고객관리 화면을 열고, 로그인 화면이 아닌 고객 테이블을 캡처했다.
