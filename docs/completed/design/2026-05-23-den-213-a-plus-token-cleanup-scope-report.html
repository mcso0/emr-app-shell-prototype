DEN-213 A+ Token Cleanup Scope & Measurable Gates

A 등급 이후 남은 전역 spacing/font arbitrary utility, token/variant 전환, responsive QA, screenshot regression 후보를 같은 기준으로 판단할 수 있게 범위와 측정 gate를 고정했다. 이 문서는 다음 구현 이슈가 시작되기 전 승욱이 확인할 scope matrix다.

Linear: DEN-213 Project 11 Milestone: 00 A+ Scope & Metrics Status target: Human Review Docs-only

비개발자 요약

무엇을 정했나

A+는 화면을 새로 디자인하는 일이 아니라, 이미 A까지 올라온 대표 workflow를 해치지 않으면서 반복되는 임의 간격, 폰트, 폭, radius 값을 token이나 variant로 줄이는 작업으로 정의했다.

왜 중요한가

후속 이슈가 각각 다른 기준으로 “정리했다”고 말하지 않도록, 수치 기준, 예외 기준, responsive blocker 기준, screenshot 후보 기준을 먼저 고정했다.

무엇은 하지 않나

DEN-213은 구현 작업이 아니다. 화면 코드, live Supabase, DB migration, RLS, 결제, 이메일, 외부 연동, full mobile redesign은 전부 제외한다.

Exception discipline 예외는 owner, reason, affected module, user impact, revisit trigger를 포함한다. dense clinical/billing table min-width, icon alignment, viewport containment calc(), generated tokens는 정당화되면 허용한다. “나중에 정리”만 적고 이유나 재검토 기준 없이 arbitrary 값을 남긴다. 각 issue report의 remaining exceptions section
13px and odd-pixel typography/spacing 13px, 15px 같은 dense UI용 홀수 font size나 optical alignment용 홀수 간격은 금지 대상이 아니다. 다만 one-off arbitrary utility가 아니라 metadata, dense table body, menu item, compact label 같은 semantic role로 설명되고 token/variant 또는 documented local exception으로 남아야 한다. text-[13px] 자체를 제거 목표로 오해해 dense 화면의 가독성이나 수직 rhythm을 망가뜨린다. 또는 홀수 간격을 이유 없이 여러 call site에 새로 흩뿌린다. Out Of Scope

  • DEN-213 안에서 실제 token migration, UI component refactor, 화면 코드 수정은 하지 않는다.
  • live Supabase validation, DB migration, RLS, server enforcement, role/permission policy 변경은 제외한다.
  • 결제, VAT, 영수증, 환불, 정산, 이메일, KakaoTalk, PACS, 장비, 외부 provider 연동은 제외한다.
  • 전체 visual redesign, mobile-only redesign, IA 변경, table engine 교체는 제외한다.
  • 승욱 승인 전에는 Linear 이슈를 Done으로 이동하지 않는다.

리뷰 요청

다음 구현 이슈로 넘어가기 전에 승욱이 이 matrix에서 두 가지만 확인하면 된다. 첫째, A+ 후보 기준을 “baseline 대비 25% 이상 감소 + top repeated high-confidence 후보 처리/예외화”로 두는 것이 충분한지. 둘째, responsive blocker 기준을 “대표 viewport blocker 0개, low-risk debt 문서화 허용”으로 두는 것이 맞는지다. 추가로 dense UI에서 13px 같은 홀수 font size와 optical alignment용 홀수 간격은 금지가 아니라 semantic role과 예외 사유를 요구하는 것으로 해석한다.
