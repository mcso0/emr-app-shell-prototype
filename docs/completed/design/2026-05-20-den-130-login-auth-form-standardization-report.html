DEN-130 로그인/인증 폼 표준화 작업 보고

로그인 화면의 UI 상태 표현과 접근성 라벨을 정리해, mock/Supabase auth 동작을 바꾸지 않고 폼 품질만 보강했다.

변경 내용

  • src/features/auth/login-form.tsx에서 로그인 입력 설명과 오류 표시를 shadcn FieldDescription, FieldError 흐름에 맞췄다.
  • 제출 중에는 이메일/비밀번호, 역할 카드, 로그인 유지 radio가 비활성화되어 중복 입력이나 상태 흔들림이 생기지 않게 했다.
  • 역할 카드 접근성 이름을 제출 버튼과 충돌하지 않는 “역할 선택” 의미로 정리했다.
  • 반복되는 로그인 화면 폭/패널 class를 local 상수로 모아 의도적인 고정 폭 예외를 더 쉽게 확인할 수 있게 했다.

범위 제외

Supabase 로그인 구현, session model, safe next-url 처리, mock role sign-in, 서버 권한 enforcement, role/permission 정책은 변경하지 않았다.

검증

  • npx eslint src/features/auth/login-form.tsx tests/auth.spec.ts 통과
  • npx tsc --noEmit 통과
  • npx playwright test tests/auth.spec.ts --reporter=line: 첫 실행은 role button accessible name 충돌로 실패했고 수정 후 재실행했다.
  • npx playwright test tests/auth.spec.ts -g "non-admin roles cannot manage workspace invitations" --reporter=line 통과

리뷰 포인트

로그인 화면에서 “역할 선택” 카드와 제출 버튼의 이름이 명확히 분리되어 있는지, 제출 중 disabled 상태가 제품 감각에 맞는지만 확인하면 된다.
