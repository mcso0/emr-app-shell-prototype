DEN-395 전역 알림 센터 v0 계약 완료 보고서

전역 알림 센터 v0를 구현하기 전에 따라야 할 제품 계약과 fixture schema를 canonical 문서로 정리했다. 이제 후속 이슈는 badge, drawer, toast, read/archive, source navigation을 같은 기준으로 구현할 수 있다.

요청

오른쪽 drawer형 전역 알림 센터 v0 기획안을 구현 기준으로 바꾸고, requires_action, badge_count, toast_policy, recipient, source target, dedupe key, localStorage read/archive boundary를 명확히 정의한다.

변경

  • 새 canonical 문서 docs/product/features/notifications/global-notification-center-v0-contract.md를 추가했다.
  • v0 이벤트 10개를 event key와 source 기준으로 정리했다.
  • fixture 필수/선택 필드와 TypeScript 예시를 작성했다.
  • badge 계산식을 unread && badge_count === true로 고정했다.
  • read/archive는 localStorage 기반이며 역할 큐는 브라우저/사용자 간 동기화하지 않는다고 명시했다.
  • source missing, closed encounter, permission unavailable fallback을 정의했다.
  • 동일 환자+동일 오더+동일 event의 미확인 알림은 append가 아니라 update/bump하도록 정리했다.
  • toast max 3 + queue 정책을 계약에 포함했다.

문서 연결

  • Docs portal, GitBook summary, Product README에 새 notification contract를 추가했다.
  • Home 관련 문서의 Notification Boundary 섹션에서 새 계약 문서로 연결했다.
  • 기존 work inbox의 notification shaping 항목을 work item으로 승격했다.
  • 새 work item NOTIFICATION-PR-001을 추가했다.

제외 범위

live push, service worker, provider/device delivery, Kakao/SMS/email, remote Supabase migration/RLS/live validation, 공지 발행 시스템, 자유 멘션 시스템, 알림 안 final action 직접 수행, 역할 큐 read/archive 실시간 동기화는 이번 작업 범위에서 제외했다.

검증

  • npm run docs:check로 내부 문서 링크를 검증한다.
  • 코드 구현은 하지 않았기 때문에 lint/typecheck/build는 실행 대상이 아니다.
  • 후속 구현은 DEN-396 이후 이슈에서 이 계약을 기준으로 진행한다.
