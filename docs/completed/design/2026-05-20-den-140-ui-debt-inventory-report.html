핵심 요약

현재 UI debt는 단순 색상 문제가 아니라 큰 화면 파일, 고정 레이아웃 값, 화면별 table/form/dialog/status/empty state 변형이 겹친 문제다. 다만 이미 shadcn/ui와 EMR 공통 컴포넌트가 꽤 있으므로, 새 공통 컴포넌트를 성급히 만들기보다 기존 primitive 재사용과 feature-local 분리를 먼저 하는 쪽이 안전하다.

다음 시작 추천

00 프로젝트가 끝난 뒤 첫 화면 리팩토링은 Linear 순서대로 01 진료/차트부터 시작하는 것을 추천한다. 차트는 파일 크기와 UI 복잡도가 크지만 이미 EMR queue/history/status/dialog primitive를 일부 쓰고 있어, “기존 behavior를 지키면서 feature-local 분리부터 진행한다”는 패턴을 만들기 좋다.
