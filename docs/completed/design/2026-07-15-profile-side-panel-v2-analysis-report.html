RECEPTION-PR-010 · UX/UI Research

프로필 사이드 패널 V2 분석 및 시안

CDS V2 Figma를 현재 접수 캘린더의 직원 운영 프로필에 적용하기 위한 설계·개발 분석이다. 이번 문서는 구현 전 판단 자료이며, 제품 코드는 수정하지 않았다.

2026-07-15 · 사용자 지정 Figma 핵심 노드, 현재 Vercel 화면, 로컬 컴포넌트/API/RLS/Storage 계약 기준

결론

Figma 방향은 적용 가능하다. 다만 현재의 다른 직원 조회 패널과 Figma의 내 프로필 편집 패널을 권한 구분 없이 합치면 안 된다. 권장안은 동일한 380px 패널을 쓰되 본인에게만 상태메시지·사진 편집을 노출하고, 다른 직원은 읽기 전용으로 유지하는 것이다.

채택

380px 전용 패널

프로필 패널만 336px에서 380px로 변경한다. 다른 우측 패널 폭은 유지한다.

채택

본인만 편집

actorUserId === userId일 때만 아바타와 상태메시지 편집을 허용한다.

확정

업무 현황 타임라인

담당 오더를 요청 시각 최신순으로 묶고, 전용 read API와 권한별 이동 동작을 제공한다.

1. 조사 범위와 증거

  1. 현재 상태: Vercel 접수 캘린더에서 김도윤 직원 운영 프로필 패널을 캡처했다.
  2. Figma 전체: 프로필 헤더 상태, 4개 탭, 계정/근무 정보, 아바타 메뉴, 업로드 다이얼로그 흐름을 확인했다.
  3. 코드: StaffOperationalProfilePanel, Base UI tabs, 공용 dialog shell, 개인 프로필 API, Presence hook, avatar Storage migration과 RLS를 확인했다.
  4. 제한: 캡처만으로 실제 키보드 포커스, 스크린리더 발화, 업로드 파일 검증, 네트워크 실패 동작은 확인할 수 없으므로 구현 테스트가 필요하다.

4. 인터랙티브 시안

아래는 구현 방향을 검토하기 위한 로컬 HTML 시안이다. ‘내 프로필/다른 직원’ 전환, 프로필·업무 현황 2개 탭, 근무·부재 요약, 헤더 보조 메뉴, 상태메시지 편집, 아바타 메뉴와 업로드 다이얼로그를 눌러볼 수 있다.

아바타 hover 시 Figma edit icon이 나타난다. 상태메시지는 Enter 또는 focus-out으로 저장되고 result 배경은 투명해진다. 이미지 제거는 이름 첫 글자 fallback으로 전환되며, 업로드 dialog는 열 때마다 icon + placeholder 상태로 초기화된다. 파일 선택 후 미리보기 우측 상단 X를 누르면 선택 파일만 제거하고 같은 placeholder 상태로 돌아간다. 임의로 넣었던 ‘닫기’ 텍스트는 제거하고 Figma의 X icon button만 유지했다. 캘린더·더보기 탭은 제거하고 전체 근무표 등 저빈도 액션을 헤더 ··· 메뉴로 이동했다.

항목 권장 계약 이유
사용자 안내 정사각형 512×512px 이상 권장 · JPG, PNG, WebP · 최대 5MB GitHub는 약 500×500px, Slack은 512×512~1024×1024px을 권장한다. 5MB는 고해상도 모바일 사진을 받되 서버 비용을 제한하는 제품 상한이다.
허용 형식 image/jpeg, image/png, image/webp 사진·투명 이미지·효율적인 웹 이미지를 세 형식으로 커버한다. 브라우저 accept와 서버 검증 목록을 동일하게 둔다.

서버 정규화 magic bytes 확인 후 decode·방향 보정·metadata 제거·정적 재인코딩 확장자나 클라이언트 MIME만 신뢰하지 않고 animated WebP와 손상 파일, 과도한 pixel count를 차단한다.

8. 데이터·API·권한 분석

상태메시지

현재 스키마/API에는 필드가 없다. 근무 맥락 문구이므로 전역 user_profiles보다 workspace-scoped member profile이 안전하다. 새 테이블 또는 권한 필드와 self-write RPC가 필요하다.

프로필 이미지

현재 avatars bucket은 public, PNG 2MB, trusted seed upload 전용이다. 제품 업로드 계약은 JPG/JPEG·PNG·정적 WebP, 최대 5MB로 확장하고, 브라우저 업로드를 위해 self-only write 정책 또는 서버 업로드 경계와 avatar reference 갱신이 필요하다.

편집 권한

기본은 본인만 수정이다. 관리자 대리 수정은 별도 permission, 감사 이벤트, UI 표시, 서버 강제가 모두 합의될 때만 추가한다.

업무 현황

기존 order_fulfillment_work_items와 source snapshot을 재사용한다. 새 이력 테이블 없이 프로필 전용 read API가 담당자, 요청 시각, 권한, 이동 목적지를 정규화한다.

권장 API 분리: 조회용 operational-profile GET은 유지하고, 상태메시지와 아바타는 self-owned mutation route로 분리한다. 기존 개인 프로필 PATCH는 전체 필드를 요구하므로 그대로 재사용하면 부분 수정 충돌 위험이 있다.

9. 접근성·반응형 기준

  • 아바타 편집은 hover에만 의존하지 않고 실제 button, accessible name, focus-visible 상태를 제공한다.
  • Presence는 색상 외에 “온라인/오프라인/상태 확인 중” 텍스트를 제공한다.
  • 상태메시지는 Enter 또는 focus-out 저장, Escape 취소, 60자 제한, 저장 중/실패 안내를 갖는다.
  • 탭은 Base UI semantics, 좌우 화살표 이동, 활성 tab과 tabpanel 연결을 유지한다.
  • 업무 날짜 헤더는 실제 button과 aria-expanded를 사용하고, 더보기 메뉴와 이동 dialog는 키보드·focus return을 지원한다.
  • 업로드 dialog는 열릴 때 파일 선택 영역 또는 닫기에 focus, 닫힐 때 아바타 버튼으로 focus를 돌린다.
  • desktop은 380px + 10px gap, 좁은 화면은 backdrop 없는 full-width panel을 유지한다. dialog는 viewport보다 작게 축소하고 350px preview는 가용 폭에 맞춘다.
  • 200% zoom, 긴 이름, 긴 상태메시지, 긴 이메일에서 close/Presence가 겹치지 않는지 브라우저로 확인한다.

10. 구현 순서

구현 데이터 금지사항: 이 보고서의 예시 이름·프로필· 환자·보호자·업무·근무시간·부재 일정을 제품 코드의 상수, fixture, in-memory row 또는 API 실패 시 mock fallback으로 만들지 않는다. 데이터가 없거나 조회에 실패하면 shared loading/empty/error/disabled 상태를 표시해야 하며, 예시 데이터로 성공 화면을 꾸미면 안 된다.

실제 데이터 경로를 사용하는 검증 계약

  • 업무 현황: 격리된 합성 테스트 workspace에서 실제 차트·오더·fulfillment 생성 경로로 업무를 만들고 특정 합성 테스트 유저를 담당자로 지정한다. 프로필 업무 API가 동일한 업무 ID, 요청 시각, 카테고리, 상태를 반환하는지 검증한다.
  • 프로필 정보: 사용자·workspace membership·직무·진료과· 연락처 source에서 읽은 값을 검증한다. 시안의 이름과 연락처를 기본값 또는 fallback으로 사용하지 않는다.
  • 오늘 근무 정보: 실제 published schedule과 time-clock facts로 표시 여부와 상태를 검증한다. 일정이 없으면 정상 empty/off 계약을 사용하고 임의 시간대를 생성하지 않는다.
  • 전체 근무표 이동: 프로필 패널에서 별도 캘린더 데이터를 조회하지 않는다. 권한 확인 후 기존 병원관리 근무표의 해당 직원·기준 주로 이동하고, 근무표의 loading/error/permission 상태는 원본 화면이 소유한다.
  • 테스트 데이터 안전: 실제 고객·환자·보호자·직원 개인정보는 사용하지 않는다. 테스트 전용 합성 엔티티를 seed/API/RPC로 생성하고 ID 기반 read-back 후 transaction rollback 또는 명시적 cleanup으로 제거한다.
  • 실패 경계: API·권한·DB 조회 실패를 빈 목록이나 시안 데이터로 바꾸지 않는다. 실패 원인을 구분한 오류 상태와 재시도를 표시한다.

12. 승욱 승인으로 확정된 구현 결정

  1. 상태메시지 범위: workspace별 메시지로 확정.
  2. 탭 변경: 최근활동을 업무 현황으로 변경. 담당 오더를 요청 시각 최신순의 날짜별 타임라인으로 표시.
  3. 아바타 공개성: private storage와 signed URL 방향으로 확정.
  4. 다른 직원 편집: 본인만 편집. 관리자 대리 편집은 후속 이슈로 분리.
  5. 업무 포함 기준: 활성 업무는 현재 담당자, 완료·취소는 종료 시점 담당자 기준. 완료 전 인계된 업무는 기존 담당자 목록에서 제외.
  6. 정렬·조회: 오더 요청 시각 기준 최신순, 전체 이력을 최초 20개와 20개 단위 더보기로 제공.
  7. 이동: 카드 자체는 정보용. 더보기 → 업무 보러가기 → 확인 dialog 후 이동.
  8. 공개 범위: 같은 workspace 구성원은 업무 요약을 볼 수 있고, 상세 이동은 별도 환자·오더 권한이 있는 경우에만 제공.
  9. API 접근: 기존 fulfillment 데이터를 재사용하는 프로필 전용 read API로 확정. 이번 범위에 신규 DB 이력 테이블은 추가하지 않음.
  10. 업무 탭 상태 UI: 최초 로딩은 EmrQueueLoadingState, 정상 empty는 EmrQueueEmptyState의 md 계약, 읽기 실패는 EmrInlineAlert로 확정.
  11. 실데이터 경로 원칙: 시안의 합성 예시는 제품 코드에 넣지 않는다. 업무·프로필·오늘 근무·다가오는 부재는 실제 API/DB read model로 구현하고, 검증은 격리된 합성 테스트 엔티티를 실제 생성·배정· read-back·cleanup하는 방식으로 확정.
  12. 탭 IA: 프로필·업무 현황 2개 탭으로 확정. 캘린더· 더보기 탭은 제거하고, 전체 근무표·연락처 복사·권한별 멤버 관리는 헤더 보조 메뉴로 제공.
