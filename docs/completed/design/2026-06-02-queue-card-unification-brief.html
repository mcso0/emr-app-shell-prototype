대기열 카드 공통 컴포넌트 제안

승욱이 준 규칙을 기준으로 진료, 임상병리, 영상, 조제/처치, 수납 카드의 공통 본체와 화면별 데이터 변환 방식을 다시 정리했다. 이 문서는 구현 전 브리핑용 시안이다.

의견: 공통 컴포넌트가 맞다

하나의 공통 카드 본체를 두고, 각 화면이 데이터를 변환해서 넣는 방식이 관리상 가장 낫다. 화면별 컴포넌트를 계속 유지하면 1줄/3줄 같은 공통 규칙이 다시 벌어질 가능성이 크다.

권장

EmrTaskQueueCard 본체 + 화면별 adapter. 카드 UI, hover action, selected state, badge 규칙은 한 곳에서 관리.

허용 변형

2번째 줄의 badge/text 조합과 3번째 줄 event label만 화면별 데이터로 다르게 표기.

주의

수납은 order 실행 큐가 아니라 guardian checkout 큐다. 같은 카드 본체를 쓰되 수납 전용 adapter가 필요하다.

공통 카드 규칙

1번째 줄과 3번째 줄은 모든 화면 공통이다. 2번째 줄만 화면별로 의미가 달라진다.

줄 공통 UI 데이터 규칙
1번째 줄 접수 타입 badge + 환자명 · 보호자명 + hover outline icon button badge는 외래 또는 예약. 환자명/보호자명은 한글 표시. 버튼은 hover/focus/selected에서 노출.
2번째 줄 ghost badge + ellipsis text. 단, 수납은 badge 없음. 진료는 방문목적, 검사/영상은 카테고리와 오더명, 조제/처치는 오더 타입과 오더명, 수납은 오더 n건 · 총 가격.
3번째 줄 clock icon meta badge + person line icon 담당자 badge 요청/재요청/취소 시각과 행위자를 표시. 완료는 별도 표기하지 않음. 담당 전이면 항상 미지정.

화면별 adapter 규칙

공통 카드에는 같은 view model을 넘기고, 화면별 selector/adapter가 아래 값을 만든다.

화면 2번째 줄 badge 2번째 줄 text 3번째 줄 event
진료/차트 방문목적 방문목적 값. 길면 말줄임. 접수/요청/재요청/취소 중 최신 의미 있는 이벤트. 완료는 표시하지 않음.
임상병리 첫 검사 카테고리명. 여러 카테고리면 첫 카테고리 외 n. 첫 검사 오더명. 여러 오더면 첫 오더명 외 n. 검사 오더 요청/재요청/취소 이벤트의 시각과 사용자.
영상검사 첫 영상 카테고리명. 여러 카테고리면 첫 카테고리 외 n. 첫 영상 오더명. 여러 오더면 첫 오더명 외 n. 영상 오더 요청/재요청/취소 이벤트의 시각과 사용자.
조제/처치 조제, 처치, 기타 중 하나. 첫 오더명. 여러 오더면 첫 오더명 외 n. 오더 요청/재요청/취소 이벤트의 시각과 사용자.
수납 없음 오더 n건 · 총 가격 수납 후보를 만든 요청/재요청/취소 이벤트. 담당자는 수납 담당자, 없으면 미지정.

컴포넌트 API 제안

구현한다면 이 정도의 작은 view model로 시작하는 게 적절하다.

필드 의미
receptionType외래 또는 예약. 수납도 가능하면 encounter 기준으로 유지.
patientName, guardianName1번째 줄 한글 이름.
secondLineBadgeLabel?수납에서는 undefined로 넘겨 badge를 렌더하지 않음.
secondLineText방문목적, 오더명 요약, 또는 수납 금액 요약.
eventKindrequest, reRequest, cancel. 완료는 없음.
eventTime, eventActorName첫 meta badge에 hh:mm 사용자명 요청/재요청/취소로 표시.
assigneeName?두 번째 meta badge. 없으면 미지정. 아이콘은 항상 표시.
selected, onSelect, action기존 side panel 카드 동작과 hover action 유지.

구현 시 기존 EmrSidePanelCard primitive 위에 EmrTaskQueueCard를 얹고, ChartQueueItemAdapter, LabQueueItemAdapter, ImagingQueueItemAdapter, DispensingQueueItemAdapter, BillingQueueItemAdapter를 두는 방향이 좋다.
