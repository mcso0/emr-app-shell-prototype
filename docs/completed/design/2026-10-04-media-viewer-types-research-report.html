1 / ACCEPTED DECISIONS

이번에 구현한 범위

  • 파일 형식JPEG·PNG·WebP·PDF·CSV·TXT.
  • 파일 간 이동현재 연 항목 또는 종합소견 첨부 영역의 순서와 범위만.
  • 다크 기본 배경이미지는 그레이·체커 배경도 선택. 원본 색은 유지.
  • 이미지 보기 회전화면에서만 회전. 저장 원본은 그대로.
  • 보기 상태 기억같은 모달 세션에서 파일별 배율·회전·PDF 페이지 복원. 닫기·문맥 변경 때 초기화.
  • 기존 삭제 정책권한·확인창 유지. 중복 요청 방지와 실패 뒤 재시도. 새 휴지통 정책은 추가하지 않음.

2 / CODE INVESTIGATION

확인한 원인과 소유자

  • 밝은 화면 토큰lab-attachment-viewer.tsx가 밝은 EMR 표면을 사용하고 있었어. 모달 안에서만 다크 토큰을 적용해.
  • CSV와 TXT가 같은 화면CSV는 문자열을 보존하는 읽기 전용 표로 구분해. TXT는 원문·찾기·줄바꿈을 제공해.
  • 파일 전환마다 상태 소실모달이 열린 동안 파일별 보기 상태를 보관해.
  • 호출부가 문맥과 삭제를 소유LabResultAttachmentArea의 영역별 목록·권한·삭제 확인을 유지해.
  • 보호된 원본 API현재 앱은 서명 읽기 링크 대신 보호 GET/DELETE 경로를 사용해. 권한 거부·파일 없음 응답에 맞게 처리해.

실제 뷰어 컴포넌트로 파일별 화면을 볼 수 있어.

이미지 · PDF · CSV · TXT

합성 파일을 사용해. 이 컴포넌트 예시의 다운로드·삭제 콜백은 모의 동작이야. 결과 화면의 보호 API 연결과 삭제 확인 흐름은 별도 통합 검사에서 확인해.

시안 대조와 로컬 구현 검증을 마쳤어. 통과한 후보를 PR과 main으로 전달하는 단계야. Chromium 관련 검사 64개, Storybook 6개, 서버 계약 18개가 통과했어. 모바일 44×44px 보완을 포함한 최종 관련 검사에서도 이 결과를 확인했어. lint·TypeScript·빌드·문서·UX 문구·비밀정보 검사와 정확한 커밋의 Release Check·Ready Preview를 확인한 뒤 머지해.

검증 한계결과표 레이아웃 검사 2개는 기준 코드에서도 실패했어. 이번 뷰어 검사에서 제외했고, 전체 테스트 통과로 표시하지 않아. 빌드에는 기존 문서 읽기 경로의 추적 경고가 남아 있어. 실제 고객 파일과 원격 저장소 변경은 검사하지 않아. 앱 화면과 파일 동작은 합성 자료로 검증했어. 배포 결과는 PR과 최종 전달에서 별도로 확인해. 구현 코드는 별도 작업 폴더에 있어.

목록 갱신 오류도 구분했어. 통신·서버 오류에는 마지막으로 확인한 미리보기와 실패 안내·재시도를 제공해. 목록을 다시 확인할 때까지 삭제 버튼은 숨겨. 파일 읽기가 거부되면 내용·파일명·조작을 제거해. 첨부 목록에서도 권한 상실·삭제가 확인되면 모달을 닫아. 보기 상태는 닫으면 버려.

시안 대조 결과

데스크톱 모달은 화면 폭의 80%·높이의 86%, 모서리 12px, 상단 바 54px·하단 바 40px로 맞췄어. 1280×720 화면에서 실제 모달은 1024×619.2px야. 상단 아이콘과 버튼은 시안처럼 배치하고, 파일 형식·크기 정보는 하단에 모았어. 캔버스 #171717, 상단 #262626, 그레이 배경 #737373을 기존 색상 토큰으로 적용했어.

태블릿은 폭 92%·높이 88%야. 390px 모바일에서는 좌우 8px 여백, 높이 92%, 상단 56px를 사용해. 다운로드·삭제·닫기와 이전·다음 조작은 44×44px야. 모바일 하단은 이 조작 영역을 담도록 48px로 보완했어. 버튼 글자는 숨기고 접근성 이름은 유지해. 이미지·PDF·CSV·TXT 화면과 줄바꿈, 잘림, 파일 전환을 실제 컴포넌트에서 확인했어.

CSV 표는 앞 200행·50열·셀당 4,000자, TXT는 앞 50,000자를 표시해. 일부 표시임을 화면에서 안내해. 업로드 제한과 원본 다운로드는 바뀌지 않아. 긴 TXT의 첫 표시를 확인한 뒤 표시량을 줄였어.

06 / EDGE CASES

경계 상황에서도 다음 행동이 명확하게.

네 가지 핵심 상황을 시안에 반영했어. 아래의 기대 동작은 설계 제안이야. 실제 서버 권한·파일 처리의 완료 여부와는 구분해.

위쪽의 ‘시안 검증용’ 조작과 ‘상태’ 선택기로 재현할 수 있어. 삭제는 1초 동안 합성 응답을 기다려. 실제 파일이나 서버 데이터는 삭제하지 않아.

EC-01 / CONTENT VISIBILITY

검은 이미지·투명 PNG

기대 동작: 다크 프레임을 유지하고 내용 주변 배경만 다크·회색·체크무늬로 선택해. 이미지 색·투명도·비율과 다운로드 파일은 바뀌지 않아. 보기 배경은 이미지에만 적용해.

시안에서 확인: ‘이미지 예시’를 검은 이미지 또는 투명 PNG로 바꾸고, 뷰어의 ‘보기 배경’을 비교해. 다른 파일을 선택하면 다크 기본값으로 돌아가.

실제 구현 검사: 투명·반투명·완전 투명 PNG와 검은 테두리를 포함한 실제 파일로 경계·색·방향을 확인해. 완전 투명은 빈 파일과 구분해.

EC-02 / CONTEXT & ACCESS

열람 중 권한·환자 문맥 변경

기대 동작: 환자·워크스페이스가 바뀌면 기존 뷰어를 닫고 읽기·변환 요청과 재생을 중단해. 권한 회수를 확인하면 내용·파일명·메타데이터·다운로드·삭제를 즉시 제거하고 닫기 안내를 보여줘.

시안에서 확인: ‘상태’에서 권한 회수 또는 환자·워크스페이스 변경을 선택해 제거된 화면을 확인해. 문맥 변경 시안은 종료 직전 안내야. 실제 앱에서는 문맥 변경과 함께 모달을 닫도록 제안해.

실제 구현 검사: 요청에 파일·워크스페이스·화면 문맥을 묶고, 이전 문맥의 늦은 응답은 표시하지 않아. 서버에서 접근을 다시 확인해. 권한 회수를 감지하는 방식과 보유 중인 화면 데이터의 정리 시점을 정해야 해.

EC-03 / DELETE CONCURRENCY

연속 클릭·실패·다른 사용자의 삭제

기대 동작: 삭제 확인 뒤 요청이 끝날 때까지 삭제를 비활성화해. 성공을 확인하기 전에는 파일을 삭제 완료로 표시하지 않아. 실패하면 파일과 보기 조작을 유지하고 재시도와 닫기를 제공해.

시안에서 확인: ‘삭제 응답’을 바꾸고 상단 삭제를 실행해. 대기 중에는 한 번만 처리해. 실패 시 파일이 남고, 이미 삭제된 응답은 파일 없음 안내로 바뀌어. 아래 요청 횟수는 합성 요청만 세어.

실제 구현 검사: 서버의 반복 요청 처리, 삭제 권한 재확인, 네트워크 단절·시간 초과·403·이미 없는 파일을 구분해. 연결이 끊긴 경우 삭제 결과부터 확인한 뒤 재요청해. 목록은 서버 결과로 갱신해.

EC-04 / FOCUS RETURN

모달을 연 버튼이 사라짐

기대 동작: 닫으면 원래 실행 버튼으로 초점을 돌려. 버튼이 삭제·갱신으로 사라졌거나 비활성 상태라면 현재 문맥의 첨부 목록으로 돌려. 다른 환자 문맥의 이전 버튼으로는 돌아가지 않아.

시안에서 확인: 아래 예시 첨부파일을 열고 ‘삭제 → 확인 → 닫기’를 실행해. 삭제 성공으로 실행 버튼이 사라지면 예시 첨부 목록이 초점을 받아. 취소·삭제 실패 때에는 원래 버튼으로 돌아가.

근거와 검증: WAI 모달 패턴의 실행 요소가 사라졌을 때 논리적인 위치로 복귀하는 원칙을 적용했어. 실제 첨부 목록의 삭제·필터·새로고침 후에도 복귀 위치가 존재하는지 확인해.

상황기대 동작·판정 기준확인 방법

14 · 재생·원본 다운로드자동 재생하지 않기. 닫기·전환·권한 회수 시 중단. 보조 배경·보기 회전을 다운로드에 섞지 않기.합성 재생 + 실제 전체화면·탐색·다운로드 원본 해시 확인.

추가 항목 브라우저 확인: 검은·투명 이미지와 회색·체크무늬 배경, 파일 전환 뒤 다크 기본값 복귀를 확인했어. 권한 회수 시 재생 요소·내용·파일명·작업·파일 위치가 제거되고, 문맥 변경·파일 없음·링크 만료·빈 파일 안내도 표시돼. 삭제 확인을 연속 클릭해도 합성 요청은 1회였어. 대기 중 작업 비활성화, 실패 시 파일 유지·재시도, 이미 삭제된 응답을 확인했어. 원래 실행 버튼으로의 복귀와 버튼이 사라졌을 때 예시 첨부 목록으로의 초점 복귀도 확인했어. 390px 화면의 가로 넘침 없이 상단 버튼 44×44px, 모달 Tab·Shift+Tab 초점 유지·Escape 닫기를 확인했어. JavaScript 구문과 문서 내부 링크를 검사했어. 실제 서버 요청 중복 방지·권한 회수 감지·문맥 변경 이벤트·파일 내용 검사·다운로드 저장 결과와 나머지 실제 파일 조건은 별도 검증이 필요해.

07 / DECISIONS TO CONSIDER

확정안의 결정 근거와 확장 검토.

모든 기능을 먼저 넣을 필요는 없어. 기본 동작을 정하고, 실제 사용 수요가 있는 확장만 이어가면 돼.

01

다크 테마는 어디까지 적용할까?

모달 프레임·이미지 주변·조작부는 다크로 고정해. 문서 종이와 실제 이미지의 색까지 반전하면 도표와 색 구분이 달라질 수 있어.

추천: 콘텐츠의 원래 색을 유지. 밝기·대비 조정은 일반 뷰어 기본 기능에서 제외.

02

첨부파일 이동 순서는 무엇일까?

현재 검사결과·선택 항목에 속한 파일만 이동할지, 전체 결과의 첨부를 이동할지 정해야 해. 화면 밖 파일로 넘어가면 문맥을 잃기 쉬워.

추천: 현재 첨부 영역의 순서와 범위를 따르고 파일 위치를 표시.

03

누가 다운로드·삭제할 수 있을까?

열람·다운로드·삭제는 다른 권한일 수 있어. 버튼 숨김은 UX이고 실제 허용 여부는 서버에서 확인해야 해.

추천: 기존 권한 계약 유지. 확정 기록의 삭제 범위와 변경 이력은 별도 정책으로 결정.

04

대용량 파일을 어디까지 보여줄까?

처음부터 PDF 전체 페이지·긴 CSV·큰 영상·원본 이미지를 모두 읽으면 대기와 메모리 부담이 커져. 잘린 내용은 범위를 알아야 해.

추천: 필요한 페이지·구간부터 읽고 표시 범위를 명시. 새 제한은 실제 파일·기기 실측 후 결정.

05

휴대전화 파일의 방향과 형식은?

세로 사진과 영상, EXIF 방향, HEIC·MOV 등은 별도 확인이 필요해. 단순 확장자 허용만으로 브라우저 표시를 보장할 수 없어.

추천: 현재 허용 형식 우선. 새 형식은 변환·실패 처리와 함께 검토.

06

이미지와 데이터의 의미를 보존할까?

이미지 크기·색, PDF 색·도표, CSV 값·단위·선행 0·행 순서가 원본과 달라지지 않아야 해. 보기 회전과 파일 편집도 구분해야 해.

추천: 기본 읽기 전용. 미리보기 변환과 원본 다운로드를 명확히 분리.

07

키보드·터치로도 조작할 수 있을까?

아이콘은 이름과 초점 표시가 필요해. WAI는 모달 초점 계약을 설명하고 WCAG 2.2는 대상 크기와 대비 기준을 제시해.

추천: 데스크톱 32px 이상, 모바일 상단 작업 44px를 설계 목표로. 기준은 최소 24×24 CSS px 또는 예외 조건이며, 의미 있는 아이콘 대비는 3:1. 대상 크기 · 비텍스트 대비

08

변환·OCR·음성 대본은 어디서 처리할까?

파일을 외부 변환 서비스로 보내는 선택은 처리 위치·보관·비용·허용 범위에 영향을 줘. 원본과 파생 파일의 접근 권한도 맞춰야 해.

추천: 첫 적용은 원본 보기부터. 별도 서비스 도입은 파일 범위와 처리 정책을 먼저 결정.

09

편집·주석·비교까지 확장할까?

주석 저장과 두 파일 비교는 화면 조작 외에 버전·작성자·저장 충돌·열람 범위를 추가해. 파일 보기의 첫 범위가 크게 커져.

추천: 수요 확인 뒤 별도 작업. 첫 시안의 기본은 읽기와 원본 다운로드.

10

기능을 다른 화면에도 재사용할까?

검사실·영상실·차트 첨부에 같은 프레임을 쓰되 파일의 결과·항목·권한 문맥은 유지해야 해.

추천: 실제 두 번째 적용 화면을 확인한 뒤 공통화. 현재 뷰어 소유자와 기존 계약부터 확인.

08 / IMPLEMENTATION & VERIFICATION

시안 다음의 작업 범위.

시안은 구현 후보를 검토하는 자료야. 승인한 디자인과 신규 파일 처리 기능의 범위를 따로 확인하면 돼.

첫 구현 후보

기존 파일 뷰어의 다크 프레임, 다운로드·삭제·닫기 아이콘, 이미지·PDF·CSV·TXT 보기 조작과 실패·권한 상태. 파일 읽기·다운로드·삭제와 워크스페이스 권한을 보존해. 관련 기록은 LAB-PR-004와 검사결과 스펙에서 이어가면 돼.

확장 전 확인

영상·음성·Office·DICOM의 업로드 허용, 서버 내용 검증, 처리·변환·저장·비용, 파생본 권한과 브라우저 호환성. 뷰어·변환·주석·편집의 소유권은 실제 호출 화면과 파일 처리 경계를 보고 결정해.

검증할 항목

실제 허용 파일의 렌더링, PNG/JPEG/WebP 방향·투명도, PDF 페이지·텍스트·암호·손상, CSV 구분자·한글·선행 0, TXT 공백·긴 줄. 긴 파일명, 200% 화면 확대, 390px 모바일, 키보드·초점 복귀, 워크스페이스·권한·삭제 경계. 영상은 브라우저·코덱·탐색·파일 전환 시 재생 중단을 별도로 검증.

이 HTML의 검증 결과: 이미지 조작, 문서 레이아웃 페이지 이동, CSV 8행·선행 0, TXT 검색·태그 표시, 합성 영상·음성 재생, Office 화면 전환, DICOM·기타 안내, 6가지 상태, 예시 파일 삭제·복구를 브라우저에서 확인했어. 모달·삭제 확인창의 Tab·Shift+Tab 초점 유지와 Escape 닫기·초점 복귀도 확인했어. 390px 화면의 가로 넘침은 없고 상단 동작 버튼은 44×44px이야. JavaScript 구문과 자체 포함 자산을 검사했어. 실제 PDF·Office 파싱, 다운로드 저장 완료, 실제 앱·원격 파일·DB·서버 권한·전체 브라우저 호환성은 검증 범위 밖이야.
