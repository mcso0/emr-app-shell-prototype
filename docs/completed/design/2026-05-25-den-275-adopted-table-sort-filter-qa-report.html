Adopted Table Sort / Filter QA

이번 작업은 Project 13에서 이미 적용한 정렬/필터 테이블들이 같은 정책으로 안정적으로 동작하는지 확인한 QA이다. 새 테이블 채택이나 새 기능 추가 없이, 수납·차트 오더·고객관리·병원관리 오더 카탈로그의 핵심 동작과 화면 evidence를 확인했다.

QA 범위

  • 수납 청구 항목 테이블: 단일 정렬, 섹션 Filter, empty state, reset, 기존 수납 workflow.
  • 차트 오더 테이블: 단일 정렬, 분류 탭과 필터 AND 조합, empty state, reset, 기존 오더 draft workflow.
  • 고객관리 동물 테이블: 단일 정렬, Filter N, 다중 조건 AND, narrow viewport 접근성.
  • 병원관리 오더 카탈로그: 단일 정렬, 기존 카테고리/검색/상태/청구 필터와 table filter 조합.

확인한 항목

  • 헤더에는 정렬만 있고, active sort 상태가 헤더 버튼 이름과 화면 상태에 남는다.
  • 필터는 섹션 header/action area의 Filter 버튼에서 열리고, 조건이 적용되면 Filter N으로 표시된다.
  • 필터 builder footer에 초기화, Apply filters, Close가 유지된다.
  • Escape 키로 popover를 닫을 수 있다.
  • 조건 결과가 없을 때 각 테이블의 empty state 문구가 보인다.
  • 초기화 후 기존 visible row가 복구된다.
  • mock auth 상태로 실제 workspace 화면을 캡처했고, evidence에는 로그인 화면이 없다.

QA 중 발견 및 조치

  • Found / Fixed 390px narrow viewport에서 고객관리 Filter popover가 shell chrome에 시각적으로 가려질 수 있어 shared popover positioner layer를 올렸다.
  • No blocker adopted table sort/filter 동작, empty state, reset, 기존 workflow regression에서 blocking defect는 발견하지 못했다.

Evidence

각 이미지는 mock auth storage state로 실제 workspace 화면을 열어 캡처했다.
