DEN-434 Empty/Info State Contract Report

2026-06-06 · 공통 UX/UI 기준 정리 및 화면 적용

요약

빈 상태와 정보 박스가 로딩, 오류, 권한/범위, 검색 결과 없음, 안내/주의 상태와 섞이지 않도록 공통 기준을 정리했다. 후속 대기열, 환자정보바, SOAP 화면 적용 이슈에서 같은 판단표를 사용할 수 있다.

승욱이 지금 확인할 것

이 이슈는 화면 구현이 아니라 빈 상태와 안내 박스 기준 승인이야. 확인할 것은 "사용자가 지금 무엇이 없는지, 왜 없는지, 다음에 무엇을 해야 하는지"가 한눈에 구분되는 기준인지야.

  • 데이터 없음, 검색 결과 없음, 필터 결과 없음, 권한/범위 없음, 아직 생성 전을 서로 다르게 보는 기준이 맞는지
  • 정보 박스가 오류나 권한 문제를 덮지 않고, 진짜 오류/복구는 EmrInlineAlert로 분리되는지
  • 빈 상태 안의 주요 액션에는 DEN-433 기준대로 E1 shadow를 주는 방향이 맞는지
승인하면 다음 화면 이슈에서 이 기준을 적용

판단 기준

상황 사용 패턴 사용자에게 알려야 할 것
아직 생성된 항목 없음 Empty state 무엇이 없고, 만들 수 있으면 어디서 추가하는지
검색/필터 결과 없음 Empty state 검색어 또는 필터 때문에 안 보이는지, 어떻게 초기화하는지
작업 전제나 주의 필요 Info box 계속하기 전 알아야 할 조건 또는 주의점
읽기/저장 실패, 복구 필요 Inline alert 영향, 복구 액션, 현재 표시 데이터의 신뢰 범위
로딩 중 Skeleton 또는 loading copy 아직 비어 있는 것이 아니라 불러오는 중이라는 점

시각 샘플

Empty · 검색 결과 없음

해당 조건에 맞는 검사 결과가 없어. 검색어를 줄이거나 필터를 초기화해.

필터 초기화

Info · 작업 전제 안내

오더 확정 전에는 결과 입력이 잠겨 있어. 차트에서 오더 상태를 먼저 확인해.

차트로 이동

Alert · 복구 필요

서버 대기열을 불러오지 못했어. 현재 화면은 마지막 로컬 상태를 보여줘.

다시 시도

주요 결정

  • 빈 상태는 missing object, 이유, 다음 액션을 설명한다.
  • 정보 박스는 안내/전제/주의/시스템 경계처럼 workflow를 설명하는 데 사용한다.
  • 오류, degraded read/write, permission blocker, recovery path는 정보 박스가 아니라 EmrInlineAlert를 사용한다.
  • 빈 상태와 정보 박스 표면은 E0 flat이고, 내부 액션만 E1 shadow를 사용한다.
  • 공통 컴포넌트는 바로 만들지 않고, 최소 두 화면군에서 같은 구조가 반복될 때 검토한다.

제외 범위

  • 앱 코드 변경, 전체 화면 일괄 적용, 새 React 공통 컴포넌트 생성은 하지 않았다.
  • 실제 권한/서버 보안 정책, DB/API 오류 처리 계약은 변경하지 않았다.
  • live Supabase, migration, RLS, server enforcement, production deploy, real data는 건드리지 않았다.
