01공통 프로필

02읽기 전용

본인·관리자 설정 화면과 운영 조회를 분리한다.

직무·권한으로 가능한 업무를 추론하지 않는다.

결론

프로필의 중심은 사람과 조직 정보이며, 근무·예약 정보는 실제 원본이 있을 때만 맥락별로 덧붙인다.

채택 구조

공통 기본 프로필 + 관리자 조직정보 + 기준일 근무 + 선택적 화면 정보

이번 기능에서 제외

담당 업무, 업무 역량, 진료 분야, 가능한 예약 유형. 정의가 불명확한 정보를 권한이나 직무에서 추론해 보여주지 않는다.

프로필 정보 구조

모든 직군이 같은 뼈대를 사용하되, 현재 화면이 신뢰할 수 있는 데이터가 있을 때만 마지막 영역을 추가한다.

1공통 기본 프로필사진, 이름, 이니셜, 공개 가능한 업무용 연락처본인 관리
2조직 정보직무, 직책, 부서, 소속 상태, 근무 지점관리자 관리
3기준일 근무근무시간, 근무 label, 위치, 예정·근무 중·종료 상태근무표 원본
4화면별 정보접수 화면에서는 선택 날짜 예약 건수만 선택적으로 제공업무 원본

날짜 표시 원칙

오늘 캘린더에서 열면 오늘 근무, 다른 날짜에서 열면 7월 15일 근무처럼 기준일을 그대로 제목에 반영한다. 다른 날짜의 정보를 오늘 일정으로 잘못 표현하지 않는다.

최초 입력과 수정 권한

한 사람이 모든 필드를 수정하는 프로필이 아니다. 개인·조직·운영 원본의 책임을 나눈다.

정보최초 입력이후 수정다른 직원
초대 이메일운영 관리자본인 인증·이메일 변경 정책제한 조회
직무·직책·부서운영 관리자권한 보유 운영 관리자조회만
이름·이니셜·사진초대 수락자본인조회만
개인 전화번호본인본인기본 비공개
기준일 근무근무표 관리자근무표 관리자조회만
예약 요약시스템 계산직접 수정 불가권한 범위 조회

초대 수락 시 이메일 앞부분을 이름으로 임시 생성할 수 있지만, 최종 흐름은 본인이 이름·이니셜·사진을 확인하는 기본 프로필 설정 단계를 제공한다.

접수 캘린더 동작

레인 헤더의 오른쪽 끝에 액션 공간을 미리 확보해 hover 때 버튼이 나타나도 이름이 흔들리지 않는다.

1. 레인 hover/focus더보기 버튼 노출
2. 메뉴 열기정확히 두 항목 제공
3A. 숨기기상단 필터와 같은 상태 변경
3B. 프로필읽기 전용 드로우 열기

메뉴 항목

  • 캘린더에서 숨기기: 개인의 현재 보기 상태만 바꾸고 직원·근무표·예약 데이터는 변경하지 않는다.
  • 운영 프로필 보기: 같은 workspace shell 위에서 공통 드로우를 연다.

마지막으로 보이는 수의사 한 명은 숨길 수 없다. touch 환경에서는 hover가 없으므로 더보기 버튼을 항상 표시한다.

DB/API 고려 결과

기반 테이블과 일부 route는 이미 존재하지만 공통 운영 프로필 전용 조회 경계는 추가가 필요하다.

구분현재 상태판단
users, user_profiles이름·이니셜·연락처·사진 기반 존재재사용
user_memberships부서·직책·상태와 직무 연결 존재재사용
근무표 테이블membership와 shift, 위치 연결 존재재사용
본인 프로필 API본인만 이름·이니셜·전화·알림 수정기존 경계 유지
운영 프로필 조회 API공통 응답과 필드별 공개 정책 없음신규 read route 필요
활성 구성원 조직정보 수정초대 시 입력 기반은 있으나 일반 수정 경로 불완전관리자 route 보완

조회 API 제안

GET /api/workspaces/{workspaceId}/staff/{userId}/operational-profile
    ?date=2026-07-14&context=reception

profile  → 모든 허용 사용자에게 필요한 최소 직원 정보
shift    → 기준일 근무가 있을 때만 반환
context  → 화면과 권한이 지원할 때만 반환
  • 같은 workspace의 active member인지 서버에서 확인한다.
  • 접수 요약에는 reception:view 권한이 필요하다.
  • 개인 전화번호·권한 역할·로그인 이력·내부 ID는 일반 응답에서 제외한다.
  • 예약 건수는 원본에서 계산하며 프로필 테이블에 중복 저장하지 않는다.

1차 범위

포함

  • 레인 hover/focus 더보기 버튼
  • 숨기기와 운영 프로필 메뉴
  • 읽기 전용 공통 드로우
  • 조직 정보와 기준일 근무
  • 접수 예약 건수 요약
  • 로딩·빈 상태·부분 오류·권한 상태

제외

  • 업무 역량과 진료 분야
  • 다른 직원 정보 편집
  • 권한 역할과 로그인 이력
  • 개인 전화번호 공개
  • 근무표 편집
  • 새 DB 테이블

승욱 검토 포인트

  1. 프로필이 수의사 전용 화면이 아니라 모든 직원이 공유할 수 있는 뼈대로 보이는지
  2. 조직 정보와 개인 프로필의 수정 주체가 명확한지
  3. 오늘 근무와 선택 날짜 예약이 서로 다른 원본 정보로 이해되는지
  4. 레인 숨기기와 운영 프로필 보기가 캘린더 작업 흐름을 방해하지 않는지
  5. 이번 기능에서 제외한 정보가 실제 1차 범위에 적절한지
