EmrDialogShell 보고서

Product MVP의 확인, 폼, 넓은 폼 다이얼로그가 서로 다른 폭과 footer 규칙으로 보이는 문제를 줄이기 위해 공통 EmrDialogShell foundation과 migration 기준을 추가했다.

이번 작업은 화면 반영 전 foundation 단계다. 기존 다이얼로그 call site는 바꾸지 않았고, 실제 앱 화면에서 확인 가능한 변화는 후속 screen-level 이슈에서 시작한다.

Human Review 준비 화면 미반영 foundation

Variant 규격

Variant 폭 용도 동작 기준
confirm 420px 짧은 확인, 상태 변경, destructive-feeling session action compact body, secondary → primary action order
form 520px 작은 등록/수정 폼, membership-like form viewport 내 grid shell, scrollable body, footer 고정
wide-form 680px 접수/프로필 같은 multi-section form 넓은 body padding, scroll containment, footer 고정

변경 파일

  • src/components/emr/dialog-shell.tsx: 공통 shell과 variant layout 정의
  • docs/design/system/dialog-shell-rules.md: action order, width, scroll, migration 규칙 문서화
  • docs/design/system/component-ownership-rules.md: 기존 confirm dialog와 새 shell의 역할 경계 갱신
  • docs/design/system/README.md, docs/design/changelog.md: 문서 인덱스와 변경 이력 갱신
  • tests/design-tokens.spec.ts: shared EMR component semantic token guard에 새 shell 포함

호환 계획

  • EmrConfirmDialogContent는 기존 simple confirmation에 계속 유효하다.
  • 새 확인 다이얼로그나 migration 대상은 EmrDialogShell variant="confirm"을 우선 사용한다.
  • 차트 작성완료, 수납 financial CTA, 접수/프로필 form dialog는 각 후속 이슈에서 화면 QA와 함께 이 shell로 옮긴다.
  • route state, test ID, scroll containment, close/Escape behavior는 screen-level 이슈에서 보존 확인한다.

A등급 기준에 주는 효과

  • 화면마다 다른 dialog 폭과 padding이 반복되는 문제를 variant 선택 문제로 낮췄다.
  • primary/secondary action order를 고정해 사용자가 화면마다 다른 결정 규칙을 학습하지 않게 했다.
  • form/wide-form의 scroll containment 기준을 문서화해 긴 접수/프로필 폼의 후속 QA 기준을 만들었다.

제외 범위와 스크린샷

  • 이번 이슈에서는 앱 화면에 visible adoption을 적용하지 않았다.
  • 따라서 대표 스크린샷은 캡처하지 않았다. 화면 반영은 DEN-209, DEN-208, 접수/프로필 후속 이슈에서 시작한다.
  • Base UI/shadcn 전체 교체, 서버 검증, mutation policy 변경, live Supabase, payment/email/provider 작업은 포함하지 않았다.
