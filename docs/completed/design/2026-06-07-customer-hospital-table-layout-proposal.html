고객관리 및 병원관리 목록 화면 구조 통일 제안

고객관리의 동물, 보호자, 삭제된 보호자/동물 화면과 병원관리의 Order 관리 목록 화면은 같은 정보 구조를 써야 한다. 왼쪽 사이드패널에서 목록을 고르면 오른쪽 contents 영역은 항상 같은 순서로 구성한다.

좌측 목록 선택 contents 헤더 선택적 탭그룹 공유 데이터 테이블 행 클릭 드로어
이번 제안의 결론

고객관리 동물 페이지의 테이블을 별도 카드 안에 다시 감싸는 구조를 제거한다. 테이블은 병원관리처럼 contents의 직접 하위 영역으로 두고, 헤더, 선택적 탭, table controls의 역할을 분리한다.

✓ 구현 시 새 데이터그리드 도입 없이 기존 EMR table primitives를 재배치하는 범위가 적절하다.

요구사항 정리

1. 선택 구조

왼쪽 사이드패널의 leaf 목록을 선택하면 해당 목록 화면이 오른쪽 contents에 열린다.

2. 콘텐츠 슬롯

contents는 헤더, 선택적 탭그룹, table controls, 데이터 테이블, 하단 상태 영역으로 정리한다.

3. 상세 진입

체크박스는 bulk action용이고, 행 클릭은 오른쪽 드로어 상세 조회, 수정, 삭제 액션으로 연결한다.

현재 차이와 수정 방향

현재 고객관리 동물 화면 수정 필요

콘텐츠 제목 아래에 테이블 카드가 한 번 더 생겨서 병원관리 목록 화면보다 깊이가 많아 보인다.

제안 구조 통일

contents 내부에서 헤더와 테이블이 바로 이어져 같은 목록 화면 계열로 인식된다.

검색/필터/밀도 컨트롤 배치 원칙

헤더 오른쪽

복제, 등록, 삭제, 더보기처럼 화면 전체에 작동하는 page action만 둔다.

탭 있는 화면

왼쪽은 탭, 오른쪽은 검색, 빠른 필터, 밀도, 컬럼처럼 현재 탭의 테이블에 작동하는 control을 둔다.

탭 없는 화면

왼쪽은 작은 scope summary, 오른쪽은 compact controls를 둔다. 필터는 탭이 아니라 목록 축소 조건으로 처리한다.

✓ 동물의 `전체/고양이/강아지`, 보호자의 `수신/미수신`, 삭제 목록의 `동물/보호자`는 화면 전환이 아니라 같은 테이블을 좁히는 조건이므로 탭이 아닌 filter chip으로 둔다.
목록 화면왼쪽 표시오른쪽 compact controls탭 사용 여부
고객관리 · 동물 전체 동물 · 5건 검색, 종, 상태, 수신, 밀도, 상세 필터, 컬럼 사용하지 않음. 종은 필터로 처리
고객관리 · 보호자 전체 보호자 · 5명 검색, 수신, 최근방문, 미수납, 밀도, 상세 필터, 컬럼 사용하지 않음. 보호자 속성은 필터로 처리
고객관리 · 삭제된 보호자/동물 삭제된 항목 · 0건 검색, 대상, 삭제일, 삭제 사유, 복구 가능, 밀도, 상세 필터, 컬럼 사용하지 않음. 동물/보호자 구분은 대상 필터로 처리
병원관리 · Order 하위 목록 section tab group 검색, 유형, 상태, 대상, 밀도, 상세 필터, 컬럼 실제 하위 카탈로그 전환이 있을 때만 사용

체크박스 선택 상태 작업 계획

조제/처치 테이블에는 이미 체크박스 선택 후 하단 bulk action bar가 뜨는 구현이 있다. 고객관리와 병원관리 목록도 이 패턴을 재사용하되, 각 화면의 도메인 액션만 바꾼다.

수정 후 시안: 고객관리 동물

아래 시안은 고객관리 동물 목록을 병원관리 Order 목록과 같은 구조로 맞춘 모습이다. 테이블 자체는 별도 장식 카드가 아니라 contents의 데이터 영역이고, 상단 헤더는 화면 제목과 등록 액션만 처리한다. 탭이 없는 고객관리 목록은 왼쪽에 작은 scope summary를 두고, 검색, 필터, 밀도, 컬럼은 오른쪽 compact controls로 분리한다.
