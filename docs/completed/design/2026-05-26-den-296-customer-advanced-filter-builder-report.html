Project 13 / DEN-296

고객관리 테이블 필터 UI를 공용 Advanced Filter Builder로 이전

고객관리의 동물/보호자 테이블이 기존 feature-local 필터 UI 대신 공용 EmrTableFilterBuilder를 사용하도록 변경됐다. 이제 billing, chart/order, customer 화면이 같은 필터 builder 규칙을 공유한다.

Human Review 준비 완료

무엇이 바뀌었나

  • 고객관리 테이블의 로컬 draft/apply 필터 builder를 제거하고 공용 builder/model helper를 적용했다.
  • 완성된 field/operator/value 조건만 Filter N과 결과 필터링에 반영된다.
  • 처음 열면 조건 row 하나가 draft 상태로 보이고, 미완성 row는 결과에 영향을 주지 않는다.
  • 테이블 헤더 정렬은 기존처럼 단일 컬럼 정렬만 유지하고, 필터는 섹션 action 영역의 Filter 버튼에서 연다.
  • 고객 선택, 상세 drawer, 검색, 컬럼 표시, density, row action, mock/session 흐름은 유지했다.

왜 중요한가

화면마다 다른 필터 UI를 유지하면 QA와 사용성이 흔들리기 쉽다. 이번 변경으로 고객관리도 공용 필터 builder의 첫 draft row, 완료 조건 count, incomplete row ignore, reset/Escape 동작을 같은 방식으로 따르게 됐다.
