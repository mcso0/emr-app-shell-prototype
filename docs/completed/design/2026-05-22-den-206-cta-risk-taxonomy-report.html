CTA Risk Taxonomy 보고서

차트 작성완료, 청구 확정, 수납 완료, 삭제, 미연결 기능 CTA가 화면마다 다른 규칙처럼 보이는 문제를 줄이기 위해 CTA risk taxonomy와 확인/preflight/feedback 기준을 정의했다.

이번 작업은 화면 반영 전 foundation 단계다. 앱 화면에서 확인 가능한 CTA 변경은 DEN-208, DEN-209 등 후속 screen-level 이슈에서 시작한다.

Human Review 준비 화면 미반영 docs foundation

Risk Taxonomy

Risk 정의 기본 기준
safe 보기, 필터, 패널 열기, preview처럼 상태를 커밋하지 않는 action 확인 불필요, 결과가 보이지 않을 때만 toast
state-changing 진료/운영 workflow 상태를 session/local-first 경계 안에서 바꾸는 action 완료/확정/다중 객체 변경이면 confirmation 필요
financial 청구, 수납, 금액, 보호자-facing money state를 바꾸는 action 항상 preflight summary와 confirmation 필요
destructive 삭제, 취소, 초기화, 입력 폐기, 숨김/복원 action destructive confirmation과 affected object identity 필요
unavailable MVP에서 미연결, provider 의존, future scope, 권한 차단 action 조용히 실패 금지, unavailable 이유와 다음 행동 안내 필요

대표 CTA 매핑

  • 차트 작성완료: state-changing, patient/encounter context와 clinical artifact summary 필요
  • Order 확정: state-changing, selected-order summary 필요
  • 청구 확정: financial, invoice/guardian/amount preflight와 실패 복구 필요
  • 수납 완료: financial, payment-state boundary와 실제 PG 미연동 copy 필요
  • 삭제/초기화: destructive, affected object identity와 destructive confirm 필요
  • 출력, external-provider tools: unavailable, 지원 범위와 MVP boundary 안내 필요

A등급 기준에 주는 효과

  • financial/state-changing CTA의 확인 기준을 한 곳에서 판정할 수 있게 했다.
  • 청구/수납처럼 신뢰도가 중요한 action에 preflight summary를 필수 기준으로 고정했다.
  • unavailable action이 조용히 실패하거나 실제 provider 연동처럼 보이지 않도록 기준을 만들었다.
  • 후속 DEN-208, DEN-209가 같은 taxonomy를 기준으로 화면을 바꿀 수 있다.
