Table Sort / Filter Behavior Contract

이번 작업은 화면을 바로 바꾼 것이 아니라, 테이블 헤더의 정렬/필터를 실제 동작으로 구현하기 전에 어떤 컬럼이 정렬되고, 어떤 필터가 상태를 가지며, 어디까지 보존해야 하는지를 정한 계약 작업이다. 다음 이슈부터는 이 기준을 따라 대표 테이블 하나씩 구현하면 된다.

왜 먼저 계약이 필요한가

  • Project 12는 헤더/셀 표준과 resize affordance를 정리했지만, 실제 sort/filter 동작은 일부러 제외했다.
  • EMR 테이블은 차트, 수납, 고객관리, 병원관리마다 성격이 달라서 모든 헤더에 같은 기능을 붙이면 workflow가 흔들린다.
  • 정렬/필터가 row identity, order draft, confirmation, billing totals를 깨지 않도록 먼저 공통 규칙이 필요하다.

결정 사항

항목 결정
적용 방식 전체 테이블 일괄 적용이 아니라 Linear 이슈가 지정한 테이블만 PR 단위로 적용한다.
정렬 대상 이름, 날짜/시간, 금액, 수량, 명시적 상태 순서처럼 안정적인 scalar 데이터만 허용한다.
필터 대상 상태, 카테고리, 타입, 담당자, 날짜 범위, 검색처럼 실제 workflow에서 좁혀보는 값만 허용한다.
제외 대상 checkbox, action, icon-only, attachment, memo, warning/change, summary, total, command 컬럼은 static이다.
상태 저장 초기 Project 13 구현은 table local state만 사용한다. URL, localStorage, Supabase, server persistence는 제외한다.
첫 pilot DEN-271에서 billing invoice table을 먼저 구현한다.

Sort Contract

  • 각 sortable column은 sort key, sort type, empty handling, tie-breaker, reset behavior를 가진다.
  • 기본은 단일 컬럼 정렬이며 cycle은 none → ascending → descending → none이다.
  • 비어 있는 값은 ascending/descending 모두에서 마지막으로 보낸다.
  • 동률은 원래 row order 또는 명시적 secondary key로 안정적으로 처리한다.
  • 정렬은 화면 row 순서만 바꾸고 원본 배열, 선택 row, draft state, billing totals를 변형하지 않는다.

Filter Contract

  • 각 filter는 filter key, option source, active state, empty state, clear action, composition rule을 가진다.
  • 서로 다른 필터와 검색은 AND로 조합한다.
  • 첫 pilot은 단일 선택 필터를 기본으로 하고, multi-select는 별도 scope가 있을 때만 켠다.
  • 상태/카테고리/담당자/검색은 column-local menu보다 기존 toolbar/global filter를 우선한다.
  • 필터 결과가 없으면 조건 때문에 비어 있음을 보여주고 clear action을 제공한다.

접근성 기준

  • 정렬 trigger는 실제 button 또는 동등한 interactive element여야 한다.
  • aria-sort는 active sorted header에만 사용한다.
  • 정렬/필터 trigger는 keyboard로 도달 가능해야 하며 active state가 hover 없이 보여야 한다.
  • static header는 의미 없는 tab stop을 만들지 않는다.

인터랙티브 시안

Sort/filter UX는 별도 프로토타입 보고서에서 수정된 세 가지 방향으로 비교할 수 있다: DEN-270 Sort/Filter Interactive Prototype Options.

  • A: section-level Filter button plus header sort. Billing pilot 기본안.
  • B: admin filter builder plus header sort. Customer/admin master-data grid 후보.
  • C: compact clinical filter builder plus header sort. Chart/order 후보.

수정된 원칙은 테이블 헤더에는 정렬만 두고, 필터는 섹션 헤더 오른쪽 액션 영역의 Filter 버튼에서 다중 조건으로 관리하는 것이다. 정렬 상태는 별도 chip이나 summary row가 아니라 정렬된 헤더 자체에서 화살표와 active 상태로 표시하고, hover/focus 시 현재 정렬과 다음 동작을 안내한다. 섹션 액션 영역에는 Filter 버튼만 두고 Save view나 바깥 Clear는 기본 제공하지 않는다. 필터 버튼은 조건이 있으면 Filter N으로 조건 수를 표시하며, 별도 active filter chip row는 두지 않는다. 필터 dropdown footer에는 Close 옆에 초기화 action을 둔다.
