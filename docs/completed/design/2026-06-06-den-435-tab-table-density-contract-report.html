Tab/Table Density Contract 보고서

이번 작업은 탭과 테이블 밀도 조절을 실제 화면에 바로 적용하기 전에, 어떤 UI가 탭이고 어떤 UI가 필터/모드/표시 옵션인지 구분하는 기준을 만든 문서 작업이다.

승욱이 확인할 결정

  • Workspace tab은 shell navigation으로 유지하고, 필터나 density 설정으로 쓰지 않는다.
  • Section tab은 같은 화면 안의 peer panel 전환에만 쓴다.
  • 상태/분류/담당자처럼 데이터를 좁히는 UI는 tab이 아니라 filter control로 둔다.
  • 테이블 밀도는 compact, standard, comfortable 세 단계 유지.
  • Density dropdown은 전면 교체가 아니라, 좁은 toolbar나 view options 묶음에서만 조건부로 쓴다.

Tab 유형 기준

유형 쓸 때 피할 때
Workspace tab 열린 업무, route/history, tab close/restore 테이블 필터, density, section 설정
Section tab 한 화면 안에서 동등한 panel을 전환 긴 분류 목록, transient filter
Segmented mode 2-5개 정도의 고정된 mode 선택 route navigation, 늘어나는 category taxonomy
Filter control 테이블 row를 status/category/date/search로 좁힘 content panel navigation처럼 보이게 만드는 경우

Density 기준

Density는 행 높이와 padding을 바꾸는 표시 설정이다. row identity, sort/filter 결과, 청구 금액, 권한, DB/API 동작은 바꾸지 않는다.

Mode 표시 문구 권장 사용
compact 좁게 임상/오더/관리처럼 행 수가 중요한 테이블
standard 기본 기본 운영 테이블
comfortable 넓게 검토형, 다중 line preview, 낮은 row count 화면

Dropdown 결정

결론: density dropdown은 조건부 허용이고, 기본은 기존 icon segmented selector 유지.

  • 자주 쓰는 테이블은 한 번에 누를 수 있는 icon segmented selector가 더 낫다.
  • 좁은 화면, 복잡한 toolbar, 여러 테이블을 한 설정으로 묶는 화면에서는 dropdown이 가능하다.
  • Dropdown trigger는 보기 또는 표시 옵션처럼 view option 성격으로 둔다.
  • Saved view, URL state, localStorage, server preference는 이번 범위가 아니다.
