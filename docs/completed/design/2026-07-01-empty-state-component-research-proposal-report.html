CLAiR EMR Design System Research

Empty State 컴포넌트 조사 및 최종 제안

접수/예약 큐처럼 항목이 없을 때 표시되는 빈 상태를 공용 컴포넌트로 만들기 전에, 주요 디자인 시스템의 정의와 컴포넌트 구조를 조사하고 Figma 시안의 보완점을 정리했다. 이 보고서는 구현 전 판단 기준과 추천 API 방향을 제안한다.

요청과 결론

요청은 Figma 시안을 기준으로 Default, 1 action, 2 action 세 스타일의 empty state 컴포넌트를 만들기 전에 다른 서비스 사례를 조사하고, 시안 보완점을 제안하는 것이었다.

최종 제안은 액션 개수만을 variant로 삼지 않는 것이다. 액션 수는 actions 속성으로 분리하고, 실제 컴포넌트 판단은 kind, size, align, tone, title, description, primaryAction, secondaryAction 중심으로 잡는 것이 더 안전하다.

조사에서 나온 공통 원칙

1. Anatomy는 거의 동일하다

대부분의 시스템은 아이콘 또는 일러스트, 제목, 설명, 주 액션, 보조 액션을 기본 구성으로 둔다. CLAiR도 이 다섯 영역을 컴포넌트의 기본 slot으로 잡는 편이 좋다.

2. 유형 분리가 액션 개수보다 중요하다

실제 사용자가 헷갈리는 지점은 버튼이 몇 개인지가 아니라 왜 비었는지다. 검색 결과 없음, 필터 결과 없음, 아직 생성되지 않음, 권한 없음, 장애를 별도로 표현해야 한다.

3. 액션은 최대 두 개가 적절하다

empty state 안의 주 액션은 하나가 가장 명확하다. 두 번째 액션은 보조 또는 우회 행동으로 제한하고, 세 개 이상은 toolbar, menu, link 영역으로 분리하는 편이 안전하다.

4. 접근성은 API로 노출해야 한다

headingLevel, action group label, icon의 aria-hidden 또는 aria-label 처리는 구현자가 매번 추측하지 않도록 컴포넌트 계약에 포함되어야 한다.

Figma 시안 확인 결과

확인한 Figma 노드는 CDS.V2 CLAiR EMR Design System Ver.2 / emptyPlaceholder 이다. 내부에는 style=Default, style=1 action, style=2 action 세 변형이 있다.

좋은 점 아이콘, 제목, 보조 설명, 액션 영역의 기본 골격이 명확하다.
보완 필요 variant가 액션 개수에만 묶여 있어 상황 유형, 크기, 정렬, 톤을 표현하기 어렵다.
구현 위험 한국어 버튼 길이, 좁은 side panel 폭, 접근성 heading, error/loading 구분이 아직 보이지 않는다.

시안 보완 제안

  • pleaceholder 텍스트는 placeholder 또는 실제 샘플 문구로 수정한다.
  • Figma variant명은 style=Default보다 actions=None, actions=One, actions=Two가 더 명확하다.
  • kind 속성으로 no-data, no-search-results, no-filter-results, no-scope-result, no-permission, upstream-pending을 분리한다.
  • size=compact를 추가해 접수/예약 큐, 차트 큐, 검사 큐처럼 좁은 패널에서도 과하게 보이지 않게 한다.
  • align=start를 지원해 CLAiR의 대기열 패널처럼 좌상단 기준의 업무형 empty state를 표현할 수 있게 한다.
  • 아이콘은 장식용인지 상태 의미를 갖는지 정하고, 장식용이면 assistive technology에서 읽히지 않게 처리한다.

CLAiR 최종 컴포넌트 제안

추천 이름은 EmrEmptyState다. 기존 EmrQueueEmptyState는 즉시 삭제하지 않고, 새 컴포넌트를 감싸는 queue 전용 wrapper로 점진 이관하는 방식이 안전하다.

권장 속성 구조

type EmrEmptyStateKind =
  | "no-data"
  | "no-search-results"
  | "no-filter-results"
  | "no-scope-result"
  | "no-permission"
  | "upstream-pending";

type EmrEmptyStateProps = {
  kind?: EmrEmptyStateKind;
  title: React.ReactNode;
  description?: React.ReactNode;
  icon?: React.ReactNode;
  primaryAction?: React.ReactNode;
  secondaryAction?: React.ReactNode;
  size?: "compact" | "standard";
  align?: "start" | "center";
  tone?: "neutral" | "info" | "warning";
  headingLevel?: 2 | 3 | 4 | 5 | 6;
  actionGroupLabel?: string;
  "data-testid"?: string;
};

Variant 계약

축 값 역할
kind no-data, no-search-results, no-filter-results, no-scope-result, no-permission, upstream-pending 왜 비었는지와 기본 문구 방향을 정한다.
actions none, one, two Figma 시안의 세 스타일과 대응한다. 코드에서는 action slot 유무로 계산해도 된다.
size compact, standard side panel, table, full section의 밀도를 조절한다.
align start, center 업무형 리스트는 start, 큰 빈 화면이나 onboarding은 center를 사용한다.
tone neutral, info, warning 단순 빈 상태와 주의가 필요한 상태를 구분한다. 실패와 복구는 empty state가 아니라 alert로 처리한다.

문구 계약

  • 제목은 한 줄로, 빠르게 스캔 가능한 업무 문장으로 쓴다.
  • 설명은 원인이나 다음 행동이 필요할 때만 1-2문장으로 쓴다.
  • 큐 패널의 기본 empty copy는 마침표 없는 짧은 운영 문구를 유지한다.
  • 검색 결과 없음과 필터 결과 없음은 같은 문구로 뭉치지 않는다.
  • 권한, 서버 장애, live read 실패는 단순 빈 상태처럼 보이게 만들지 않는다.

상황 권장 kind 권장 copy 권장 action
오늘 접수/예약 큐가 비어 있음 no-scope-result 접수/예약이 없습니다 없음 또는 신규 접수
검색어 결과가 없음 no-search-results 검색 결과가 없습니다 검색 초기화

상위 workflow가 아직 결과를 만들지 않음 upstream-pending 확정된 오더가 없습니다 차트로 이동
사용자가 볼 수 없는 범위 no-permission 이 범위의 업무를 볼 권한이 없습니다 관리자 문의 또는 workspace 이동. 보안 완료를 암시하지 않는다.

구현 순서 제안

  1. Figma 컴포넌트 property를 actions, kind, size, align, tone으로 보완한다.
  2. Storybook에서 EmrEmptyState를 먼저 구현하고 compact, standard, no search, no filter, one action, two action 사례를 검증한다.
  3. 기존 EmrQueueEmptyState는 새 컴포넌트 wrapper로 바꿔 reception, chart, lab-imaging, dispensing, billing 큐의 현재 동작을 보존한다.
  4. 검색/필터 empty state부터 action slot을 붙인다. 예: 검색 초기화, 조건 초기화.
  5. DOM 측정 또는 Playwright로 좁은 side panel에서 아이콘 크기, 텍스트 gap, 버튼 overflow, 모바일 폭을 검증한다.

구현 전 Acceptance Criteria

  • loading, empty, error, permission, info state가 문구와 시각 톤에서 구분된다.
  • 모든 empty state는 무엇이 없는지 제목에서 말한다.
  • 다음 행동이 있는 경우 primary action은 하나만 가장 강하게 보인다.
  • secondary action은 보조 행동이며 primary action보다 시각 우선순위가 낮다.
  • 3개 이상의 행동은 empty state 내부 버튼으로 직접 나열하지 않는다.
  • 아이콘은 장식인지 의미인지 접근성 처리가 정해져 있다.
  • 한국어 버튼 문구가 side panel 폭에서 깨지지 않는다.
  • 기존 큐 empty state의 compact spacing과 짧은 periodless copy를 깨지 않는다.

위험과 범위 밖

이번 보고서는 조사와 제안 산출물이다. 런타임 컴포넌트 구현, Storybook 추가, 기존 큐 컴포넌트 이관, 테스트 작성은 아직 수행하지 않았다.
  • Figma 시안은 구조와 screenshot 기준으로 확인했다. 실제 Figma variant property 전체 정리는 별도 편집 단계가 필요하다.
  • 권한 없음, API 실패, degraded read/write는 empty state가 아니라 inline alert 또는 별도 error state로 처리해야 한다.
  • 공용 컴포넌트를 너무 빨리 넓히면 화면별 업무 맥락이 사라질 수 있다. 먼저 큐와 검색/필터 계열부터 적용하는 것이 좋다.
  • 외부 디자인 시스템은 패턴 참고용이다. CLAiR의 밀도, 좌상단 정렬, 운영형 짧은 문구 기준을 우선해야 한다.

관련 CLAiR 문서와 현재 코드 기준

  • docs/design/system/empty-info-state-contract.md 는 empty state, info box, inline alert의 경계를 이미 정의한다.
  • src/components/emr/subpanel.tsx에는 현재 큐 전용 EmrQueueEmptyState, EmrQueueLoadingState, EmrListSearchEmptyState가 있다.
  • tests/queue-loading-state.spec.ts는 기존 큐 empty state의 아이콘 크기와 텍스트 gap 회귀 검증에 적합하다.
