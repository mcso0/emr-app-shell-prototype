CLAiR EMR Empty State Surface Placement

Empty State Surface별 배치 기준 보고서

기존 18개 시안은 state별 컴포넌트 표현을 정리한 자료다. 이번 보고서는 그 다음 단계다. 같은 empty 원인이 대기열, 본문, 드로어, 표, 위젯에 동시에 나타날 때 어느 영역이 상태를 표시하고 어느 영역이 primary action을 가져야 하는지 정한다.

결론

상태 표기는 여러 surface에 가능하지만, primary action은 한 화면에서 하나의 owner surface만 갖는다. 대기열과 본문이 함께 비어 있다면 작은 대기열은 compact 상태 확인용으로 둔다. 사용자가 다음 업무를 결정해야 하는 primary CTA는 본문 content surface에 배치한다.
Toolbar 예외 다른 디자인 시스템을 보면 toolbar/header에 항상 보여야 하는 primary entry를 별도로 남기는 경우가 있다. 이때 empty state 안의 action은 중복 primary가 아니라 같은 행동으로 들어가는 낮은 강도의 shortcut 또는 보조 안내로 본다. 즉 “CTA owner는 하나”라는 원칙은 유지하되, persistent toolbar entry와 empty-state shortcut의 역할을 분리한다.

Queue는 local 상태를 설명한다

대기열은 검색 초기화, 필터 초기화, 대기열 다시 시도처럼 큐 안에서 바로 해결되는 action만 강하게 가져간다. 전체 workflow를 시작하거나 다른 모듈로 이동시키는 CTA는 기본적으로 본문이 맡는다.

Content는 decision owner다

진료/차트, 조제/처치, 검사, 수납처럼 사용자가 “다음에 무엇을 하지?”를 판단하는 큰 빈 영역은 설명과 primary CTA를 함께 가져야 한다. 예: 접수/예약으로 이동, 차트로 이동.

외부 디자인 시스템 참고

다른 시스템들도 empty state를 단일 컴포넌트 하나로만 정의하지 않는다. full page, card, table, filtered results, permission/error 같은 맥락을 나눠 다룬다.

시스템 공식 가이드에서 확인한 기준 CLAiR 적용 의미
Shopify Polaris Empty state 컴포넌트는 admin full page가 비었을 때 쓰며, 개별 작은 영역용 패턴으로 보지 않는다. 큰 content empty와 작은 queue empty를 같은 강도와 같은 action 구조로 만들면 안 된다.
Cloudscape 새 데이터가 없는 empty state와 필터 결과가 없는 zero results state를 구분한다. 검색/필터 결과 없음은 queue/table 내부의 local recovery로 처리한다.
PatternFly Card 안의 empty state에는 action을 둘 수 있지만, 그 action이 화면 밖에 있을 수 있으면 toolbar primary button도 유지한다. persistent toolbar entry와 empty-state shortcut은 함께 둘 수 있다. 다만 둘이 같은 위계의 primary처럼 보이면 안 된다.
GitHub Primer Empty state는 빈 공간을 채우며 왜 비었는지와 어떻게 진행할지 알려주는 패턴이다. CLAiR content surface에도 단순 문구가 아니라 다음 판단을 돕는 설명이 필요하다.
GitLab Pajamas Empty state의 목표를 feature adoption, learnability, usability로 본다. 빈 상태는 장식이 아니다. 사용자가 다음 업무 경로를 이해하게 만드는 교육적 표면이다.
Evergreen Primary CTA는 optional이며 empty state를 해결하는 action, text link는 보조 지원으로 정의한다. 모든 empty state에 action이 필요한 것은 아니다. 해결 가능한 상태일 때만 action을 둔다.

Action Placement Rules

  1. 한 화면에 primary CTA는 하나만 둔다. 같은 원인의 empty state가 queue와 content에 동시에 나타나면 content가 primary CTA owner다.
  2. Persistent toolbar entry는 예외적으로 공존할 수 있다. toolbar/header에 항상 보여야 하는 생성/이동 action이 있다면 유지한다. 단 empty state 안의 같은 action은 보조 shortcut으로 낮추거나, 설명만 남겨 같은 화면에 두 개의 primary가 있는 것처럼 보이지 않게 한다.
  3. Queue action은 local recovery만 허용한다. 검색어 지우기, 필터 초기화, 대기열 read 재시도는 queue에 둘 수 있다.
  4. Workflow 이동/생성은 content에 둔다. 접수/예약으로 이동, 차트로 이동, 상위 workflow 확인은 큰 본문 surface에서 설명과 함께 보여준다.
  5. Drawer는 selected object가 있을 때만 강해진다. 선택 대상이 없을 때 drawer는 안내만 하고, 원천 CTA는 content나 shell/header로 넘긴다.
  6. Error, permission blocker, degraded read는 empty가 아니다. EmrInlineAlert를 영향받는 surface 가까이에 배치하고, retry 또는 문의 action을 둔다.
  7. 3개 이상의 action은 empty state 안에 넣지 않는다. primary/secondary를 넘는 선택지는 toolbar, menu, source workflow로 분리한다.

컴포넌트 계약 보완안

기존 kind만으로는 위치와 CTA 소유권을 결정하기 어렵다. 구현할 때는 최소한 surface와 priority 축이 필요하다. 

type EmrEmptyStateKind =
  | "no-data"
  | "no-search-results"
  | "no-filter-results"
  | "no-scope-result"
  | "no-permission"
  | "upstream-pending";

type EmrEmptyStateSurface =
  | "queue"
  | "content"
  | "drawer"
  | "table"
  | "widget"
  | "global-shell";

type EmrEmptyStatePriority =
  | "supporting"        // 상태 확인용, primary CTA 없음
  | "local-recovery"   // 검색/필터/재시도처럼 해당 surface 안에서 해결
  | "primary-decision"; // 화면의 main CTA owner

type EmrEmptyStateProps = {
  kind: EmrEmptyStateKind;
  surface: EmrEmptyStateSurface;
  priority?: EmrEmptyStatePriority;
  title: React.ReactNode;
  description?: React.ReactNode;
  primaryAction?: React.ReactNode;
  secondaryAction?: React.ReactNode;
};

Reject Criteria

  • Reject: Queue와 content에 같은 primary CTA를 같은 강도로 중복 노출한다.
  • Reject: 권한 차단, API 실패, degraded read를 “데이터 없음”처럼 보이게 한다.
  • Reject: 좁은 queue surface에 workflow 이동 CTA 2개 이상을 넣는다.
  • Reject: Drawer에서 원천 workflow 생성/이동을 primary로 소유한다.
  • Reject: Empty state 안에 action 3개 이상을 직접 나열한다.
  • Reject: 로딩, error, no-data copy가 같은 아이콘/톤/문구 강도로 보인다.
  • Reject: Toolbar primary와 empty-state shortcut을 모두 primary 스타일로 보여준다.

  • 서브 에이전트 spark-explorer 2개를 read-only로 사용했다.
  • 코드 탐색: queue/content/drawer/table/widget empty state 사용처와 동시 empty 가능성을 확인했다.
