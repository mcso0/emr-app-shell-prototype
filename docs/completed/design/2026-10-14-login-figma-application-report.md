# 로그인 Figma 시안 실제 앱 적용

확인일: 2026-10-14. 작업: AUTH-PR-042 후속 구현. 기준 커밋: `513143f9b7a673804357e5239bc046c7264b8df0`.

## 적용 결과

승욱이 확인한 HTML 시안을 실제 Next.js 로그인·계정 복구 화면에 적용했다. 기존 작업을 보존하기 위해 `codex/login-figma-application`의 별도 작업 폴더에서 구현했다. 운영 배포와 원격 인증 설정은 수행하지 않았다.

- Figma 원본 Mesh gradient와 Water caustic 로고의 정적 렌더링 이미지를 사용했다. 공유 컴포넌트와 전역 토큰은 변경하지 않았다.
- 실제 빌드 화면의 1920×1080 기준 컨테이너는 440×548, 위치 x=740/y=266, 입력 폭은 376px이다. 카드 배경·테두리·그림자는 제거했다.
- 이메일 형식과 비밀번호 입력 여부로 로그인 버튼을 활성화한다. 로그인 비밀번호를 자르거나 공백을 제거하지 않는다. 기존 비밀번호 로그인, 초대 OTP, 비밀번호 설정, 안전한 이동과 워크스페이스 진입 표시를 유지한다.
- 일반 OTP는 기존 계정만 대상으로 요청한다. 초대 OTP는 기존 초대 검증 뒤에만 계정 생성 옵션을 사용한다. 일반 OTP 확인과 초대 인증 경로는 구분한다.
- OTP 입력, 불일치·만료·요청 제한 안내, 재발송, 다른 이메일로 변경, 중복 제출 방지, 안전한 메일 링크 복귀를 연결했다. 서버가 인증 유효성과 권한을 판단한다.
- 비밀번호 찾기는 기존 메일 요청·복구 링크 검증·서버 비밀번호 변경을 사용한다. 이메일 존재 여부를 드러내지 않는다. 새 비밀번호는 8~1024자이고 확인 값과 일치해야 한다. 변경 성공 후 세션을 종료하고 로그인으로 돌아간다.
- 아이디 찾기는 휴대전화 형식 검증과 미연결 안내를 표시한다. 본인확인 업체가 정해지지 않아 인증번호 버튼은 비활성이다. 문자 발송과 계정 조회는 수행하지 않는다.

## 시안과 실제 인증의 차이

HTML 시안의 8자리·5분 만료·30초 재발송·5회 실패 잠금은 운영 정책이 아니다. 후속 운영 설정 조회에서 이메일 OTP가 8자리임을 확인했다. 일반 OTP 입력 조건과 로컬 이메일 OTP 설정도 기존 초대와 같은 8자리로 맞췄다. 재발송 60초 대기는 화면의 요청 간격이다. 실제 만료와 제한은 인증 서버의 결과를 따른다.

운영 환경의 8자리 OTP·SMTP·숫자 코드 메일 템플릿을 읽기 전용으로 확인했다. 운영 콜백 주소는 설정 변경안을 준비했고 별도 승인을 기다린다. 실제 메일 전달은 아직 확인하지 않았다. 로컬 미리보기에는 운영 인증 정보를 복사하지 않았다. 문자 본인확인 업체 선정과 검증된 신원에 따른 아이디 조회는 후속 연동 의존성이다.

## 검증

관련 고유 테스트 45개가 통과했다. 실제 인증 정보 대신 로컬 가짜 인증 서버와 예시 계정만 사용했다.

- 기존 인증·초대·복구 계약: 22개 통과. 첫 실행의 준비 시간 초과 2개는 재실행에서 통과했다.
- 로그인 입력·이동 주소 검증: 2개 통과.
- 새 OTP·복구·미연결 아이디·반응형 통합 테스트: 14개 통과. 8자리 인증 확인과 일부 입력의 제출 제한, 계정 생성 옵션, 재발송 실패 후 재시도, 일반 OTP 세션의 비밀번호 변경 거부, 검증된 복구 후 로그아웃, 링크 실패, 중복 요청 방지를 포함한다.
- 실제 호출자 Storybook: 7개 통과.
- `npm run lint`, `npx tsc --noEmit`, `npm run build`, `npm run docs:check`, `npm run security:secrets`, `npm run ux-copy:check`, `git diff --check` 통과.
- 내부 브라우저에서 빌드된 앱의 기본 화면·입력 조건·OTP 전환·아이디 안내·비밀번호 찾기를 확인했다. 390×844 화면은 가로·세로 넘침이 없다. 320px 및 390px의 다섯 진입 화면도 통합 테스트에서 가로 넘침을 확인했다.

## 기존 실패와 확인 한계

선택한 기존 테스트 25개 중 3개는 변경 전 기준 코드에서도 같은 지점에서 실패했다. 이번 변경으로 확대 수정하지 않았다.

| 테스트 | 기존 기대값과 실제 차이 |
| --- | --- |
| 로그인 후 localStorage 세션과 요청 워크스페이스 | 인증·워크스페이스 이동 후 기존 수납 예시 행을 찾지 못함 |
| 기본 워크스페이스 진입 | 접수 화면에서 기존 환자 예시를 찾지 못함 |
| 로그인 후 선택한 역할 표시 | 테스트는 과거 `clair-demo` 기본 경로를 기대하지만 현재 기본 경로는 준비된 청담 워크스페이스 |

빌드에는 기존 문서 뷰어가 프로젝트 전체를 추적한다는 경고 1개가 남는다. 빌드는 성공했다. 실제 메일·문자·계정 정보나 운영 로그인은 검증하지 않았다. 로컬 구현과 가짜 인증 서버 검증은 운영 전달 확인이나 사용자 수락을 대신하지 않는다.
