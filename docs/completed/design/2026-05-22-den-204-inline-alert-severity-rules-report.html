Inline Alert Severity Rules 보고서

Product MVP 전반에서 오류, 주의, 안내, 성공 피드백을 같은 규칙으로 보여주기 위한 공통 EmrInlineAlert 컴포넌트와 severity 판단 기준을 추가했다.

이번 작업은 화면별 적용 전 단계의 foundation 작업이며, 접수/수납/차트/메뉴 흐름 적용은 후속 이슈에서 진행한다.

Human Review 준비 A등급 기반 강화

변경 사항

  • src/components/emr/inline-alert.tsx를 추가해 error, warning, info, success severity와 기본 ARIA role을 표준화했다.
  • docs/design/system/inline-alert-feedback-rules.md에 persistent inline alert, toast, field error, dialog의 사용 경계를 정리했다.
  • docs/design/system/global-feedback-ui-audit.md와 README/changelog를 갱신해 공통 피드백 primitive 기준을 최신화했다.
  • tests/design-tokens.spec.ts의 shared EMR component 토큰 가드에 새 컴포넌트를 포함했다.

A등급 기준에 주는 효과

  • 오류/주의/안내/성공 상태가 화면마다 다른 시각 규칙으로 흩어지는 문제를 줄이는 기반을 만들었다.
  • 복구 행동 슬롯을 컴포넌트 계약에 포함해 접수 read failure와 수납 save failure에 적용할 수 있게 했다.
  • mock/live 경계 안내를 info 또는 warning으로 일관되게 표현할 기준을 만들었다.
  • 색상만으로 상태를 구분하지 않고 제목, 본문, icon, role, action을 함께 쓰는 규칙을 명시했다.

제외 범위

  • 이번 이슈에서는 실제 접수/수납/차트 화면에 전체 적용하지 않았다.
  • live Supabase 검증, 서버 권한 enforcement, 원격 retry 내부 구현, 결제/이메일/provider 연동은 포함하지 않았다.
  • 새 toast 시스템이나 dialog shell은 만들지 않았다. 각각 기존/후속 이슈 범위로 유지했다.

  • npx tsc --noEmit: 통과
