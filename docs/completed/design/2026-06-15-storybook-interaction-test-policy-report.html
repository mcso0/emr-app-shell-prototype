Storybook Interaction Test Policy

Storybook interaction test는 당분간 안정성을 우선한다. storybook/test helper는 MCP runner에서 초기화 문제가 확인됐으므로 새 play function에는 사용하지 않고, 필요한 경우 DOM API 기반 검증을 표준으로 둔다.

결정 사항

  • 기본은 rendering-only story로 유지한다.
  • 입력, 필터, disclosure, keyboard, disabled-state처럼 동작 검증이 필요한 경우에만 play function을 둔다.
  • 새 play function은 canvasElement 내부 DOM query, native event, plain Error throw를 사용한다.
  • storybook/test helper import는 별도 후속 검증 전까지 보류한다.
  • MCP focused test는 stories: [{ storyId: "..." }] shape로 호출한다.

왜 중요한가

Storybook이 컴포넌트 카탈로그에서 실제 검증 도구로 커지려면 test가 예측 가능해야 한다. 현재는 helper 편의성보다 MCP runner에서 반복 통과하는 단순 DOM API 방식이 더 안정적이다.

범위 밖

Storybook/Vitest/Vite/Playwright 설정 변경, 기존 story test migration, 신규 컴포넌트 story 추가, DB/Supabase/권한/배포/외부 연동은 포함하지 않았다.

검증

  • docs/design/system/storybook-operating-rules.md에 interaction test 정책을 추가했다.
  • npm run docs:check 통과.
