Popover 컴포넌트 시스템 실행 리포트

Popover를 바이탈 입력, 접수 단일 선택, 다중 선택, 검색 선택, 작은 액션에 공통으로 쓸 수 있도록 리포트, Figma 컴포넌트, 코드 primitive, pilot 적용까지 연결했다.

핵심 변경

  • Linear 프로젝트 CLAiR EMR Popover Component System와 DEN-330~334 이슈를 생성했다.
  • 기존 HTML 리포트에 접수형 단일 선택 popover와 single/multiple option 시안을 추가했다.
  • Figma 섹션 27344:9927 안에 Popover 단일 컴포넌트셋을 생성했다.
  • 초기 과생성된 240개 variant 구조는 제거하고, 최종은 type 5개 variant만 남겼다.
  • 코드에는 EmrPopoverShell 계열과 Base UI 기반 RadioGroup primitive를 추가했다.
  • 환자 인포바 바이탈 버튼과 접수 등록 유형 선택을 pilot 적용했다.

  • Browser QA: 차트 바이탈 popover 열기/입력/저장/닫힘, 접수 radio 단일 선택 role/checked 상태 확인

리서치 반영

  • Figma Help Center의 variants 문서는 component set 안에서 variant property가 작동하는 구조를 설명한다.
  • Figma component management 가이드는 content-level 변경은 component properties로 처리해 variant 수를 늘리지 않는 방향을 권장한다.
  • 이번 Popover는 그 기준에 맞춰 시각적으로 의미 있는 type만 variant로 두고, 나머지는 boolean/text property로 낮췄다.

남은 리스크

  • Figma 생성 폰트는 API 환경에서 Pretendard 로드가 실패해 NanumGothic으로 생성했다. 실제 파일에서는 텍스트 스타일/타이포는 승욱이 별도로 정리 가능하다.
  • QA는 mock app 기준으로 완료했다. 실제 환자 데이터 저장이나 서버 저장은 이번 범위에 포함하지 않았다.
  • live backend 저장, Supabase, RLS, production deploy는 범위 밖이다.
