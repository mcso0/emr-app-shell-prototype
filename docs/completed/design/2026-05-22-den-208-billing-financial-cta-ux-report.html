Billing Financial CTA UX 보고서

청구/수납 화면의 청구 확정, 미납 처리, 수납 완료 CTA를 financial risk taxonomy에 맞춰 저장 전 preflight 확인 단계로 감쌌다. 금액, 보호자/환자, 결제 수단, 변경 후 상태, MVP 결제 경계를 저장 전에 확인할 수 있다.

Human Review 준비 앱 화면 반영

변경 사항

  • EmrDialogShell variant="confirm" 기반의 청구/미납/수납 financial preflight dialog를 추가했다.
  • preflight body에 청구서, 보호자/환자, 청구 항목 수, 확인 금액, 결제 수단, 변경 후 상태를 표시한다.
  • 실패 시 다이얼로그를 닫고 EmrInlineAlert severity="error"로 저장 안 됨, MVP 경계, 다시 시도 action을 수납 패널 안에 남긴다.
  • 결제 수단 저장 실패와 수납 상태 저장 실패를 구분해 복구 action label을 다르게 보여준다.

A등급 기준에 주는 효과

  • UXA-02: 청구/수납의 financial CTA가 동일한 confirm shell, action order, width 규격을 따른다.
  • UXA-03: 저장 실패가 토스트성 문구가 아니라, 수납 패널 내부의 복구 가능한 inline alert로 남는다.
  • UXA-04: 금전 상태 변경 전에 금액과 상태 변경 결과를 확인해 accidental commit 위험을 낮춘다.
  • UXA-08: 실제 PG, VAT, 영수증, 환불, 정산 미연동 경계를 preflight와 failure copy에서 반복 확인한다.
