Sort / Filter UX 수정 시안

수정 방향은 명확하다. 테이블 헤더에는 정렬만 둔다. 필터는 테이블이 속한 섹션 헤더의 오른쪽 액션 영역에 Filter 버튼으로 제공하고, 버튼을 열면 여러 조건을 추가/삭제할 수 있는 builder형 드롭다운을 사용한다.

레퍼런스 조사 요약

  • shadcn/ui Data Table은 TanStack 기반으로 테이블마다 sorting/filtering 요구가 다르므로 재사용 가능한 거대 컴포넌트보다 조합 가능한 구조를 권장한다.
  • TanStack Table sorting과 column filtering은 state를 분리해 제어할 수 있어, header sort와 section-level filter builder를 함께 쓰기 좋다.
  • MUI X Filtering은 toolbar의 Filters 버튼으로 filter panel을 여는 방식을 지원한다. 이 패턴은 CLAiR의 섹션 헤더 액션 영역과 잘 맞는다.
  • AG Grid External Filter는 grid 컬럼 필터와 별개로 앱 레벨 필터를 둘 수 있음을 보여준다. EMR에서는 이 방식이 workflow 보존에 유리하다.

제안 시안

A · 권장 기본안

Section filter button

섹션 타이틀 오른쪽에 Filter 버튼을 두고, 현재 활성 조건 수를 버튼에 표시한다. 헤더는 정렬만 담당한다.

Billing pilot과 chart/order에 가장 안전한 기본안.

B · 관리형

Admin filter builder

다중 조건 builder는 현재 조건 편집에 집중하고, 섹션 액션에는 Filter 버튼만 유지한다. 관리자/운영 테이블에 적합하다.

Customer/admin master-data grid 후보.

C · 임상 간소형

Compact clinical filters

같은 builder를 쓰되 field 후보를 상태, 유형, 담당자 정도로 제한한다. 임상 테이블에서 과한 조작감을 줄인다.

Chart/order처럼 흐름 방해가 적어야 하는 화면 후보.

A. Section filter button

Filter 버튼은 섹션 헤더 오른쪽 액션 영역에 둔다. 사용자는 현재 필터 개수를 버튼에서 확인하고, 드롭다운 안에서 여러 조건을 추가/삭제한다.

  • 테이블 헤더에는 filter trigger를 두지 않는다.
  • 정렬은 scalar 컬럼의 헤더 버튼으로만 제공하고, 현재 상태는 해당 헤더에서 표시한다.
  • 필터 조건은 AND로 조합하고 조건 수는 Filter 버튼에 표시한다.
