01

왜 필요한가

BEFORE · 수정 전 소스

열린 순서가 곧 탭 순서다.

탭은 배열 순서로 표시되고, 새 탭은 끝에 추가된다. 수정 전 상단 컴포넌트와 상태 저장소에는 순서 변경 동작이 없었다. 닫기·선택·뒤로가기 기능은 이미 있다.

TARGET · 사용 가설

업무 묶음을 가까이 둔다.

진료 중에는 차트 옆에 검사 탭을, 접수 업무에서는 원내 현황 옆에 접수 탭을 둔다. 다시 열거나 닫지 않고 사용자가 순서를 직접 정한다. 탐색 시간 감소는 도입 후 검증할 가설이다.

대상은 화면 맨 위의 열린 업무 탭이다. 왼쪽 모듈 메뉴, 차트 내부 탭, 화면 안의 상태 필터는 이번 대상에 포함하지 않는다.

원내 현황

순서 변경 중에도 이 화면과 입력한 메모가 유지돼.
탭 제목을 좌우로 드래그해 봐.

시안 지원: 마우스 드래그, 바깥에 놓기·Esc 취소, 가장자리 자동 스크롤, 탭 선택, 추가·닫기, 같은 브라우저 탭 새로고침 시 순서 복원. 순서 변경은 데스크톱 마우스·트랙패드로 체험해. 저장은 이 HTML의 샘플 세션에만 적용하며 서버와 연결하지 않는다. 좁은 화면에서도 시안을 볼 수 있지만 실제 앱의 모바일 지원을 뜻하지 않는다.

01 / READY

잡기

02 / DRAG

이동

6px 이상 이동하면 드래그를 시작한다. 원래 자리는 흐리게 남기고 삽입선을 표시한다.

03 / DROP

확정

탭 영역에 놓으면 해당 위치에 삽입한다. 선택된 탭은 유지한다.

04 / CANCEL

취소

Esc 또는 탭 영역 밖에 놓으면 원래 순서를 유지한다. 저장하지 않는다.

03

헷갈리지 않는 동작 규칙

사용자 행동제품 동작 · 권장안
탭 클릭기존과 같이 탭을 선택한다. 6px 미만의 손 떨림은 클릭으로 처리한다. 드래그를 마친 뒤 발생한 클릭은 무시한다.
비활성 탭 이동이동한 탭을 자동으로 선택하지 않는다. 현재 화면, URL, 입력 포커스는 유지한다.
삽입 위치다른 탭의 중앙을 지날 때 앞·뒤 삽입 위치가 바뀐다. 탭을 서로 교환하지 않고, 지정 위치에 끼워 넣는다.
드래그 시각 상태이동 중인 탭은 얕은 그림자, 원래 자리는 낮은 불투명도, 목적지는 삽입선으로 구분한다. 초록색 외에 선·위치·형태로도 상태를 전달한다. 실제 적용은 CLAiR 토큰에 맞춘다.
+ · 닫기 버튼+는 이동 목록 밖에 둔다. 닫기를 눌러도 드래그가 시작되지 않는다. 마지막 탭은 닫을 수 없다. 새 탭은 현재 순서의 끝에 추가한다.
활성 탭 닫기변경된 화면 순서 기준으로 왼쪽 탭을 선택한다. 왼쪽이 없으면 첫 번째 남은 탭을 선택한다. 기존 닫기 정책을 따른다.
키보드← →로 탭 포커스를 이동하고 Enter / Space로 선택한다. 키보드는 탭 포커스 이동과 선택을 지원한다. 이번 범위에서 키보드 순서 변경은 제공하지 않는다.
보조 기술이동 후 “진료/차트, 6개 중 2번째로 이동”을 알린다. 활성 탭은 aria-selected로 표시한다. 순서 변경 결과를 읽어 주되, 별도 키보드 재정렬 조작은 제공하지 않는다.
탭이 많을 때크롬·Codex처럼 공간이 부족해지면 탭들이 같은 비율로 줄어든다. 기본 최대 너비는 148px, 최소 너비는 80px이다. 최소 너비로도 들어가지 않을 때만 탭 목록을 가로 스크롤한다. 긴 제목은 말줄임하고 아이콘·닫기 버튼은 유지한다. 양 끝 32px 구간에서 드래그하면 자동 스크롤한다. +·알림·프로필은 밀려나지 않는다. 두 줄 배치는 사용하지 않는다.
터치·좁은 화면v1 드래그는 데스크톱 마우스·트랙패드 우선이다. 터치 재정렬은 이번 범위에서 제공하지 않는다. 현재 탭바가 숨겨지는 모바일 구간의 새 UI는 별도 범위다.

드래그 시작 6px, 자동 스크롤 가장자리 32px, 탭 너비 80~148px을 사용한다. 너비 변경은 업무 탭 컴포넌트 안에 적용하며 공용 토큰은 변경하지 않는다.

04

순서는 저장하고, 작업은 보존한다

SAVE · 기존 경로 확장

놓았을 때 한 번 저장

드래그 중에는 임시 위치만 계산한다. 유효한 위치에 놓으면 탭 배열을 갱신하고 기존 저장 함수를 호출한다. 현재 코드는 sessionStorage와 500ms 지연 서버 저장을 사용한다.

권장 범위는 사용자 × 워크스페이스다. 서버 저장도 이 조합을 사용한다. 다른 직원의 탭 순서는 바꾸지 않는다.

PRESERVE · 불변 조건

탭 ID와 내용은 그대로

탭 ID, 활성 탭 ID, 화면 주소, 환자·진료 연결, 탭별 이동 기록을 유지한다. 재정렬만으로 화면 이동·재마운트·저장 확인창·업무 데이터 저장을 발생시키지 않는다.

홈 고정, 탭 그룹, 자동 정렬, 다른 창으로 분리하기는 v1에 넣지 않는다.

예외 상황처리 원칙
제자리 드롭 · 탭 1개순서가 같으면 저장·알림을 만들지 않는다. 탭 1개에서는 이동 조작을 비활성화한다.
드래그 중 탭 구성 변경대상 탭 닫힘, 워크스페이스 전환, 포인터 취소가 발생하면 임시 이동을 취소한다. 오래된 배열로 최신 탭 목록을 덮어쓰지 않는다.
서버 저장 실패현재 화면의 순서를 유지한다. 브라우저 세션 복사본을 우선 사용한다. 서버 실패 시 다른 기기 복원은 보장하지 않는다. 현재 코드에는 저장 성공을 보여 주는 UI가 없으므로 ‘동기화 완료’ 표시는 추가하지 않는다.
로컬 저장도 실패현재 화면 조작은 유지하되 새로고침 복원을 보장하지 않는다. 기존 저장 예외 처리를 유지하며 별도의 저장 성공·실패 알림은 추가하지 않았다.
새로고침 · 재접속기존 복원 순서대로 브라우저 세션을 먼저 읽고, 없으면 서버를 읽는다. 서버 저장 전 창 종료와 동시 접속 사이의 실시간 동기화는 보장하지 않는다.
검증 범위에 남은 경계
현재 브라우저 저장 키에는 workspaceId만 포함되고, 서버는 userId와 workspaceId를 함께 사용한다. 기존 계정 전환·세션 정리 정책은 유지했다. 이번 검증은 합성 데이터와 모의 서버를 사용했으며, 실제 다중 계정 복원이나 원격 저장 성공을 검증한 결과는 아니다.
05

첫 구현은 여기까지

V1 · 제안 범위

상단 업무 탭 공통 동작

  • 좌우 드래그 정렬과 삽입선·이동 미리보기
  • 활성 상태·입력·탭별 기록 보존
  • Esc / 바깥 드롭 취소
  • 화면 너비에 따른 탭 축소, 최소 너비 이후 넘침과 자동 스크롤
  • 기존 세션 저장 연결
LATER · 후속 검토

별도 사용자 경험

  • 탭 정리 패널, 버튼 재정렬, 순서 되돌리기
  • 탭 고정, 그룹, 색상, 이름 변경
  • 다른 창으로 분리하거나 병원 간 탭 이동
  • 모바일 탭바 신설과 길게 누르기 드래그
  • 탭 순서의 기기 간 실시간 공동 동기화
  • 자주 쓰는 업무의 기본 순서 템플릿
검토한 대안판단
제목 전체 드래그권장. 작은 탭에서도 제목 영역을 넓게 잡을 수 있다.
항상 보이는 전용 손잡이보류. 탭 제목 공간을 줄이고 상단바 밀도를 높인다. 드래그 발견성이 낮다는 피드백이 있으면 다시 검토한다.
정렬 설정창에서만 변경주 동작으로는 제외. 눈앞의 탭을 즉시 옮기려는 목적과 거리가 있다. 이번 구현에서 제외한다.
드래그 즉시 탭 활성화제외. 순서 정리 중 화면이 바뀌어 입력 흐름을 끊을 수 있다.
구현 설계 메모 · 개발 검토용

WorkspaceChromeTabs가 드래그를 소유하고, WorkspaceTabsBar / AppShell은 순서 변경 콜백만 전달한다. 공용 Button·일반 Tabs API를 확장하지 않는다.

저장소에 reorderTabs(workspaceId, orderedTabIds)를 추가했다. 현재 탭 ID 집합과 workspaceId를 검증하고, 같은 위치면 종료한다. 새 탭 생성·탭 선택 함수를 재사용하지 않는다. 상태 변경은 한 번, 저장도 한 번만 수행한다.

2026.10.11 승욱 승인: 기존 @dnd-kit/core 6.3.1·@dnd-kit/sortable 10.0.0를 재사용한다. 새 라이브러리는 추가하지 않는다. HTML 시안은 독립 체험용으로 유지한다. 실제 앱은 dnd-kit으로 드래그 감지·정렬·스크롤을 처리하고, 제품 규칙은 기존 탭 컴포넌트와 저장소에 연결한다. 새 의존성·DB 마이그레이션 필요성은 현재 확인되지 않았다.

기존 상단바 항목 DESIGN-SYSTEM-PR-040은 시각·내비게이션 보존 근거다. 재정렬에 대한 승인 기록은 아니다. 중복 확인 후 WORKSPACE-TABS-PR-003에 승인 범위와 검증 근거를 기록했다.

06

이렇게 동작하면 구현 완료

최종 로컬 검증 결과 · 2026.10.12
저장소 20개, Storybook 4개, 실제 앱 브라우저 검사 16개가 최종 통과했다. 차트 탐색 2개도 포함한다. 차트 주소 준비와 화면 전환 완료를 기다리도록 검사 순서를 고쳤고, 최소 너비 검사도 승인된 80px에 맞췄다. 깨끗한 빌드에서 이전 자바스크립트 구문 오류는 재현되지 않았다. 오류 검사를 생략하거나 대기 제한을 늘리지 않았다. TypeScript·lint·UX 문구·비밀정보·기본 배포 빌드도 통과했다.
기본 탭 · 자동 축소 · 많은 탭 · 탭 1개

합성 데이터와 모의 저장 서버 기준이다. 이전 구문 오류의 정확한 원인은 확정하지 않았다. 로컬 검사와 별개로 PR Preview·해당 커밋의 Release Check·정확한 배포 후보 승인이 남는다. 배포본·실제 계정 전환·원격 저장 성공·전체 접근성 적합성은 확인 범위 밖이다.

아래 항목은 실제 앱의 인수 기준이다. HTML 시안 통과가 앱 검증 완료를 뜻하지 않는다.

AC 01첫·중간·마지막 위치로 이동하며 탭 ID 집합이 유지된다.
AC 02비활성 탭을 옮겨도 활성 탭·URL·입력값이 같다.
AC 03활성 탭 이동 시 콘텐츠가 다시 마운트되지 않는다.
AC 04Esc·바깥 드롭·포인터 취소에는 저장이 발생하지 않는다.
AC 05닫기·추가·클릭 선택과 드래그가 서로 오작동하지 않는다.
AC 06새로고침 후 순서 복원과 서버 실패 시 대체 동작을 확인한다.
AC 07탭 정리 UI가 없고, 기존 키보드 탭 선택과 드래그 결과 알림이 동작한다.
AC 08탭이 많아지면 최소 너비까지 축소되고, 그 이후에만 넘친다. +와 알림은 보인다.
AC 09계정·워크스페이스 전환과 지연된 복원이 새 순서를 덮지 않는다.
AC 10실제 상단바 회귀 검사, 관련 저장소 테스트, lint·타입 검사가 통과한다.
권장 사용성 확인: 설명 없이 탭을 옮길 수 있는지, 비활성 탭 이동이 화면 전환으로 오해되지 않는지 확인한다. 수치 목표는 사용 관찰 후 정한다.
