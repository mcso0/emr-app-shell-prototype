DESIGN-SYSTEM-PR-070

EmrEmptyState 컴포넌트 계약과 Storybook 시안화

Empty state를 화면마다 다르게 해석하지 않도록, 공통 컴포넌트의 상태 이유, 배치 surface, CTA 소유권을 코드와 Storybook에서 먼저 고정했다.

이번 작업은 실제 업무 화면을 일괄 교체하지 않는다. 새 컴포넌트와 Storybook 시안으로 기준을 먼저 고정하고, 화면 적용은 chart queue + content 동시 empty 파일럿으로 분리한다.

무엇이 바뀌었나

  • EmrEmptyState 런타임 컴포넌트를 추가했다.
  • kind, surface, priority, density, align prop으로 계약을 나눴다.
  • Iconly Motion JSON은 기존 로컬 motion icon 자산과 EmrMotionIcon을 통해 사용한다.
  • Storybook에 queue, content, drawer, table, widget, permission-info, two-action, 6-kind 검토 시안을 추가했다.
  • 디자인 시스템 문서와 work item에 새 컴포넌트 기준을 연결했다.

왜 중요한가

기존 보고서에서 정한 핵심은 단순히 empty state 종류가 아니라 “어느 surface가 primary action을 소유하는가”였다. 이번 컴포넌트는 그 결정을 props로 드러내서, queue와 content가 동시에 비는 화면에서도 CTA가 중복 primary로 보이지 않게 한다.
