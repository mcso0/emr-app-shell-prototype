UI/UX 리팩토링 운영 기준 정리

요약

00 프로젝트의 첫 이슈로, 앞으로 진행될 화면 컴포넌트 오딧과 리팩토링이 같은 기준으로 움직이도록 운영 기준을 문서화했다. 이 기준은 새 기능 개발이 아니라 기존 EMR 프론트엔드 화면의 일관성, 유지보수성, 접근성, 반응형 안정성을 높이는 데 초점을 둔다.

무엇이 정리됐나

  • UI/UX 리팩토링 initiative의 목적과 frontend-only 범위를 명확히 했다.
  • DB, Supabase, RLS, live persistence, server enforcement, payment, email, deploy, role/permission policy 변경을 명시적으로 제외했다.
  • 00부터 09까지 프로젝트 진행 순서와, 프로젝트 내부에서 마일스톤 및 제목 prefix 순서를 따르는 규칙을 정리했다.
  • 공통 컴포넌트로 올릴 조건, feature-local로 남길 조건, 피해야 할 추상화 기준을 문서화했다.
  • Linear 이슈 작업 시 영어/한국어 사용 구분, 검증, Human Review 종료 기준을 정리했다.
  • App Shell 08-01 중복 의심 항목은 현재 active issue 기준으로 실제 중복이 발견되지 않았고, 08 프로젝트 시작 전 재확인 대상으로 남겼다.
