DEN-516 Reception Reservation Create Flow Report

DEN-516 replaced the reservation placeholder with a real drawer-based reservation create path and added a reservation-to-reception check-in form backed by server permission checks, appointment writer validation, audit emission, and focused UI regression coverage.

What Changed

  • + 접수/예약 > 예약하기 opens a reservation creation drawer.
  • Reservation creation posts to /api/workspaces/[workspaceId]/reception/appointments.
  • public.clair_create_reception_appointment(...) validates workspace scope, patient/guardian, veterinarian, business hours, closed day, and occupied slots.
  • Created reservations are applied to reception state and opened in the reservation detail drawer.
  • Reservation detail now uses 접수하기 to open a prefilled check-in form before creating the waiting encounter.
  • The check-in API can receive form payloads for patient weight, visit purpose, department, veterinarian, duration, memo, and checked-in time.
  • public.clair_check_in_reception_appointment(..., jsonb) updates the linked encounter and patient weight through the DB boundary.
  • Audit support now includes reception.appointment_created for helper, review filter, UI labels, and DB event-type constraint.

Verification

  • 36 server/API/permission/audit tests passed.
  • 7 focused reception UI tests passed, including reservation creation and reservation check-in form paths.
  • npx tsc --noEmit --pretty false --incremental false passed.
  • npm run lint passed with 5 pre-existing warnings outside DEN-516 changes.
  • npm run docs:check passed for 714 docs/agent markdown files.
  • git diff --check passed.

Downstream Note

Calendar drag creation and detail edit work should reuse the appointment writer, check-in payload boundary, and audit event. They should not introduce separate local-only reservation creation or conversion state.
