DEN-66 Chart Order Billing Handoff Closeout 보고서

대표 요약

접수/encounter persistence 작업을 다음 차트·오더·수납 persistence가 이어받을 수 있게 정리했다. 다음 단계는 실제 구현 전에 DEN-67에서 차트/오더/수납 범위와 encounter 의존성을 먼저 확정하는 것이다.

완료된 접수 범위

  • 환자/보호자 조회와 등록 boundary
  • 현장 접수 encounter 생성 boundary
  • 예약 check-in에서 appointment와 encounter를 연결하는 boundary
  • 접수 대기열과 day calendar read boundary
  • 권한 기준과 cross-workspace 차단 테스트
  • 세일즈 데모와 mock fallback 보존 테스트
  • 저장 후 새로고침 회귀 테스트

다음 프로젝트가 믿어도 되는 계약

  • encounter.id를 차트, 오더, 수납의 기본 연결 ID로 사용한다.
  • workspaceId는 모든 읽기/쓰기 scope에 필수다.
  • status는 waiting, in_consultation, ordered, ready_for_billing, completed, cancelled 흐름으로 해석한다.
  • queue row는 운영 대기열 위치이고, encounter 존재의 원천은 아니다.

남은 리스크

  • Docker daemon이 꺼져 있어 local Supabase SQL runtime replay는 아직 별도 환경에서 필요하다.
  • final domain RLS policy SQL과 Supabase advisor review는 다음 단계에서 필요하다.
  • remote Supabase, 실서버, 실제 환자/병원 데이터는 계속 건드리지 않았다.

검증

  • npm run docs:check: passed
  • npm run security:secrets: passed

chart/order/billing 구현, issue Done 처리, remote Supabase, 실서버, 실제 환자/병원 데이터는 진행하지 않았다.
