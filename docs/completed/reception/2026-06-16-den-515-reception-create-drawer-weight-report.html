DEN-515 접수 생성 드로우와 환자 체중 저장 보고

접수/예약 화면의 첫 번째 생성 QA를 처리하면서 접수 생성 진입점, 드로우 기반 접수 폼, 환자 체중 조회/저장 계약을 정비했다.

핵심 결론

이제 접수 생성은 오른쪽 드로우에서 열리고, 체중은 환자 선택 전에는 입력할 수 없다. 환자를 선택하면 DB/API에서 내려온 최근 체중이 채워지고, 접수 생성 시 입력한 체중이 환자 프로필의 weight_kg로 다시 저장되는 계약까지 연결했다.

변경 내용

  • 상단 버튼을 + 진료 접수에서 + 접수/예약 드롭다운으로 변경했다.
  • 접수하기는 오른쪽 접수 생성 드로우를 열도록 연결했다.
  • 예약하기는 DEN-516에서 실제 예약 시간 검증과 함께 연결하도록 임시 안내만 남겼다.
  • 기존 모달 접수 폼을 제거하고, 접수 생성 UX를 드로우 경로로 통일했다.
  • 환자 미선택 상태에서는 체중 입력을 비활성화했다.
  • 환자 선택 시 patient.weightKg를 체중 입력에 반영하고, 없으면 빈 활성 입력으로 유지했다.
  • 방문 목적 하단의 빠른 태그와 설명 문구를 제거했다.
  • 드로우 셸 타이틀을 접수 상세, 드래그 초안 타이틀을 접수 생성으로 맞췄다.

DB/API 고려

  • 환자/보호자 검색 API 응답에 patient.weightKg를 포함하도록 매퍼와 RPC reader를 확장했다.
  • walk-in 접수 생성 payload에 weightKg를 추가했다.
  • walk-in writer RPC는 양수 체중만 허용하고, 제공된 경우 public.patients.weight_kg를 갱신한다.
  • mock-only 처리가 아니라 synthetic/demo DB SQL과 서버 core 테스트로 read/write 계약을 검증했다.
  • 원격 Supabase migration 실행이나 비용 발생 작업은 수행하지 않았다.
