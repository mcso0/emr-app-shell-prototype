RECEPTION-PR-019 · 2026-08-30

접수/예약 대기열 상태 표시 개선 결과

데스크가 지금 처리해야 할 접수와 예약에 집중하도록 대기열을 정리했다. 진료를 시작한 환자는 더 이상 대기로 남지 않고, 수납 인계와 당일 취소·노쇼는 별도의 접힌 보조 그룹에서 확인할 수 있다.

요청과 결정

  • 호출 버튼은 진료 시작으로 보고 활성 접수 대기열에서 제외한다.
  • 다시 대기로 돌아오면 최초 접수 시각 기준의 원래 순서를 유지한다.
  • 접수와 예약의 담당자는 동일한 담당의 정보를 사용한다.
  • 취소·노쇼는 자동 만료하지 않고 선택한 운영일의 예외 기록으로 남긴다.

변경 내용

  • 접수에는 진료 전 환자만 남기고 진료대기로 표시했다.
  • 진료 중과 오더 진행 상태는 활성 대기열에서 빼고 캘린더·상세에 진행 상태만 표시했다.
  • 수납대기와 취소·노쇼를 접힌 보조 그룹으로 분리했다.
  • 전체/접수/예약 탭 수는 실제 활성 업무만 계산한다.
  • 검색 중에는 보조 그룹도 자동으로 펼쳐 검색 결과를 숨기지 않는다.
  • 노쇼에는 잘못된 취소 복구 액션을 제공하지 않는다.

범위와 안전성

  • 기존 DB, API, RPC, RLS, 권한과 상태 전이 계약은 변경하지 않았다.
  • 대기열의 분류와 표시만 바꿔 저장 상태와 화면 상태가 엇갈리지 않게 했다.
  • 수납 모듈의 실제 업무 소유권 이전과 수동 노쇼 처리는 후속 범위다.

검증

  • 접수/예약 상태, 검색, 상세, 재대기 순서를 포함한 Playwright 9개 시나리오 통과.
  • 호출 후 진료 시작 전환 차트 시나리오 1개 통과.
  • 1327×880 화면에서 기본·보조 그룹과 캘린더 상태를 시각 점검했다.
  • 전체 lint, TypeScript, production build, docs 링크, secret scan, diff check를 통과했다.
  • 빌드는 성공했고 기존 프로젝트의 NFT trace 경고 1건은 그대로 유지된다.
  • Release Check와 배포 검증은 커밋된 동일 릴리스 후보로 수행한다.

남은 확인

  • 실사용 중 취소·노쇼 목록을 당일 마감 업무에 어떻게 활용하는지 관찰한다.
  • 수납 화면이 새 대기열을 소유하면 임시 수납대기 그룹 제거 시점을 정한다.
  • 재대기 환자의 실제 대기시간 경고를 최초 접수 기준으로 볼지 별도 정책을 정한다.
