직원 운영 프로필 사이드 패널

2026-07-14 · RECEPTION-PR-009 · Figma 27682:46426

결론

기존 화면을 가리던 modal Sheet를 제거하고, 메인 콘텐츠가 자연스럽게 줄어드는 독립형 패널로 바꿨다. 프로필은 실제 구성원 연락처와 workspace 단위 접속 상태를 표시할 준비가 됐고, 예약 통계는 제거됐다.

화면 변경

  • desktop 패널 336px, 콘텐츠 간격 10px, backdrop·blur·inert 없음
  • 좁은 화면은 backdrop 없는 full-width 패널
  • Figma의 헤더, 아바타, 상태 badge, tabs, 근무 카드, 계정 행과 spacing 반영
  • 프로필만 활성화하고 tab2, tab3는 비활성 표시
  • 선택 날짜 예약과 전체·처리·남은 예약 카드 제거

데이터와 권한

  • 이메일·전화번호는 public.users의 실제 nullable 값만 사용
  • active same-workspace member만 조회하며 reception:view에는 종속되지 않음
  • online은 private Realtime Presence로만 판정하고 multi-tab/device를 지원
  • 최근 접속은 workspace + user 범위의 60초 제한 heartbeat로 저장
  • is_online, 세션, token, Auth 내부 값은 저장·노출하지 않음

검증

  • 서버·migration·Presence 12개, 패널 브라우저 5개, Storybook tabs 4개 통과
  • TypeScript, 변경 범위 lint, Storybook build, Next production build 통과
  • 브라우저 측정: 336px / 10px / blur none / overlay 0 / inert false
  • 모바일 390px viewport에서 full-width 동작 확인

남은 위험과 다음 단계

원격과 로컬 migration 이력이 어긋나 있어 새 activity/Presence migration은 원격에 적용하지 않았다. 이력이 정리되기 전에도 기본 프로필은 정상 동작하고 최근 접속만 생략된다. 다음 단계는 migration history 정합화 후 synthetic 계정으로 RLS, RPC throttle, private Presence를 staging에서 재검증하는 것이다.
