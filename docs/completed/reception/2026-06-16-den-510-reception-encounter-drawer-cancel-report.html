DEN-510 접수 상세 드로어 및 접수 취소 구현 리포트

결과: 구현 완료. 캘린더의 현장 접수 카드를 누르면 환자 정보가 아니라 접수 상세가 열리고, 대기 중 접수는 권한이 있는 사용자가 취소할 수 있게 되었다.

요청 내용

Reception 캘린더에 생성된 접수 카드를 눌렀을 때 환자 상세가 열리는 문제가 있었다. 사용자가 기대하는 화면은 환자 프로필이 아니라 접수 상세이며, 여기에서 접수 취소도 가능해야 한다.

변경 사항

  • 캘린더 walk-in 카드를 클릭하면 reception-encounter 드로어가 열린다.
  • 접수 상세 드로어에 접수 취소 확인 모달과 실행 버튼을 추가했다.
  • 새 API POST /api/workspaces/[workspaceId]/reception/encounters/[encounterId]/cancel를 추가했다.
  • 취소 권한은 reception:update로 분리했다.
  • Supabase RPC 마이그레이션으로 encounter와 consultation queue row를 같은 트랜잭션 안에서 cancelled로 바꾸도록 했다.
  • 취소 후 Reception 캘린더/대기열에서 해당 접수가 즉시 빠지도록 로컬 store 정리를 추가했다.
  • 감사 로그 이벤트 reception.encounter_cancelled를 등록했다.

왜 중요한가

접수 카드는 환자 자체가 아니라 “오늘의 접수 업무”를 대표한다. 따라서 카드 클릭 시 접수 상세가 열려야 접수 시간, 담당 수의사, 차트 이동, 취소 같은 업무 판단을 같은 화면에서 할 수 있다. 이번 변경으로 Reception → Chart 흐름에서 접수 상태를 더 신뢰할 수 있게 되었다.
