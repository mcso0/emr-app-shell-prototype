DEN-517 접수 상세 드로어 및 수정 모드 리포트

결과: 접수 상세 드로어의 정보 위계를 환자/보호자 중심으로 정리하고, 접수 정보 수정을 실제 API/DB 계약을 통과하는 흐름으로 구현했다.

요청 사항

  • 접수 상세 드로어에서 내부 코드와 중복 방문 목적 표시를 제거한다.
  • 푸터를 접수 취소와 닫기, 수정하기 구조로 바꾼다.
  • 수정하기 전 확인 모달을 거쳐 수정 모드로 들어간다.
  • 환자와 접수일자는 수정하지 않고, 체중/방문 목적/소요시간/진료과/담당의/접수 메모만 수정한다.
  • 수정 저장은 mock-only가 아니라 API/DB write/readback 기준을 포함한다.

변경 사항

영역내용
UI 상단 요약을 환자/보호자 중심으로 재구성하고, 중복 방문 목적과 차트보기 버튼을 제거했다.
수정 모드 수정하기 확인 모달, 보기/수정 전환, 저장/닫기 동작을 추가했다.
API/DB PATCH /api/workspaces/[workspaceId]/reception/encounters/[encounterId]와 clair_update_reception_encounter RPC 계약을 추가했다.
보안/감사 encounter_update는 reception:update 권한을 요구하고, reception.encounter_updated audit event를 남긴다.
