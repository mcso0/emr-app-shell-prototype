DEN-514 접수 날짜/검색/필터 UX 개선 보고

접수/예약 화면에서 날짜 이동, 날짜 선택, 대기열 필터, 검색 UX가 실제 일정 화면처럼 동작하도록 정비했다.

핵심 결론

이제 사용자가 접수 캘린더의 날짜를 바꾸면 화면만 이동하는 것이 아니라 선택한 일자로 캘린더 API를 다시 읽고, 대기열도 선택 일자 기준으로 표시된다. 검색과 필터는 임상병리 대기열과 같은 인라인 패턴으로 맞췄다.

변경 내용

  • 이전/다음/오늘/날짜 선택 컨트롤이 실제 선택 일자를 변경하도록 연결했다.
  • 선택 일자가 오늘이면 오늘 버튼을 비활성화했다.
  • 선택 일자 변경 시 캘린더 day API가 해당 날짜로 다시 호출되도록 검증했다.
  • 접수/예약 대기열 목록을 선택 일자 기준으로 필터링했다.
  • 전체, 대기, 예약 필터를 목록 헤더로 이동하고 각 건수를 표시했다.
  • 대기열 검색을 공유 인라인 검색 UX로 교체하고, 방문 목적/메모/담당의 검색도 가능하게 했다.
  • 카드 설명 영역 왼쪽 여백과 영업시간 텍스트 색상 요청사항을 반영했다.

DB/API 고려

  • 캘린더는 선택 일자를 query string으로 전달해 API readback을 검증했다.
  • 대기열은 기존 API read 경로를 유지하되, 화면 요약은 선택 일자 기준으로 제한했다.
  • mock-only 성공이 아니라 Playwright request assertion으로 선택 일자 API 요청을 확인했다.
  • 이번 이슈에서는 DB 스키마, RPC, 원격 Supabase 변경을 수행하지 않았다.
