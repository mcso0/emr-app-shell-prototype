현장 접수 바이탈 이력 구현

2026-07-14 · RECEPTION-QA-PR-011 · Human Review

요청과 결과

예약 생성에서는 바이탈을 제거하고, 실제 측정 시점인 현장 접수에서만 체중·체온·호흡·혈압을 입력해 이력으로 남기도록 구현했다. 화면, API, DB 트랜잭션을 하나의 계약으로 연결했으며 로컬 Supabase에서 실제 저장과 실패 롤백을 확인했다.

주요 변경

  • 현장 접수에 추가·삭제·값 복원·키보드 포커스·Escape·aria-live를 포함한 바이탈 입력을 추가했다.
  • 혈압을 수축기/이완기 두 값으로 받고, 한쪽만 입력하면 접수를 막는다.
  • 예약 생성 화면과 payload에서는 바이탈 및 weightKg를 제거했다.
  • patient_vital_measurements와 RLS/권한 제한을 추가하고, 브라우저 직접 쓰기를 차단했다.
  • 현장 접수 RPC가 encounter, queue, optional measurement, 체중 snapshot을 한 트랜잭션에서 처리한다.

검증

  • Docker local Supabase 전체 reset/seed 및 신규 migration 적용 통과
  • 직접 쓰기 거부, 모든 측정값 readback, 체중 동기화, 강제 실패 전체 롤백 통과
  • 기능 UI 8건 통과, migration/서버 focused 14건 통과
  • secret scan, lint, typecheck, docs check, diff check, production build 통과
  • 전체 선택 서버 묶음은 61건 통과, origin/main에도 존재하는 unrelated audit source-contract 1건 실패

남은 승인 항목

원격 Supabase migration 적용, production DB 변경·검증, 실데이터 접근, 바이탈 이력 조회 화면, production 배포는 수행하지 않았다. 앱 배포 전에는 신규 DB migration과 앱 배포 순서를 별도 승인으로 확정해야 한다.
