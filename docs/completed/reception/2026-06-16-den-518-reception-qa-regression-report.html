DEN-518 접수/예약 QA 회귀 검증 리포트

DEN-514부터 DEN-517까지 반영된 접수/예약 개선 사항을 통합 회귀 검증했다. 결과적으로 날짜 이동, 대기열 검색/필터, 접수 생성, 예약 생성, 예약 접수 전환, 캘린더 드래그 생성, 접수 상세/수정 API 경계가 모두 자동 검증을 통과했다.

결론

Human Review로 넘길 수 있는 상태다.

새 기능 구현은 추가하지 않았고, 최종 UI 문구와 운영일 기준 동작에 맞춰 회귀 테스트만 안정화했다. 원격 Supabase, fixed staging alias, production 배포, 실제 환자/보호자 데이터는 사용하지 않았다.

수정한 회귀 테스트

  • 수정 가능한 접수 fixture를 사용하도록 encounter update route 테스트를 보정했다.
  • 수정 불가 encounter가 409 encounter_not_editable을 반환하는 검증은 유지했다.
  • 드로어 제목이 여러 곳에 표시되는 최종 UI에 맞춰 테스트 선택자를 active drawer 범위로 좁혔다.
  • 자정 이후에도 깨지지 않도록 Cheongdam walk-in/readback 테스트의 날짜 fixture를 현재 로컬 운영일 기준으로 변경했다.
  • 예약/접수 상세 요약 기대값을 최종 환자/보호자 중심 UI 문구로 갱신했다.

범위와 리스크

이번 검증은 로컬 Playwright 브라우저와 서버/API 테스트를 사용했다. fixed staging alias 변경이나 production 배포는 DEN-518 제외 범위였으므로 수행하지 않았다. 실제 환자/보호자/병원 데이터 및 외부 발송/결제/provider side effect도 사용하지 않았다.

다음 단계

현재 DEN-518 기준으로 Rework 이슈는 필요하지 않다. 다음 이슈로 넘어가기 전에는 이 검증 결과를 반영해 후속 작업이 기존 접수/예약 API 경계와 최종 드로어 문구를 재사용하는지 확인하면 된다.
