결론

직원 프로필은 더 이상 보기 전용 보조 화면이 아니다. 현재 업무를 가리지 않는 비모달 패널에서 동료의 공개 가능한 운영 정보와 배정 업무를 확인하고, 본인은 상태 메시지와 비공개 프로필 이미지를 직접 관리할 수 있다. 화면, API, DB/RLS, private Storage, Realtime Presence까지 같은 권한 규칙으로 연결했다.

최종 합성 QA에서 실제 세션의 업무 목록 읽기를 막던 DB 권한 누락을 발견해 SELECT만 추가했다. 이 보완 마이그레이션은 앱 머지보다 먼저 원격 합성/데모 프로젝트에 적용했고, 쓰기 권한은 계속 닫혀 있다.

출시 QA에서 발견한 결함

RLS 정책은 있었지만 테이블 읽기 권한이 없었다

목 API를 사용한 UI 테스트는 통과했지만, 전체 로컬 DB 재생 뒤 실제 authenticated 역할로 배정 업무를 읽자 permission denied for table order_fulfillment_work_items가 재현됐다. RLS는 SQL을 실행할 권한을 대체하지 않기 때문이다.

해결은 20260716030000_staff_assigned_work_items_authenticated_select.sql의 단일 GRANT SELECT다. 기존 active-workspace RLS가 행 범위를 계속 제한하고, INSERT·UPDATE·DELETE 권한은 모두 false로 확인했다. 원격 이력 버전은 20260715180209다.

배포 원칙

보고서에는 존재하지 않는 배포 ID를 미리 쓰지 않는다

이 문서가 포함된 최종 PR을 머지한 뒤 origin/main의 정확한 merge SHA를 확인한다. production runbook 승인 게이트에서 그 SHA만 배포하고, Vercel deployment ID·배포 SHA·합성 계정 smoke 결과는 최종 작업 리뷰에 기록한다. 원격 DB 보완 마이그레이션은 이미 먼저 적용되어 앱/스키마 역전은 없다.

남은 위험과 범위 밖

  • 삭제 전 발급된 signed URL 또는 캐시는 최대 5분간 유효할 수 있다. 새 signing과 원본 object는 즉시 차단·삭제된다.
  • Supabase advisor의 세 feature RPC 경고는 본인/활성 구성원이 호출하도록 의도한 SECURITY DEFINER entrypoint다. 함수 내부 membership/ownership 검증을 합성 QA로 재검증했다.
  • 기존 fulfillment 테이블의 중복 permissive policy와 일부 FK index 권고는 이 읽기 권한 보완 이전부터 존재한 성능 정리 항목이다. 이번 변경의 권한 결과를 바꾸지 않아 별도 최적화 범위로 남겼다.
  • 실제 병원 구성원·환자·보호자·결제·외부 메시지·provider 연동과 외부 사용자 공개는 이번 범위가 아니다.

의사결정자를 위한 다음 확인

최종 PR merge → main...origin/main = 0 0 → exact SHA production deploy → 합성 계정으로 프로필/업무/상태/아바타/Presence smoke → 배포·DB 잔여물 재확인 순서만 남는다. 이 순서가 끝나기 전에는 전체 목표를 완료로 표시하지 않는다.
