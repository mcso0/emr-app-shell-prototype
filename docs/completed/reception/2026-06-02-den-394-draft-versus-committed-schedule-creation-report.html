DEN-394 Draft와 확정 접수 생성 기준 정리 보고서

캘린더를 클릭하거나 드래그한 직후에는 접수 task가 생성 완료된 것으로 보이지 않게 정리했다. 이 단계는 임시 선택이며, drawer에서 생성을 누르고 walk-in API 저장이 성공했을 때만 확정 schedule card가 추가된다.

요청 배경

승욱은 “바로 생성되어서는 안 되고, 드로우에서 생성 버튼을 누르고, DB에 저장되어야만 그때 생성 완료”라고 기준을 정했다. 따라서 selection preview, temporary draft card, committed walk-in card의 상태와 문구를 분리해야 했다.

변경 내용

  • temporary card 문구를 임시 선택 · 생성 전으로 변경했다.
  • draft drawer badge를 임시 선택으로 변경했다.
  • drawer의 생성 버튼은 walk-in API submit 성공 후에만 applyWalkInCheckIn을 호출한다.
  • API 실패 시 확정 schedule card를 만들지 않고, error toast 후 temporary 상태를 유지한다.
  • Playwright에 생성 버튼 전에는 committed walk-in card가 없고, API 성공 후에만 생기는 검증을 추가했다.

검증된 시나리오

  • 15분 click 후 drawer와 temporary card만 표시된다.
  • 생성 버튼 전에는 같은 환자의 committed walk-in card가 없다.
  • 생성 버튼 후 mocked walk-in API가 1회 호출된다.
  • API 성공 후 temporary card가 사라지고 committed walk-in card가 나타난다.
  • multi-hour drag도 같은 생성 전/후 기준을 따른다.

제한 및 다음 판단

현재 walk-in create API 입력 계약은 durationMinutes를 저장하지만, 캘린더에서 선택한 plannedStartAt은 API 입력 필드가 아니다. 이번 변경은 API 성공 후에만 화면의 확정 card를 반영하도록 고쳤고, 선택 시작시간 자체를 DB 컬럼으로 저장하는 작업은 별도 DB/API 계약 확장 이슈로 다루는 것이 맞다.
