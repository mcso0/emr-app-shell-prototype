DEN-59 Reception Appointment Check-In Transition 보고서

작성일: 2026-05-19

예약 확정 건의 접수 처리를 서버 route가 소유하는 저장 경계로 연결했다. 이제 예약 접수는 서버가 예약 상태와 중복 여부를 확인한 뒤 appointment, encounter, 대기열을 같은 transaction boundary에서 처리한다.

무엇을 만들었나

  • POST /api/workspaces/[workspaceId]/reception/appointments/[appointmentId]/check-in route
  • server-owned appointment check-in core, mock fallback writer, Supabase writer gateway
  • appointment status update, linked encounter, consultation queue row, appointment change log를 함께 만드는 local-first SQL writer function
  • 접수 appointment card와 drawer의 접수 처리 route 연결
  • active workspace membership, reception:create, route-level rate limit 적용
  • missing/non-confirmed/already checked-in appointment의 안정적인 차단 응답

왜 중요한가

예약 환자가 내원했을 때 "예약확정에서 접수완료로 바꾸고 진료대기 encounter를 만드는 일"이 서버 경계 뒤로 이동했다. Project 03의 두 핵심 접수 생성 흐름인 현장 접수와 예약 접수가 모두 같은 패턴을 갖게 됐다.
