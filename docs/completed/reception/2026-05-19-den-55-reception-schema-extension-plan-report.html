DEN-55 Reception Schema Extension Plan 보고서

작성일: 2026-05-19

접수 live persistence를 위해 필요한 최소 DB 테이블과 필드, 상태값, 개인정보/동의 범위를 구현 전 계획으로 정리했다.

제안한 테이블

  • guardians
  • patients
  • patient_guardians
  • consents
  • appointments
  • appointment_change_logs
  • encounters
  • waiting_queue_entries

중요 결정

  • 모든 업무 데이터는 workspace 범위 안에서 저장한다.
  • 환자번호, 마이크로칩, 환자등록번호, appointment-linked encounter 중복 방지 기준을 제안했다.
  • 접수에서 쓰는 reception_type, department, duration_minutes, reception_memo, checked_in_by_user_id를 encounter 확장 후보로 확정했다.
  • DB 상태값은 영어 enum 문자열로 유지하고, 한국어 표시는 UI mapper에 남긴다.
  • RLS와 서버 권한 enforcement는 DEN-61 등 후속 issue로 분리했다.

개인정보/동의 질문

  • 보호자 생년월일을 첫 live slice에서 저장할지 여부
  • 보호자 휴대전화 중복을 DB unique로 막을지, 경고/서버 validation으로 둘지 여부
  • 최소 등록 필수 동의를 개인정보 동의만으로 둘지, 메시지 동의까지 요구할지 여부
  • 마케팅 동의를 Project 03에서 허용할지 또는 후속으로 미룰지 여부
