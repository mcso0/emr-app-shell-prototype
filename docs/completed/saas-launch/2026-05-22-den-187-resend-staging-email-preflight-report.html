비개발자 요약

Resend 도메인 인증은 완료됐고, 앱도 이제 staging Preview에서만 Resend 초대 이메일을 보낼 수 있도록 연결했다. 안전장치도 추가했다. Preview 환경이 아니거나, Resend 발송 플래그가 꺼져 있거나, 승인된 테스트 수신자가 아니면 이메일은 발송되지 않는다.

승인된 테스트 수신자 gofldi65@gmail.com에게 staging Preview 초대 이메일 1회를 실제 발송했고, Resend에서 sent 및 delivered 상태를 확인했다.

2026-05-22 추가 확인: 승인 후 Preview API를 통해 실제 발송을 1회 시도했지만, 이메일은 발송되지 않았다. Supabase 로그인은 통과했으나 초대 API가 live Supabase 멤버십 권한을 읽지 못해 403 workspace_membership_missing으로 차단됐다. 이 차단은 안전한 실패이며, 로컬 코드에는 Supabase 권한 어댑터 연결을 추가했다. 재배포와 재발송은 별도 승인이 필요하다.

2026-05-22 최종 확인: 재승인 후 Vercel Preview의 Resend env를 staging 전용 값으로 재설정하고, 재발송 route를 Supabase membership-status RPC 기반 권한 어댑터와 Resend 발송 어댑터로 보강했다. 새 Preview에서 기존 pending 초대 1건을 재발송했고, 앱 응답은 emailDelivery=sent_staging_resend, inviteLink=generated_for_email_only였다.

2026-05-22 링크 수락 경로 추가 확인: 수신 메일의 초대 링크를 열면 앱 화면이 missing으로 표시됐다. 원인은 발송/링크 문제가 아니라 /invite 페이지가 실제 staging Supabase 초대 UUID를 읽는 서버 조회 경로를 아직 갖고 있지 않았기 때문이다. 20260522143815_invite_acceptance_lookup.sql을 staging에 적용했고, RPC 검증 결과 해당 초대는 pending, workspace clair-demo, role vet로 조회된다.

2026-05-22 Preview 재배포 확인: staging lookup 코드가 포함된 새 Preview를 배포했다. 같은 초대 링크를 새 Preview에서 서버 렌더링으로 확인한 결과 초대 수락, pending, gofldi65@gmail.com이 표시되고 missing 문구는 사라졌다.

2026-05-22 추가 재발송: 기존 메일은 이전 Preview 도메인을 가리켜 missing이 계속 표시될 수 있어, 승인 후 같은 수신자 gofldi65@gmail.com에게 새 Preview 링크가 포함된 초대 이메일을 1회 추가 재발송했다. Resend에서 최신 메일이 새 Preview 도메인을 포함하고 sent/delivered 상태임을 확인했다.

2026-05-23 초대 UX 재설계 및 최신 메일 확인: 초대 수락 페이지를 로그인 페이지와 같은 좌우 분할 구조, 앱 토큰, 공용 컴포넌트 기반으로 재구성했다. 초대 정보, 신규/기존 계정 경로, 수락 상태가 한 화면에서 이어지도록 했고, 새 Preview https://emr-app-shell-prototype-m83b1tc4a-mcso0s-projects.vercel.app로 배포했다. 동일 pending 초대를 gofldi65@gmail.com으로 1회 재발송했고, Resend와 Gmail에서 최신 메일이 도착했으며 링크 호스트가 새 Preview 도메인임을 확인했다.
