Why Deploy Was Not Executed

  • Creating a Vercel deployment can consume deployment quota/build minutes and may create an externally reachable staging URL.
  • The available Vercel MCP can deploy, but does not expose a safe env mutation flow for this session.
  • Vercel documentation indicates env variables are typically configured through Project Settings or token-based SDK/API; this session should not handle raw secret values in chat, docs, Linear, screenshots, or logs.
  • DEN-186 proved the code-side bypass boundary, but actual platform env values still need secure entry by the secret owner.

Required Before Retrying DEN-188

  1. Name the staging deploy target and owner.
  2. Enter public env and server-only secret values through Vercel Project Settings or an approved secure secret manager, without exposing values to Codex logs.
  3. Confirm expected cost/quota impact of a staging deploy.
  4. Run deploy from a reviewed branch/commit.
  5. Smoke the staging URL for login/session, workspace entry, invite path, tenant isolation denial, audit review, and no demo-header bypass in Supabase auth mode.
