비개발자 요약

staging과 synthetic dataset이 준비되면 누구나 같은 순서로 CLAiR EMR의 핵심 업무 흐름을 리허설할 수 있도록 접수/예약, 진료, 오더, 검사/처치, 결과 확인, 수납 또는 입원 연결 순서를 정의했다.

Happy Path Script

  1. Front desk가 synthetic guardian/patient를 검색한다.
  2. 예약 환자는 appointment check-in, 워크인 환자는 walk-in encounter 생성으로 시작한다.
  3. Reception queue와 calendar에 encounter 상태가 반영되는지 확인한다.
  4. Vet가 encounter를 열고 SOAP draft, vitals, assessment, diagnosis를 작성한다.
  5. Vet가 order group을 생성하고 lab/imaging/dispensing/treatment order를 확정한다.
  6. Technician이 각 queue에서 work item을 시작/완료하고 manual result 또는 completion note를 입력한다.
  7. Vet가 결과를 확인하고 open order가 없으면 encounter를 billing-ready로 보낸다.
  8. Front desk가 invoice candidate를 확인하고 line edit/recalculation 후 paid 또는 approved unpaid closure를 기록한다.
  9. Hospital admin이 audit event summary와 role/tenant boundary evidence를 확인한다.

Negative Scenario

  • Non-member 또는 다른 workspace member는 protected workspace data를 볼 수 없어야 한다.
  • front_desk는 SOAP/diagnosis mutation을 할 수 없어야 한다.
  • technician은 chart authoring 대신 assigned operational work만 완료해야 한다.
  • Open order가 남아 있으면 billing closure가 block되거나 reason이 필요해야 한다.
  • Client-side amount tampering은 trusted total로 반영되면 안 된다.
  • 실패/denial은 안전한 401/403 또는 stable error로 남고 상태를 바꾸지 않아야 한다.

Evidence 기준

  • 각 scenario는 시작 전 fixture ID, actor role, workspace ID를 기록한다.
  • 각 transition은 screenshot 또는 short screen recording으로 남긴다.
  • Readback/reload checkpoint: reception queue, encounter, orders, invoice, audit summary.
  • Evidence에는 secret, real data, raw token, service role key, 실제 개인정보를 포함하지 않는다.

Blockers

  • DEN-190 migration/RLS/schema apply가 credential blocker로 dry-run 전 중단됨.
  • DEN-191 dataset contract는 정의됐지만 실제 seed 구현/적용은 별도 이슈 필요.
  • DEN-186 env/secret wiring과 demo bypass disablement proof 전에는 staging app smoke 불가.
  • Lab/imaging/dispensing full live persistence는 current-status상 아직 완료 claim 금지 영역이다.

DEN-189 Go/No-Go로 넘어갈 조건

  • Staging DB foundation migration apply와 RLS read-only verification 통과.
  • Synthetic seed 적용과 fixture readback 통과.
  • DEN-186 env/secret wiring과 demo bypass proof 통과.
  • Core replay happy path 2개 이상, negative scenario 3개 이상 evidence 확보.
  • Launch blockers가 없거나 representative가 명시 수용한 non-blocker로 분류됨.
