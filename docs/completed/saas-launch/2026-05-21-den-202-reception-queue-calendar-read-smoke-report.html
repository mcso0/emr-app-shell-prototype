요약

Synthetic 계정 로그인은 DEN-201에서 복구되었지만, 로그인 후 접수 화면에서 서버 대기열을 불러오지 못했습니다와 서버 캘린더를 불러오지 못했습니다가 표시됐다. 원인은 Supabase 세션 사용자 UUID로 서버 API를 호출하면서도 permission adapter가 기존 mock user id 기반 데이터에 머물러 있었기 때문이다. 접수 대기열/캘린더 read route가 Supabase 세션일 때 DB-backed workspace permission adapter를 사용하도록 고쳤고, 새 Vercel Preview에서 실제 로그인 화면 smoke가 통과했다.

변경 사항

  • src/features/auth/supabase-workspace-permission-gateway-core.ts: Supabase client로 user_memberships, users, permission_policies를 workspace/user scope에 맞게 읽는 permission gateway를 추가했다.
  • src/features/auth/supabase-workspace-permission-gateway.ts: server-only wrapper를 추가해 서버 route에서만 사용할 수 있게 했다.
  • src/app/api/workspaces/[workspaceId]/reception/queue/route.ts, src/app/api/workspaces/[workspaceId]/reception/calendar/day/route.ts: Supabase session 요청에서는 DB-backed permission adapter를 주입해 실제 staging membership/role policy를 기준으로 read 권한을 판단한다.
  • 관련 server regression test에 DB-backed permission adapter 연결과 server-only boundary 확인을 추가했다.
