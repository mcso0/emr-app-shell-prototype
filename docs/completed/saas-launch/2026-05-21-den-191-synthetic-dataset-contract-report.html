DEN-191 Synthetic Medium Hospital Dataset Contract Report

작성일: 2026-05-21

비개발자 요약

중형 동물병원 하나가 CLAiR EMR staging에서 실제처럼 돌아가 보이기 위한 synthetic dataset 계약을 정의했다. 이 계약은 실제 고객 데이터가 아니라 가상의 병원, 직원, 보호자, 환자, 예약, 진료, 오더, 결과, 수납/입원 데이터를 만드는 기준이다.

Guardian / Patient Fixture

  • 최소 8-12명의 synthetic guardian, 10-15마리 patient.
  • 각 patient는 species, breed, age, weight, sex/neuter, allergy/주의메모를 가진다.
  • 동명이인, 다환자 보호자, 전화번호 검색, 재진 history, duplicate review case를 포함한다.
  • 이름, 전화번호, 이메일, 주소, 주민/사업자/결제 정보는 모두 fake-only 값이어야 한다.

Seed Scope

  • Workspace auth and membership: canonical roles, active memberships, permission policies.
  • Reception: guardians, patients, patient_guardians, consents, appointments, encounters, waiting queue.
  • Clinical: SOAP drafts/signed samples, diagnoses, order groups, orders, order events.
  • Work completion: lab/imaging/treatment/dispensing pending, in-progress, completed fixtures.
  • Billing: invoice candidates, invoice lines, paid/unpaid synthetic states.
  • Audit: safe event summaries for key transitions without raw sensitive payloads.

Naming And Data Rules

  • Email domains: @clair.local, example.test.
  • IDs: deterministic demo UUIDs or readable synthetic IDs.
  • Memo text must include synthetic, demo, or issue marker where useful.
  • No real clinic, guardian, patient, staff, billing, identity, or clinical record data.
  • Reports and screenshots must not include secrets or real personal data.

Seed 구현으로 넘어갈 조건

  • DEN-190 migration/RLS/schema apply and read-only verification 통과.
  • 승욱이 이 dataset 규모와 scenario 구성을 승인.
  • Seed 구현 이슈에서 reset/replay 가능성과 idempotency를 포함.
  • DEN-192 replay script와 fixture ID가 서로 맞아야 함.

검증 기준

  • Outpatient workflow state model의 appointment -> encounter -> orders -> results -> billing 흐름과 일치.
  • EMR entity map의 workspace/guardian/patient/encounter/order/invoice/audit 관계를 유지.
  • Mock/live boundary와 persistence data security checklist의 synthetic-only, workspace-scoped 기준 준수.
