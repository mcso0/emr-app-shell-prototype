초대 이메일 OTP Handoff 구현 리포트

DEN-246의 email-first 초대 화면 다음 단계로, 초대받은 이메일을 잠그고 OTP 요청/검증 후 초대 화면으로 돌아오는 handoff 경계를 구현했다.

구현 내용

  • /api/auth/invite-otp/request에서 pending 초대, locked email, safe /invite/... next를 검증한다.
  • /login?reason=invite_email_otp 화면을 초대 이메일 인증 전용 UI로 전환하고 이메일을 readonly로 고정했다.
  • Supabase mode는 signInWithOtp와 verifyOtp boundary를 사용한다.
  • local/mock mode는 실제 이메일을 보내지 않고 000000 데모 코드로 링크 확인이 가능하다.
  • /auth/confirm route를 추가해 Supabase email link의 token_hash를 검증하고 safe invite next로만 redirect한다.
  • 계정 존재 여부는 API/UX에서 직접 노출하지 않는다.

남은 범위

원격 Supabase/staging OTP delivery, redirect URL allow-list, email template rollout, 실제 production email provider 검증은 명시 승인 후 별도 작업에서 진행해야 한다.
