워크스페이스 active membership 런타임 검증 보고

로그인만 된 사용자가 아무 병원 워크스페이스에 들어가지 못하도록, 워크스페이스 진입과 selector 표시 기준을 active membership 중심으로 보강했다. 이제 권한 기준은 화면의 역할 라벨이 아니라 membership 상태다.

Status: Active Membership Runtime Guarded

Membership 상태별 접근표

상태Selector직접 진입결과
active표시허용워크스페이스 진입 가능
pending제외차단초대 수락/활성화 전 접근 불가
inactive제외차단비활성 멤버 접근 불가
suspended제외차단정지 멤버 접근 불가
membership 없음제외차단해당 병원 소속이 아님
session 없음N/A차단reason=session_required 로그인 이동

변경 내용

  • AuthGate가 workspace id를 받아 active membership이 없는 workspace entry를 reason=unauthorized로 차단한다.
  • Session-only workspace state에 pending 상태를 추가하고, 현재 session id 기준 active membership 판정 함수를 추가했다.
  • Persisted workspace list mapper를 core 파일로 분리하고 non-active rows를 방어적으로 제거한다.
  • 페이지 shell route에서 AuthGate workspaceId를 전달하도록 연결했다.

남은 보강점

  • 이 변경은 page shell 진입 guard다. 각 clinical/reception/billing/admin API route의 server-side active membership enforcement는 계속 별도 보안 경계로 유지해야 한다.
  • 향후 production UX에서는 로그인 화면 notice 대신 전용 access denied 또는 request access 화면을 둘 수 있다.
  • remote Supabase staging/live, email delivery, production deploy, role-policy 변경은 계속 승인 gate 밖에서 진행하지 않았다.
