DEN-155 / SaaS Launch Foundation / 2026-05-20

CLAiR 운영자 접근 모델 및 어드민 가드 보고

CLAiR 내부 운영 어드민은 병원관리자보다 강한 권한을 가진다. 그래서 일반 병원 워크스페이스 역할로 처리하지 않고, 검증된 세션과 서버 소유 operator source를 통과해야만 tenant 승인과 최초 관리자 초대를 할 수 있도록 기준을 고정했다.

Status: Operator Guard Model Defined

핵심 결정

  • CLAiR operator는 hospital_admin이 아니라 별도의 서버 소유 권한 source다.
  • 기존 canonical 병원 역할은 hospital_admin, vet, technician, front_desk 그대로 유지한다.
  • 운영 어드민 route는 readServerSession() 이후 operator allowlist/table을 확인해야 한다.
  • client-only guard, browser storage, profile metadata, workspace role만으로 운영자 권한을 인정하지 않는다.

구현 전 보안 블로커

블로커이유
operator source 부재누가 CLAiR 내부 운영자인지 서버가 판단할 기준이 없다.
client-only guard화면에서 버튼을 숨기는 것은 tenant approval 보안이 아니다.
서비스 키의 브라우저 노출운영 어드민 작업은 server-only boundary를 통과해야 한다.
audit 누락tenant 승인, workspace 생성, 최초 관리자 초대는 추적 가능해야 한다.
MFA/strong-auth 미검토staging/live 운영자 mutation 전에는 강한 인증 요구사항을 다시 확인해야 한다.

다음 구현 이슈에 주는 기준

  • DEN-156: tenant application model은 operator guard가 참조할 상태와 audit hook을 포함해야 한다.
  • DEN-157: workspace 생성과 최초 hospital admin 초대는 approved tenant와 operator guard를 모두 통과해야 한다.
  • DEN-158: tenant status 변경은 별도 상태 전환 규칙과 operator audit event가 필요하다.
