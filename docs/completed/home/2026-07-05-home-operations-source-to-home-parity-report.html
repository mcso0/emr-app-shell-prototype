HOME-PR-012 · 2026-07-05

원내 현황 Source-to-Home 검증 결과

진료만 보이는 상태를 넘어서, 원천 업무 생성 흐름으로 만든 예약, 오더 fulfillment, 수납 업무가 Home 원내 현황에도 같은 카드 정보 계약으로 노출되는지 검증했다.

요청

  • Home 전용 더미 업무를 만들지 않는다.
  • 각 원천 화면/대기열에서 생긴 업무가 Home에도 같은 업무 정보로 보이는지 확인한다.
  • 예약, 진료, 임상병리, 영상검사, 조제, 처치, 수납을 검증 범위에 포함한다.
  • 접수는 실제 source writer가 명확해질 때까지 가짜 생성 로직을 만들지 않는다.

변경 내용

  • tests/home-operations-source-parity.spec.ts를 추가해 source API로 업무를 만든 뒤 Home API를 읽어 비교한다.
  • 로컬 clair-demo 전용 source replay gateway를 추가했다.
  • RPC가 없는 환경의 fallback reader에 수납 source 테이블 집계를 추가했다.
  • Home UI 회귀 테스트에서 예약, 진료, 임상병리, 영상검사, 조제, 처치, 수납 카드 필드를 함께 검증한다.

검증

  • npx playwright test tests/home-operations-source-parity.spec.ts --reporter=line 통과
  • npx playwright test tests/home-operations-work-items-server.spec.ts --reporter=line 통과
  • npx playwright test tests/home.spec.ts --grep "home live operations cards match source queue card fields" --reporter=line 통과
  • npx tsc --noEmit --pretty false 통과
  • npm run lint 통과, warning은 기존 코드와 이번 작업 전부터 남아 있던 항목 위주로 유지

남은 범위

  • 접수 column의 실제 생성 기준과 writer가 제품 결정으로 확정되면 별도 구현한다.
  • 원격 Cheongdam smoke는 승인된 synthetic 데이터와 연결된 Supabase 환경에서 별도로 수행해야 한다.
  • 입원 업무는 기존 결정대로 v2 범위다.
