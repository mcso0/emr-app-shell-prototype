HOME-PR-011 · 2026-07-05

원내 현황 실제 업무 연동 결과

원내 현황이 단순 mock 화면이나 빈 상태가 아니라, 서버가 집계한 병원 전체 업무를 읽는 상황판으로 동작하도록 첫 live 연동을 구현했다.

요청

  • 운영일 기준으로 병원 전체 업무를 원내 현황에 표시한다.
  • 완료/취소 업무는 기본 숨김 처리하고 옵션으로만 포함한다.
  • 업무가 진짜 없을 때만 empty state를 보이고, API 실패나 권한 부족을 빈 업무로 숨기지 않는다.
  • DB 작업은 additive/read-only 중심으로 진행하고 실제 고객 데이터 변경이나 destructive 작업은 하지 않는다.

변경 내용

  • clair_list_home_operations_work_items RPC를 추가해 접수/예약, 대기열, 오더 fulfillment, 수납 후보 업무를 Home 공통 상태로 집계한다.
  • GET /api/workspaces/[workspaceId]/operations/work-items API를 추가했다.
  • Cheongdam/prepared-clinic Home은 mock fallback 없이 새 API를 사용한다.
  • 업무 없음, 오류, 권한 부족, 완료/취소 포함, 내 업무 보기, 팀 큐/배정 누락 신호를 UI와 타입 계약에 연결했다.
  • 카드 클릭은 상세 drawer를 열고, 실제 업무 화면 이동은 drawer/footer 또는 overflow 액션으로 유지했다.

검증

  • npx playwright test tests/home-operations-work-items-server.spec.ts tests/home.spec.ts --reporter=line 통과
  • npx tsc --noEmit --pretty false 통과
  • npm run docs:check 통과
  • npm run lint 통과, 기존 warning 10건은 유지
  • git diff --check 통과

원격 DB 상태

  • 초기 완료 시점에는 실행 환경에 Supabase project link와 access token이 없어 원격 demo DB 적용을 완료하지 못했다.
  • 2026-07-05 후속 확인에서 승인된 clair-emr-staging Supabase project에 additive migration home_operations_work_items_reader를 적용했다.
  • Cheongdam synthetic smoke에서 clair_list_home_operations_work_items RPC가 sourceStatus=live와 총 7건을 반환하는 것을 확인했다.
  • 반환된 업무 유형은 진료 3건, 임상병리 2건, 영상검사 1건, 처치 1건이다.

남은 범위

  • 원격 DB migration은 적용됐지만, 다른 Supabase 환경을 추가로 만들 경우 동일 migration 적용 여부를 다시 확인해야 한다.
  • 공식 지연 정책은 아직 만들지 않았고, v1은 long_stay 주의 신호만 사용한다.
  • 긴급 요청 생성 UI와 입원 업무 연동은 후속 작업이다.
