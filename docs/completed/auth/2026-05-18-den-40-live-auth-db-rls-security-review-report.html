DEN-40 Live Auth DB/RLS Security Review 보고서

Project 01의 server session, role-update route, workspace auth migration, last-admin DB guard, RLS baseline, DB-backed permission adapter, cross-workspace denial coverage를 보안 리뷰했다. 결론은 Project 01 handoff는 가능하지만, pilot/live 적용은 아직 차단이다.

Blockers before pilot/live

  • 실제 Supabase migration/RLS 실행 검증이 아직 없다. 현재 머신에 Docker/local Postgres가 없어 local DB apply를 실행하지 못했다.
  • 역할 관리 UI는 아직 session-only이며, live DB write/private helper에 연결되지 않았다.
  • Remote Supabase staging/live validation은 대표 승인 gate 뒤에 남아 있다.

Positive evidence

  • readServerSession()은 server-only이며 auth.getClaims() 기반이다.
  • Role update route는 verified session seam을 사용하고, demo header는 mock fallback mode에서만 허용한다.
  • Server resolver는 unauthenticated, inactive, missing membership, permission missing, last-admin, cross-workspace case를 거절한다.
  • Last active hospital_admin DB guard는 private trigger/helper foundation으로 작성되어 있다.
  • Workspace auth RLS는 to authenticated, auth.uid(), active app user, active membership row 기준으로 제한한다.
  • 권한 source는 user-editable metadata가 아니라 app-domain membership/permission rows로 유지된다.

Verification

  • Source/security rg scan 완료
  • npx playwright test tests/server-session-reader.spec.ts tests/server-permission-enforcement.spec.ts tests/workspace-membership-rls-migration.spec.ts tests/workspace-last-admin-protection-migration.spec.ts tests/db-workspace-permission-adapter.spec.ts tests/permission-resolver.spec.ts --reporter=line 통과: 26 passed
  • npm audit --audit-level=high 통과: found 0 vulnerabilities
  • npm run docs:check 통과: 571 docs/agent markdown files checked

하지 말아야 할 것

  • 대표 승인 없이 remote Supabase project link, SQL execution, migration push를 하지 않는다.
  • Service-role key, secret key, DB password, remote connection string, CLI token을 client/public docs/chat/Linear/log에 노출하지 않는다.
  • 실제 DB/RLS execution test 전에는 pilot/live ready로 표시하지 않는다.
  • DEN-40 범위에서 Project 02 작업을 시작하지 않는다.
