직원 초대와 멤버십 상태 흐름

병원관리자가 직원을 이메일로 초대하고, 초대 상태를 관리하며, 수락 시 활성 멤버로 전환되는 session-only 기반 흐름을 구현했습니다.

요청 내용

병원관리자가 직원을 초대하고, 초대 상태가 pending에서 active membership으로 전환되는 제품 기반을 만들어야 했습니다. 실제 이메일 발송이나 Supabase 저장은 제외 범위였습니다.

구현 내용

  • session workspace state에 invitation 모델을 추가했습니다.
  • 초대 정보로 email, workspace, invited roles, status, inviter, expires/accepted/canceled/resend metadata를 저장합니다.
  • 병원관리 module의 병원구성원 관리 메뉴를 활성화했습니다.
  • 초대 form에서 이메일, 다중 역할, 직책, 부서를 입력할 수 있습니다.
  • 중복 pending invite와 이미 active member인 이메일 초대를 차단합니다.
  • pending invite에 대해 재발송, 취소, 수락 시뮬레이션을 제공합니다.
  • 수락 시뮬레이션은 invitee:<email> active membership을 생성합니다.
  • 비관리자 mock role은 구성원 화면을 볼 수 있지만 초대와 변경 action은 차단됩니다.

왜 중요한가

DEN-23은 병원 대표가 워크스페이스를 만드는 첫 관문이었습니다. DEN-24는 그 다음 단계인 “직원을 병원 워크스페이스에 합류시키는 운영 관문”입니다. 이 흐름이 있어야 실제 EMR SaaS처럼 병원 단위 권한 관리와 역할 기반 업무 분리가 가능해집니다.

남은 범위와 리스크

  • 주의 이번 구현은 browser storage 기반 session-only prototype입니다.
  • 실제 이메일 발송, 공개 초대 링크, SSO/SCIM/domain auto-join은 아직 구현하지 않았습니다.
  • 실제 Supabase persistence, migration SQL, RLS SQL은 아직 구현하지 않았습니다.
  • 좌석 과금과 구독 seat charging은 아직 구현하지 않았습니다.
  • 서버 권한 enforcement와 마지막 active 병원관리자 보호 transaction은 후속 티켓 범위입니다.
