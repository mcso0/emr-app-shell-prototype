파일럿 병원 워크스페이스 로그인 복구 보고서

한 줄 요약

계정 권한은 정상이었지만 브라우저에 남은 예전 병원 목록이 서버보다 먼저 접근을 막고 있었다. 이제 운영 로그인에서는 서버의 최신 활성 멤버십을 최종 기준으로 확인한다.

무엇이 문제였나

  • admin@clair.local은 파일럿 병원의 활성 병원관리자로 운영 DB에 정상 등록돼 있었다.
  • 워크스페이스 전환 목록에도 CLAiR Clinical Master Pilot가 표시됐다.
  • 하지만 접근 게이트가 브라우저의 오래된 목록만 보고 권한 없음으로 잘못 판단했다.

어떻게 수정했나

  • Supabase 운영 로그인은 서버가 반환하는 최신 활성 워크스페이스 목록을 최종 권한 근거로 사용한다.
  • 서버가 워크스페이스를 반환하지 않거나 응답이 실패·손상되면 기존처럼 안전하게 접근을 차단한다.
  • 다른 병원으로 전환하는 동안 이전 병원의 허용 상태가 잠깐 재사용되지 않도록 병원별로 검증 상태를 분리했다.
  • 로컬 데모 로그인 방식과 DB·RLS·멤버십 데이터는 변경하지 않았다.

운영 확인 범위

배포 후 파일럿 병원의 Order 관리에서 중앙 마스터 기반 31개 항목을 확인하고, 청담 병원의 기존 13개 항목이 그대로 조회되는지도 함께 확인한다. 파일럿의 새 31개 항목을 청담에 자동 복사하는 작업은 이번 로그인 수정 범위에 포함하지 않는다.
