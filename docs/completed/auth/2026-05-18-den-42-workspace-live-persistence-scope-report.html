DEN-42 Workspace Live Persistence Scope 보고서

작성일: 2026-05-18

Project 02의 범위를 확정했다. 이제 바로 구현부터 들어가지 않고, 어떤 흐름을 라이브 저장으로 옮기고 어떤 범위는 승인 전 금지할지 기준이 생겼다.

요청

DEN-94 이후 Project 02의 다음 이슈인 DEN-42를 진행해 workspace/member live persistence의 범위, dependency, 승인 gate, 다음 이슈를 확정한다.

결정

포함 제외
workspace 생성과 creator hospital_admin membership 저장 remote Supabase link/push/SQL 실행
persisted membership 기반 workspace selector 실제 병원/환자/보호자/직원 데이터 사용
초대 생성, 수락, 취소, 재발송 상태 저장 실제 이메일 발송과 public invite link launch
역할 변경/비활성화 server handoff와 DB last-admin guard 결제, 구독, seat billing provider 연동
개인 프로필 저장, 단 권한 source와 분리 접수/차트/오더/수납 등 Project 03+ clinical persistence

왜 중요한가

Project 02는 제품 MVP의 첫 live persistence 구간이다. 범위를 먼저 고정하지 않으면 원격 DB, 이메일, 결제, 임상 데이터 저장이 섞여 위험해진다. 이번 문서는 그 경계를 막고 DEN-43부터 순서대로 구현할 수 있게 한다.

npm run docs:check 통과. 내부 문서 링크 검증 결과 정상.

남은 위험과 제외 범위

  • remote Supabase 작업은 아직 승인되지 않았다.
  • 실제 이메일/결제/구독 연동은 제외했다.
  • 접수, encounter, chart, order, billing persistence는 Project 03 이상 범위다.
  • DEN-42는 범위 확정 이슈라 app code나 DB migration은 변경하지 않았다.
