초대 수락 앱 사용자 연결 보강 리포트

일자: 2026-05-24

이메일 OTP 인증 뒤 초대 화면으로 돌아왔지만 초대가 계속 pending에 머무르는 상황을 확인했다. 원인은 새 Supabase Auth 사용자가 아직 public.users 앱 사용자 row로 연결되지 않은 상태에서 초대 수락 RPC가 멤버십 생성을 시도할 수 있다는 점이다.

변경 내용

  • clair_accept_workspace_invitation RPC를 보강하는 local-first migration을 추가했다.
  • 인증된 OTP 세션의 auth.uid()와 auth.jwt().email이 초대 이메일과 일치할 때만 public.users를 upsert한다.
  • 이메일 불일치, 비인증, 이미 활성 멤버 상태는 기존 denial boundary를 유지한다.
  • 초대 수락 문서와 lifecycle regression coverage를 갱신했다.

검증

  • npx playwright test tests/workspace-invitation-lifecycle-server.spec.ts --reporter=line passed.
  • npx playwright test tests/invite-otp-handoff.spec.ts tests/invite-acceptance.spec.ts --reporter=line passed.
  • npx tsc --noEmit passed.
  • npm run docs:check passed.
  • npm run lint passed with existing warnings only.
  • npm run security:secrets passed.
  • git diff --check passed for the touched files.

주의 사항

원격 Supabase staging DB에는 이 migration을 아직 적용하지 않았다. 현재 리포지토리 변경은 local-first 기준이며, Vercel preview/staging에서 같은 초대 링크를 다시 검증하려면 별도 승인 후 staging migration push가 필요하다.
