서버 권한 판정 계약 구현

워크스페이스 멤버십과 역할을 기준으로 권한을 계산하는 서버 전용 계약을 추가했습니다. 이번 작업은 실제 DB/RLS 적용 전, 앞으로 모든 서버 API가 따라야 할 권한 판단 기준선을 세운 작업입니다.

상태 Human Review 준비
범위 권한 계산 계약과 테스트
서버 경계 server-only entrypoint 추가
검증 resolver 6개 테스트 통과

대표 요약

권한 판단을 브라우저 세션이나 Supabase Auth metadata가 아니라 앱의 워크스페이스 멤버십 데이터로 계산하도록 표준 계약을 만들었습니다. 아직 실제 Supabase DB에 연결한 것은 아니지만, 어떤 사용자가 어떤 병원 워크스페이스에서 어떤 권한을 갖는지 서버 코드가 일관되게 판단할 수 있는 기준이 생겼습니다.

핵심 의미: 이후 차트 저장, 멤버 초대, 병원 설정 변경 같은 민감한 기능은 이 계약을 기준으로 서버에서 허용 또는 차단해야 합니다. 화면에서 버튼을 숨기는 것만으로는 보안 완료로 보지 않습니다.

구현 내용

  • src/features/auth/permission-resolver.ts에 순수 권한 계산 계약을 추가했습니다.
  • src/features/auth/permission-resolver.server.ts에 import "server-only"를 적용해 서버 전용 진입점을 만들었습니다.
  • hospital_admin, vet, technician, front_desk 4개 MVP 역할을 기준으로 권한을 계산합니다.
  • 여러 역할을 가진 사용자는 각 역할 권한의 합집합을 갖고, hospital_admin이 포함되면 전체 관리자 권한을 갖습니다.
  • 비로그인, 비활성 사용자, 미소속 워크스페이스, 비활성 멤버십, 권한 없음, 마지막 관리자 보호를 typed denial reason으로 반환합니다.
  • 조회, 생성, 수정 권한을 빠르게 확인하는 canView, canCreate, canUpdate helper를 추가했습니다.

권한 기준

역할 이번 계약의 핵심 기준
hospital_admin 워크스페이스 전체 권한. 역할/권한 관리와 병원 설정 변경까지 가능.
vet 차트 작성과 오더 요청/변경 가능. 관리자 설정과 역할 권한 관리는 불가.
technician 차트 조회 가능, 차트 수정 불가. 검사/영상/조제 완료 같은 운영 지원 권한 가능.
front_desk 접수/예약, 고객/환자 기본 정보, 수납 처리 가능. 차트 수정 불가.

보안 판단

이번 구현은 실제 운영 보안을 완성한 것이 아니라, 운영 보안을 만들기 위한 첫 번째 서버 계약입니다. 이후 API Route, Server Action, Data Access Layer가 이 계약을 호출하도록 연결해야 실제 보호가 시작됩니다.

  • 적용됨 서버 전용 entrypoint, typed resolver, 테스트 기반 권한 matrix
  • 후속 필요 Supabase DB adapter, migration, RLS policy, 실제 API enforcement
