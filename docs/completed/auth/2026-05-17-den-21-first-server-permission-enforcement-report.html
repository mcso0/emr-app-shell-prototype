첫 서버 권한 Enforcement Slice

역할 변경 요청을 서버 Route Handler에서 검증하는 첫 권한 enforcement 경계를 추가했습니다.

상태Human Review 준비
BoundaryRole update route
핵심 권한role_permission:manage
주의Demo identity seam

선택한 서버 경계

POST /api/workspaces/[workspaceId]/memberships/[membershipId]/roles를 첫 적용 대상으로 선택했습니다.

DEN-25에서 병원관리자의 역할 수정 UI가 생겼기 때문에, 같은 고위험 mutation intent를 서버에서 먼저 검증하는 것이 가장 작은 범위로 실제 제품 리스크를 줄이는 선택입니다.

구현 내용

  • Next.js Route Handler를 추가했습니다.
  • server-only enforcement module에서 DEN-19 permission resolver를 호출합니다.
  • active workspace membership을 요구합니다.
  • role_permission:manage 권한을 요구합니다.
  • canonical role 입력만 허용합니다.
  • 마지막 active hospital_admin 강등을 서버 경계에서도 차단합니다.

남은 보안 Gap

이 작업은 전체 보안 완성이 아닙니다.

현재 actor identity는 demo-only x-clair-demo-session-user-id header입니다. 운영 전에는 Supabase verified session으로 교체해야 하고, DB writes, migration/RLS, route-backed UI persistence도 후속으로 필요합니다.
