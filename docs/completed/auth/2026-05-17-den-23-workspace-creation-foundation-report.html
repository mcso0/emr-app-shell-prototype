워크스페이스 생성 기반 구현

병원 대표/관리자가 구독 후 병원 워크스페이스를 만들고, 최초 생성자가 자동으로 병원관리자 권한을 받는 session-only 기반 흐름을 구현했다.

요청 내용

병원 대표나 병원 관리자가 EMR 구독 후 워크스페이스를 만들 수 있고, 최초 생성자가 병원관리자 권한을 갖는 제품 기반을 먼저 만들라는 요청이었다.

구현 내용

  • /workspace/new 온보딩 route를 추가했다.
  • 로그인 전 접근 시 기존 AuthGate로 /login?next=/workspace/new로 이동한다.
  • 병원/워크스페이스 이름, 대표/관리자 이름, 연락 이메일, 연락처를 입력받는다.
  • 필수값과 이메일 형식 검증을 추가했다.
  • 생성된 workspace와 creator membership을 browser storage contract에 저장한다.
  • 생성자는 active hospital_admin role을 받는다.
  • 생성 후 새 workspace의 home 화면으로 이동한다.
  • App Shell workspace switcher가 session workspace 표시명을 보여준다.

왜 중요한가

지금까지는 모든 사용자가 데모 workspace인 clair-demo에 들어가는 구조였다. 이번 작업으로 “병원이 자기 workspace를 만든다”는 SaaS 제품의 첫 관문과, 최초 관리자 멤버십 계약이 코드와 테스트에 생겼다.

남은 범위와 리스크

  • 주의 이번 구현은 browser storage 기반 session-only prototype이다.
  • 실제 Supabase persistence, migration SQL, RLS SQL은 아직 구현하지 않았다.
  • 실제 결제/구독 제공자 연동은 아직 구현하지 않았다. 현재 구독 상태는 trialing placeholder다.
  • 서버 권한 enforcement와 마지막 병원관리자 보호 transaction은 후속 티켓 범위다.
  • 직원 초대와 멤버 관리 UI는 DEN-24 이후 범위다.
