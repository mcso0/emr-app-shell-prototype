DEN-46 Workspace Invitation Create Live Persistence 보고서

작성일: 2026-05-18

병원관리자 직원 초대 생성이 이제 서버 route와 local Supabase DB transaction을 거친다. 실제 이메일 발송은 아직 하지 않는다.

무엇이 바뀌었나

  • POST /api/workspaces/[workspaceId]/invitations를 추가했다.
  • public.clair_create_workspace_invitation() DB transaction RPC를 추가했다.
  • 초대 이메일을 정규화하고 pending invitation으로 저장한다.
  • 비관리자, 중복 pending 초대, 이미 활성 멤버인 이메일을 차단한다.
  • 기존 mock/demo UI는 route 응답을 browser-state fallback에 저장한다.

제외 범위

  • 실제 이메일 발송과 public invite link는 구현하지 않았다.
  • 초대 재발송, 취소, 수락 persistence는 DEN-47로 남겼다.
  • remote Supabase와 실제 데이터는 건드리지 않았다.

다음 추천

DEN-47에서 초대 재발송, 취소, 수락 lifecycle을 persisted route/DB transaction으로 연결한다.
