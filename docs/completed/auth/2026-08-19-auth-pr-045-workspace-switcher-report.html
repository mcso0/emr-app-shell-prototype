AUTH-PR-045 · 2026-08-19

워크스페이스 전환이 실제로 동작해

표시만 되던 App Shell 버튼을 사용자의 활성 워크스페이스 목록으로 연결했다. 사용자는 현재 위치에서 목록을 확인하고 다른 병원 워크스페이스로 안전하게 이동할 수 있다.

구현 및 릴리스 후보 검증 완료

무엇이 달라졌나

활성 목록

현재 사용자의 활성 멤버십만 목록으로 보여준다.

빠른 구분

현재 워크스페이스, 병원 이름, 사용자의 역할을 함께 표시한다.

검색과 예외 상태

5개 이상이면 검색을 제공하고 로딩·오류·재시도·단일 목록 상태를 처리한다.

안전한 이동

기존 환자·차트·청구 식별자는 새 워크스페이스 URL로 넘기지 않는다.

권한 fallback

비관리자가 병원관리에서 전환하면 대상 워크스페이스의 홈으로 이동한다.

작성 중 보호

연결된 미저장 상태가 있으면 전환 전에 계속 작성하거나 폐기할 수 있다.

검증 결과

  • 워크스페이스 목록·라우팅·기존 App Shell 회귀 테스트 14개 통과
  • 390px 좁은 화면과 기존 52px 축소 스위처 기하 검증 통과
  • ESLint, TypeScript, 문서 링크, 시크릿 검사, diff 검사 통과
  • Next.js 프로덕션 빌드 통과

주요 변경 위치

  • src/shell/workspace-switcher.tsx — 목록 팝오버와 상태 UI
  • src/features/auth/workspace-display.ts — 서버 목록과 브라우저 fallback 병합
  • src/shell/app-shell.tsx — 안전한 전환과 미저장 확인
  • src/shell/workspace-surface-route.ts — 워크스페이스 전환 전용 URL 생성
  • tests/app-shell.spec.ts — 전환·오류·권한·좁은 화면 회귀 검증

제외 범위와 다음 판단

공개 병원 검색, 참여 요청, 대기 중 초대 자동 검색, 일반 사용자의 워크스페이스 생성은 포함하지 않았다. CLAiR의 초대 전용 B2B 정책과 권한·감사 경계를 먼저 설계한 뒤 별도 작업으로 진행해야 한다. 이번 릴리스는 애플리케이션 코드만 대상으로 하며 원격 Supabase 데이터, 마이그레이션, 환경 설정은 변경하지 않는다. 최종 main 머지와 Vercel 상태는 릴리스 결과에서 별도로 확인한다. 기존 워크스페이스 생성 온보딩 테스트의 5초 대기 실패는 수정하지 않은 origin/main에서도 동일하게 재현되어 이번 변경의 회귀와 분리했다.
