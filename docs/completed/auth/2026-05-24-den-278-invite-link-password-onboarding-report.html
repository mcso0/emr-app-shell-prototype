DEN-278 Invite Link Password Onboarding

초대 메일 링크를 연 사용자가 다시 OTP를 요청하지 않고, 초대 링크에서 확인된 이메일 컨텍스트로 비밀번호 설정 또는 기존 계정 로그인을 진행한 뒤 워크스페이스로 이동하도록 초대 수락 흐름을 정리했다.

What Changed

  • pending 신규 사용자 초대는 비밀번호와 비밀번호 확인을 입력해야 워크스페이스로 이동 버튼이 활성화된다.
  • pending 기존 계정 초대는 초대받은 이메일을 고정하고 비밀번호 입력 후 로그인으로 초대 수락을 이어간다.
  • 만료되었거나 취소된 초대는 관리자에게 재요청을 제공하고, 성공/실패 다이얼로그로 결과를 알려준다.
  • 재요청 API는 초대 존재 여부, 초대 이메일 일치 여부, 초대 상태를 검증한 뒤 응답한다.
  • 구현은 재사용 가능한 초대 카드, 읽기 전용 이메일 필드, 비밀번호 필드, 보조 액션, 재요청 다이얼로그 단위로 구성했다.

Validation

  • 비밀번호는 필수, 8자 이상, 확인값 일치를 통과해야 한다.
  • 기존 계정 로그인은 비밀번호 입력 전에는 제출할 수 없다.
  • 초대 재요청은 만료/취소 상태에서만 성공하며, 이메일 불일치와 이미 수락된 초대는 거부한다.

Safety Notes

  • Production Supabase, production deploy, DB, RLS, migration은 변경하지 않았다.
  • 실고객 데이터와 실고객 메일은 사용하지 않았다.
  • Secret, OTP 원문, magic link, raw invite token, password 값은 문서나 로그에 남기지 않았다.
  • 관리자 재요청은 이번 범위에서 검증된 route feedback까지만 구현했고, 실제 관리자 알림 저장/전송은 후속 범위다.
