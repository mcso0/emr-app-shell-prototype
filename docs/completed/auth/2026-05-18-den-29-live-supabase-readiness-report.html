DEN-29 Live Supabase Readiness 실행 모드 보고서

Project 01의 첫 이슈로, live Supabase/DB/RLS/server enforcement 작업에 들어가기 전 실행 모드와 승인 게이트를 정리했다. 결론은 local-first Supabase validation이다.

요청

01 Live Auth & Supabase DB/RLS Foundation 프로젝트의 첫 마일스톤 첫 이슈부터 진행하되, Project 02는 시작하지 않는 범위에서 Project 01 작업을 시작한다.

결정

  • Project 01은 기본적으로 로컬 Supabase 검증을 우선한다.
  • remote Supabase staging/live 변경은 별도 대표 승인 없이는 하지 않는다.
  • migration/RLS/server-session 구현은 각 Linear 이슈가 허용하는 범위 안에서만 진행한다.
  • Project 02는 Project 01 handoff 전까지 시작하지 않는다.

왜 중요한가

Project 01은 실제 DB schema, migration, RLS, server-side permission enforcement로 이어지는 고위험 기반 작업이다. 실행 모드를 먼저 고정하지 않으면 로컬 검증, staging 적용, production 적용이 섞이면서 의도하지 않은 live project 변경이나 권한 경계 오해가 생길 수 있다.

검증

  • npm run docs:check 통과
  • Supabase 공식 docs/changelog 기준으로 local development, CLI, migrations, RLS, API keys, Data API grants, RLS Tester를 확인했다.

리스크와 제외 범위

  • 이번 이슈에서는 코드 구현, migration 작성, RLS SQL 작성, live Supabase 변경을 하지 않았다.
  • remote Supabase 검증은 아직 승인되지 않았다.
  • Project 02 범위는 시작하지 않았다.
