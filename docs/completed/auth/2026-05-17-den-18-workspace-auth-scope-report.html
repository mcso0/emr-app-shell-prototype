대표 요약

결론: 이번 작업으로 프로젝트 범위를 단순 로그인 화면 구현이 아니라 워크스페이스 기반 인증·권한 시스템으로 확정했습니다. 이제 다음 구현 작업이 역할과 권한을 다시 해석하지 않고 진행될 수 있습니다.

확정한 핵심 결정

1. 프로젝트 범위

기존 /login을 새로 만드는 작업이 아니라, 워크스페이스 생성, 직원 초대, 역할/권한, 개인 프로필까지 포함하는 제품 기반 작업으로 확정했습니다.

2. 기본 역할

MVP의 canonical role은 hospital_admin, vet, technician, front_desk 네 가지로 정했습니다.

3. 중복 역할 정책

한 사용자가 여러 역할을 가질 수 있고, 권한은 합산합니다. 병원관리자 역할이 포함되면 관리자 권한을 우선합니다.

4. 관리자 보호

워크스페이스에는 항상 최소 1명의 활성 병원관리자가 남아야 합니다. 최초 생성자도 실수로 관리자 권한을 잃지 않도록 보호해야 합니다.

5. 개인 프로필 경계

사용자는 개인 프로필을 수정할 수 있지만, 개인 프로필 값은 권한 판단에 쓰지 않습니다. 권한은 membership과 permission policy에서만 판단합니다.

검증 결과

통과 npm run docs:check

문서 내부 링크 검사가 통과했습니다. 이번 작업은 문서/기준 정리 작업이라 앱 빌드나 Playwright 실행은 필요 범위에 포함하지 않았습니다.

주의할 점

  • 현재 코드에는 nurse, billing_admin seed가 남아 있습니다. 새 기준에서는 technician과 네 가지 canonical role로 정리해야 합니다.
  • 이번 작업은 권한 기준 확정입니다. 실제 서버 권한 검증, DB migration, RLS 정책은 아직 구현하지 않았습니다.
  • 클라이언트 화면에서 버튼을 숨기는 것만으로는 보안 완료로 보지 않습니다. 후속 이슈에서 서버 기준 permission resolver와 enforcement가 필요합니다.

  3. DEN-24 이후: 직원 초대, 권한 resolver, 관리자 UI, 개인 프로필, 서버 enforcement 순서로 진행합니다.
