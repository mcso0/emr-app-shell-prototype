Project 06 / DEN-102 / 2026-05-20

고객관리 스키마 Delta 계획

Project 03의 접수용 최소 DB를 고객관리 프로필 저장소로 확장하기 위한 마이그레이션 기준을 정리했다. 이 문서는 다음 이슈 DEN-105가 구현해야 할 컬럼, 신규 테이블, 삭제 잠금 소스, 제외 데이터를 고정한다.

Status: Human Review

핵심 결정

  • 별도 customer master table을 만들지 않고 기존 guardians, patients, patient_guardians, consents를 확장한다.
  • 보호자/동물의 1:1 프로필 값은 기존 master row 컬럼으로 추가한다.
  • 내원경로, 중복 override, 주치의 배정, 고객 프로필 변경 이력은 별도 row table로 둔다.
  • 보호자-동물 관계는 hard delete하지 않고 unlinked_at으로 soft unlink한다.

민감정보 경계

  • 실제 주민등록번호, 실제 현금영수증 식별값, 실제 주소/전화/이메일은 저장하지 않는다.
  • 현금영수증 번호와 주민등록번호는 synthetic placeholder 또는 masked display 값만 허용한다.
  • Kakao/SMS/email provider payload와 실제 동의서 파일 저장은 Project 06 범위가 아니다.
  • remote Supabase, staging/live migration, production deploy는 별도 승인 전까지 제외한다.

DEN-105 구현 대상

  • guardians: guardian code, 주소/이메일 parts, cash receipt demo fields, soft delete/restore audit.
  • patients: breed split, mixed breed, estimated age parts, weight/color, message consent, primary vet, soft delete/restore audit.
  • patient_guardians: 관계 label, message consent, sort order, unlink audit, primary-change audit.
  • consents: source surface, document version, granted/refused/unknown status, consent/refusal timestamps.
  • 신규 테이블: referral sources, duplicate overrides, patient staff assignments, customer profile change logs.
