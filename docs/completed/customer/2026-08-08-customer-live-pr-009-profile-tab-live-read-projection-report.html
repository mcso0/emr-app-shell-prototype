고객 프로필 실데이터 탭 연결

2026-08-08 · Customer · CUSTOMER-LIVE-PR-009

준비된 청담 워크스페이스의 고객 프로필이 레거시 mock bundle에 의존하지 않고 workspace-scoped read projection을 사용하도록 연결됐다. DB에 없는 진료·예약·수납 기록은 만들거나 보강하지 않으며, 실제 빈 결과는 빈 상태로 표시된다.

변경 내용

  • 프로필 overview와 진료 이력·예약·수납 section을 위한 함수 전용 Supabase migration, 서버 core/gateway, 공통 GET route를 추가했다.
  • patient:view, chart:view, reception:view, billing:view를 RPC와 UI 양쪽에서 적용하고, 허용되지 않은 탭은 데이터·건수·금액을 호출하거나 노출하지 않는다.
  • 6/12개월·월 필터와 최대 50건 keyset cursor를 적용하고, 보호자 수납은 선택 보호자 소유 청구만 반환하도록 제한했다.
  • 패널은 lazy loading, 로딩·재시도 가능한 오류·권한 없음·실제 빈 상태를 구분한다. 세로 본문은 단일 shadcn ScrollArea와 기존 scroll-fade-y scroll-fade-8를 사용한다.
  • 프로필 수정, URL drawer, 관련 프로필 이동, 기존 레거시 clair-demo 경로와 사용자 시각 WIP는 보존했다.

데이터 무결성 및 보안 경계

새 테이블·인덱스·seed·DML은 추가하지 않았다. RPC는 인증 사용자·활성 workspace membership·subject workspace·soft-delete 상태·section 권한을 확인하고, 민감한 주민번호 토큰·현금영수증 번호·차량번호·SOAP/진단/처방은 projection에서 제외한다.

검증 결과

  • TypeScript, 변경 파일 ESLint, docs:check, security:secrets 통과
  • 프로필 live-read core/API 테스트 5개 통과
  • 고객관리 전체 Playwright 21개 통과
  • 공용 reception 프로필 편집·활동 탭·레이아웃 회귀 3개 통과
  • Storybook production build 완료; 프로필 패널 380px stories와 ScrollArea bundle 생성 확인
  • migration을 로컬 PostgreSQL 트랜잭션에서 생성·overview/section read 후 rollback하여 SQL·grant·comment와 실제 projection 실행을 확인
  • git diff --check 통과

로컬 Supabase lint는 기존 migration의 선행 lint 오류를 함께 보고했으며, 새 함수의 추가 오류는 확인되지 않았다.

현재 상태와 남은 게이트

현재 작업 항목은 Human Review 상태다. 원격 clair-emr-staging에는 migration을 적용하지 않았고, 원격 row를 생성·수정·삭제하지 않았다.

읽기 전용 승인 준비에서 원격 프로젝트는 qmerxgzrwaaahpkhjqlc·ACTIVE_HEALTHY·PostgreSQL 17.6.1.121로 확인됐다. 새 4개 함수는 아직 원격 catalog에 없고, 대상 도메인 테이블은 RLS·정책·직접 SELECT 차단 상태였다.

migration history는 원격 116개·로컬 144개이며, 버전 ID 공통 108개·원격에만 있는 버전 8개·로컬에만 있는 버전 36개로 현재 문서의 2026-07-22 “remote-only 0” 기록과 일치하지 않는다. 일부는 기존 timestamp alias지만, 이 작업에서 history repair나 광범위한 db push를 실행하지 않는다.

Security Advisor는 기존 baseline으로 189건(정보 44, 경고 145), Performance Advisor는 210건(정보 192, 경고 18)이 있어 전역적으로 clean하지 않다. 새 함수가 아직 없어 새 함수 대상 finding은 없으며, 적용 후 4개 함수 범위의 advisor 재검증을 별도 게이트로 둔다.

따라서 승인 패킷은 준비됐지만 원격 적용은 migration-history mismatch를 별도 승인·정리하거나 명시적으로 예외 승인하기 전까지 보류한다. 다음 적용 단계는 이 함수 전용 migration 하나만 대상으로 하며, 기존 pending migration·history repair·DML·배포는 포함하지 않는다.

범위 밖

SOAP 상세, 데이터 정리, 관계·archive mutation, 권한 체계 신설, 원격 배포와 실사용자 브라우저 sign-off는 이번 로컬 구현에 포함하지 않았다.
