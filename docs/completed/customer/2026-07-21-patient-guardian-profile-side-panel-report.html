현재 상태: 기능 구현·검증 완료, exact match 판정은 미해결

환자·보호자 패널을 Figma의 380px 표면, 151px 프로필 헤더, 4탭 구조로 교체했다. 기존 수정·저장, URL/전역 선택, 연결 프로필 이동은 유지했다. 다만 엄격한 픽셀 비교가 0이 아니므로 사용자 조건에 따라 최종 완료로 판정하지 않는다.

무엇이 바뀌었나

  • 정보, 진료 이력, 예약, 수납의 환자·보호자 공통 패널을 기능 전용 컴포넌트로 구현했다.
  • Figma 원본 환자·보호자 사진과 22px 보호자·동물 SVG 자산을 적용했다.
  • 진료 이력은 날짜별 최신순 그룹으로 구성하고, 잘못되거나 없는 날짜는 날짜 미상 그룹의 마지막에 둔다.
  • 수납 카드는 청구 주제, 수납 상태, 요청자·담당자, 결제 수단·승인 금액, 총액 순으로 구성했다.
  • 탭 ArrowLeft/Right, Home/End, Escape 닫기, reduced-motion, 독립 내부 스크롤을 적용했다.

승인 예외 적용

  • 진료 이력: 날짜 그룹과 그룹 내부 최신순 정렬을 적용했다. 이 부분의 raw diff는 의도적 구조 차이를 포함한다.
  • 수납: 리포트의 결제·금액 위계를 사용하고 Figma 카드의 표면 스타일을 유지했다. 이 부분의 raw diff도 의도적 정보 추가를 포함한다.

기능·데이터·권한 보존

  • 기존 환자·보호자 PATCH 저장과 실패 toast, 연결 프로필 이동, drawer URL/전역 상태를 보존했다.
  • API, DB, migration, RLS, 권한 정책, 공용 토큰, 새 의존성은 변경하지 않았다.
  • 활동 탭은 현재 mock/read-model 데이터다. live projection은 별도 권한·RLS 설계와 승인이 필요하다.
  • Figma 프로필 이미지는 시각 fixture이며 실제 Patient/Guardian avatar 필드로 저장하지 않는다.

검증 결과

  • 통과 대상 ESLint 및 npx tsc --noEmit
  • 통과 패널 집중 Playwright 3건 + 고객 공통 패널 4건
  • 통과 Storybook build, Next.js production build
  • 통과 380 × 1105, 151px 헤더, 탭 키보드, Escape, reduced-motion
  • 전체 기준선 미통과 전체 117건 중 49건까지 실행 후 중단: 32 통과, 기존 업무시간·날짜·캘린더 fixture·등록 타이포그래피 불일치 15건, 수정 전 프로필 저장 assertion 1건, 중단 1건. 프로필 assertion은 수정 후 집중 테스트로 재통과했다.

리스크와 다음 결정

  • 보호자 정보 Figma는 카드 2개를 그리면서 개수 배지를 1로 표시한다. 실제 화면은 데이터 개수를 사용하고, 픽셀 Story만 시안 값을 격리 재현한다.
  • 동기 mock 투영이어서 별도 로딩·부분 실패 UI는 연결하지 않았다. live API 작업 때 디자인·권한 계약이 필요하다.
  • 완료하려면 허용할 정량 픽셀 임계값을 승인하거나, Figma와 같은 렌더러의 비교 기준을 제공해 0-diff 판정을 다시 수행해야 한다.
