보호자 프로필 저장 경계

보호자 상세정보가 서버 route를 통해 읽고 저장되도록 경계를 추가했다. 고객관리와 공통 보호자 drawer는 이제 저장 시 workspace 권한 확인과 민감값 검증을 거친다.

Status: Human Review

구현 내용

  • 보호자 프로필 read/update server core를 추가했다.
  • GET/PATCH /api/workspaces/[workspaceId]/customer/guardians/[guardianId]/profile route를 추가했다.
  • 공통 보호자 drawer의 저장 버튼을 persistence route에 연결했다.
  • mock gateway와 Supabase gateway를 분리해 demo-header mode와 Supabase session mode를 모두 지원한다.

보호한 경계

  • 읽기는 patient:view, 수정은 patient:update 권한을 요구한다.
  • 다른 workspace 보호자 접근은 차단한다.
  • 주민등록번호 원문 형태와 숫자형 cash receipt identifier 저장은 거부한다.
  • soft delete/restore, 관계 변경, 실제 데이터 import, provider 연동은 제외했다.
