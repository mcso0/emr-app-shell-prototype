근무표 운영 완성도 및 기본 근무 개선

긴 직원 목록이 잘리던 문제를 해결하고, 로딩·편집·게시 상태를 실제 운영 화면처럼 명확하게 만들었습니다. 반복되는 근무는 역할·요일·시간을 한 번에 입력하고 다음 주에 지난주 근무표를 가져오는 흐름으로 정리했습니다.

구현 및 집중 검증 완료 · Human Review

무엇이 바뀌었나

  • 근무표가 작업영역 안에서 세로 스크롤되고, 상단 주요 행동은 스크롤 중에도 유지됩니다.
  • 텍스트 한 줄뿐이던 로딩을 진행 표시와 표 스켈레톤으로 바꾸고 aria-busy를 추가했습니다.
  • 초안 시작, 게시본처럼 시스템 중심이던 표현을 근무표 편집, 현재 게시된 근무표, 게시 전 확인으로 바꿨습니다.
  • 수의사·테크니션·접수 역할과 요일, 시작/종료 시간을 골라 현재 주에 기본 근무를 일괄 입력할 수 있습니다.
  • 이미 입력된 근무·휴무·휴가는 덮어쓰지 않고 건너뜁니다.

안전성과 데이터 경계

  • 일괄 입력은 관리자 권한을 API와 DB 함수에서 각각 확인합니다.
  • 한 트랜잭션으로 저장해 일부 직원만 저장되는 중간 상태를 만들지 않습니다.
  • 동시편집 버전, 중복 요청, 병원 휴무일, 운영시간, 직원 활성/워크스페이스 범위를 기존 V2 규칙으로 검증합니다.
  • 감사 로그에는 작업 종류와 리비전 식별 정보만 남기고 개인 메모나 휴가 사유는 기록하지 않습니다.

검증 결과

  • TypeScript 및 대상 ESLint 통과
  • 고정 근무 API·마이그레이션·UI 계약 Playwright 6개 통과
  • 로컬 트랜잭션 리플레이에서 합성 수의사 6명 × 평일 5일 = 30건 입력, 동일 키 재시도, 전체 롤백 확인
  • 스테이징 마이그레이션 20260722090248_hospital_schedule_fixed_week_batch 적용 및 권한·함수·무데이터변경 확인

남은 확인

스테이징 DB 마이그레이션과 PR Preview 배포까지 진행했습니다. 인증된 브라우저에서 스크롤, 로딩, 기본 근무 입력, 게시 반영을 확인한 뒤 별도의 production 승인 패킷이 필요합니다. 실제 직원 데이터 입력과 production 코드 배포는 하지 않았으며, 복잡한 교대·야간·자동 미래 주 생성은 별도 범위입니다.
