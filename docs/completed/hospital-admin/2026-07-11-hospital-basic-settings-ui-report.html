병원 기본 설정 UI 구현 결과

2026-07-11 · HOSPITAL-ADMIN-PR-003

요청과 결과

기존 콘셉트 화면을 전용 설정 화면으로 교체했습니다. 화면에는 개발용 워크스페이스 ID, 영향 범위, 향후 데이터 안내를 노출하지 않으며, 사용자가 수정 가능한 정보와 저장 상태만 보여줍니다.

구현한 경험

  • 병원명·대표자/원장명·주소는 읽기 전용으로 표시하고, 우측의 병원 정보 변경 요청으로 사유 확인 흐름을 제공합니다.
  • 주소 복사는 아이콘과 복사됨 라벨, 스크린리더 상태 메시지로 결과를 알려 줍니다.
  • 연락처, 요일별 운영일/휴무일, 30분 단위 진료·휴게시간, 공휴일 정책, 예외 일정 추가·수정·삭제를 제공합니다.
  • 수정 전에는 저장 버튼을 보이지 않고, 수정 후에만 화면 하단 고정 변경 바에서 저장 또는 되돌리기를 선택합니다.
  • 운영시간 저장은 별도 토스트로 안내하고, 병원관리 내부 메뉴 이동과 브라우저 이탈 시 저장하지 않은 변경을 보호합니다.

검증

  • npx tsc --noEmit 통과
  • 관련 파일 ESLint 통과
  • 병원 기본 설정 모델 테스트 4개 통과
  • 병원 기본 설정 브라우저 흐름(정보 위계, 변경 요청, 복사 피드백, 저장·되돌리기·토스트, 예외 일정·이탈 보호, 768px 단일 열) 통과
  • tests/hospital-admin.spec.ts 17개 통과, npm run docs:check 통과, npm run build 통과

완료 범위 밖

저장은 브라우저 세션 메모리에만 남습니다. 실제 병원 프로필/운영시간 DB·API 저장, 관리자 서버 권한, RLS, 감사 이벤트, 고객센터 요청 전달은 포함하지 않았습니다.

빌드는 통과했습니다. 다만 격리 워크트리의 추가 package-lock.json과 기존 PRD 뷰어의 동적 파일 경로 추적으로 Next.js/Turbopack 경고가 출력됩니다. 이번 병원 기본 설정 변경으로 새로 만든 경고는 아닙니다.

다음 단계

라이브 저장이 필요해지면 데이터 계약 → API/RLS → 감사 이벤트 → 이 화면 연결 순서로 확장합니다.
