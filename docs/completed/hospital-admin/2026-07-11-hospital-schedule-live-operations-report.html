2026-07-11 · Hospital Admin

근무표를 “보이는 화면”에서 “권한이 있는 운영 기능”으로 확장했어.

관리자 편성·게시와 직원 요청·출퇴근을 Supabase DB와 서버 API가 확인한다. 직원이 브라우저에서 편성 정보를 직접 바꾸거나 다른 병원 데이터를 건드리는 경로는 RLS와 RPC에서 차단된다.

이번에 바뀐 점

영역구현 결과
근무표 저장주간 편성, 근무 추가·수정·삭제, 게시 상태를 workspace 단위 DB에 저장한다.
권한직원은 본인 요청·출퇴근만, 병원관리자는 편성·승인·게시·급여 미리보기만 수행한다.
요청과 알림휴무·변경 요청은 승인 전에는 근무표를 바꾸지 않는다. 승인/반려와 게시 시 인앱 알림 레코드가 생성된다.
자동 배정역할·시간 충돌·주간 배정량을 기준으로 추천만 제공한다. 관리자가 저장해야 반영된다.
출퇴근·급여합성 시간당 단가로 출퇴근 기록과 급여 미리보기만 만든다. 결제·세금·정산은 하지 않는다.

검증

통과: 대상 ESLint, TypeScript, 순수 추천/급여 모델 테스트, 서버 권한 테스트, SQL 계약 테스트.

격리 로컬 DB: 직원의 직접 근무 수정은 UPDATE 0으로 차단됐고, 본인 요청은 생성됐다. 관리자가 승인·게시하면 휴무 반영과 요청/게시 알림이 생성되는 것을 확인했다.

주의: 저장소 전체 로컬 Supabase 초기화는 이 작업보다 앞선 reception 마이그레이션의 weight_kg 누락에서 멈춘다. 이 변경은 원격/운영 DB에 적용하지 않았다.

현재 범위 밖

실제 직원/급여, 세금·연장근로 규칙, 출퇴근 장비, 이메일·SMS·푸시, 원격 배포와 운영 DB 마이그레이션은 포함하지 않았다.

다음 권장 작업

먼저 기존 reception 마이그레이션 체인을 복구한 뒤, 스테이징의 합성 데이터로 원격 RLS/API 회귀 테스트를 실행해. 그 다음 실제 알림 채널이나 급여 규칙을 별도 승인 범위로 확장하는 것이 안전해.
