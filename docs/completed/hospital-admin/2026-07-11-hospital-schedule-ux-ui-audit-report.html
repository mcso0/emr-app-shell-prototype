CLAiR EMR · Hospital admin · UX/UI audit

Flex처럼 직관적으로 보고,
병원 운영에 맞게 깊게 편성한다.

현재 화면의 정적인 표를 Flex의 구성원 중심 캘린더 경험으로 재구성했다. To‑Be는 주간 매트릭스에서 편성하고 → 일간 타임라인에서 커버리지를 확인하고 → 직원 개인 캘린더에서 요청을 관리하는 하이브리드 근무표다.

범위: 2026-07-11 CLAiR 배포 화면과 Flex 공식 근태관리 공개 화면·가이드를 직접 확인했다. Flex의 정보 구조와 상호작용 원칙을 참고했지만 브랜드를 복제하지 않았고, CLAiR 컴포넌트·토큰·접근성 계약을 유지했다. 실제 앱 코드, DB/API, 권한, 알림은 변경하지 않았다.

1. 현재 화면 근거

P0

핵심 행동이 없다

조회·추가·수정·삭제·게시가 구분되지 않고, `시안 저장`만 존재한다.

P0

개인 일정 진입점이 없다

직원 이름이 단순 텍스트라 근무 가능 시간, 휴무, 요청을 확인할 수 없다.

P1

운영 상태가 행동으로 연결되지 않는다

미배정 슬롯 2개를 표시하지만 해당 슬롯을 찾거나 채우는 방법이 없다.

2. 문제점과 개선 우선순위

우선순위현재 문제사용자 영향개선 방향
P0근무표 표가 읽기 전용으로 보이고 셀 클릭, 추가 버튼, 행 메뉴가 없다.관리자가 이 화면에서 실제 편집이 가능한지조차 판단하기 어렵다.빈 셀과 근무 카드 모두 조작 대상으로 만들고, 상단에 `근무 추가`를 고정한다.
P0`시안 저장`이 근무 한 건 저장, 전체 초안 저장, 직원 공개 중 무엇인지 불명확하다.변경이 직원에게 즉시 보이는지 알 수 없어 운영 실수가 생긴다.근무 편집의 `저장`과 주간 근무표의 `게시`를 분리한다. 게시 상태와 시각을 헤더에 표시한다.
P0직원별 상세 정보와 개인 일정 관리가 없다.근무 가능 시간·정기 휴무·휴가 요청을 다른 화면이나 기억에 의존하게 된다.직원명을 클릭하면 상세 패널을 열고 개인 일정, 가능 시간, 요청, 주간 합계를 함께 보여준다.
P1미배정·인력 부족·충돌이 요약 카드에만 존재한다.문제를 발견해도 어느 날짜·직군을 수정해야 하는지 연결되지 않는다.그리드 위에 문제 스트립을 두고 클릭 시 해당 셀과 근무를 강조한다.
P1월–금만 보여 주고 주간 탐색, 오늘 이동, 역할 필터가 없다.주말·야간·응급 운영과 이전/다음 주 검토가 불가능해 보인다.7일 주간 그리드, 주 이동, 오늘, 직군·상태 필터, 개인 검색을 제공한다.
P1주간 시작·잠금·경고 같은 정책 설정이 편성 화면의 중심을 차지한다.가끔 바꾸는 설정이 매주 반복하는 편성 업무보다 먼저 보인다.설정은 `근무표 설정` 다이얼로그로 이동하고 기본 화면은 편성에 집중한다.
P2휴무, 교육, 대체 근무, 미배정 근무가 동일한 텍스트 셀로 표현된다.근무 유형과 예외 상황을 빠르게 구분하기 어렵다.절제된 색·테두리·텍스트 라벨을 함께 사용하고 색만으로 의미를 전달하지 않는다.

3. Flex에서 확인한 핵심 패턴

1

구성원이 탐색의 시작점

Flex는 직원 사진·이름·직무·총 근무시간을 일정과 같은 행에 둔다. CLAiR도 직원 행을 단순 라벨이 아니라 개인 일정과 요청으로 들어가는 진입점으로 사용한다.

2

목적에 따라 시간 해상도를 바꾼다

교대근무는 월간 매트릭스로 패턴을 보고, 구성원 근무는 시간축으로 실제 근무 범위를 본다. CLAiR은 주간 매트릭스와 일간 타임라인을 전환해 편성과 커버리지 검토를 분리한다.

3

근무 유형은 낮은 채도의 블록

민트·노랑·파랑·라일락을 넓은 흰 캔버스와 얇은 그리드 위에 사용한다. 상태를 빠르게 찾되 화면이 경고판처럼 보이지 않는다.

4

개인 일정은 캘린더로 직접 입력

Flex는 근무·외근·휴가를 시간 블록으로 배치한다. 직원용 `내 근무`도 목록보다 주간 시간 캘린더를 우선해 변경 전후를 공간적으로 이해하게 한다.

5

정책과 일상 업무를 분리

근무 유형·휴가·승인 정책은 설정하고, 일상 화면은 입력·조회·요청에 집중한다. CLAiR의 주간 시작·잠금·경고도 별도 설정으로 이동한다.

6

병원 운영 정보는 보강한다

Flex에는 없는 진료실·직군 커버리지·야간/응급 배정을 CLAiR이 추가한다. Flex를 복제하는 것이 아니라 병원 운영 의사결정에 맞게 확장하는 부분이다.

적용 경계: Flex의 구성원 중심 캘린더와 교대근무 시각화는 가져오지만 급여·출퇴근 기록·근로기준법 자동화는 이번 범위에서 제외한다. 초안과 직원 게시를 분리하는 안전장치는 Deputy의 게시 패턴을 보조 근거로 유지한다.

4. To‑Be 인터랙티브 시안

관리자 화면 안에서 `주간 편성`과 `일간 커버리지`를 전환할 수 있고, 상단 탭에서 직원용 개인 캘린더로 이동할 수 있어. `근무 추가`, 근무 블록, 직원 이름을 누르면 우측 편집 패널이 열린다.

5. 관리자와 직원이 연결되는 흐름

1. 초안 만들기빈 셀·템플릿·근무 추가에서 편성
2. 문제 해결미배정·충돌·휴무 요청 확인
3. 게시직원 공개 및 변경 알림
4. 직원 확인내 근무와 변경 내역 조회
5. 요청 반영관리자 승인 후 재게시

6. 상태·접근성·반응형 기준

빈 상태

근무가 없는 주

`템플릿 적용`과 `첫 근무 추가`를 제공한다. 정책 설정으로 보내지 않는다.

오류·권한

읽을 수 있는 상태를 유지

최근 근무표를 유지하고 재시도한다. 비관리자는 편집 행동을 숨기고 읽기 전용 이유를 표시한다.

접근성

드래그 없이도 완전하게

키보드로 셀 선택·추가·편집이 가능해야 한다. 색뿐 아니라 시간·상태 텍스트를 함께 쓴다.

로딩

그리드 위치를 보존

행·열 크기를 유지하는 스켈레톤을 사용해 직원과 날짜 위치가 움직이지 않게 한다.

게시 후 변경

변경 범위를 먼저 확인

변경된 근무 수와 대상 직원을 보여주고, 재게시할 때 변경 메모를 받는다.

모바일

주간 표를 억지로 축소하지 않기

관리자는 날짜별 목록으로 전환하고, 직원은 세로형 개인 주간 목록을 기본으로 쓴다.

8. 권장 개발 순서

  1. 관리자 편성 기반: 주간 이동, 직원×7일 그리드, 근무 CRUD, 직원 상세 패널, 초안 상태.
  2. 운영 안전: 충돌·미배정·권한·오류·삭제 확인, 게시/재게시 흐름.
  3. 직원 셀프서비스: 내 근무, 근무 가능 시간, 휴무·변경 요청, 승인 상태.
  4. 연동: 서버 권한, 감사 로그, 알림, API/DB/RLS는 별도 스코프와 검증으로 진행.
