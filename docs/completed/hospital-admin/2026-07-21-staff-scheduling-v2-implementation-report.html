근무표 MVP v2 구현 완료

기존 근무표를 지우지 않고, 게시 이력과 정규화된 근무 데이터를 기반으로 하는 v2를 추가했다. 이제 청담 워크스페이스만 단계적으로 비교하고 전환할 수 있으며, 게시된 근무가 직원 프로필에 실제로 반영되는지도 별도로 확인한다.

로컬 구현 및 검증 완료 · 프로덕션 전환 대기

무엇이 달라졌나

안전한 v2 전환

v1 → compare → v2 플래그를 추가했다. 문제가 나면 데이터 삭제 없이 즉시 v1 읽기로 되돌릴 수 있다.

게시 이력과 초안 분리

주차별 초안은 하나만 허용하고, 게시본은 불변으로 유지한다. 새 게시본은 이전 게시본을 대체 이력으로 남기며, 과거 게시본은 새 초안으로 복원할 수 있다.

프로필 상태의 정확성

미배정, 휴무일, 휴가, 병원 휴무일을 구분한다. 휴가 사유와 개인 메모는 프로필로 전달하지 않는다.

운영자 편집 화면

주간 그리드와 모바일 일자 목록, 초안 편집, 검증, 게시 검토, 동시 편집 충돌 복구를 컴포넌트로 분리했다.

핵심 구현 범위

  • DB/백엔드: revision, validation, work block, non-work, 정책, 멱등성, rollout 테이블과 RLS/RPC 경계를 가산형 migration으로 추가.
  • 데이터 안정성: 동일 워크스페이스 FK, 주차 날짜, 중복 초안, 시간 중첩, 영업시간/휴무일, 비활성 직원, lock version, idempotency를 서버에서 검증.
  • 프론트엔드: 기존 EMR 컴포넌트와 shadcn/Base UI를 조합하고 --emr-schedule-* 토큰으로 근무표 전용 상태와 레이아웃을 관리.
  • 프로필 소비: v2일 때 최신 게시 리비전만 최소 형태로 읽고, 게시 뒤 프로필 읽기 경로를 다시 조회해 반영 확인 중, 게시 완료 · 프로필 확인 필요를 구분.

배포 전 결정이 필요한 항목

아직 프로덕션 DB migration이나 rollout 플래그 변경은 하지 않았다. 구현은 기본값 v1으로 안전하게 준비된 상태다. 승인 뒤에는 청담 합성 데이터만 backfill하고, compare에서 불일치 0건과 권한 거부/게시/프로필 readback을 확인한 뒤 청담만 v2로 전환해야 한다.
