Order 관리 데이터테이블 헤더 개편

2026-08-02 · Hospital Admin UI

고객관리 데이터테이블 헤더를 공용 컴포넌트로 승격하고, Order 관리의 데이터테이블 15개 leaf 화면에 같은 구조를 적용했다. 제목 아래 설명과 카테고리 탭을 제거해 검색·조건·필터·등록 작업의 위계를 단순화했다.

변경 내용

  • EmrTableWorkspaceHeader가 제목, 결과 건수, 검색, 테이블 제어, 주요 액션을 공통 소유한다.
  • 고객관리는 기존 CustomerListHeader API와 test id를 호환 래퍼로 유지한다.
  • Order 관리 15개 leaf에서 설명·상태 문구의 시각 노출과 내부 타입 탭을 제거했다.
  • 임상병리 검사에만 검사 카테고리 고급 필터를 제공한다.
  • 검색, 빠른 조건, 고급 필터는 기존처럼 AND로 결합하고 정렬·선택·복제·Drawer 동작은 유지한다.

작업 범위

기본 진료비, 기타 진료비, 예방, 영상검사, 임상병리 검사, 계통 검사, 의뢰 검사, 처치, 마취, 수술, 입원, 치료, 처방, 조제, 의료물품의 15개 화면이다.

검증 결과

  • TypeScript 및 변경 파일 ESLint 통과
  • Storybook 전체 story/a11y 테스트 통과
  • Customer + Hospital Admin 전체 58개 Playwright 테스트 통과
  • 15개 Order leaf, 탭 부재, 임상병리 전용 카테고리 필터 집중 테스트 통과
  • 390px 필터 접근성과 1920×1080 실제 화면 확인

범위 밖

좌측 Order 카탈로그 메뉴, 권한·RLS, 서버 검색, 페이지네이션, 다른 14개 leaf의 분류 체계와 원격 배포는 변경하지 않았다.

주의 사항

임상병리 카테고리는 현재 workspace catalog의 명시적 categoryLabel을 화면용 category id로 매핑한다. 별도 영속 id가 서버 계약에 추가되면 이 매핑을 해당 필드로 교체하는 것이 다음 단계다.
