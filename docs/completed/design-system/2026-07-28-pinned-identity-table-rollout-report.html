DESIGN-SYSTEM-PR-088

고정 식별 컬럼 데이터 테이블 확장

가로 스크롤 중 고정 영역 뒤로 다른 셀 내용이 비치던 문제를 공통 테이블 계약에서 해결하고, 고객관리 3개 화면과 병원관리 Order 15개 화면에 동일한 정렬·스크롤 규칙을 적용했습니다.

구현 및 기능 검증 완료 · 사용자 검토 대기
3개 고객관리 테이블 화면
15개 Order 관리 하위 화면
1개 테이블 가로 스크롤 소유자

요청 사항과 결과

  • 동물·보호자·삭제 화면의 첫 식별 컬럼을 불투명한 왼쪽 고정 컬럼으로 통일했습니다.
  • 제목, 검색창, 고정 헤더, 행 식별 텍스트, 하단 합계가 화면별 하나의 수평축을 공유합니다.
  • 고정 테이블 헤더의 위쪽 패딩을 공통 계약에서 0px로 적용했습니다.
  • Order 관리의 모든 하위 화면은 표준 Order명을 첫 고정 컬럼으로 사용하는 하나의 공통 렌더러를 사용합니다.
  • Order의 바깥 ScrollArea를 제거하고 공통 Table 컨테이너만 가로·세로 테이블 스크롤을 소유하도록 정리했습니다.

삭제 화면 연결

단순한 빈 화면 교체가 아니라 기존 archive GET API로 삭제된 동물·보호자를 조회하고, 대상별 기존 PATCH API로 복원하도록 연결했습니다. 로딩, 데이터 없음, 검색 결과 없음, 조회 권한 없음, 재시도 가능한 조회 실패, 복원 권한 없음, 복원 실패 상태를 각각 화면에 표시합니다. 복원 성공 시 행과 좌측 삭제 건수가 함께 갱신됩니다.

공통 구현 기준

  • EmrPinnedTableWorkspace가 화면별 식별 텍스트 축을 한 번만 정의합니다.
  • EmrTableHeaderCell identity와 EmrTableIdentityCellContent가 헤더·행 정렬을 공유합니다.
  • 고정 셀의 기본·호버·선택·로딩 배경과 경계 그림자는 공통 Table 스타일이 소유합니다.
  • 기능 화면은 sticky 위치, z-index, 배경을 개별 계산하지 않습니다.

변경 범위

공통 Table primitive와 스타일, 고객관리 테이블 렌더러·archive 화면·store·권한 어댑터, 병원관리 Order 공통 렌더러, Playwright 및 Storybook 검증, 설계 문서와 작업 문서를 변경했습니다.

검증 결과

  • 공통 Table Storybook 상호작용 테스트 5/5 통과
  • 고객관리 및 archive Playwright 테스트 23/23 통과
  • 병원관리 전체 테스트에서 변경 관련 33개 테스트 통과; 기존 바이탈 설정 테스트 1건은 전체 실행에서 시간 초과했지만 단독 재실행 통과(전체 타임아웃을 60초로 늘려도 같은 격리 실패 유지)
  • 집중 ESLint 및 TypeScript 검사 통과
  • 전체 lint, TypeScript, 문서 링크 888건, 비밀정보 스캔 3,485개 파일, Storybook 빌드, Next 프로덕션 빌드 통과

제외 범위와 위험

스키마·마이그레이션·하드 삭제·새 의존성·실데이터·Order drawer 업무 흐름은 변경하지 않았습니다. 이번 로컬 작업은 원격 push, PR, main 병합, 배포를 포함하지 않습니다.

권장 다음 단계
