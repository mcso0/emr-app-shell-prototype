DESIGN-SYSTEM-PR-090

워크스페이스 진입 스플래시

로그인 뒤 업무 화면이 준비되는 짧은 공백을 하나의 일관된 브랜드 motion으로 연결했습니다. 로딩이 언제 끝나더라도 로고가 pulse 중간에서 갑자기 끊기지 않고 원래 크기와 밝기로 돌아온 뒤 화면이 열립니다.

구현 및 핵심 브라우저 검증 완료
600ms fade in + scale up
1.6초 breathing pulse 전체 주기
180ms 메인 화면 fade 전환

무엇이 달라졌나

  • 흰 배경 중앙에 옅은 회색 CLAiR mark를 표시합니다.
  • 로고는 85% 크기에서 진입한 뒤 100%와 92% 사이를 호흡하듯 반복합니다.
  • 로딩 완료 신호는 진행 중인 pulse를 끝까지 마친 뒤 반영합니다.
  • 업무 화면은 스플래시 아래에 먼저 준비되고, 마지막 180ms 동안 자연스럽게 드러납니다.
  • 동작 줄이기 환경에서는 반복 animation 없이 즉시 전환합니다.

적용 범위

이번 구현은 로그인 성공부터 워크스페이스 셸 진입까지만 담당합니다. 세션·권한 확인용 skeleton과 각 업무 화면의 데이터 loading 상태는 기존 흐름을 유지합니다. 접근 실패 시에도 스플래시가 무한히 남지 않고 기존 로그인 또는 오류 화면이 나타납니다.

motion 계약

구간 opacity scale 시간·이징
진입 0 → 1 0.85 → 1 600ms ease-out
pulse 한 방향 1 ↔ 0.5 1 ↔ 0.92 800ms ease-in-out
종료 overlay 1 → 0 로고 1 유지 180ms ease-out

검증 결과

  • 전용 motion·auth Playwright 검증 6개가 통과했습니다.
  • 전체 ESLint, Next production build, Storybook static build가 통과했습니다.
  • Storybook에 무한 로딩과 정상 종료 예시가 추가되었습니다.
  • 문서 링크, secret, 한국어 UX copy 검사도 통과했습니다.

별도 TypeScript 명령은 이번 작업과 무관한 고객 프로필 test fixture의 기존 generic type 오류로 중단됐습니다. Next production build의 TypeScript 단계와 이번 변경 대상 lint는 통과했습니다.

다음 확인

실제 데스크톱 창에서 제공된 영상과 나란히 비교해 로고의 시각적 중심과 호흡 속도를 최종 승인하는 것이 다음 단계입니다. native 앱 시작 창이 별도로 생기면 renderer splash와 분리된 lifecycle로 연결해야 합니다.
