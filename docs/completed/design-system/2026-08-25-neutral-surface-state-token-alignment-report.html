DESIGN-SYSTEM-PR-094

Neutral 표면·행 상태 토큰 정리

실제 화면의 흰색·Neutral 표면 체계와 상호작용 상태를 분리하고, 데이터테이블의 hover와 selected가 명확한 단계로 보이도록 전역 계약을 정리했다.

로컬 구현·집중 검증 완료
4% hover 검정 오버레이
6% selected 검정 오버레이
8% active 검정 오버레이

문제와 결정

  • 기존 selected는 보라 기운이 있는 cool-gray 고정색이었고, hover는 화면별로 4% 또는 6%가 섞여 있었다.
  • 정적 배경은 equal-channel Neutral 계열로, 상호작용은 검정 alpha 오버레이로 분리했다.
  • --emr-surface-hover와 --emr-surface-selected는 호환 별칭만 유지한다.

구현 결과

  • 앱·패널은 흰색, workspace는 #FCFCFC, muted/table header는 Neutral 50, disabled는 Neutral 100으로 정리했다.
  • 공용 데이터테이블의 전체 행과 pinned cell이 동일한 hover/selected 상태 토큰을 사용한다.
  • pinned cell은 상태 오버레이를 불투명한 기본 행 표면 위에 합성해 스크롤 콘텐츠가 비치지 않는다.
  • 고객관리, 병원관리, Order 세트, 역할·권한, 차트의 기존 #FCFCFC 배경은 semantic workspace 토큰을 사용한다.

검증 범위

  • 전역 토큰 계산값, legacy 별칭 방지, 고객관리 pinned 행, 병원관리 Order drawer 활성 행, Order 세트 진입을 확인했다.
  • ESLint, TypeScript, 문서 링크, 비밀정보, diff, Storybook build, Next production build가 통과했다.
  • Toggle·table workspace header Storybook 검증은 6/6 통과했다.
  • 공용 Table Storybook의 pinned-content 10px inset 1건은 동일한 origin/main에서도 재현되는 기존 실패이며, 이번 상태색 변경과 무관하다.

제외 범위

내비게이션 rail의 기존 Gray 팔레트와 정보·성공·경고·위험 등 semantic status 색은 유지했다. 데이터, API, 권한, drawer, 저장, Order 세트 동작도 변경하지 않았다.
