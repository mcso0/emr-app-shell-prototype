DESIGN-SYSTEM-PR-088

선택형 고정 식별 컬럼 · Empty State 수정 보고서

고객관리 동물 화면의 돌출 아바타 문제를 화면 한 곳의 예외로 처리하지 않고, 고객관리와 병원관리에서 선택 가능한 고정 테이블이 공유하는 레이아웃 계약으로 수정했다.

구현 및 로컬 검증 완료
44px + identity 선택 열과 도메인 식별 열을 함께 고정
48px 제목·헤더·행 식별 텍스트 공통 축
57 / 57 고객관리·병원관리 Playwright 통과

요청과 결정

  • 고객관리 동물명의 텍스트 축은 유지하고, 이름 앞의 아바타를 제거했다.
  • 선택 가능한 테이블은 선택 열을 첫 번째로, 화면별 표준 식별 값을 두 번째로 고정한다.
  • 동물·보호자는 이름, 병원관리 Order는 표준 Order명을 식별 값으로 사용한다.
  • 실제 데이터 없음, 검색·필터 결과 없음, 전체 읽기 오류, 권한 없음은 표 전체를 공용 EmrEmptyState로 교체한다.

구현 결과

  • 공용 고정 테이블 workspace가 선택 열 너비와 식별 텍스트 축을 함께 소유한다.
  • 헤더 전체 선택은 항상 보이고, 데스크톱 행 선택은 hover, focus-within, selected 상태에서 노출된다. 터치 환경에서는 항상 사용할 수 있다.
  • 고객관리 동물·보호자와 병원관리 Order는 선택 열과 식별 열이 가로 스크롤에도 고정된다.
  • 비선택형 고객관리 삭제 내역은 기존처럼 식별 열만 고정한다.
  • Empty State의 등록, 조건 초기화, 다시 시도 액션은 기존 화면 workflow를 재사용한다.

변경 범위

공용 테이블 primitive와 전역 고정열 상태 스타일, 고객관리 데이터 테이블·archive·store, 병원관리 Order renderer, Storybook 예시, Playwright 회귀 테스트, 관련 design-system 문서를 변경했다.

검증

  • 고객관리 Playwright: 20/20 통과
  • 병원관리 Playwright: 37/37 통과
  • 공용 Table Storybook interaction: 5/5 통과
  • ESLint, TypeScript, 문서 링크, 비밀정보, diff, Storybook build, Next production build 통과
  • 제목·식별 헤더·행 값의 동일 축, 선택/식별 다중 고정, 단일 스크롤 owner를 브라우저 geometry로 확인했다.
  • no-data, no-filter-results, read-error, no-permission 상태와 복구 액션을 확인했다.

위험 및 제외 범위

스키마, API 의미, 실제 고객 데이터, Order drawer·저장 workflow, 비선택형 테이블 구조는 바꾸지 않았다. 실제 동물 이미지를 사용하는 다른 화면의 공용 아바타 컴포넌트도 유지했다.
