MVP 파일럿 readiness 기준 보고서

이번 작업은 “파일럿 가능/불가능”을 감으로 판단하지 않도록 기준표와 blocker 정책을 만든 작업이다.

결정한 기준

구분파일럿 전 꼭 필요후속 가능
Auth/권한서버 세션, active membership, cross-workspace denial로그 정리, rate limit 저장소 고도화
DB/RLSlocal-first replay 근거와 domain RLS 계획remote 적용 전 advisor review
Persistence접수-차트-오더-수납 핵심 reload checkpoint검사/영상/조제/처치 전체 live 전환
Audit핵심 mutation event matrix대시보드, export, 장기 보관 정책
QA외래 workflow와 권한 denial 점검부하 테스트, provider별 QA

Blocker 정책

  • 다른 병원 데이터 노출, 권한 없는 변경, 핵심 외래 상태 유실, 시크릿 노출, 청구 금액 불신은 파일럿 blocker다.
  • 안전하게 파일럿은 가능하지만 신뢰도를 높이는 일은 follow-up으로 둔다.
  • PACS, KakaoTalk, PG 정산, AI, compliance dashboard는 Post-MVP로 분리한다.

대표 체크리스트

  • 로그인 후 올바른 병원 workspace에 들어가는가?
  • 접수에서 만든 encounter가 차트와 수납까지 이어지는가?
  • 권한 없는 사용자가 안전하게 차단되는가?
  • 실제 의료 자문이나 실제 환자 데이터처럼 보이지 않는가?
  • 보안/QA가 다음 이슈에서 같은 기준으로 판단할 수 있는가?

현재 판단

Project 04 handoff는 충분하지만, MVP 전체는 아직 파일럿 준비 완료가 아니다. DEN-83부터 DEN-91까지 audit, 보안 리뷰, QA, 대표 리허설을 거쳐야 한다.
