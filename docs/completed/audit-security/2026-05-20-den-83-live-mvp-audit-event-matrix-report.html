DEN-83 / Project 05

Live MVP Audit Event Matrix 보고서

누가, 언제, 어떤 핵심 데이터를 바꿨는지 추적하기 위한 이벤트 계약을 정리했다.

이번에 정한 것

  • 모든 audit event가 가져야 할 공통 envelope를 정의했다.
  • workspace/member/profile, reception/encounter, chart/diagnosis, order, billing/payment 이벤트 이름을 확정했다.
  • 민감 정보 저장 금지 범위를 명확히 했다.
  • DEN-84부터 어떤 순서로 구현해야 하는지 정리했다.

대표 이벤트

영역이벤트 예시의미
권한/멤버workspace.membership_roles_changed구성원 역할이 바뀐 기록
접수reception.walk_in_created현장 접수 encounter 생성 기록

수납billing.payment_state_changed미납/수납 완료 상태 변경 기록

저장 금지

  • 서비스 role key, DB password, authorization header, session token, invite token
  • PG, KakaoTalk, PACS, 장비, 이메일 provider raw payload
  • stack trace, SQL error detail, 내부 파일 경로
  • 전체 SOAP 본문, 전체 개인정보 snapshot, 실제 환자/병원 데이터
  • client가 보낸 금액을 청구 기준으로 저장하는 것

다음 순서

DEN-84에서 audit_events schema와 server-only append helper를 만들고, DEN-85에서 실제 mutation route에 event emit을 연결하는 순서가 자연스럽다.
