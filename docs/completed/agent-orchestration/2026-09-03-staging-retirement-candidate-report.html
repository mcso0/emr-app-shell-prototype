staging 운영 폐기 후보 보고서

상태: Human Review — exact candidate 승인 전이며 아직 main, Production, fixed staging alias, 원격 staging 브랜치는 변경하지 않았습니다.

요청

혼자 운영하는 현재 방식에 맞춰 origin/main을 단일 최신 기준으로 유지하고, 별도 staging 브랜치와 fixed staging alias 및 관련 자동화를 폐기합니다.

후보 변경

  • 활성 배포 경로를 PR Preview → exact Release Check → 명시적 승인 → main/Production으로 단순화
  • fixed staging alias GitHub workflow, helper script, package command 제거
  • 과거 staging 문서는 삭제하지 않고 superseded 기록으로 보존
  • exact candidate 승인 후에만 fixed alias와 원격 staging 브랜치 제거

중요한 비변경 범위

애플리케이션 기능, Supabase, migration, RLS, 실데이터, 인증, 결제, 메시지, Production 도메인·환경값은 변경하지 않습니다.

검증과 승인

로컬 문서·비밀값·문구·diff 검증과 exact SHA Release Check, Vercel Preview Ready를 확인한 뒤 승욱에게 정확한 후보를 제시합니다. 승인 전에는 main 병합, alias 제거, staging 브랜치 삭제를 실행하지 않습니다.

복구

정책 병합 전에는 PR을 병합하지 않으면 됩니다. 병합 후 저장소 변경은 revert PR로, fixed alias는 보존된 이전 Preview deployment로, staging 브랜치는 기록된 기존 SHA로 복구할 수 있습니다.
