PR/main CI Workflow 보고서

PR preview와 main 통합 전에 기본 품질 게이트가 자동으로 실행되도록 GitHub Actions CI workflow를 추가했다.

완료추가한 workflow

  • 파일: .github/workflows/ci.yml
  • Trigger: pull_request, push to main
  • Node version: 24, Vercel Project 설정과 정렬
  • Permissions: contents: read
  • Concurrency: 같은 ref의 이전 CI run은 취소

실행 명령

  • npm ci
  • npm run docs:check
  • npm run lint
  • npx tsc --noEmit
  • npm run build

안전 범위

  • 이 workflow는 배포하지 않는다.
  • fixed staging alias를 움직이지 않는다.
  • production deploy/promote를 하지 않는다.
  • Vercel token, env secret, provider secret을 추가하지 않는다.
  • 원격 GitHub branch rule 설정은 변경하지 않았다.

남은 수동 설정

  • Linear connector가 401 reauthentication required 상태라 02-04 Linear 이슈 생성/업데이트는 아직 못 했다.
  • 승욱 승인 후 GitHub branch protection required checks 설정을 시도했지만, GitHub API가 private repo branch protection/rulesets에는 GitHub Pro 또는 public repo가 필요하다는 403을 반환했다.
  • 따라서 현재는 GitHub UI/API에서 CI와 Secret Scan을 required checks로 강제할 수 없다.
  • 결정: 작업 repo는 private으로 유지하고, CI/Secret Scan은 자동 실행하되 merge 전 수동으로 성공 여부를 확인한다.
  • public 포트폴리오는 나중에 별도 sanitized public repo로 분리한다.
  • fixed staging을 main 기준으로만 이동시키는 작업은 02-05에서 별도 승인 후 진행한다.

검증
