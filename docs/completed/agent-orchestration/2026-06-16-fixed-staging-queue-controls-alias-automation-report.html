고정 스테이징 대기열 컨트롤 및 alias 자동화 결과

진료/차트와 조제/처치 좌측 대기열 헤더가 다시 compact 컨트롤 형태로 보이도록 정리했고, staging 브랜치 배포가 완료되면 고정 staging URL이 최신 배포를 따라가도록 자동화 경로를 추가했다.

변경 사항

  • 대기열 정렬 버튼은 아이콘과 요청순 같은 짧은 텍스트만 보이도록 유지했다.
  • 필터, 표시 옵션, 검색은 각각 아이콘 버튼, M/S 밀도 버튼, inline search 트리거로 동작한다.
  • 현재 정렬:, 필터: 전체 조건, 표시 옵션: 기본 같은 과거형 상태 문구가 주 컨트롤 이름으로 노출되지 않게 했다.
  • GitHub Action과 dry-run 가능한 스크립트로 fixed staging alias 업데이트를 자동화했다.
  • 필요한 GitHub Secret과 배포 후 사람이 확인해야 하는 smoke checklist를 문서화했다.

검증

  • npm run docs:check 통과
  • npx tsc --noEmit --pretty false 통과
  • npm run lint 통과, 기존 warning 5개만 남음
  • npm run build 통과
  • Focused Playwright: 진료/차트와 조제/처치 대기열 헤더 테스트 통과
  • Alias dry-run: staging branch alias 기준 실행 계획 검증 통과
  • 로컬 브라우저 DOM 확인: 두 화면 모두 과거형 문구 count 0, inline search 열림

남은 리스크

  • 실제 GitHub Action alias 변경은 GitHub에 VERCEL_TOKEN secret이 설정된 뒤 staging deployment status 이벤트에서 확인해야 한다.
  • 고정 staging은 Vercel Deployment Protection 또는 SSO 설정에 따라 브라우저 접근 방식이 달라질 수 있다.
  • Production alias와 main promote는 이번 범위에서 제외했다.
