Vercel Git Integration 실행 계획 보고서

실제 Vercel/GitHub 설정은 변경하지 않고, PR preview 자동화로 넘어가기 전에 필요한 읽기 전용 확인과 승인 조건을 정리했다.

확인추가로 확인한 현재 상태

  • Vercel Project API의 link와 gitRepository는 null이었다.
  • 최근 Vercel deployment들은 target: null이며 Preview/manual 성격으로 보인다.
  • 최근 deployment metadata에는 GitHub branch/commit 정보가 있으나, 여러 항목에 gitDirty=1이 있어 CLI/manual 배포 메타로 해석해야 한다.
  • 최근 GitHub PR checks에는 secret-scan과 GitBook status context만 보였고, Vercel check run은 확인되지 않았다.

결론

  • 현재 증거로는 Vercel Git Integration 연결을 확정할 수 없다.
  • Git metadata가 있는 배포가 존재해도 자동 PR preview 연동의 증거로 보지 않는다.
  • 다음 단계는 명시 승인 후 Vercel Dashboard 또는 승인된 CLI/API 경로로 Git 연결을 확인하거나 연결하는 것이다.

아직 실행하지 않은 것

  • vercel git connect를 실행하지 않았다.
  • Vercel/GitHub 원격 설정을 변경하지 않았다.
  • fixed staging alias를 변경하지 않았다.
  • production deploy/promote를 하지 않았다.
  • secret/env 값을 출력, 저장, 회전하지 않았다.
  • Linear connector가 401 재인증 필요 상태라 새 Linear 이슈는 만들지 못했다.

다음 승인 문구

원격 설정 변경으로 넘어가려면 아래와 같이 대상과 금지 범위를 함께 승인해야 한다.

승인: 02-03에서 Vercel Project emr-app-shell-prototype을 GitHub repo mcso0/emr-app-shell-prototype에 연결/확인하고, production branch를 main으로 확인/설정하며, PR preview 생성 확인용 테스트 브랜치와 PR을 만들어도 된다. fixed staging alias와 production은 건드리지 마.
