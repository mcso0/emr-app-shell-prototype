Fixed Staging Main-only 계획 보고서

fixed staging을 main 기준으로만 이동시키는 v1 절차를 정리했다. 실제 alias 이동은 하지 않았다.

확인읽기 전용 결과

  • Vercel Git Integration은 GitHub repo mcso0/emr-app-shell-prototype에 연결되어 있다.
  • Vercel production branch는 현재 main이다.
  • fixed staging alias는 여전히 emr-app-shell-prototype-gbj5vwjhd... deployment를 가리킨다.
  • production aliases는 여전히 emr-app-shell-prototype-32da67as6... deployment를 가리킨다.
  • PR #97 preview deployment는 Ready 상태이며, PR preview 자동화는 검증되어 있다.

결정

  • 현재 상태에서 fixed staging을 Vercel production branch 자동화에 바로 묶지 않는다.
  • 이유: Vercel production branch가 main이므로 production 정책과 충돌할 수 있다.
  • v1은 clean origin/main worktree에서 Preview deployment를 만들고, 명시 승인 후 fixed staging alias만 이동하는 방식이다.

아직 하지 않은 것

  • fixed staging alias를 이동하지 않았다.
  • production deploy/promote를 하지 않았다.
  • production aliases/domains를 변경하지 않았다.
  • Vercel production branch 설정을 변경하지 않았다.
  • GitHub Action으로 staging alias를 자동 이동시키지 않았다.

다음 승인 문구

실제 fixed staging 이동은 아래처럼 source commit을 명시한 뒤 진행한다.

승인: fixed staging을 main commit <SHA> 기준으로 업데이트해줘. 포함 PR/이슈는 <list>이고, production은 건드리지 마.
