DEN-422 Owner OS Work Packet Template And Validator

Human Review handoff · 2026-06-05 · Project: CLAiR Owner OS Implementation

요약

Owner OS가 넓은 요청을 바로 실행하지 않고, 실행 가능한 작업 패킷으로 고정할 수 있는 템플릿과 필수 필드 validator를 추가했다. 이제 작업 패킷에는 범위, 금지된 부작용, 승인 게이트, 검증, eval, trace, parent model tier, 5.5 승격 판단, subagent 비용 근거가 빠지면 안 된다.

무엇이 바뀌었나

  • docs/_meta/templates/owner-os-work-packet.md: 재사용 가능한 Owner OS work packet 템플릿 추가.
  • docs/product/service/owner-os-work-packet-examples.md: good/bad 예시 추가.
  • scripts/validate-owner-os-packets.mjs: Markdown fenced block 기반 필수 필드 validator 추가.
  • package.json: npm run owner-os:packet:check 명령 추가.
  • docs/work/agent-orchestration/OWNER-OS-PR-003-work-packet-template-validator.md: DEN-422 repo work item 추가.

왜 중요한가

이 작업은 Owner OS의 실행 단위를 표준화한다. 앞으로 Codex가 어떤 모델 tier로 일할지, 언제 5.5로 승격할지, 서브에이전트를 왜 쓰는지, 어떤 검증과 trace를 남길지 패킷에서 먼저 확인할 수 있다.

검증

  • npm run owner-os:packet:check: 통과. 템플릿과 good example은 통과하고 bad example은 의도대로 거부된다.
  • npm run docs:check: 통과. 885개 docs/agent markdown 내부 참조가 정상이다.

제외 범위와 리스크

  • OpenAI API 호출, 실제 multi-agent dispatch, Linear 자동 상태 변경은 구현하지 않았다.
  • validator는 YAML 전체 파서가 아니라 Owner OS packet 구조에 필요한 key path와 list item 존재를 검사하는 deterministic checker다.
  • 다음 DEN-423 eval dataset과 DEN-424 trace contract는 이 패킷 필드를 재사용해야 한다.

다음 단계

다음 순서는 DEN-423에서 scenario eval dataset과 judge rubric을 만들고, 이 템플릿의 필드를 기준으로 라우팅 품질과 패킷 완성도를 평가하는 것이다.
