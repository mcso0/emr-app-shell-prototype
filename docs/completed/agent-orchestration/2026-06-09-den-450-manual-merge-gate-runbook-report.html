DEN-450 Manual Merge Gate Runbook

2026-06-09 · CLAiR EMR Release & Deployment Operations

요약

현재 GitHub private/free 환경에서는 CI와 Secret Scan을 자동으로 실행할 수 있지만, required check로 강제할 수 없다. 그래서 이번 작업은 사람이 merge 전에 무엇을 확인해야 하는지 runbook으로 고정했다.

원격 Vercel/GitHub 설정, fixed staging alias, production은 변경하지 않았다.

적용한 운영 구조

흐름 의미 게이트
work branch / PR 개별 작업 또는 작업 묶음 검수 Vercel Preview, CI, Secret Scan, scope 확인
staging 고정 스테이징 리뷰 대상 included PR/issues, source SHA, fixed staging URL 확인
main Vercel Production branch 승욱의 production 승인, smoke, rollback 후보 필수

Runbook에 고정한 게이트

Gate 1: 작업 PR을 staging에 merge하기 전

  • PR target이 staging 또는 승인된 integration branch인지 확인한다.
  • CI, Secret Scan, Vercel Preview Ready 상태를 확인한다.
  • fixed staging alias, production alias, production 설정, secret 변경이 없는지 확인한다.

Gate 2: staging을 fixed staging URL에 반영하기 전

  • source branch와 commit SHA를 기록한다.
  • npm run security:secrets, npm run docs:check, git diff --check 결과를 기록한다.
  • fixed staging alias target과 production non-change를 확인한다.

Gate 3: staging에서 main production으로 가기 전

  • 승욱의 명시적인 production 승인 없이는 중단한다.
  • source SHA, 포함 PR/이슈, env/secret source, smoke path, rollback 후보를 승인 packet에 포함한다.
  • remote Supabase, real data, provider, email, payment, RLS 작업이 섞이면 별도 승인을 요구한다.

검증

  • npm run docs:check
  • npm run security:secrets
  • git diff --check

이 보고서 생성 후 최종 검증을 실행한다.

남은 리스크

  • GitHub required checks는 현재 private/free 제약 때문에 자동 강제되지 않는다. merge 전 사람이 직접 check 상태를 확인해야 한다.
  • fixed staging URL은 여전히 mutable alias다. source branch와 deployment id를 기록하지 않으면 어떤 변경이 반영됐는지 추적하기 어렵다.
  • production은 main과 연결되어 있으므로, main merge는 일반 통합이 아니라 production release로 취급해야 한다.
