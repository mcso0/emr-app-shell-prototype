Hobby/free Staging Branch Release Model 보고서

Hobby/free 기준으로 최종 릴리즈 구조를 PR Preview -> staging branch fixed staging -> main Production 으로 정리했다.

결정최종 구조

  • 작업 브랜치/PR: Vercel Preview
  • staging 브랜치: fixed staging
  • main 브랜치: Vercel Production
  • GitHub required checks는 현재 private/free 조건에서 강제할 수 없으므로 merge 전 수동 확인한다.
  • public 포트폴리오는 나중에 별도 sanitized public repo로 분리한다.

Linear 조정 필요

  • 02-05 Redefine Hobby/free staging branch release model: 기존 main-only 계획을 supersede하고 새 구조 확정
  • 02-06 Create staging branch and connect fixed staging URL: 실제 staging 브랜치와 Vercel branch URL 연결, 별도 승인 필요
  • 02-07 Define manual merge gate for staging and production: GitHub required checks 미사용 상태의 수동 merge gate 정의
  • 03-02 Define production release from staging to main: production release 승인/검증/롤백 절차 정의

아직 하지 않은 것

  • staging remote branch를 만들거나 push하지 않았다.
  • Vercel domain/alias를 변경하지 않았다.
  • fixed staging alias를 이동하지 않았다.
  • main이나 production을 건드리지 않았다.
  • Linear connector가 401 reauthentication required라 실제 이슈 생성은 아직 못 했다.
