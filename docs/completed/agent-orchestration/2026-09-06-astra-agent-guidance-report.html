2026-09-06 · OWNER-OS-PR-012 · 로컬 적용 완료 / 검토 가능

Astra에 맞춘 작업 지침과 설정

승욱과 결정한 모델 구성과 위임 한도를 적용했어. 이미 승인한 작업을 다시 묻는 지시, 일반 리뷰를 막는 지시, 예전 모델로 전환하라는 지시를 정리했어.

적용한 결정

항목결과
모델주 작업과 보안 검토 Astra high, 계획 xhigh, Spark low. 테스트 분류는 지원 종료된 5.4-mini를 대신해 5.6 Luna medium으로 변경.
위임독립적인 읽기 전용 작업을 최소 인원으로 분담. 주 에이전트 제외 전체 작업 트리에서 동시 최대 4개. 병렬 구현은 별도 명시적 요청 필요.
질문·승인같은 대상·작업·범위의 기존 승인 유지. 일반 리뷰는 바로 읽기 전용 수행, 명시적인 Safety OS 게이트는 범위 제안 후 대기.
검증·보고필수 검증 통과 후 새로운 문제가 있을 때만 확대. 읽기 전용 상담은 요청된 경우에만 별도 보고서 작성.
시작 문서약 48KB → 8KB. 이전 본문은 상세 문서에 그대로 보존.

실험적 컨텍스트 관리 추가

첨부한 설정을 공식 문서와 설치된 Codex의 설정 지원 여부에 대조한 뒤, 전역 ~/.codex/config.toml에 [features.context_management]와 experimental_mode = true를 추가했어. 전역 설정의 다른 값과 프로젝트의 모델·추론·동시 실행 한도는 유지했고, 이후 승인된 테스트 분류 모델만 Luna로 바꿨어.

Pro 계정과 새 검증 작업의 컨텍스트 조회·전환 도구를 확인했고, 전환을 한 번 실행했어. 다만 실험 모드 활성화를 명시하는 런타임 값이나 전용 이력 검색 결과는 확보하지 못했어. 따라서 기능 전체 활성화·검색 성공으로 단정하지 않아. 이 기능은 같은 작업의 이전 메시지와 도구 결과를 찾는 기능이며, 모든 작업을 영구적으로 기억한다는 의미는 아니야. 공식 기능 안내

Luna 실제 실행 확인

테스트 분류 모델을 gpt-5.6-luna / medium으로 바꾸고 관련 지침도 맞췄어. 새 검증 작업에서 모델·추론 값을 따로 덮어쓰지 않고 해당 역할을 하나 실행했으며, 하위 작업 자체의 실행 메타데이터에서 Luna / medium을 확인했어. 부모도 Astra / high로 실행됐어. 공식 모델 교체 안내

검증 결과

  • 회귀 테스트 6개 통과, 실제 로컬 분류 시나리오 15개 통과.
  • 작업 패킷 검증 3개 통과. 이전 필드 이름의 읽기 호환성 유지.
  • 수정 스크립트 ESLint, TOML 값, 스킬 frontmatter, 변경 Markdown 링크 검사 통과.
  • 독립 보안 경계 검토 후 남은 필수 수정 사항 없음.

최신 origin/main에서 분리한 릴리스 후보는 전체 문서 검사 975개와 비밀값 검사 4,018개 파일을 통과했어. 기존 폴더에서 실패하던 _workspace/2026-08-01-002/summary.md의 누락 링크는 개인 작업 메모에만 있어 PR에는 포함하지 않았어.

저장소 반영 준비

이번 작업의 31개 파일만 codex/astra-agent-guidance-release 브랜치로 분리했어. 기존 임상 마스터 작업은 원래 폴더에 보존했고, 최신 main의 staging 폐기와 Production 승인 규칙도 유지했어. 원격 Release Check와 Preview 결과, 정확한 후보 커밋의 최종 승인 근거는 PR에서 확인하면 돼. 전역 AGENTS와 실험적 컨텍스트 설정은 저장소 밖이라 PR에 포함되지 않아.

새 작업에서 확인한 설정

모델과 추론 수준을 따로 지정하지 않은 새 작업에서 Astra / high / Default 실행과 부모 포함 5슬롯을 확인했어. 공식 하위 에이전트 한도는 부모를 제외한 4개로 유지하고, 이 데스크톱 런타임의 V2 슬롯값만 5로 맞췄어. 두 숫자가 세는 대상이 달라서 설정 주석과 작업 기록에 구분을 남겼어. 공식 설정 문서

Plan xhigh는 저장값을 확인했어. Codex 앱의 자동 조작 접근이 차단돼 실제 Plan 전환은 시험하지 못했어. 실제 에이전트 생성에 의한 한도 강제 적용도 미검증이야. LazyCodex의 기존 V2 비활성화 설정은 유지했고, 비활성화 값과 현재 런타임 사이의 내부 우선순위나 재시작 시 설정 덮어쓰기는 확인하지 않았어. 기존 작업에 소급 적용됐다고 주장하지 않아.

시나리오 검증은 로컬 분류 도우미를 실행한 결과이며 Astra 실사용 성능 평가가 아니야. 도우미는 승인이나 실행 권한을 부여하지 않아. 기존 임상 마스터 작업과 그 작업 중 새로 생긴 변경은 건드리지 않았고, 커밋·원격 작업·배포는 수행하지 않았어.
