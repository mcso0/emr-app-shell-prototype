GitHub/Vercel 릴리즈 자동화 계획 보고서

실제 Vercel/GitHub 설정을 변경하지 않고, 현재 설정을 점검한 뒤 PR preview, main fixed staging, production promote로 가는 목표 자동화 구조를 문서화했다.

완료현재 상태 점검

  • GitHub repo는 mcso0/emr-app-shell-prototype이고 기본 브랜치는 main이다.
  • GitHub Actions에는 Secret Scan과 Docs External Link Check만 있다.
  • Vercel 프로젝트는 로컬 .vercel/project.json과 연결되어 있다.
  • 최근 Vercel 배포는 대부분 Preview 환경이다.
  • fixed staging alias는 현재 preview deployment를 가리킨다.
  • GitHub branch protection/rulesets는 private repo 플랜/API 제한으로 CLI 확인이 막혔다.

완료자동화 목표

  • feature/PR branch push는 Vercel preview만 생성한다.
  • PR to main은 preview URL과 필수 체크를 제공한다.
  • main 병합 후에만 fixed staging 후보가 된다.
  • fixed staging은 main 또는 승인된 integration branch에서만 이동한다.
  • production promote는 자동화하지 않고 명시 승인으로 분리한다.

후속 실행 이슈 후보

  • 02-02 Configure Vercel Git integration and preview deployment checks
  • 02-03 Add CI workflow for PR and main checks
  • 02-04 Configure fixed staging from main only
  • 03-02 Production promote dry-run checklist

제외한 것

  • Vercel/GitHub 설정을 변경하지 않았다.
  • fixed staging alias를 변경하지 않았다.
  • production deploy/promote를 하지 않았다.
  • secret 생성, 저장, 회전 작업을 하지 않았다.

검증

  • npm run docs:check
  • npm run security:secrets
  • git diff --check
