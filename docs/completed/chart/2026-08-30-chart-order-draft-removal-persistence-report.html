삭제한 오더 후보가 다시 나타나는 저장 불일치 수정

2026-08-30 · 진료/차트 > Plan/Order · CHART-PR-027

행 누락을 삭제로 추정하지 않고 removedOrderIds로 삭제 의도를 명시했다. 삭제 대상은 서버 응답 전까지 삭제 중으로 남고, 성공 응답 후에만 사라진다. 실패하면 행과 의도를 유지하고 다시 저장할 수 있어, 삭제 직후 사라졌다가 서버 readback으로 복원되던 문제를 막았다.

사용자 경험

  • 단건과 일괄 후보 삭제에 동일한 확인 다이얼로그 적용
  • 저장 중·저장됨·저장 실패·충돌 상태를 표 하단에 상시 표시
  • 삭제 실패 시 행을 유지하고 다시 저장 제공
  • 오더 추가 성공은 로컬 반영 시점이 아니라 서버 저장 완료 후 안내

데이터 안전 경계

  • 같은 workspace·encounter의 미확정 루트와 미확정 세트 하위만 soft-cancel
  • 확정·Task·fulfillment·청구 연결 대상은 원자적으로 거부
  • 취소 사유와 행별 order_events 감사 이벤트 기록
  • 기존 클라이언트처럼 삭제 ID를 생략하면 누락 행을 삭제하지 않음
