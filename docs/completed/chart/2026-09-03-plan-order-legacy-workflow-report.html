1. 최종 판단

Plan/Order 전체 탭은 동적 합집합 컬럼 대신 승인된 25개 업무 컬럼을 고정 순서로 표시한다. 오더 초안·확정·수정·재확정·취소, 대상 담당자, 실제 조제량, fulfillment 업무 상태와 담당, 반려·재요청, 선청구 조정과 청구 검토 경계는 서버·DB 권한과 불변 이력 아래 연결됐다.

PR #698은 후보 2870d30594c8d367f1bffed2c29826042768b3a3에서 모든 필수 체크를 통과한 뒤 merge SHA f86ff1c31c6c288b5ba9697e5ad3902bd17f48ee로 origin/main에 반영됐다. Vercel 운영 배포 dpl_BekLknn1zHvZexMs2eniy4aSz5fG는 해당 merge SHA를 빌드해 Ready가 되었고 운영 별칭에 연결됐다.

2. 구현 내용

  • 화면 계약: 분류부터 수의사까지 정확한 25개 컬럼, 비적용 빈칸, 과거 미기록, 한국어 상태값, 담당자 표시를 기존 표 구조 안에 구현했다.
  • 작성·확정: 초안 저장, 계산 설명, 실제 조제량 override/reset, intended assignee, 수정·재확정·취소를 revision CAS와 idempotency key로 보호했다.
  • 업무 전달: 배정과 상태를 분리하고 requested/in-progress/paused/completed/returned/cancelled 시도 이력, handoff, 재요청을 서버 권한과 DB 제약으로 보장했다.
  • 청구: 임상 확정 snapshot과 청구 전용 override를 분리하고, 반려·취소·미완료·중복·음수 금액을 fail-closed 처리했다.
  • 권한·격리: workspace 범위, RLS, authenticated-only RPC 실행, 서버 산술, 감사 이벤트와 immutable history를 적용했다.
  • 마스터 transport: 승인된 값만 이동하며, Airtable에 없는 계산·조제·가격·과세·담당 정책은 생성하지 않고 null/unconfigured로 남긴다.
