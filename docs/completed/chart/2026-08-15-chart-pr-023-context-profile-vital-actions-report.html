CHART-PR-023 · Implementation Result

선택 환자의 맥락을 바로 확인하고 이어서 작업한다

환자와 보호자는 가벼운 미리보기 뒤 기존 상세 패널로 연결하고, 바이탈은 대기와 진료 중 화면에서 같은 입력 창과 권한 규칙을 사용하도록 통합했다.

핵심 서버 계약 11/11 통과 2026-08-15 Additive migration

무엇이 달라졌나

실제 프로필 미리보기

선택 encounter에 이미 포함된 환자·보호자 데이터만 사용한다. 주소, 생년월일, 식별정보, 동의 토큰은 노출하지 않는다.

기존 상세 패널 연결

클릭, Enter, Space, 터치로 기존 URL 기반 환자·보호자 패널을 연다. 보호자가 없으면 실행 요소 자체를 만들지 않는다.

공용 바이탈 입력 창

대기 화면의 입력 로직을 ChartVitalDialog로 분리해 진료 중 헤더에서도 같은 필드, 검증, 저장·비움 규칙을 쓴다.

이중 권한 검증

클라이언트는 상태와 서버 계산 권한을 함께 보고, API와 새 RPC가 workspace, actor, permission, 직군, encounter/queue 상태를 다시 확인한다.

공용 컴포넌트 경계

  • EmrPatientContextBar는 선택적 interaction 계약과 접근 가능한 표시만 소유한다.
  • 데이터 조회, 프로필 store hydrate, URL drawer, 저장 권한과 API 호출은 chart 기능에 남긴다.
  • 조제·검사·영상·처치는 interaction을 전달하지 않으므로 기존 표시 전용 동작을 유지한다.

데이터·보안 경계

  • 새 writer: clair_upsert_chart_encounter_vitals
  • 허용 상태: waiting + waiting, in_consultation + in_progress
  • 기존 clair_upsert_waiting_encounter_vitals는 waiting 전용으로 유지
  • 고정 empty search_path, schema-qualified relation, authenticated-only 실행

원격 migration은 연결 대상이 synthetic/demo임을 확인한 뒤 적용한다. production smoke에서는 바이탈 값을 저장하지 않는다.
