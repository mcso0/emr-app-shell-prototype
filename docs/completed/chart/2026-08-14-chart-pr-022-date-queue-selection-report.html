CHART-PR-022 · Implementation Result

날짜와 차트가 어긋나지 않게 동기화했다

선택 날짜를 진료 대기열, URL, 환자 헤더, 차트 본문의 단일 기준으로 만들었다. 업무가 있으면 첫 차트를 바로 열고, 업무가 없으면 이전 날짜 차트를 남기지 않는다.

집중 회귀 7/7 통과 전체 차트 exit 0 2026-08-14 API·DB·권한 변경 없음

무엇이 달라졌나

업무가 있는 날짜

유효한 직접 링크가 있으면 유지하고, 없으면 서버 정렬의 첫 업무를 자동 선택한다. 최초 진입에서 엠티 상태가 잠깐 보이지 않는다.

업무가 없는 날짜

이전 encounter와 URL 파라미터를 즉시 지우고, 선택 날짜가 포함된 빈 상태만 보여준다. 차트 헤더와 실행 버튼도 함께 숨긴다.

로딩·실패·권한

로딩은 접근 가능한 Skeleton 상태로, 읽기 실패와 권한 거부는 별도 복구 상태로 표현한다. 세 상태를 빈 대기열로 오인하지 않는다.

패널이 접힌 경우

항상 마운트되는 coordinator가 조회와 선택을 담당해 좌측 패널이 닫혀 있어도 직접 링크와 자동 선택이 작동한다.

선택 순서

1. 선택 날짜의 유효한 URL encounter
2. 같은 날짜의 유효한 현재 선택
3. 서버 정렬 첫 업무
4. 업무가 없으면 선택 없음

변경 범위

  • src/features/chart/store.ts: workspace별 날짜와 queue scope 상태
  • src/features/chart/module.tsx: coordinator, URL 정규화, 로딩·날짜별 빈 상태
  • tests/chart.spec.ts: 초기 선택, 직접·stale 링크, 날짜 전환, race, 오류·권한 회귀
  • CHART-PR-022 작업 문서, 화면 상태 spec, current status와 work index

SOAP·진단·Order 저장, 진료 완료, API 응답, DB, Supabase, RLS, 권한은 변경하지 않았다. 작성 중 보호도 기존 차트 이동 규칙을 유지한다.
