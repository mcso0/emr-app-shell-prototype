최종 Figma 구현 보고서의 화면·상태·간격을 반영하고, workspace 진단 카탈로그를 사용자 범위 캐시와 커서 검색으로 읽으며 복수 주진단을 순서대로 저장할 수 있는 로컬 후보를 완성했다.

UI 구현

정확한 모달 구조

데스크톱 1120 × 680, 헤더 56px, 푸터 64px, 섹션 여백 16px과 1:1:2:2 열 비율을 적용했다. 계통·질환 목록은 기존 탐색 행을 34px 높이로 사용한다.

진단명 검색 상태

평상시 검색 아이콘은 헤더 오른쪽에 위치한다. 열면 제목·개수 대신 최소 148px 검색 필드가 표시되고 검색결과 개수는 노출하지 않는다.

선택 행 인터랙션

드래그·키보드 순서 변경, 복수 ghost 주진단, 확진·감별·의심 선택을 지원한다. hover/focus한 한 행에서만 흰색 그라데이션 위 outlined 휴지통 버튼이 나타난다.

상태와 완료

진단명 기본·hover·선택·비활성 상태, 빈 결과·읽기 오류·권한 없음·로딩을 분리했다. 선택 항목이 있을 때만 선택 완료가 활성화된다.

실제 DB 읽기와 속도 전략

  • 화면은 기존 chart/diagnosis-catalog route와 clair_search_diagnosis_catalog RPC가 반환한 계통, 질환 구분, 진단명을 그대로 사용한다.
  • 첫 50건과 facet을 actor + workspace 키로 메모리 캐시하고 같은 요청은 한 Promise로 합쳐 중복 fetch를 막는다.
  • nextCursor = null이면 클라이언트 메모리에서 즉시 필터링한다. 더 큰 카탈로그만 150ms debounce, AbortController, request sequence, 커서 append를 사용한다.
  • 새 요청 동안 기존 결과를 유지해 목록 깜박임을 줄인다. 권한/멤버십/세션 거부가 오면 해당 actor-workspace 캐시를 폐기한다.
  • route의 chart:view 확인과 RPC workspace 범위는 그대로 유지하며 private master DB를 브라우저에 직접 노출하지 않는다.

복수 주진단 저장 계약

클라이언트의 단일 선택 강제와 서버 입력 거부를 제거했다. 로컬 migration은 encounter별 unique partial index를 비고유 ordered index로 바꾸고 최신 clair_save_chart_diagnoses의 단일 주진단 제약만 제거한다. 기존 권한, encounter 잠금, catalog snapshot, audit before/after, sort_order 계약은 보존한다.

migration 20260825133000_chart_multi_primary_diagnoses.sql은 로컬 파일만 생성했다. 실제 원격 DB에 적용하기 전 별도 승인과 exact-candidate 재검증이 필요하다.
