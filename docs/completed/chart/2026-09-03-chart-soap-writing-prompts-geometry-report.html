CHART-PR-034 · 2026-09-03 · PR #703

SOAP를 바로 쓰기 시작하고
블록 컨트롤은 겹치지 않게

새 UI나 기능을 추가하지 않고, 기존 BlockNote 문단에 편집 가능한 작성 단서를 넣고 플러스·그랩·가이드선의 충돌을 제거했다.

4S/O/A/P 작성 안내 문단
24×24플러스·그랩 타깃
8px컨트롤과 본문 간격
47/47집중 자동화 통과

1. 무엇을 바꿨나

  • 작성 시작: 새 차트, SOAP 초기화, 슬래시 메뉴의 기본 SOAP 템플릿이 동일한 S/O/A/P 작성 단서를 실제 paragraph 내용으로 제공한다.
  • 기존 에디터 유지: soapSection 4개와 각 섹션의 paragraph 1개, 기존 편집·서식·드래그·자동저장·수동저장 동작을 그대로 사용한다.
  • 겹침 제거: SOAP 섹션의 첫 입력 블록에만 생기던 중첩 가이드선을 숨겼다. 사용자가 만든 더 깊은 중첩 블록의 가이드선은 유지한다.
  • 조작 면적: 16px이던 그랩 폭을 24px로 넓히고 플러스와 동일한 높이·폭으로 맞췄다. 메뉴의 오른쪽 끝과 본문 사이 8px 간격은 유지했다.

2. 새 기본 작성 문구

구역실제 편집 가능한 시작 문구
S[주호소와 시작 시점] [빈도·지속시간·악화/호전 요인] [식욕·음수·배뇨·배변·활력 변화] [보호자가 오늘 확인하고 싶은 점]
O[체중·체온·심박·호흡·BCS] [이상 소견] [관련 정상 소견] [검사·영상 결과 또는 결과 대기]
A[문제명과 상태] — [가장 가능성 높은 판단과 근거]. DDx: [핵심 감별 1–3개]. [추가 확인이 필요한 점]
P[검사와 이유] [치료·처방] [보호자 설명 및 동의·보류] [결과 연락·재진 시점·즉시 내원 기준]

확인하지 않은 WNL, “이상 없음”, 정상 판단은 미리 넣지 않았다. 이 문구들은 화면에만 보이는 가상 placeholder가 아니라 실제 편집 문단이므로, 수의사가 삭제하거나 진료 내용으로 덮어쓴 뒤 저장하는 형태다. 그대로 둔 채 저장하면 SOAP 내용으로 저장될 수 있다.

3. 조사 근거

수의 진료기록의 S/O/A/P 내용, 문제 목록·감별·진단/치료 계획, 보호자 소통 기록을 빠뜨리지 않도록 짧은 단서로 압축했다.

  • University of Wisconsin Veterinary Medical Teaching Hospital · SOAP Writing Guide
  • University of Minnesota · Client Encounters
  • College of Veterinarians of Ontario · Medical Records Guide
  • Australian Small Animal Veterinarians · Hospital Standards

4. 검증 결과

  • SOAP 문서 단위 테스트 8/8 통과: 새 문구, 기존 기록 보존, 정상 소견 선입력 금지.
  • SOAP 에디터 Storybook 상호작용 35/35 통과: 편집, 플러스·그랩, 메뉴, 드래그, 가이드선, 320/420/566.5/720px.
  • 실제 차트 SOAP 집중 회귀 4/4 통과: 단일 문서, 선택 툴바, 슬래시 메뉴·템플릿, 긴 내용 레이아웃.
  • 렌더 좌표 확인: 플러스 24×24px, 그랩 24×24px, 본문 간격 7.75px(서브픽셀 반올림), SOAP 첫 문단 가이드 0px.

5. 변경 범위와 남은 확인

변경 파일은 SOAP 문서 기본값, BlockNote 템플릿 팩토리, 에디터 CSS, Storybook 회귀, 문서 단위 테스트와 작업 기록이다. DB·API·RPC·권한·저장 포맷·감사·진단계통 전용 템플릿은 변경하지 않았다.

로컬 구현 검증 후 PR #703의 최종 커밋을 대상으로 전체 릴리스 게이트와 프로덕션 smoke를 수행한다. 운영 문제가 생기면 직전 production 배포로 애플리케이션을 되돌리며 DB 롤백은 필요 없다.
