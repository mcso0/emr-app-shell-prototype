WORKSPACE-TABS-PR-002 / 2026-06-25

탭별 업무 Surface 독립화

워크스페이스 탭이 모듈 이름만 나누는 수준을 넘어, URL query의 실제 업무 surface 기준으로 복원되고 중복 감지되도록 정리했다.

Status: Human Review

핵심 변경

  • 새 업무 탭은 현재 화면 복제가 아니라 /w/:workspaceId/home?modulePanel=open에서 시작한다.
  • 진료/차트, 조제/처치, 검사, 영상, 수납 선택은 각각 route query에 구체 surface ID를 남긴다.
  • 중복 경고는 module-only 탭이 아니라 같은 encounterId, labResultId, imagingStudyId, invoiceId에만 반응한다.
  • 비활성 탭 preview는 현재 전역 선택 store가 아니라 해당 탭 route metadata에서 환자 맥락을 계산한다.

사용자 관점

  • 초코 차트 탭과 구름 차트 탭처럼 서로 다른 encounter를 동시에 열 수 있다.
  • 환자나 차트가 아직 선택되지 않은 진료/차트 탭을 하나 더 여는 것만으로는 중복 안내가 뜨지 않는다.
  • 같은 차트나 같은 검사/영상/수납 작업을 다른 탭에서 다시 열 때만 기존 탭 이동 안내가 뜬다.

명시적 비범위

  • DB, migration, 서버 세션 스키마는 변경하지 않았다.
  • 완전한 component keep-alive나 전역 store의 탭별 인스턴스 분리는 포함하지 않았다.
  • SOAP 충돌 방어 범위는 PR-001의 기존 구현을 그대로 유지했다.

검증 증거

  • ./node_modules/.bin/tsc --noEmit 통과.
  • npm run docs:check 통과.
  • 변경 파일 대상 eslint error 0, 기존 chart hook warning 1개.
  • App Shell workspace tabs focused Playwright 6개 통과.
  • 검사/영상 URL surface 회귀 Playwright 2개 통과.
  • 수납 URL surface 회귀 Playwright 1개 통과.
  • workspace tabs server-session Playwright 4개 통과.
  • SOAP note persistence server Playwright 7개 통과.

남은 리스크

이번 변경은 URL을 탭별 source of truth로 삼는 1차 독립화다. 전역 store 자체를 탭별로 완전히 분리하거나 inactive DOM을 보존하는 작업은 후속 PR에서 별도 범위로 다루는 것이 안전하다.
