지금 준비된 것

CBC를 구성할 하위 오더 26개와 결과 정의를 만들었다. 기본 수치 20개, 선택 수치 5개, 수기 혈액도말 1개다. ProCyte Dx 공개 자료를 사용한 개·고양이 프로필 2개와 별도 CLAiR 데모 프로필 2개, 수기 프로필 1개를 준비했다.

이번 산출물은 비적용 후보다. 실제 마스터·병원관리·차트·DB는 수정하지 않았다. 조사 상태와 오더 사용 상태도 분리했다. 후보는 active / not_clinically_validated이며 검수 대기로 두지 않았다.

기본 항목과 선택 항목의 구분은 이번 프로토타입을 위한 제안이다. 모든 병원의 CBC 구성을 규정하지 않는다. 제조사의 수치 항목 목록과 Cornell의 자동 CBC·도말 포함 CBC 구분을 참고했다. nRBC와 BAND의 의심 표시는 별도 장비 플래그로 남긴다. 이를 실제 세포수처럼 입력하지 않는다. IDEXX 검사 항목, Cornell 혈액검사 구성

세트는 적혈구계·백혈구계·혈소판계의 하위 세트를 포함한다. 망상적혈구 세트와 선택 항목도 연결돼 있다. 한 요청에 같은 항목이 여러 번 포함되면 한 번만 생성하고 포함 경로를 보존한다. 별도로 요청한 재검은 합치지 않는다.

확보한 값과 남겨 둔 예외

데모값에는 상용 장비 이름을 붙이지 않았다. 공개 범위가 있는 항목은 하한을 0.9배, 상한을 1.1배 한 뒤 지정 소수점에서 하한은 내림하고 상한은 올림한 범위를 사용했다. 비율과 고양이 PDW는 별도 합성 규칙을 JSON에 명시했다. 이 값들은 임상 판단용이 아니다. 프로필을 선택하지 않으면 다른 프로필로 대체하지 않는다.

후보값 확인

HTML 보고서에서는 프로필을 선택해 각 항목의 단위·범위·판별을 확인할 수 있다. 기본 결과값은 비어 있다. 데모 예시 채우기는 사용자가 눌렀을 때만 동작하며 저장이나 DB 요청을 하지 않는다. 독립 항목별 경계 테스트와 한 검체의 일관된 결과 예시는 구분했다.

프로필을 선택하면 해당 단위와 범위를 표시해요.

입력과 판별

숫자 0은 값이고 빈칸은 미입력이다. 잘못된 숫자, 음수, 단위·동물종 불일치는 따로 표시한다. 범위의 하한·상한을 포함하면 정상으로 보는 규칙은 이번 후보의 제품 규칙이다. 화면 반올림 전에 입력값으로 판별한다.

장비가 값을 내지 못한 경우, 의심 플래그가 붙은 값, 부등호가 붙은 결과는 정상·미달·초과로 단정하지 않는다. 원본 표시를 보존하고 판별 보류 사유를 함께 보여준다. 표시 가능 범위, 분석 성능 범위, 정상범위도 서로 바꾸어 쓰지 않는다. IDEXX 사용 설명서, 46·50–51쪽

검체는 EDTA 전혈로 기록했다. 설명서의 마이크로튜브 최소량은 본문과 부록에 차이가 있어 공통 기본값으로 확정하지 않았다. 표준 튜브의 최소량을 채혈 목표량처럼 사용하지도 않는다. IDEXX 검체 안내, 32–33·51쪽

결과 확정 및 담당자·수행 시각 기록 새 결과 저장, 기존 값은 유지

WBC만 요청할 수 있어도 실제 장비는 여러 항목을 함께 측정할 수 있다. MCH·MCHC 같은 계산값은 기초 측정값이 필요하다. 필요한 측정은 같은 검사 시도의 근거로 연결하며, 이를 임의의 추가 주문이나 청구로 만들지 않는다. 기초값이 없을 때 이전 검사값을 가져와 계산하지 않는다. Cornell 개별 검사 안내, 계산 지수 설명

요청·결과·검체·프로필은 별도 ID로 연결한다. FHIR의 요청과 관찰 구조를 참고했지만 FHIR 연동을 구현한 것은 아니다. 재검 연결을 기존 요청을 대체한다는 의미의 replaces로 자동 매핑하지 않는다. FHIR ServiceRequest, FHIR Observation

기존 ID와 화면 표시

WBC·HCT·PLT 오더, 기존 망상적혈구 비율 오더와 혈액도말 오더의 ID를 유지하는 후보를 만들었다. 기존 RETIC은 단위가 %이므로 절대수로 의미를 바꾸지 않았다. RBC·HGB 결과 정의도 유지한다. 신규 후보는 오더 21개, 결과 정의 19개다. 과거 결과나 세트 구성을 덮어쓰는 backfill은 하지 않았다.

병원관리에는 핵심 구성·검체·기본 수행 프로필·단위·범위 요약을 표시한다. 차트는 워크스페이스에서 정한 값을 사용하고 환자별 수정값을 별도로 남긴다. 결과 화면은 항목·결과·단위·판별·정상범위·담당자를 중심으로 구성한다. 장비 이름 옆에는 수동 입력·연동 안 됨·합성 출처와 버전을 보여준다. 여기까지는 화면에 무엇을 표시할지 정한 계약이다. 실제 앱 구현은 다음 단계에서 진행한다.

검증과 다음 작업

로컬 테스트 10개가 통과했다. 837개 수치 분기를 재현했고, 개·고양이의 일관된 CBC 예시 2개를 확인했다. 세트 중첩·중복·순환 거부, 프로필 미선택·오입력, WBC 단일 재검, 기존 결과와 프로필 복사본 보존도 검사했다. 이 검증은 임상 검증이나 실제 앱·DB 통합 테스트가 아니다.

별도 HTML 브라우저 테스트 1개도 통과했다. 프로필 선택, 예시 입력, 판별 변화, 내부 링크, 데스크톱·모바일 화면 넘침을 확인했다. 전체 문서 검사에는 기존의 다른 문서에서 깨진 링크 1건이 남아 있다. 이번 보고서와 관련된 링크 검사는 통과했다.

다음은 OED-LAB-03 — 이 후보를 현재 코드·DB가 어떻게 저장하고 전달할지 읽기 전용으로 조사하는 작업이다. 마스터 오더·세트 관계, 워크스페이스 수정값, 차트 확정본, 결과 프로필, 검체, 재검 이력을 필드 단위로 대조한다. 원격 접근이 안 되면 그 부분을 미검증으로 남긴다.

이후 변경 범위·migration·backfill·rollback 계획을 작성한다. 가격과 부분 재검 청구 정책은 아직 확정하지 않았다. 실제 장비 연동, CBC 외 검사군 정밀 조사, 마스터·DB 적용은 이번에 진행하지 않았다.
