이번 결과

이름에 포함된 단어로 분류를 추정하던 코드를 제거했다. 저장된 오더 유형을 기준으로 상위 카테고리를 정하고 세부 분류가 불분명한 오더도 각 카테고리의 전체 목록과 분류 확인 필요 목록에서 찾도록 했다.

병원관리 테이블은 카테고리별 핵심 항목을 고정해 보여준다. 값이 없다고 열을 없애지 않고 미설정으로 표시한다. 상세창도 같은 핵심 값과 누락 개수를 보여준다. 핵심 값 입력 여부는 임상 검수나 차트 확정 가능 여부를 뜻하지 않는다.

분류를 지운 것은 아니다

병원관리 조회 응답에는 분류 ID가 있지만 그 ID가 어떤 세부 분류인지 해석하는 정보가 없다. 이 경우 세부 분류 확인 필요로 표시한다. 값 자체가 없는 미설정과 구분하며 원래 저장된 분류 ID는 수정하지 않는다. CBC라는 이름만으로 CBC 세부 분류를 만들어 넣거나 조제 출처만 보고 주사 오더로 분류하지 않는다.

검증

기존 82개에 새 분류·표시 테스트 24개를 더해 106개가 통과했다. 수정 파일 린트도 통과했다. 테스트는 합성 데이터로 수행했으며 원격 DB나 로그인 화면을 조작하지 않았다.

독립 검토에서 잘못된 오더 유형이 정상 유형으로 추정되는 문제를 발견해 차단했다. 저장된 유형이 잘못된 응답은 조회 실패로 처리한다.

전체 타입 검사는 기존 @blocknote/* 의존성 누락과 관련 오류로 실패했다. 이번 수정 파일의 타입 오류는 남아 있지 않다. 문서 검사에는 기존 persona-qa 누락 링크가 남아 있다.

남은 작업

Slice 03은 진행 중이다. 실제 세부 분류 조회 연결과 로그인한 화면 검증은 아직 끝나지 않았다. 일부 세부 분류 목록은 비어 보일 수 있으며 해당 오더는 상위 카테고리의 전체 목록에서 확인한다. 원격 DB·마스터 데이터·배포는 변경하지 않았다. 기존 작업 파일도 보존했다.

바로 다음

분류 ID에 대응하는 실제 세부 분류 정보를 병원관리에서 읽도록 연결한다. 이를 마친 뒤 테이블·상세창·API의 분류 일치를 확인하고 Slice 04로 넘어간다. Slice 04는 병원관리 오더와 차트 검색 후보의 ID·대상 조건·기본값을 비교하는 작업이다. 분류를 확인하기 위해 임시 목록이나 이름 추정으로 되돌아가지 않는다.
