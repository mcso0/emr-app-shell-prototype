대상·예외·신규 가격 승인 · PR과 배포 검사 준비

병원관리의 기본값이 차트와 실제 수행 기록까지 이어지도록 연결했습니다. 정상 반영, 실패 시 되돌리기, 재실행을 로컬에서 검증했습니다. 실제 서버 적용과 운영 배포는 아직 하지 않았습니다.

원본 522개를 모두 대조했습니다

522 − 기존 대체 항목 51 + 새 항목 53 = 후보 524

새 항목은 조제 제품 19개와 개별 검사 오더 34개입니다. 기존 51개는 삭제하지 않고 앞으로의 선택만 중단할 계획입니다. 과거 처방과 병원별 수정값은 보존합니다.

대체 제품은 명시한 합성 오더 정의입니다. 기존 항목과의 임상적 동등성을 의미하지 않습니다.

무엇이 연결됐나요?

영역이번에 연결한 내용
병원관리·차트저장 데이터 조회, 병원별 응답 구분, 기본값 상속·수정·초기화·충돌 해결. 실패한 조회를 예전 목록으로 숨기지 않습니다.
조제·처치조제 127개와 처치 111개 정의. 계획과 실제량을 나누고 수행자·시간·수정 이력을 기록합니다.
검사원본 86개를 개별 실행 오더 90개와 중첩 구성 35개로 정리했습니다. 결과 프로필 24개, 병원별 정상범위 버전, 판별·재검사·과거 결과 보존을 연결했습니다.
영상30개 정의와 실제 결과 기록. 기존 CT 판독과 새 촬영을 구분하며 실제 촬영시간을 임의로 만들지 않습니다.
입원·상담·기타·계통검사136개 정의. 입원은 등록된 위치와 기존 처치 업무 흐름을 사용합니다. 차트 기록은 수행시간과 실제 내용을 직접 확인해야 확정됩니다.

검사 구간은 합성 기능검증용이며 임상 정상범위가 아닙니다. 실제 장비 연동은 없습니다. 실제 진료에 사용할 수 있다는 검증도 하지 않았습니다.

어디까지 확인했나요?

계약 테스트 203개, 게시 API 호환 테스트 35개, 후보·설정·보고서 테스트 93개를 통과했습니다. 배포용 작업 폴더에서 타입·문서·비밀정보 검사와 빌드도 통과했습니다. 앞서 화면 테스트 14개와 별도 검사 화면 2개를 확인했습니다.

통합 DB 테스트는 새 마이그레이션 18개와 기존 선행 마이그레이션 1개를 포함했습니다. 병원마다 선택 가능한 후보 524개, 기존 51개의 선택 중단, 새 항목 53개의 가격을 확인했습니다. 장비 9개, 프로필 연결 519개, 검사 묶음 90건도 검증했습니다. 정상 반영·실패·재실행을 시험한 뒤 모두 되돌렸습니다.

화면 테스트는 모의 API를 사용했습니다. 실제 로그인한 배포 환경 검증이나 전체 동시 실행 경합 검증은 아직 하지 않았습니다. 최종 후보의 필수 검사는 문구·문서 정리 후 다시 실행합니다.

실제 서버는 아직 바꾸지 않았습니다

원격 DB를 조회해 clair-demo, workspace-clair-cheongdam, workspace-clinical-master-pilot-v1에 원본 마스터 522개씩 연결된 것을 확인했습니다. 이 세 곳을 적용 대상으로 승인받았으며 clair-foreign-demo는 변경하지 않습니다. 수동 검사 프로필, 부모 항목만 청구, 재검 기본 비청구도 승인됐습니다.

기존 프리셋 471개의 ID와 이력을 보존합니다. 검사 69개씩, 총 207개의 ID도 반영 전에 고정합니다. 갱신 검토 항목이 없어 15개가 이전 버전에 남던 문제를 수정했고, 검사 연결·과거 결과·기존 알림·읽음 상태·다른 병원 자료를 보존하는 검사를 통과했습니다.

승인받은 예외와 신규 가격

기존 약품 108개는 보호 규칙을 유지하면서 합성 데모에서 선택·확정합니다. DB 상태는 pending_activation이며 임상 승인이 아닙니다. 새 합성 프로필과 카탈로그 연결을 함께 갱신하는 검증을 마쳤고, 과거 프로필과 임상 리뷰는 보존합니다.

파일럿 병원의 metabolic 검사 묶음 하나는 기존 비청구를 유지하고 다른 89건은 부모 가격을 유지하기로 승인받았습니다. 같은 병원의 기존 초진 상담도 가격과 비청구 상태를 보존합니다.

새 항목 53개에만 종류별 합성 데모 가격을 정했습니다. 조제 19개는 건당 7,000~45,000원, 개별 검사 34개는 5,000~20,000원입니다. 알약·용량별 단가나 실제 병원 견적이 아닙니다. 기존 가격이나 검사 묶음의 부모 청구 정책은 바꾸지 않습니다.
