1. 최종 판단

기존 510개 마스터 오더와 새로 정의한 12개 계통별 신체검사 오더를 합쳐 522개 오더 모두에 정확히 하나의 현재 실행 프리셋이 존재한다. 최종 게시 입력은 689개 레코드 / 522개 오더이며 고정 산출물 SHA-256은 1eeb5035d70d5f28035df49d1d32c3689ffe79a4bb28062e5606256802572e0c다.

병원은 워크스페이스 복사본을 수정하거나 사용 중지할 수 있다. 수정하지 않은 복사본은 마스터 개정에 자동 동기화되고, 수정한 복사본은 덮어쓰지 않고 검토 대상으로 남는다. 필수값이 비어 있으면 확정을 막고, 확정된 유효 세부값은 이후 마스터·워크스페이스 변경과 무관하게 보존된다. system_exam은 차트에서 완료되고 fulfillment queue로 전달되지 않는다.

모든 프리셋은 synthetic_unreviewed, clinicalUseAllowed=false다. 기술 후보가 완성됐다는 뜻이지 임상 승인 또는 실제 진료 활성화를 뜻하지 않는다.

승인된 원격 Supabase에는 PR-022 migration 6개가 적용됐다. 689-record publish는 두 번 모두 약 120초 뒤 Cloudflare 524로 종료됐지만, 10:19:53 UTC 권위 SQL readback으로 두 번째 호출도 완전 rollback됐음을 확인했다.

새 performance migration은 정확한 510/108 기준 DB에서 중앙값 5.703초를 3.136초로 약 45.0% 줄였고, cold 3회 모두 60초 gate를 통과했다. 원격 적용은 별도 승인 대상이다.

current-main 최종 호환 migration은 상담 담당자 정규화, billing summary, Realtime, 선행 권한 검사를 한 transaction에 보존하며 독립 재심사 High/Medium/Low 0/0/0 LOCAL APPROVE를 받았다.

  1. 모든 적용 대상 마스터 오더가 버전이 있는 실행 프리셋을 보유한다.
  2. 워크스페이스 채택 시 오더와 세부 기본값을 함께 복사한다.
  3. 병원은 복사본을 수정하거나 사용 중지할 수 있다.
  4. 사용자가 수정한 값은 다음 마스터 채택에서 자동 덮어쓰지 않는다.
  5. 차트 초안은 유효 프리셋 값을 자동 입력한다.
  6. 환자·담당자·장소처럼 마스터가 알 수 없는 값은 runtime 또는 workspace에서 해석한다.

5. 구현 내용

공통 마스터 프리셋

master.order_execution_presets와 current pointer에 preset/order revision, clinical type, schema version, defaults, field policies, provenance, review/activation state, canonical hash, source artifact와 release lineage를 저장한다. 버전 update/delete, unknown field, enum·schema·hash 불일치, 동일하거나 낮은 revision을 fail closed 처리한다. 현재 publisher는 synthetic_unreviewed와 clinicalUseAllowed=false만 허용해 payload가 임상 검토 증거 없이 스스로 승격할 수 없다.

필드 소유권

값은 encounter/runtime → workspace override → master preset → schema default → 사용자 입력 순으로 해석한다. 정책은 preset_fixed, derived_from_profile, schema_default, workspace_resolved, runtime_resolved, required_manual, not_applicable다. 장비·외부기관·병동·케이지·가격은 중앙 마스터가 소유하지 않으며 담당 수의사는 actor가 아닌 encounter 주치의에서 해석한다.

게시·채택

  • publisher의 executionPreset envelope와 canonical hash를 검증해 immutable master version으로 투영한다.
  • 689개 payload를 정확한 allowlist workspace에만 채택한다.
  • 재게시·재채택은 idempotent하며, 생략된 기존 lab dependency revision도 보존한다.
  • lab conflict counter는 실제 insert가 발생했을 때만 증가한다.
  • 기존 조제 nested default와 새 generic default를 호환한다.

워크스페이스 관리

병원관리 drawer에서 타입 스키마에 맞는 세부 기본값을 확인·수정·사용 중지한다. partial edit는 가격·조제·백신 metadata를 지우지 않는다. CAS revision을 강제하고 stale revision은 40001로 거부한다. 사용자 수정은 customized와 변경 필드를 기록하며, 다음 채택은 값을 보존하고 review 행을 만든다. 사용 중지는 order_catalog.paused / pause 감사 이벤트로 남는다.

차트와 snapshot

개별 오더와 Order Set child 모두 유효 기본값을 초안에 복사한다. 상담 담당자는 encounter 주치의로 해석하며 없으면 임의 actor를 넣지 않는다. required/unknown field 검증 후 확정하고, 확정 오더·fulfillment source·billing candidate는 당시 snapshot을 유지한다. system_exam queue projection은 서버가 fail closed로 버린다.

보안 경계

master preset은 RLS enabled이며 client role에 직접 공개하지 않는다. private publisher/adopter/project/sync와 내부 chart draft base RPC execute를 회수했다. catalog writer와 master-update resolver는 역할 label이나 TypeScript 선검사에 의존하지 않고 DB에서 service_catalog:manage를 다시 확인한다. 차트 runtime read는 chart:update preflight 뒤에만 실행한다. security-definer 함수는 빈 search_path, workspace/actor permission, CAS와 audit를 유지하고, candidate-only backfill 감사 324건은 재적용에도 증가하지 않는다. current preset identity 교체와 activated/source release 불일치도 거부한다.

사용자 수정 보존

청담의 복부 방사선 프로토콜을 청담 워크스페이스 복부 촬영 프로토콜로 수정하고 사용 중지했다. revision 1 → 2 → 3, customized, 변경 필드 defaultDetailInputs·availabilityStatus와 order_catalog.paused / pause 감사 이벤트가 기록됐다. 재채택 뒤 수정값·revision·paused 상태는 그대로였고 pending review가 생성됐다.

재적용·권한·음성 게이트

6개 PR-022 migration 재적용이 통과했고 backfill 감사 행은 324개를 유지했다. default/resolver가 모두 없는 required field와 current preset identity 교체는 23514, stale CAS는 40001, immutable preset update는 55000으로 거부됐다. master 직접 접근과 private/internal writer execute도 client role에 거부된다.

hospital_admin 역할을 유지한 채 permission assignment에서 service_catalog:manage를 제거한 격리 트랜잭션에서는 master-update accept_source와 dismiss가 모두 42501로 거부됐다. 트랜잭션 rollback 뒤 원래 assignment와 감사 324건이 그대로임을 확인했다.

과거 실행 데이터

orders, order_confirmation_commands, order_fulfillment_work_items, order_tasks, order_billing_candidates는 모두 0을 유지했다. 게시·채택 리허설이 확정·실행·청구 데이터를 만들거나 수정하지 않았고 snapshot 불변은 집중 테스트로 별도 검증했다.

Publisher timeout 원인 조사와 성능 구현

두 번째 호출은 동일 semantic JSON을 1,443,553 bytes로 줄였어도 같은 120초 timeout에 도달했다. 정확한 510-order / 108-preset 기준선을 별도 Supabase DB에 복원하고 689-record payload를 실행해 함수별 시간을 수집했다.

  • 한 publish의 fan-out은 535개 master version, 522개 preset/current projection, 1,070개 review event, 689개 manifest row다.
  • canonical payload를 두 번 정규화해 약 1.86초를 사용했다.
  • preset 계약 검증은 2,610회, detail schema 생성 체인은 5,220회 호출됐고 누적 약 4.45초와 4.24초였다.
  • 522 × 86 profile 반복 탐색은 cumulative publisher에서 발생한다. projection trigger가 profile 집합을 탐색한다는 이전 설명은 잘못이므로 정정한다.

20260831103000_clinical_master_publisher_performance.sql은 공개 signature, diagnosis dispatch, ACL/RLS, advisory lock, fingerprint, manifest, trigger와 단일 transaction을 유지하면서 측정된 중복만 제거한다.

  1. preset 계약 검증에서 이미 만든 detail schema를 입력 helper에 전달해 한 번만 생성
  2. outer publisher가 canonical payload SHA-256을 transaction-local marker로 전달
  3. cumulative core는 marker와 payload SHA가 정확히 같을 때만 두 번째 canonicalization 생략
  4. 직접 호출·hash 불일치에는 기존 canonicalization fallback 유지
  5. 더 큰 bulk writer/statement-trigger 재작성은 60초 gate 통과에 불필요해 범위에서 제외

9. 변경 범위

기존 기능 범위에 로컬 publisher performance migration, current-main 상담/billing/Realtime 최종 호환 migration, 두 rollback-only rehearsal과 집중 spec을 추가했다. 기존 확정 기록·fulfillment DML, Airtable, Vercel, dependency version은 변경하지 않았다. 원격 Supabase에는 기존 migration 6개와 publisher 2회만 실행됐고 새 migration과 adoption은 실행하지 않았다.

10. 현재 차단 조건과 재개 계획

  6. 성공 뒤에만 adoption, advisor, 인증 브라우저 smoke 진행

“지금 원격 병원에서 바로 임상 사용 가능한가?”에 대한 답은 아니오다. 성능 candidate는 로컬 격리 검증을 통과했지만 아직 원격 적용·게시 승인을 받지 않았다. 새 exact SHA 승인, 원격 publish/adoption 검증과 임상 검토가 남아 있다.
