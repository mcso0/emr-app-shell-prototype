이번에 바뀐 것

01 · 오류를 구분

조회 실패와 오더 0개는 다르다

DB 조회 실패를 성공한 빈 목록으로 돌려주던 코드를 제거했다. 인증, 권한, 버전 충돌, 응답 오류, 조회 장애를 구분한다. 정상 조회 결과가 0개라면 그대로 빈 목록을 반환한다.

02 · 임시 카탈로그 차단

실패 후 다른 목록을 읽지 않는다

다른 테이블로 재조회하는 경로와 요청 처리 함수의 자동 가짜 카탈로그·권한 생성을 제거했다. 병원관리 오더 API는 임시 세션 헤더를 실제 로그인으로 인정하지 않는다.

03 · 같은 오더인지 확인

ID가 없거나 서로 다르면 거절한다

차트 검색 응답과 스냅샷의 오더 ID, 마스터 프리셋 ID·버전이 충돌하면 응답을 실패로 처리한다. 병원관리 응답에 다른 워크스페이스의 오더가 섞여도 거절한다.

04 · 저장 전 확인

조회 실패 뒤에 저장하지 않는다

차트 저장 전 카탈로그 조회 권한을 확인한다. 카탈로그 조회나 변경 전 원본 읽기에 실패하면 차트 저장 또는 오더 변경을 중단한다.

어디까지 확인했나

점검결과확인 범위
계약 테스트58개 통과새 오류·식별·권한 테스트 38개와 기존 카탈로그 테스트 20개. 테스트용 클라이언트 주입, DB 접근 없음.
로컬 HTTP 요청8건 모두 401조회 2종·생성·수정 API에 인증 정보 없음 / 임시 헤더만 있음. 실제 저장 요청은 실행되지 않음.
수정 파일 린트통과소스 3개, 테스트 2개, 테스트 설정 파일. 전체 저장소 린트는 아님.
독립 코드 검토지적 2건 수정오더 식별과 카탈로그 권한 검사를 보완. 재검토에서 추가 필수 수정 사항 없음.
전체 타입 검사실패설치 환경의 @blocknote/* 누락과 관련 오류. 수정 파일의 타입 오류는 없음.
문서 링크 검사기존 오류 1건이전 persona-qa 보고서의 누락 링크. 이번에 추가한 링크 오류는 없음.

로컬 HTTP 점검은 인증 거절만 확인했다. DB 오류의 HTTP 상태 전달은 소스 검사로 확인했으며, 로그인한 실제 워크스페이스의 화면 검증과 원격 RLS 검증은 하지 않았다.

아직 해결하지 않은 것

병원관리와 차트의 화면이 아직 모두 일치하지는 않는다.

화면의 임시 초기 목록, 조제 기본값의 임의 보충, 분류 추정, 워크스페이스 전환 처리는 후속 단계에 남아 있다. 이번 단계만으로 원래 문제가 모두 해결됐다고 볼 수 없다.

검사 항목 삭제 잠금 API는 저장된 DB를 읽는 연결이 없어 이제 503 catalog_gateway_required를 반환한다. 임시 데이터로 삭제 가능 여부를 답하지 않는 상태이며, 아직 사용할 수 있는 기능은 아니다.

다음 단계 완료 기준: 저장된 값 하나를 제거했을 때 병원관리와 새 차트 오더 모두 그 값을 없는 상태로 보여야 한다.
