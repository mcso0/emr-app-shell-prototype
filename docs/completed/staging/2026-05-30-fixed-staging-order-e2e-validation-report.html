Fixed Staging & Order E2E Validation 중간 QA 리포트

요청 목표는 매번 바뀌는 preview/mock fallback이 아니라, 고정 staging URL과 Supabase staging Auth로 병원관리 Order 생성부터 Chart 확정, fulfillment task, billing candidate까지 대표가 직접 검수할 수 있는 환경을 만드는 것이다. 승욱이 Vercel login을 완료한 뒤 fixed staging URL에서 Supabase staging Auth와 DEN-307 핵심 흐름은 통과했다. 다만 fulfillment task 완료와 billing candidate readback은 아직 UI-only 대표 검수로는 부족하고, live row 표시 gap이 남아 있다.

항목 상태 근거

보안 및 제외 범위

  • production deploy는 수행하지 않았다.
  • 실데이터 import는 수행하지 않았다.
  • 원격 RLS policy replay는 수행하지 않았다.
  • staging DB migration은 적용하지 않았다.
  • service_role, DB password, access token 같은 server-only secret은 공개 env에 넣지 않았다.

대표 검수를 위한 다음 작업

DEN-307은 Human Review로 넘길 수 있다. 다음 blocker는 DEN-321이다. fulfillment queue 화면이 live work item을 신규 row로 보여주고, 담당자 완료와 billing candidate readback이 화면에서 직접 확인되어야 DEN-318/DEN-319를 Human Review로 넘길 수 있다. DEN-320은 현재 세션에서는 풀렸지만, 대표/QA가 매번 같은 URL로 들어가기 위한 durable Vercel 접근 정책 결정은 남아 있다.
