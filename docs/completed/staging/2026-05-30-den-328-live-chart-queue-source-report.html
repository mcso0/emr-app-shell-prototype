DEN-328 Live Chart Queue Source-of-Truth Fix

fixed staging live mode에서 진료차트 대기열이 특정 demo bridge 환자에 묶이지 않고 live reception/encounter queue를 source of truth로 읽도록 바꿨다. 이제 chart 첫 선택, chart context, downstream lab queue 표시는 live encounter의 환자/보호자 정보를 기준으로 이어진다.

변경 요약

  • /api/workspaces/[workspaceId]/chart/live-queue read route를 추가했다.
  • server gateway가 reception queue RPC를 읽고 encounter + queueEntry + patient + primaryGuardian bundle로 hydrate한다.
  • direct patients/guardians read가 RLS로 막힐 때는 기존 reception profile lookup RPC로 fallback한다.
  • chart store에 live queue 상태를 추가하고, Supabase session에서는 chart side panel이 live queue를 우선 사용한다.
  • live mode에서는 mock-only row로 조용히 mutation하지 않도록 selected bundle fallback을 live-first로 분리했다.
  • chart live queue rows를 chart handoff cache에도 저장해 lab/imaging/fulfillment 표시명 보강 경로와 연결했다.
  • server test에 multiple encounter hydrate, permission denial, server-only boundary, RLS fallback coverage를 추가했다.

Follow-up: Admin Reception Permission

  • fixed staging에서 admin 계정이 현장 접수 생성 시 reception:create 권한 없음 toast로 막히는 문제를 확인했다.
  • 원인은 Supabase session mutation route가 DB-backed workspace permission adapter를 core에 전달하지 않고 mock permission adapter fallback을 사용하던 것이다.
  • 현장 접수, 예약 체크인, 보호자/환자 등록 route가 Supabase session에서 loadWorkspacePermissionAdapterFromDb를 사용하도록 보강했다.
  • patient lookup route도 같은 DB-backed permission adapter를 사용하도록 보강했다.
  • 한국어 staging 표시명(나비, 코코 등) 검색이 live synthetic lookup으로 이어지도록 fallback을 추가했다.
  • 화면에서 mock patient id가 넘어와도 walk-in write 직전에 live patient/guardian UUID로 보정한다.
  • 검증: npx tsc --noEmit --pretty false, 접수 lookup/mutation server specs 24개, secret scan, touched files lint 통과.
