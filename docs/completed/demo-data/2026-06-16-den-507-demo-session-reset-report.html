DEN-507 Cheongdam 데모 세션 초기화 완료 보고

반복 QA와 시연을 위해 Cheongdam synthetic demo workspace를 처음 상태로 되돌리는 초기화 기능을 추가했다. 이번 작업은 실제 병원 운영 출시가 아니라 workspace-clair-cheongdam synthetic demo 환경의 반복 검증을 위한 장치다.

요청 사항

  • 데모 중 생성된 접수, 진료, 오더, 처리, 수납 흐름을 초기 상태로 되돌릴 것.
  • 실제 환자, 보호자, 병원, 결제, 신원, 외부 연동 데이터는 사용하거나 건드리지 않을 것.
  • client-only UI가 아니라 서버/API 보안 경계까지 포함할 것.

변경 내용

  • Cheongdam workspace topbar의 알림 아이콘 왼쪽에 관리자 전용 세션 초기화 버튼과 확인 다이얼로그를 추가했다.
  • POST /api/workspaces/[workspaceId]/demo/session-reset route를 추가했다.
  • Supabase RPC public.clair_reset_cheongdam_demo_session(text, text) migration을 추가했다.
  • RPC는 Cheongdam workspace allowlist, auth.uid() actor match, active workspace admin membership을 요구한다.
  • daily-work 상태는 reception, appointment, encounter, SOAP/diagnosis, order, fulfillment, invoice/payment 범위를 정리한다.
  • 신규 환자는 registration writer가 만든 P-YYMMDD-XXXXXX 형식만 삭제하고, 보호자는 그 환자와 연결된 guardian 중 CD-G-* seed가 아닌 경우만 삭제한다.

보존 범위

  • workspace, users, memberships, permission policies
  • service/order catalog, order sets, hospital-admin setup
  • Cheongdam CD-* seed guardian/patient master data
  • 외부 provider, payment, email, Kakao, PACS, device, accounting side effects

검증 결과

  • ./node_modules/.bin/tsc --noEmit 통과
  • tests/demo-session-reset-server.spec.ts 6개 통과
  • Cheongdam topbar reset confirmation/control flow 통과
  • workspace mutation route rate-limit registry check 통과
  • Staging 배포/readback 완료: final preview dpl_3pZe4hU3iHdPiMpKkcFhDkSQGxii에 API/UI가 빌드됐고, Supabase staging에 reset RPC를 적용했다. 검증 marker DEN507-STAGING-RESET-VERIFY-20260616T1518KST로 reception encounter, SOAP note, lab order, fulfillment work item, invoice line, payment를 생성한 뒤 reset을 실행했다.
  • Reset 반환 count는 encounters 11, waiting queue entries 11, soap notes 3, orders 7, fulfillment work items 6, invoices 4, invoice lines 4, payments 3, billing checkout sessions 1, billing checkout session invoices 1, billing invoice status events 2, generated patients 2, generated guardians 2였다.
  • Reset 후 readback에서 Reception, Chart, Fulfillment, Billing marker count는 모두 0이었다. Cheongdam seed master data는 seed guardians 25, seed patients 25, service items 12, user memberships 6으로 유지됐고, generated patient pattern과 daily-work/billing flow tables는 0으로 돌아왔다.

주의 사항

  • 현재 mock mode는 browser/session state reset만 수행한다. 원격 DB 보안을 대체하지 않는다.
  • Supabase 실세션에서는 클라이언트가 workspace admin 여부를 단정하지 않고, route/RPC가 최종 권한을 판정한다.
  • 이번 작업은 reset 기능 범위만 처리했다. 접수 UX, 시간, 담당자, handoff 이슈는 별도 scope다.
  • Supabase CLI가 이 worktree에 없어 migration 파일은 repo timestamp 규칙으로 직접 추가했다.
