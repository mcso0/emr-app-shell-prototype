DEMO-DATA-PR-002 Candidate 7 Cheongdam Billing Paid Action Replacement

작성일: 2026-06-17

요청

남은 tests/sales-demo-flow.spec.ts 안의 legacy Kong 수납 완료 행동 검증을 현재 목표인 workspace-clair-cheongdam seed/API 검증으로 옮기고, Kong fixture는 explicit route fixture availability 확인으로 축소했다.

변경 내용

  • tests/cheongdam-seed-workflow-replacement.spec.ts가 billing checkout preparation, 담당하기, 수납 완료 확인 dialog, paid-state readback, paid invoice checkout exclusion을 검증하도록 확장됐다.
  • tests/sales-demo-flow.spec.ts에서는 Kong billing step의 담당하기/수납 완료 클릭을 제거했다. 이 테스트는 이제 legacy fixture가 명시적 route로 열리는지만 확인한다.
  • src/features/billing/module.tsx에서 Cheongdam live invoice detail이 billing store에 저장된 payment snapshot을 병합해 읽도록 보강했다.
  • Billing checkout workspace와 right payment panel이 stale global selectedInvoiceIds에 남은 legacy Coco invoice 대신 active Cheongdam detail/group의 invoice ID를 사용하도록 정렬했다.

왜 중요한가

수납 완료는 단순 fixture 표시보다 실제 운영 검증에 더 가까운 행동이다. 이 행동을 Kong fixture에 남겨두면 Sales Demo가 계속 현재 제품 증거처럼 보인다. 이번 작업으로 수납 완료 proof는 청담 seed/API 흐름이 맡고, Kong은 삭제 전까지 남겨 둔 fixture-contract 확인 역할로 축소됐다.

중요한 발견

Cheongdam live invoice가 encounterId 기반으로 만들어지는 동안, right payment panel과 checkout workspace가 기존 store의 기본 선택값인 Coco invoice를 볼 수 있는 경계가 있었다. 이 상태에서는 수납 완료 후 API snapshot이 store에 들어와도 중앙 화면이 non-legacy filter 때문에 snapshot을 다시 반영하지 못할 수 있었다. 이번 변경은 이 경계를 active Cheongdam invoice 중심으로 좁혔다.

미변경 범위

  • kong-vomit scenario registry와 fixed May 2026 fixture data는 아직 삭제하지 않았다.
  • 원격 Supabase mutation, staging replay, production deploy는 수행하지 않았다.
  • 남은 Kong fixture tests는 아직 test-fixture coverage다. module-specific fixture assertion은 각각 Cheongdam seed/API equivalent가 생긴 뒤 삭제한다.
