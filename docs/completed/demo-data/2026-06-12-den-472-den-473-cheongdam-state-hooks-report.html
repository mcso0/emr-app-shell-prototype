DEN-472/DEN-473 Cheongdam 상태 UX 안정화 보고서

요청

Cheongdam 기본 접수 화면에서 서버 read가 로딩 또는 실패하는 동안 clair-demo의 과거 업무가 잠깐 보이거나, 빈 병원 상태가 오류처럼 보이지 않도록 정리한다. 업무 없음, 로딩, 오류, 재시도 상태를 구분하되 Sales Demo fixture는 보존한다.

변경 요약

  • Cheongdam reception queue/calendar read 실패 시 "기존 데모 업무는 표시하지 않고 준비된 빈 병원 상태를 유지"한다는 copy hook을 연결했다.
  • 대기열/캘린더 read error alert에 재시도 버튼을 유지하면서, Cheongdam에서는 legacy local demo fallback 안내가 나오지 않게 했다.
  • 빈 목록 copy를 검색 없음과 active daily work 없음으로 분리했다.
  • Reception session draft 생성이 현재 workspace/date를 사용하도록 고쳐 Cheongdam에서 만든 로컬 접수가 clair-demo workspace로 저장되지 않게 했다.
  • Drawer의 legacy encounter fallback은 clair-demo일 때만 섞이도록 좁혔다.

검증 제한

  • 전체 npx tsc --noEmit와 npm run build는 기존 미추적 lottie-ai-chart-writing/ 및 stale .next type reference 영향이 있어 이번 범위에서는 filtered TypeScript check로 확인했다.
  • 이번 배포의 고정 staging/preview alias는 Vercel Deployment Protection이 적용되어 unauthenticated browser/curl에서는 401 Vercel login으로 이동한다. 보호 설정을 변경하거나 공개 우회 링크를 만들지 않았기 때문에 in-app browser 본문 검증은 Vercel 인증 세션 뒤에서만 가능하다.
  • 이번 작업은 Cheongdam reception read state에 초점을 맞췄다. Shell search, tabs, notifications의 broader cleanup은 DEN-491로 남아 있다.
  • Supabase remote mutation, real customer data, provider/payment/email side effect는 수행하지 않았다.
