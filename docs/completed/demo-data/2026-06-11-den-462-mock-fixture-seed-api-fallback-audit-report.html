DEN-462 mock fixture seed API fallback 출처 감사 리포트

작성일: 2026-06-11 · Linear: DEN-462 · Project 00 Demo Reality Scope & Audit

요청과 결론

CLAiR EMR 청담점 데모를 "새로 개업한 병원처럼 준비된 상태"로 만들기 전에, 주요 화면이 어떤 데이터 출처를 쓰는지 감사했다. 이번 작업은 구현이 아니라 조사/보고 작업이며, 코드와 fixture 데이터는 수정하지 않았다.

결론은 명확하다. 병원관리의 오더 카탈로그 같은 master seed는 유지할 수 있지만, Home, Reception, Chart, Lab/Imaging, Dispensing/Treatment, Billing은 기본 화면에서 2026년 4월-5월 과거 업무 fixture가 노출될 가능성이 높다. 새 병원 기본값은 "마스터 데이터는 준비, 당일 업무는 비어 있음"이어야 하므로 daily-work fixture를 legacy scenario opt-in으로 격리하는 후속 구현이 필요하다.

후속 작업 후보

P0

  • 데이터 모드 계약을 먼저 만든다: empty-clinic seed, legacy scenario fixture, local-first draft, Supabase/local DB의 우선순위와 reset 범위.
  • src/mocks/emr-domain.ts를 master seed와 daily-work scenario fixture로 분리한다.
  • Home, Reception, Chart, Lab/Imaging, Dispensing/Treatment, Billing의 기본 daily-work 화면을 빈 상태로 바꾸고 legacy fixture는 명시적 scenario에서만 켠다.
  • supabase/seed.sql의 기본 local seed를 empty-clinic baseline으로 바꾸거나, 현재 활성 업무 seed를 별도 scenario seed script로 격리한다.

P1

  • Customer의 환자/보호자 master seed는 유지하되, 업무 badge/최근 업무/삭제 잠금 계산을 active daily-work source로 분리한다.
  • Hospital admin order catalog를 명시적 master seed로 정리하고, API fallback이 DB 누락을 숨기지 않게 source 표시/검증을 추가한다.
  • Audit 기본값을 setup/reset/user configuration history로 바꾸고, 임상/수납 변경 이력은 scenario mode에서만 노출한다.
  • global command palette, workspace tab metadata, notifications가 empty-clinic mode를 따르게 한다.

P2

  • legacy Sales demo scenario를 보존하되 developer/test opt-in replay와 reset UX를 별도 작업으로 설계한다.
  • 역할별 smoke test를 추가해 empty-clinic baseline과 scenario mode가 서로 섞이지 않는지 검증한다.
  • master seed 규모가 커졌을 때 command palette/search 성능과 빈 상태 UX를 점검한다.

범위 제외와 안전 기준

  • 이번 이슈에서는 코드, fixture, seed, DB, Supabase remote 데이터를 수정하지 않았다.
  • 실제 환자/보호자/병원 데이터, secret, 비용 발생 작업, destructive remote 변경, 외부 발송/결제/provider side effect, 실제 고객 launch는 수행하지 않았다.
  • 기존 PRD viewer 관련 dirty files와 package 변경은 이번 감사 범위 밖이라 건드리지 않았다.
