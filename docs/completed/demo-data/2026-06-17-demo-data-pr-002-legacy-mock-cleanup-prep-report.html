청담 Seed 운영 검증 기준 정렬 및 Legacy Mock 정리 준비

요청

코드 정리와 리팩터링 전에 현재 프로젝트 목표를 workspace-clair-cheongdam 청담 seed 워크스페이스 중심으로 고정하고, clair-demo와 Sales Demo fallback을 후속 정리 대상으로 분류해 달라는 요청이었다.

변경 내용

  • 현재 상태 문서에서 Sales Demo 보존 전제를 제거하고 청담 seed 운영 검증을 기본 목표로 명시했다.
  • mock/live boundary 문서를 Cheongdam prepared-clinic workspace 중심으로 갱신했다.
  • DEMO-DATA-PR-002 작업 항목에 legacy/mock cleanup inventory를 done criteria와 notes로 연결했다.
  • 새 inventory 문서에 legacy reference 분류 기준, 대표 파일, cleanup priority, 삭제 전 검증 기준을 정리했다.

왜 중요한가

앞으로 기능 점검은 mock 데이터가 아니라 seed 데이터와 API/Supabase 경계가 실제처럼 이어지는지를 보는 방향이다. 이번 정리는 Sales Demo fallback이 그 검증을 가리지 않도록 후속 삭제와 리팩터링의 판단 기준을 먼저 고정한다.

검증

  • npm run docs:check: 통과
  • npm run lint: 통과, 기존 warning 5개 유지
  • npx tsc --noEmit: 통과
  • Playwright Cheongdam 묶음과 단일 reset spec은 이 환경에서 장시간 무출력으로 멈춰 중단했다.

범위 밖

  • 앱 코드 삭제 또는 리팩터링은 아직 수행하지 않았다.
  • remote Supabase mutation, staging replay, production deploy는 수행하지 않았다.
  • 실제 병원/환자/보호자/결제/신원 데이터는 사용하지 않았다.
