DEN-456 Dispensing/Treatment Fulfillment Adoption Report

요청

Dispensing/Treatment execution UI가 mock/local queue 상태만 따르지 않고, seeded order_fulfillment_work_items를 읽고 상태 변경을 API 경계로 저장하도록 만드는 작업이었다.

변경

  • 조제와 처치 fulfillment queue를 함께 읽는 shared client queue state와 refresh cache를 추가했다.
  • 선택된 work item의 queue type, server status, assignee, order id를 지시서 상단에 readback으로 표시했다.
  • 담당하기, 완료, 담당취소 액션이 기존 fulfillment PATCH API를 호출하고, 성공 후 다시 조회하도록 조정했다.
  • PATCH 실패 시 화면을 임의로 진행/완료 상태로 바꾸지 않고 mutation failure alert를 표시하도록 했다.
  • queue read loading, empty, retryable error, permission denied 상태를 visible alert로 구분했다.
  • Playwright coverage를 readback 표시, status refresh, permission denial, mutation failure case로 확장했다.

현재 상태

조제/처치 화면은 Sales Demo fallback을 유지하면서도 fulfillment work item이 있으면 서버 readback을 화면에 드러낸다. 상태 변경은 API를 거쳐 re-read된 결과를 기준으로 보이므로, 서버 저장 실패가 조용한 local-only 성공처럼 보이지 않는다.

검증

  • npx playwright test tests/dispensing-fulfillment.spec.ts --reporter=line 통과
  • npx tsc --noEmit 통과
  • npm run lint 통과: 기존 warning 5개 유지, error 없음
  • npm run docs:check 통과
  • npm run security:secrets 통과

리스크와 제외 범위

  • DB schema, migration, seed, RLS는 변경하지 않았다.
  • Lab result persistence, billing checkout, provider integration은 포함하지 않았다.
  • fixture 기반 Sales Demo와 unconfigured local fallback은 유지했다.
  • remote/prod Supabase 검증은 수행하지 않았다.
