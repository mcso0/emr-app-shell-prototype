Notification Producer DB Persistence Adoption Report

NOTIFICATION-PR-025 connects selected Supabase-session notification producers to the notification DB persistence gateway while preserving demo-header mock-mode in-memory behavior.

What Changed

  • order_recheck_requested now emits through the DB persistence gateway for Supabase-session actors.
  • clinical_result_completed now emits through the DB persistence gateway after Supabase lab result save succeeds.
  • Demo-header mock-mode producers continue to use the scoped in-memory event store.
  • Lab result save remains authoritative if notification emission fails; the response reports a bounded emission issue category.
  • Direct-user recheck recipients must be active members of the same workspace.

Security Boundary

  • Removed direct authenticated table grants for notification event/state tables.
  • Added RPC actor checks so p_actor_user_id must match auth.uid().
  • Filtered event-list RPC output by recipient and source-domain visibility.
  • Restricted user-state RPCs to the current actor, current actor state scope, and visible notifications.
  • Added producer emit authorization checks and DB-backed bump read/archive-state clearing.
