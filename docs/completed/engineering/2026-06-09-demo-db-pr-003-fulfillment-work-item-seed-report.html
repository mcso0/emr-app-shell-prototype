Demo DB PR 3 Fulfillment Work Item Seed Report

요청

UI를 바꾸지 않고 clair-demo local/dev seed에 주문별 fulfillment work item을 추가해, reset 직후에도 부서별 업무 큐 데이터가 존재하도록 만드는 작업이었다. remote Supabase, production DB, 실제 병원/환자 데이터는 범위에서 제외했다.

변경

  • supabase/seed.sql에 synthetic fulfillment work item row 11개를 추가했다.
  • Lab 2개, imaging 3개, treatment 4개, dispensing 2개 queue type을 커버한다.
  • kong-vomit, nabi-urinary, bori-allergy, mango-wellness, choco-rehab 시나리오의 기존 DEN-194 orders에 1:1로 연결했다.
  • readback SQL과 focused test를 fulfillment seed가 baseline으로 필요하도록 갱신했다.
  • seed inventory 문서에서 해결된 fulfillment gap과 남은 lab/billing gap을 분리했다.

현재 상태

이제 demo DB reset 이후 order_fulfillment_work_items는 비어 있지 않아야 하며, readback은 queue type별 최소 개수를 확인한다. 남은 seed gap은 lab result-sheet catalog/link rows와 optional billing checkout session family다.

리스크와 제외 범위

  • 이번 변경은 seed/readback/test/doc 범위이며 UI 연결은 하지 않았다.
  • Lab 결과지 카탈로그와 billing checkout session seed는 다음 PR 범위로 남겼다.
  • 실제 병원, 보호자, 환자, 결제, 의료 데이터는 사용하지 않았다.
