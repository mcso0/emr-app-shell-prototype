UI PR 2 Fulfillment and Billing UI Wiring E2E Report

요청

Demo DB PR 5와 UI PR 1 이후, seed나 schema를 바꾸지 않고 downstream fulfillment, lab result-sheet, billing checkout, audit review 화면이 API/server boundary를 더 넓게 타도록 만드는 작업이었다.

변경

  • /api/workspaces/[workspaceId]/lab-imaging/result-sheet-catalog route를 추가해 seeded CBC/urinalysis catalog rows를 결과 입력 화면에서 사용할 수 있게 했다.
  • /api/workspaces/[workspaceId]/lab-imaging/result-entries route를 추가해 local/dev 범위에서 결과 입력 저장이 서버 경계를 통과하도록 했다.
  • Lab/imaging queue가 mock runtime에서도 API-only fulfillment work item을 append하도록 맞췄다.
  • Live lab work item의 빈 결과지 rows를 seeded lab catalog rows로 hydrate하도록 했다.
  • Playwright E2E가 lab result-sheet 입력/저장, fulfillment status transitions, billing checkout/payment, audit review UI/API boundary를 검증하도록 확장됐다.

현재 상태

seed-family gap은 여전히 0이다. UI PR 2는 downstream API adoption을 넓혔지만 모든 화면의 mock-first state를 제거한 것은 아니다. 특히 durable lab result value persistence와 dispensing/treatment execution screen의 full visible-control refactor는 후속 작업이다.

리스크와 제외 범위

  • remote Supabase, production DB, migration push, seed 변경은 하지 않았다.
  • 실제 병원, 보호자, 환자, 결제, 의료 데이터는 사용하지 않았다.
  • Lab result value 저장은 새 schema 없이 local/dev server-boundary proof로만 구현됐다.
  • Billing UI는 checkout/payment route를 소비하지만 기존 mock-backed store가 일부 남아 있다.
