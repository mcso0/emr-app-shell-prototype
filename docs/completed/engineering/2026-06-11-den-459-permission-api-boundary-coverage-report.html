DEN-459 Permission API Boundary Coverage Report

요청

Lab, billing, fulfillment API가 workspace, role, permission boundary를 지키는지 local/dev/test 범위에서 회귀 테스트로 보강하는 작업이었다.

변경

  • tests/api-boundary-permission-regression.spec.ts를 추가했다.
  • lab result entry read/save의 unauthenticated denial을 고정했다.
  • fulfillment queue read와 status mutation의 unauthenticated, cross-workspace, insufficient-role denial을 고정했다.
  • billing invoice-line read, payment-status mutation, guardian checkout의 denial path를 고정했다.
  • 연결된 route가 readServerSession, server identity resolver, server read/write helper를 유지하는지 static assertion을 추가했다.
  • current status, work index, route permission inventory, DEN-459 work doc을 갱신했다.

현재 의미

이번 작업은 UI에서 버튼을 숨기는 수준이 아니라 API/server boundary에서 거부 경로가 유지되는지 확인한다. 다만 새 RLS policy, remote Supabase replay, production policy 변경은 포함하지 않았으므로 실제 pilot/live 전에는 별도 RLS와 remote validation gate가 남아 있다.

검증

  • npx playwright test tests/api-boundary-permission-regression.spec.ts --reporter=line 통과
  • npx tsc --noEmit 통과
  • npm run lint 통과, 기존 warning만 남음
  • npm run docs:check 통과
  • npm run security:secrets 통과

리스크와 제외 범위

  • remote/prod Supabase는 사용하지 않았다.
  • DB schema, migration, seed, RLS는 변경하지 않았다.
  • UI rewiring이나 mock fallback 제거는 포함하지 않았다.
  • 이 테스트는 local/dev/test route boundary 회귀이며, 전체 production security signoff가 아니다.
