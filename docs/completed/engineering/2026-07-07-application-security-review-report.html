애플리케이션 보안 체크리스트와 1차 검수 결과

2026-07-07 · checklist-based first pass · synthetic/demo-data scope

요청

보안 실수 체크리스트를 CLAiR EMR 프로젝트 기준 문서로 만들고, 그 체크리스트를 기준으로 현재 프로젝트를 1차 검수하는 작업이었다.

결과

  • 재사용 가능한 애플리케이션 보안 검수 체크리스트를 추가했다.
  • 체크리스트 기반 2026-07-07 1차 검수 스냅샷을 작성했다.
  • 시크릿, 브라우저 노출 env, 서버 세션, demo header, rate limit, Supabase local config, dependency advisory를 확인했다.
  • 후속 조치로 rate-limit 누락 후보를 보강하고 dependency advisory를 해소했다.
  • 문서 포털과 Engineering README, SUMMARY 내비게이션에 새 문서를 연결했다.

핵심 검수 결과

  • npm run security:secrets는 통과했다. 2900개 tracked 파일에서 시크릿이 발견되지 않았다.
  • 클라이언트 공개 env는 Supabase public URL과 publishable key 중심으로 분리되어 있었다.
  • 서버 세션은 Supabase auth.getClaims() 기반으로 확인한다.
  • 초기 검수에서 46개 mutating route 중 7개 route가 rate-limit 후속 확인 대상으로 잡혔다.
  • 후속 조치 후 초대 재요청, 랩 결과 입력, 알림 mutation route는 shared limiter를 통과한다.
  • npm audit --json와 npm audit --audit-level=moderate --json는 현재 0 vulnerabilities로 통과한다.
  • 운영/production-demo rate limit 저장소는 managed Redis-compatible shared store로 결정했고, 실제 provision은 별도 승인 게이트로 남겼다.
