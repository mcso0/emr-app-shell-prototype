Demo DB PR 2 Order Catalog Set Seed Report

요청

UI를 바꾸지 않고 clair-demo local/dev seed에 주문 카탈로그와 주문 세트의 최소 foundation을 추가하는 작업이었다. remote Supabase, production DB, 실제 병원/환자 데이터는 범위에서 제외했다.

변경

  • supabase/seed.sql에 synthetic order catalog row 9개를 추가했다.
  • Kong vomiting compact set 1개와 Mango wellness compact set 1개를 추가했다.
  • 두 set에 포함되는 order_set_items 5개를 추가했다.
  • readback SQL과 focused test를 catalog/set seed가 baseline으로 필요하도록 갱신했다.
  • seed inventory 문서에서 해결된 gap과 남은 gap을 분리했다.

현재 상태

이제 demo DB reset 이후 order catalog와 compact order set은 비어 있지 않아야 한다. 남은 seed gap은 order_fulfillment_work_items, lab result-sheet catalog/link rows, optional billing checkout session family다.

리스크와 제외 범위

  • 이번 변경은 seed/readback/test/doc 범위이며 UI 연결은 하지 않았다.
  • Lab result sheet 항목과 fulfillment queue row는 다음 PR에서 별도 결정해야 한다.
  • 실제 병원, 보호자, 환자, 결제, 의료 데이터는 사용하지 않았다.

다음 추천

Demo DB PR 3는 lab result-sheet catalog seed 또는 fulfillment work item seed/generation 중 하나를 선택해 진행하는 것이 좋다. 두 범위를 한 PR에 합치면 검증 범위가 커진다.
