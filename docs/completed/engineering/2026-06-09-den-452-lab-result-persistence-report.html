DEN-452 Lab Result Persistence Report

요청

UI PR 2에서 서버 경계만 통과하던 lab result entry 저장을 local/dev/test Supabase DB에 영구 저장되는 구조로 확장하는 작업이었다. 실제 병원 데이터나 remote/prod Supabase는 범위 밖으로 유지했다.

변경

  • lab_result_entries, lab_result_entry_rows 테이블을 추가하는 migration을 작성했다.
  • 두 테이블에 workspace membership 기반 RLS policy와 authenticated 권한 grant를 추가했다.
  • clair_save_lab_result_entry, clair_get_lab_result_entry RPC를 추가해 encounter, lab order, lab fulfillment work item 범위를 검증한 뒤 저장/조회하도록 했다.
  • 기존 result-entry API route가 authenticated Supabase session에서는 RPC 경로를 사용하고, demo-header mock mode에서는 기존 fallback을 유지하도록 바꿨다.
  • Lab/imaging UI가 seeded lab test item id를 결과 row payload에 포함하도록 연결했다.
  • 저장 후 readback을 검증하는 focused Playwright contract와 synthetic route-boundary E2E를 보강했다.

왜 중요한가

이제 CBC/UA 같은 검사 결과 값이 단순 화면 상태가 아니라 workspace-scoped DB 모델과 서버 권한 경계를 지나 저장될 수 있다. EMR SaaS 데모에서 “오더 → 업무 큐 → 결과 입력 → 저장/조회” 흐름의 백엔드 foundation이 더 명확해졌다.

현재 상태

DEN-452는 local/dev/test foundation이다. 원격 Supabase, production DB, 실제 검사 장비/외부 검사기관 연동, 실제 병원/환자 데이터 사용은 하지 않았다. Sales Demo와 unconfigured local session을 위한 mock fallback은 유지했다.

리스크와 제외 범위

  • Local Supabase replay/readback은 완료됐다. Remote Supabase와 production DB는 건드리지 않았다.
  • Billing과 dispensing/treatment 화면의 남은 mock-first store 제거는 후속 이슈 범위다.
  • Provider/device integration, receipt/refund/settlement/accounting, production deploy는 포함하지 않았다.
