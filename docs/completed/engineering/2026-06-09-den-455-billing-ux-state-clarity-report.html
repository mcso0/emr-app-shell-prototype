DEN-455 Billing UX State Clarity Report

요청

DEN-454에서 수납 화면이 API snapshot을 우선 반영하게 된 이후, 수납 담당자가 API loading, 실패, 권한 오류, 빈 응답, checkout 준비 실패를 화면에서 구분할 수 있도록 정리하는 작업이었다.

변경

  • invoice-line과 payment-status read 상태를 billing workspace data hook에서 추적하도록 했다.
  • 중앙 수납 화면에 API loading, retryable failure, permission denied, empty state 알림을 추가했다.
  • checkout session prepare 상태를 별도로 추적하고 실패 시 재시도 버튼을 제공했다.
  • 권한 오류는 일반 네트워크 재시도와 다르게 표시해 사용자가 원인을 구분할 수 있게 했다.
  • Playwright E2E에 billing API read retry, permission denial, checkout retry assertion을 추가했다.

현재 상태

Billing selected-invoice demo path는 API 값이 우선이며, API readback 실패가 조용히 mock fallback처럼 보이지 않는다. 실패나 빈 응답이 있을 때 화면이 fallback context를 유지하더라도 상태 알림으로 원인을 드러낸다.

검증

  • npx playwright test tests/ui-demo-api-wiring-e2e.spec.ts --reporter=line 통과
  • npx tsc --noEmit 통과
  • npm run lint 통과: 기존 warning 5개 유지, error 없음
  • npm run build 통과
  • npm run docs:check 통과
  • npm run security:secrets 통과

리스크와 제외 범위

  • DB schema, migration, seed, RLS는 변경하지 않았다.
  • 실제 PG, 결제 provider, 영수증, 환불, 정산, 회계 연동은 포함하지 않았다.
  • Sales Demo와 unconfigured local session fallback은 유지했다.
  • Billing 전체 UX 재설계나 모든 mock 제거는 별도 범위다.
