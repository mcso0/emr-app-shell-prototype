DEN-458 Local Supabase Replay Hardening Report

요청

local Supabase reset, seed, readback 흐름을 다음 세션에서도 재현 가능하게 만들고, 실패 원인이 seed gap인지 환경 gap인지 분리하는 작업이었다.

변경

  • scripts/check-local-supabase-replay.mjs를 추가했다.
  • npm run demo:seed:check script를 추가했다.
  • 기본 실행은 read-only diagnostics이고, --readback에서만 SQL readback을 실행하도록 했다.
  • readback DB URL이 local host가 아니면 remote_guard로 거부한다.
  • Docker, Supabase CLI, psql, local DB connection, migration/schema gap, seed gap을 메시지로 분리했다.
  • Demo seed inventory contract 문서와 static contract test를 갱신했다.

현재 진단 결과

이 머신에서는 Docker daemon은 정상으로 확인됐다. 다만 전역 supabase CLI와 psql CLI가 PATH에서 발견되지 않아 실제 SQL readback은 environment_gap으로 차단됐다. 따라서 현재 확인된 문제는 seed gap이 아니라 local toolchain gap이다.

검증

  • npm run demo:seed:check 통과: Docker reachable, psql/supabase CLI gap 표시
  • npm run demo:seed:check -- --readback 예상 차단: environment_gap: psql CLI is required
  • npx playwright test tests/demo-seed-inventory-readback-contract.spec.ts --reporter=line 통과
  • npm run docs:check 통과
  • npm run security:secrets 통과

리스크와 제외 범위

  • remote/prod Supabase는 사용하지 않았다.
  • DB schema, migration, seed, RLS는 변경하지 않았다.
  • UI 기능 변경은 포함하지 않았다.
  • 실제 SQL readback은 psql 설치 후 다시 실행해야 한다.

다음 추천

다음 순번은 permission, RLS, API boundary test coverage 확장이다. 그 전에 실제 local SQL readback까지 하려면 psql CLI를 설치하거나 PATH에 노출해야 한다.
