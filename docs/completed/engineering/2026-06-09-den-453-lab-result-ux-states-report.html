DEN-453 Lab Result UX States Report

요청

DEN-452로 검사 결과 저장이 DB/API 경계를 타게 된 뒤, 결과 입력 화면이 loading, empty, error, retry, permission-denied 상태를 사용자에게 명확히 보여주도록 정리하는 작업이었다.

변경

  • Result-sheet catalog 조회가 loading, empty, generic error, permission-denied 상태를 구분하도록 바꿨다.
  • Catalog 조회 실패 시 결과 입력 영역 안에서 다시 불러오기 재시도 버튼을 표시한다.
  • Result save API 응답을 boolean이 아니라 success, invalid, permission-denied, retryable error outcome으로 구분한다.
  • 저장 실패가 retryable일 때 재시도 버튼을 표시하고, 권한 오류는 별도 문구로 보여준다.
  • Playwright E2E에 catalog retry, save retry, permission-denied 상태 assertion을 추가했다.

왜 중요한가

검사 결과 입력 화면이 항상 성공한다고 가정하지 않게 됐다. 포트폴리오 데모에서도 API 실패, 권한 실패, 빈 catalog를 구분해서 보여줄 수 있어 EMR SaaS 제품 foundation으로서 신뢰도가 올라간다.
