Notification Remaining Producer DB Persistence Adoption Report

NOTIFICATION-PR-026 connects the remaining approved phase-1 notification producers to the notification DB persistence gateway while preserving demo-header mock-mode in-memory behavior.

What Changed

  • waiting_over_30m now emits through the DB persistence gateway when the reception queue route runs with a Supabase-session actor.
  • billing_waiting_ready now emits through the DB persistence gateway after fulfillment completion creates billing candidates.
  • Vet-reviewed lab/imaging billing sync now emits billing_waiting_ready through the DB persistence gateway after candidate sync and audit emission succeed.
  • Demo-header mock-mode producers continue to use the existing scoped in-memory event store.
  • Notification write failures stay non-authoritative after the source read or mutation succeeds; emitted counts only include successfully persisted or emitted events.
  • Notification persistence rejection coverage now proves reception reads, fulfillment completion, and vet-reviewed billing sync remain successful when notification writes fail.

Security Boundary

  • Supabase-session producer routes create the notification persistence gateway from the request Supabase client instead of using browser-local state.
  • Demo event scope ids are only passed for demo-header mock-mode; Supabase-session events use the DB event scope boundary.
  • Existing recipient, source-domain visibility, and DB RPC actor checks remain the persistence boundary for delivered notification rows.
