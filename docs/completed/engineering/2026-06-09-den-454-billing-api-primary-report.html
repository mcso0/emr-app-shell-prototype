DEN-454 Billing API-primary State Report

요청

수납 화면에서 남아 있던 mock/local 상태 의존을 줄이고, invoice line, payment status, guardian checkout session을 API 응답 우선으로 표시하도록 만드는 작업이었다. 새 seed, schema 변경, remote Supabase, 실제 결제 연동은 범위에서 제외했다.

변경

  • Billing store가 API snapshot을 기존 mock invoice에만 덮어쓰지 않고, API가 돌려준 invoice를 새 snapshot으로 받아들일 수 있게 했다.
  • 수납 화면의 핵심 영역에 안정적인 테스트 식별자를 추가해 invoice, payment, checkout 응답이 실제 화면에 반영되는지 검증할 수 있게 했다.
  • Playwright E2E에 API invoice/payment/checkout snapshot이 fixture 값을 이기는 visible UI 테스트를 추가했다.
  • 기존 synthetic outpatient route-boundary 테스트에 payment status PATCH 후 GET readback 검증을 추가했다.
  • current-status와 work index, DEN-454 work item을 갱신했다.

현재 상태

Billing의 selected-invoice demo path는 API invoice-line, payment-status, checkout-session snapshot을 우선 반영한다. Sales Demo와 unconfigured local session을 위한 mock fallback은 계속 유지된다.

검증

  • npx playwright test tests/ui-demo-api-wiring-e2e.spec.ts --reporter=line 통과
  • npx playwright test tests/billing-security-regression.spec.ts tests/billing-payment-status-persistence-server.spec.ts tests/billing-guardian-checkout-hardening-server.spec.ts --reporter=line 통과
  • npx tsc --noEmit 통과
  • npm run lint 통과: 기존 warning 5개 유지, error 없음
  • npm run build 통과
  • npm run docs:check 통과
  • npm run security:secrets 통과

리스크와 제외 범위

  • 이번 변경은 local/dev/test 범위이며 remote Supabase와 production DB는 건드리지 않았다.
  • 실제 병원, 보호자, 환자, 결제 데이터는 사용하지 않았다.
  • 실제 PG, 영수증, 환불, 정산, 회계 연동은 포함하지 않았다.
  • Billing 전체 mock 제거와 전체 UX 재설계는 별도 이슈 범위다.
