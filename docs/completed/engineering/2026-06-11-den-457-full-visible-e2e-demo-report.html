DEN-457 Full Visible E2E Demo Report

요청

접수에서 감사 로그까지 이어지는 EMR SaaS 데모 흐름을 하나의 visible Playwright scenario로 증명하는 작업이었다. 새 seed나 schema를 추가하지 않고, 기존 API wiring과 synthetic demo data 경계를 검증하는 범위다.

변경

  • tests/ui-demo-api-wiring-e2e.spec.ts에 visible day-in-clinic E2E scenario를 추가했다.
  • 시나리오는 reception, chart queue, lab result entry, dispensing fulfillment readback, billing checkout, audit review 화면을 순서대로 방문한다.
  • 최종 assertion에서 reception, chart, fulfillment, lab, billing, audit API 호출 ledger를 요구하도록 했다.
  • Billing mock route를 API-success snapshot 중심으로 정리해 visible billing 단계가 invoice/payment/checkout API state를 보여주게 했다.

현재 상태

프로젝트에는 API request boundary를 검증하는 기존 테스트와, 사용자가 보는 화면 흐름을 검증하는 visible E2E가 함께 있다. 이 테스트는 mock-only 정적 화면만으로는 통과하지 못하고 주요 API boundary 호출이 모두 발생해야 통과한다.

검증

  • npx playwright test tests/ui-demo-api-wiring-e2e.spec.ts --reporter=line 통과
  • npx playwright test tests/demo-seed-inventory-readback-contract.spec.ts --reporter=line 통과
  • npx tsc --noEmit 통과
  • npm run lint 통과: 기존 warning 5개 유지, error 없음
  • npm run docs:check 통과
  • npm run security:secrets 통과

리스크와 제외 범위

  • DB schema, migration, seed, RLS는 변경하지 않았다.
  • remote/prod Supabase, production E2E, real provider integration은 포함하지 않았다.
  • 화면 리디자인은 포함하지 않았다.
  • Sales Demo와 unconfigured local fallback은 유지했다.

다음 추천

다음 순번은 local Supabase replay hardening이다. Docker/Supabase reset, seed, readback 실행 조건을 더 명확히 해서 다음 세션에서도 같은 데모 DB 상태를 재현할 수 있어야 한다.
