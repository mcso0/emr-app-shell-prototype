DEN-67 Clinical Billing Persistence Scope 보고서

대표 요약

Project 04에서 차트, 오더, 수납을 어디까지 실제 저장 흐름으로 바꿀지 먼저 확정했다. 핵심은 접수에서 만들어진 encounter.id를 차트/SOAP/진단/오더/수납의 공통 연결 ID로 쓰는 것이다.

확정한 범위

영역이번 프로젝트 포함
차트/SOAPSOAP 저장, autosave metadata, 차트 작성완료 상태
진단진단명 선택, 자유 입력, 확진/중점 또는 동등한 MVP 표시
오더draft line 수정, 수량/삭제/확정, 상태 변경
수납확정 오더 기반 invoice candidate, 청구 확정, 미납/수납완료 상태
회귀/인수인계외래 전체 persistence regression과 audit/security handoff

중요한 결정

  • workspaceId는 모든 읽기/쓰기의 필수 scope다.
  • encounter.id는 차트, 오더, 수납을 연결하는 기본 ID다.
  • 환자/보호자/예약 ID는 표시와 맥락용이지 권한 판단 기준이 아니다.
  • 수납 금액은 서버가 저장된 오더와 가격 기준으로 다시 계산해야 한다.
  • 권한은 active membership과 permission resolver 기준으로 확인한다.

제외한 범위

  • 검사/영상/조제/처치 전체 live 전환
  • 실제 PG/결제사 연동
  • AI/약물 안전 자동화
  • remote Supabase, 실서버, 실제 환자/병원 데이터
  • production deploy

검증

  • npm run docs:check: passed
  • npm run security:secrets: passed
