결과 요약

오더를 편집하면 다음 화면 갱신에서 즉시 예상 금액을 보여주고, 저장 성공 응답에 포함된 서버 확정 금액으로 전환한다. 정상 저장 뒤 별도 금액 GET을 없애 저장→조회 워터폴과 새로고침 의존을 제거했다.

사용자 경험 변화

상황표시와 행동
정상 편집오더 예상 총액과 예상 · 저장 중을 즉시 표시하고 청구를 잠근다.
저장 성공같은 mutation 응답의 서버 Summary로 교체하고 청구 예상 총액으로 전환한다.
잘못된 입력직전 서버 금액을 유지하고 입력 확인 필요 · 금액 미반영을 표시한다.
실패·충돌직전 서버 금액을 유지하고 저장 실패 · 금액 미반영을 표시하며 청구를 막는다.
입력 속도추가·삭제·세트·우선순위는 150ms, 연속 수량·상세 입력은 700ms, 명시적 저장·확정은 즉시 처리한다.

서버와 권한 경계

  • draft 저장, atomic 확정, 실행 변경 RPC의 공개 이름과 요청 형식을 유지하고 성공 응답에 billingSummary를 추가했다.
  • 기존 mutation 본문은 실행 권한이 회수된 base 함수로 보존하고, 공개 wrapper가 actor 일치·활성 멤버십·action별 권한과 Summary 조회에 필요한 chart:view를 함께 확인한다.
  • mutation 또는 idempotent replay가 끝난 뒤 같은 transaction에서 현재 Summary를 다시 계산한다.
  • 클라이언트는 활성 workspace와 encounter가 일치하는 Summary만 수락하고, 수락 순간 오래된 GET sequence를 무효화한다.
  • 로컬 예상값은 draft 오더 금액 차이만 반영하며 할인·할증·세금·결제·invoice 값과 청구 권한은 마지막 서버 상태를 유지한다.
