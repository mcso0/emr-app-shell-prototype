운영 방식

  • 편집 원본은 repo docs/다. GitBook은 읽기 포털이다.
  • 작업 시작점은 Linear issue다. 의미 있는 작업은 Human Review에서 멈춘다.
  • Codex는 agent-start-here, current-status, active Linear issue, agent-rag-map만 기본으로 읽고, 나머지는 작업 유형별로 추가한다.
  • Production, remote Supabase, real data, email, payment, role policy 변경은 별도 명시 승인 없이는 하지 않는다.

검증

  • npm run docs:check 통과
  • GitBook sidebar용 docs/SUMMARY.md와 신규 기준 문서 상대 링크 확인 통과

주의사항

  • 이 작업은 문서/운영 체계 구축이며 앱 기능 구현, DB/RLS 실행, Supabase remote 작업, 배포는 수행하지 않았다.
  • 현재 변경은 로컬에 있으며 GitBook 반영은 GitHub main에 커밋/푸시/머지된 뒤 동기화된다.
  • 기존 auth/ops 관련 미완료 워크트리 변경은 건드리지 않았다.
다음 추천: 승욱이 Human Review 상태의 문서들을 훑어보고, 승인되면 이 문서 묶음을 커밋/푸시해 GitBook 동기화 대상으로 만드는 것이 좋다.
