DEN-252 GitBook/docs 구조 운영 규칙 리포트

GitBook을 직접 편집하는 대신 repo docs/를 원본으로 유지하는 운영 규칙을 source-of-truth 문서로 승격했다. 앞으로 GitBook sidebar, area README, 공개 문서 민감도 판단을 같은 기준으로 처리할 수 있다.

요청

emr-docs-sync와 GitBook/docs 운영 고도화 작업이 따를 수 있도록 GitBook/docs 구조 규칙을 만들고, 스킬과 sidebar에서 찾을 수 있게 연결한다.

변경 사항

  • docs/_meta/gitbook-structure-rules.md를 추가했다.
  • docs/SUMMARY.md의 Operating Rules에 새 규칙 문서를 추가했다.
  • docs/_meta/README.md에서 새 규칙 문서를 운영 규칙 목록에 연결했다.
  • docs/README.md의 운영 모델 설명에 GitBook-facing navigation 기준을 포함했다.
  • .agents/skills/emr-docs-sync/SKILL.md가 GitBook/docs 작업 시 새 규칙 문서를 읽도록 업데이트했다.

중요한 기준

  • repo docs/가 원본이고 GitBook은 readable portal이다.
  • docs/SUMMARY.md는 모든 파일 목록이 아니라 curated sidebar다.
  • 세부 탐색은 area README.md가 담당한다.
  • completed/, archive/, compatibility stubs는 기본 읽기 경로를 오염시키지 않는다.
  • auth, security, live DB, launch, real data 관련 정보는 공개 GitBook 전 민감도 검토가 필요하다.

검증

  • 통과 npm run docs:check
  • 통과 Ruby YAML parser로 changed skill/source-doc frontmatter 검증

범위 밖

  • GitBook 직접 편집 또는 게시를 하지 않았다.
  • live Supabase, DB migration, RLS, production deploy, 제품 권한 정책은 변경하지 않았다.
  • 기존 invite/OTP, table density, UI 관련 미완료 워크트리 변경은 건드리지 않았다.
