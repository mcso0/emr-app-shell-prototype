수납 DB/RPC Hardening 프로젝트 최종 보고서

보호자 중심 수납 화면에서 확정한 규칙을 local-first 데이터 계약, local migration 초안, server/API core, regression test로 끌어내렸다. 이제 앱은 “완료/취소 이력은 볼 수 있지만 현재 받을 돈에는 합산하지 않는다”는 규칙을 코드와 테스트에서 같은 기준으로 사용한다.

핵심 결과

  • 완료: 수납이력 날짜 기준과 합산 포함/제외 규칙을 billing-data-contract로 고정했다.
  • 완료: 보호자 ledger, checkout session, selected invoice snapshot, adjustment, payment allocation, audited transition의 local migration 초안을 작성했다.
  • 완료: guardian checkout server core와 API route를 추가해 ledger 조회, checkout 준비, 상태 전환을 local/mock 및 future Supabase RPC gateway 형태로 검증했다.
  • 완료: 기존 billing UI의 합산 제외 계산이 새 데이터 계약 함수를 쓰도록 연결했다.
  • 게이트: remote Supabase migration push, remote RLS replay, fixed staging replay, production deploy, 실데이터 import는 실행하지 않았다.
