Guardian-Centered Billing Checkout UX Contract Report

DEN-358 turns the 2026-05-31 guardian-centered billing proposal into a durable implementation contract. Follow-up billing issues should now use 수납 진행 / 결제 진행, 수납 완료, and reason-backed 미납 처리 instead of a user-facing required 청구 확정 step.

확정된 UX 기준

Chart Order 청구 creates payable 수납대기; billing is guardian-level checkout.

용어 사용자 의미 구현 기준
Order 청구 수의사가 선택 오더를 수납으로 보낸다. 오더 업무 상태를 유지하고 billing candidate를 생성/갱신한다.
수납대기 지금 받을 수 있는 정상 대기건이다. same-day unpaid 대기건을 자동으로 미납 취급하지 않는다.
수납 진행 최종 금액과 결제수단을 확인하고 checkout을 시작한다. primary CTA로 사용한다.
미납 처리 보호자가 결제를 미루거나 실패/보류되어 추후 결제가 필요하다. secondary action이며 사유 입력이 필요하다.

Figma 화면 반영

  • 왼쪽 대기/미납/종료 구조는 수납대기, 미납, 완료 큐로 유지한다.
  • 상단 환자 정보바는 보호자 정보바로 교체한다.
  • 보호자 정보 아래 이력 영역은 보호자 ledger로 정리한다.
  • 중앙 청구서 항목은 selected checkout workspace로 재정의한다.
  • 오른쪽 수납 정보는 최종 결제금액과 CTA 우선의 payment summary로 재정의한다.
  • 미납은 수납과 같은 위계의 primary button이 아니라 reason-required secondary action이다.
