Local-First Unpaid State Semantics

DEN-366은 수납 화면의 수납 진행, 수납 완료, 미납 처리 의미를 local-first API/server/store 경계까지 맞췄다. 이제 issued 자체는 미납이 아니고, 사유가 있는 경우에만 reason-backed 미납으로 다룬다.

핵심 변경

미납은 사유가 있어야 저장된다.

  • saveBillingPaymentStatus validation에 unpaidReason 필수 조건을 추가했다.
  • payment-status API는 사유 없는 mark_unpaid를 400 invalid_input으로 응답한다.
  • mock payment status normalization은 issued만 보고 미납으로 추정하지 않는다.
  • billing store의 local unpaid helper도 reason-backed paymentState = unpaid를 기록하도록 정렬했다.
  • local-first RPC SQL boundary도 unpaid_reason_required를 던지도록 문서/파일 기준을 맞췄다.
