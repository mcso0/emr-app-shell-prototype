DEN-306 차트 draft 오더 ID 분리 리포트

병원관리 Order Catalog의 source id와 진료 차트 draft order의 DB id가 섞이던 문제를 분리했다. 이제 catalog 후보를 차트에 추가하면 차트 draft row는 UUID를 사용하고, 원본 catalog 정보는 sourcePresetId, source_order_id, snapshot에 따로 보존된다.

핵심 변경

  • 차트 catalog 추가 모달의 중복 판정을 order id가 아니라 catalog source id 기준으로 변경했다.
  • 저장 직전 레거시 catalog-... 형태의 draft id가 남아 있으면 UUID draft id로 보정한다.
  • staging DB 함수 clair_save_chart_order_draft가 catalog source id를 UUID로 직접 cast하지 않도록 방어했다.
  • 비UUID catalog id가 들어와도 DB가 500을 내지 않고 UUID draft order로 저장할 수 있게 보강했다.

주의

remote migration history에 과거 로컬에 없는 migration 기록이 있어 supabase db push 전체 실행은 사용하지 않았다. DEN-306 SQL만 staging DB에 직접 적용했고, production 배포나 실데이터 import는 하지 않았다.
