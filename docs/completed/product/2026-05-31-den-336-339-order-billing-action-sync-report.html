DEN-336~339 Order Billing Action Sync Report

2026-05-31 기준으로 chart Order 청구 흐름을 draft 저장 성공 여부와 분리하고, 실제 수납 후보 동기화 경로에 연결했다. 업무 상태와 수납 후보 상태는 계속 분리된다.

변경 요약

  • Order 청구는 선택된 persisted order에 대해 chart/order-actions를 바로 호출한다. 더 이상 chart/order-drafts PATCH 성공에 의존하지 않는다.
  • 저장되지 않은 신규 draft order나 선택 row의 미저장 청구명/수량 변경이 있으면 청구를 막고 명확한 toast를 보여준다.
  • 미완료 오더가 선택된 경우 확인 다이얼로그에 아직 완료되지 않은 오더가 있습니다. 수납을 진행할까요? 문구와 오더명, 현재 진행 상태 badge를 표시한다.
  • lab/imaging 완료 row의 수의사 확인 필요 billing gate와 테이블 내 수의사 확인 버튼을 제거했다.
  • 서버 saveChartOrderAction(action="bill")이 invoiceCandidateGateway.syncInvoiceCandidates를 호출한다. 단순히 billing_candidate_status만 바꾸는 경로에서 실제 invoice candidate 생성/readback 경로로 연결했다.
  • re-requested order도 billing candidate로 전진할 수 있게 로컬 sync boundary를 수정했다. cancelled order는 계속 제외된다.

상태 매트릭스

업무 상태 Order 청구 업무 상태 변경
requested / in_progress / re_requested 확인 다이얼로그 후 수납 후보 생성 가능 변경하지 않음
completed 추가 vet billing gate 없이 수납 후보 생성 가능 변경하지 않음
candidate_created 재청구해도 idempotent readback 변경하지 않음
cancelled billing sync 대상 제외 변경하지 않음
