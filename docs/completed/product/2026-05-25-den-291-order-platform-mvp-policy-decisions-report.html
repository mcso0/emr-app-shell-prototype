확정 정책

정책결정
1차 오더 범위검사, 영상, 예방, 처치, 수술, 입원, 치료, 처방/조제/의료물품을 모두 포함한다.
1차 관리 권한병원관리자만 오더를 생성, 수정, 사용 중지할 수 있다.
기본 프리셋 병합새 프리셋은 자동 추가하고, 병원이 수정하지 않은 항목은 자동 업데이트한다. 병원 수정본은 덮어쓰지 않는다.
삭제 UX삭제가 아니라 사용 중지로 표현한다.
가격 변경1차에서는 즉시 변경한다. 과거 차트와 청구 기록은 확정 시점 snapshot으로 보존한다.
수납 이동billing_only는 바로 후보 가능. lab/imaging은 담당 수의사 확인 후 가능. 처치/조제/치료는 업무 완료 후 가능.
Technician 권한후속 업무를 취소하지 않고, 차트로 반려만 가능하다.
Order set개별 오더 안정화 후 별도 단계로 진행한다.
CSV1차에서는 import 기능 없이 템플릿 설계만 진행한다.

후속 구현 이슈가 따라야 할 기준

  • DEN-281과 DEN-282는 자동 병합이 병원 수정본을 덮어쓰지 않도록 source preset metadata를 남겨야 한다.
  • DEN-283과 DEN-284는 병원관리 화면에서 사용 중지된 오더가 보이되 차트 신규 선택에서는 제외되도록 해야 한다.
  • DEN-285와 DEN-286은 chart confirmation snapshot이 과거 기록을 보호하는 기준임을 유지해야 한다.
  • DEN-287과 DEN-288은 lab/imaging 수의사 확인 gate와 technician return-only 정책을 반영해야 한다.
  • DEN-292는 CSV 업로드가 아니라 템플릿 설계만 수행해야 한다.

구현 전 남은 질문

제품 정책 관점의 필수 질문은 현재 없다. 구현 중 코드 구조상 확인이 필요한 세부 사항은 각 구현 이슈에서 좁게 다룬다. 특히 inpatient destination의 실제 화면 연결과 수술 전용 queue 분리 여부는 후속 구현에서 현재 UI 범위에 맞춰 확인한다.
