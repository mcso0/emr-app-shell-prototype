Order Platform 화면 흐름 복구 리포트

병원관리 Order Catalog 저장부터 차트 오더 확정, fulfillment queue, billing candidate까지 이어지는 대표 사용자 흐름을 다시 연결하고 regression으로 고정했다.

Status: Human Review 준비 localhost 화면 검수 완료 Remote Supabase/RLS replay 제외

비개발자용 요약

화면에서 막히던 출발점은 병원관리 Order 저장 데이터가 같은 데모 브라우저 세션 안에서 다음 API 요청으로 이어지지 않는 문제였다. 또한 차트와 billing 화면은 임의로 생성된 UI 세션 ID를 서버 권한 체크에 그대로 보내서, 서버가 데모 사용자를 알아보지 못했다. 이제 병원관리에서 만든 Order가 차트 catalog 후보로 보이고, 확정하면 snapshot이 보존되며, fulfillment와 billing 후보까지 생성되는 경로가 로컬에서 재생된다.

고친 흐름

  • 병원관리 Order Catalog read, 신규 저장, 수정 저장, 사용 중지 경로를 재확인했다.
  • 데모 UI 세션을 서버가 아는 actor로 매핑해 chart/billing 권한 실패를 제거했다.
  • 데모 client session별 mock Order Catalog gateway를 공유해 저장 결과가 다음 read/search/confirm 요청에 유지되게 했다.
  • 차트 Workspace catalog 검색에서 활성 Order만 후보로 노출되고, 사용 중지 Order는 제외된다.
  • catalog 후보를 chart draft order로 추가한 뒤 확정하면 server-owned applied snapshot이 보존된다.
  • 확정된 catalog snapshot이 lab fulfillment queue와 billing candidate sync로 전달된다.

DEN-299 / DEN-300 / DEN-284 Rework 연결

  • DEN-284: drawer mutation 자체뿐 아니라 저장 결과가 같은 데모 흐름의 chart 검색으로 이어지는 replay가 필요했다.
  • DEN-299: chart catalog search/confirmation gateway가 mock actor와 mock catalog state를 공유하지 못해 후보 없음/권한 없음/확정 실패로 보일 수 있었다.
  • DEN-300: mutation audit 경계는 유지하되, 이번 DEN-290에서는 remote audit/RLS replay 없이 local mock/live-boundary regression만 확인했다.
