DEN-365 - Human Review ready

Checkout Session / Allocation / Adjustment Model

DEN-365는 보호자 중심 합산 수납을 제품 수준으로 만들 때 필요한 DB/RPC 구조를 승인 게이트 형태로 정리했다. 이번 작업에서는 실제 migration, remote Supabase push, RLS replay, 결제 연동은 수행하지 않았다.

판단

현재 구조는 MVP UI에는 충분하지만, 합산 checkout의 영수/정산 모델로는 부족하다.

  • invoices / invoice_lines / payments는 단일 invoice payment state에는 맞다.
  • 보호자 한 명의 여러 환자/청구서를 한 번에 결제하려면 checkout session과 allocation이 필요하다.
  • 할인/할증은 단순 금액 컬럼보다 reason-backed adjustment audit이 필요하다.

작성한 설계

  • billing_checkout_sessions: 보호자 단위 checkout 시도와 payer snapshot.
  • billing_checkout_session_invoices: 선택된 invoice 묶음과 per-invoice amount snapshot.
  • invoice_adjustments: 할인/할증/가격 override 사유 audit.
  • payment_allocations: 하나의 payment를 여러 invoice에 배분하는 기록.
  • 제안 RPC: clair_prepare_billing_checkout_session, clair_apply_invoice_adjustment, clair_complete_billing_checkout_payment, clair_mark_billing_checkout_unpaid.

승인 게이트

  • 구현 전 승욱이 target environment, migration filename, table/check/RLS scope, RPC transaction behavior를 명시 승인해야 한다.
  • 승인 전에는 migration 적용, remote Supabase push, remote RLS replay, real data import를 하지 않는다.
