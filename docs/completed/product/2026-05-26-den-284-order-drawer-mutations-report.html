DEN-284 / 2026-05-26 / Hospital Admin Catalog UX

병원관리 Order Drawer Mutation 연결 보고서

병원관리 Order 상세 drawer의 저장, 신규 추가, 사용 중지 흐름을 workspace catalog mutation boundary에 연결했다. 이제 화면에서 바꾼 오더 이름, 청구명, 금액, 사용여부 같은 값이 catalog mutation 입력으로 변환된다.

Status: Human Review Remote DB: Not applied Hard delete: Not used

무엇이 바뀌었나

  • drawer 저장 버튼이 /api/workspaces/{workspaceId}/hospital-admin/order-catalog mutation route를 호출한다.
  • + Order로 만든 local draft가 저장 전 catalog 재조회로 사라지지 않도록 draft 보존 규칙을 추가했다.
  • 신규 오더는 workspace catalog create input으로 변환하고, 기존 오더는 catalog update patch로 변환한다.
  • 삭제 UX는 hard delete가 아니라 사용 중지로 바꿨다. 성공 시 row는 남고 상태만 중지로 바뀐다.
  • 필수 이름, 청구서명, 금액 검증과 권한 없음/입력 오류 메시지를 drawer footer에 표시한다.
  • 복제된 row는 기존 source catalog item을 그대로 수정하지 않도록 local custom draft로 취급한다.

왜 중요한가

이 작업으로 병원별 오더 카탈로그가 단순 조회 화면에서 병원관리자가 실제로 관리할 수 있는 작업 화면으로 한 단계 이동했다. 특히 사용 중지는 과거 진료와 청구 기록을 보존하면서 future chart selection에서만 제외하는 안전한 정책이다.

보안 및 데이터 경계

  • mutation은 기존 server/API permission boundary인 service_catalog:manage를 통과해야 한다.
  • UI 버튼 숨김만 보안으로 보지 않고, API permission failure를 drawer에 표시한다.
  • remote Supabase 적용, 원격 RLS replay, production deploy, 실데이터 import는 수행하지 않았다.
  • 과거 encounter order snapshot, fulfillment source snapshot, billing candidate amount를 변경하는 작업은 하지 않았다.
