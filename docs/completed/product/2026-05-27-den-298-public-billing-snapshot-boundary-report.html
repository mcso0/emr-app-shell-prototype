Public Billing Candidate Snapshot 신뢰 경계 차단

Public billing invoice candidate API가 클라이언트가 보낸 금액, 청구명, snapshot을 서버 소유 데이터처럼 사용하지 못하도록 입력 경계를 분리했다.

Status: Human Review 준비 DEN-289 P1 finding mitigated Remote DB/RLS/Deploy: Not run

비개발자용 요약

수납 금액은 화면이나 브라우저 요청이 보낸 값을 믿으면 안 된다. 이번 변경으로 외부 PATCH API는 오더 선택 정보만 받고, 금액과 청구명은 차트 확정 또는 fulfillment 완료처럼 서버가 소유한 snapshot 경로에서만 청구 후보에 반영된다.

변경 사항

  • Public sync input을 encounterId, orderIds만 받는 타입으로 분리했다.
  • Public route의 JSON body parser가 orderSnapshots, priceKrw, lineTotalSnapshot, billingName을 전달하지 않도록 했다.
  • Trusted gateway input은 chart/fulfillment 내부 서버 경로가 적용 snapshot을 넘길 수 있도록 유지했다.
  • 존재하지 않는 orderId와 client-submitted snapshot으로 청구 후보가 생성되지 않는 regression을 추가했다.

변경 파일

  • src/features/billing/server-invoice-candidate-sync-core.ts

  • npm run test -- --grep "invoice candidate"는 repo에 test script가 없어 실행 불가했다.

남은 범위

Remote Supabase migration push, 원격 RLS replay, production deploy, 실데이터 import는 수행하지 않았다. DEN-299에서 live chart confirmation gateway fallback 경계를 이어서 처리해야 한다.
