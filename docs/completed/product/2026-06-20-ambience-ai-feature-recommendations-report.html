Ambience AI 레퍼런스 기반 CLAiR EMR AI 기능 재정리

승욱 피드백을 반영해 기존 12개 항목을 다시 나눴다. 1번과 7번은 기능이 아니라 의료 AI 운영 규칙이다. 5번, 6번, 11번은 AI보다 룰, 상태, 템플릿으로 먼저 해결하는 편이 맞다. 실제 AI 기능 우선순위는 재진/전원 환자 요약, SOAP 초안, 안내문 생성, 템플릿/오더셋 추천, 검사 결과 소견 초안, 그리고 데모용 ambient scribe 흐름으로 다시 잡는다.

v2 정리 관점

먼저 정리할 제품 결정

1번은 기능이 아니라 AI 의료기록 승인 규칙 AI가 만든 의료 기록은 기본적으로 draft다. 사용자가 검토, 수정, 승인해야 차트, 안내문, 청구 근거, 감사 이력에 반영된다.
7번도 기능보다 근거/출처 규칙 의료 서비스 특성상 모든 AI 출력은 출처, 근거, 생성 시점, 수정자, 승인자를 남겨야 한다. 특정 기능 카드가 아니라 전역 원칙이다.
5번/6번은 AI보다 deterministic rule SOAP 누락, 미확인 결과, 오더-수납 불일치, 금액 무결성은 우선 상태와 서버 규칙으로 잡는다. AI는 설명문 보조 정도면 충분하다.
8번은 사용 데이터가 쌓인 뒤 AI KPI 대시보드는 초반 데모보다 실제 사용률, 승인률, 수정률, 차트 마감 시간 데이터가 누적된 뒤 가치가 커진다.

AI 운영 규칙

규칙 제품 의미 나중 확장
승인 레벨 초기에는 모든 AI 의료기록을 사용자 승인 필수로 둔다. Codex처럼 `항상 승인`, `저위험 자동 반영`, `고위험 항상 잠금` 같은 병원별 level 선택으로 확장 가능.
근거 표시 AI 문장마다 접수 메모, 이전 차트, 검사 결과, 오더, 승인 템플릿 같은 출처를 표시한다. 근거 없는 문장은 경고하거나 저장을 막는 품질 게이트로 확장.
수정/승인 이력 AI 초안 생성, 사용자의 수정, 최종 승인, 반영 대상을 audit event로 남긴다. AI 품질 평가, 사용자별 채택률, template 개선 루프로 연결.
템플릿/RAG 경계 반복 안내문, 주의사항, 재방문 안내는 승인된 병원 템플릿과 지식 조각에서만 생성한다. 병원별 안내문 버전관리, 변경 승인, 만료일, 법무/원장 검토 상태로 확장.

우선 구현 후보: 화면과 메인 흐름

A · 재진/전원 환자 Patient Recap P0 · 먼저 구체화

재진 환자나 타병원 전원 환자의 맥락을 진료 시작 전에 한 번에 보여준다.

대상재진, 만성질환, 반복 검사, 타병원 자료를 가져온 환자. 초진은 접수 문진 요약 정도만 가능.
화면접수 queue row의 `요약 준비` 표시, 차트 진입 후 patient context bar 아래의 우측 recap 패널.
  1. 접수에서 보호자/환자를 선택하면 시스템이 재진 여부, 최근 encounter, 미완료 오더, 검사 결과, 미납/주의 메모를 확인한다.
  2. 타병원 자료가 있으면 접수 drawer에서 `전원 자료 업로드/요약 대상`으로 표시한다. 데모에서는 synthetic 문서 카드로 충분하다.
  3. 수의사가 차트를 열면 상단 patient context bar 옆에 `AI 환자 요약` 버튼 또는 접힌 패널이 보인다.
  4. 패널은 `진료 이유`, `최근 변화`, `주의할 오더/결과`, `전원 기록 요약`, `보호자 커뮤니케이션 메모`로 나눈다.
  5. 각 문장에는 출처 칩을 붙이고, 수의사는 필요한 문장을 차트 메모나 SOAP 초안 입력으로 보낼 수 있다.

B · 재진/전원 기반 SOAP/HPI 초안 P0 · 차트 핵심

Patient Recap에서 확인한 맥락을 SOAP 초안으로 이어준다. 자동 진단이 아니라 문서 초안이다.

대상재진/전원 환자에서 가치가 가장 크다. 초진은 접수 문진과 진료 중 메모가 있어야 유용하다.
화면차트 SOAP editor 상단의 `AI 초안` 버튼, 우측 draft review drawer, section별 accept controls.
  1. 수의사가 차트를 열고 접수 사유, 이전 차트, 최근 검사/오더, 전원 기록을 확인한다.
  2. `SOAP 초안 생성`을 누르면 HPI/S/O/A/P 섹션별 초안이 생성된다. A/P는 진단 확정이 아니라 문서 구조 제안으로 제한한다.
  3. 초안은 기존 editor에 바로 덮어쓰지 않고 우측 review drawer에 나타난다.
  4. 수의사는 섹션별로 `이 문단 반영`, `수정 후 반영`, `버림`을 선택한다.
  5. 최종 차트 마감 시 AI 사용 여부, 수정률, 승인자를 audit에 남긴다.

C · 보호자 안내문: 템플릿/RAG 기반 생성 P1 · 데모 가능

항상 안내가 달라지면 안 되므로, 승인된 설명/주의사항/재방문 템플릿을 먼저 만든다.

전제별도 RAG 또는 최소한 병원 승인 템플릿 라이브러리가 필요하다. 자유 생성은 위험하다.
화면차트 마감 직전, 수납 checkout preview, customer history의 `오늘 안내문`.
  1. 먼저 병원 템플릿을 만든다: 예방접종, 피부약, 수술/처치 후, 검사 후, 재방문, 응급 주의사항.
  2. AI는 SOAP 전체를 자유롭게 해석하지 않고, 진료 유형, 오더, 약품, 재방문일 같은 변수를 템플릿에 채운다.
  3. 필요한 경우 RAG는 승인된 안내 문구만 검색한다. 출처는 `병원 템플릿 v1.2`, `오더: 피부약`, `재방문일`처럼 표시한다.
  4. 수의사가 안내문을 승인하면 보호자 출력/전송 후보가 된다. 실제 카카오/문자 발송은 별도 provider scope다.
  5. 데모에서는 3-5개 템플릿만으로도 충분히 보여줄 수 있다.

D · 진료 유형별 템플릿/오더셋 추천 P1 · 좋은 제품 기능

차트 작업 중 적절한 맥락에서 자주 쓰는 템플릿과 오더셋을 제안한다. 자동 추가는 하지 않는다.

맥락 추천 방식
접수/차트 시작 내원 목적이 `피부`, `예방`, `구토/설사`, `치과`로 분류되면 관련 SOAP 템플릿을 제안.
진단명 검색 진단명을 선택할 때 “함께 자주 쓰는 검사/처치/약품 오더셋”을 오른쪽 후보로 표시.
오더 추가 검사 하나를 추가하면 관련 채혈, 결과 리뷰, 수납 항목 누락 여부를 제안. 선택은 수의사가 한다.
차트 마감 선택한 템플릿에서 보통 필요한 항목이 빠진 경우 rule-based reminder를 표시.

E · 검사 화면의 결과 소견 AI 초안 P2 · 우선순위 낮음

차트에서 상태 확인은 이미 가능하므로, AI는 검사 화면에서 결과 해석/소견 초안을 돕는 쪽이 더 자연스럽다.

화면Lab/imaging result entry 화면. 결과값 입력 영역 옆에 `AI 소견 초안` 패널을 둔다.
흐름검사 담당자가 값을 입력하면 템플릿 기반 소견 초안이 생성되고, 수의사가 chart result review에서 승인한다.
  1. 검사 화면에서 결과값, 참고범위, 이상 플래그, 첨부 파일 상태를 입력한다.
  2. `소견 초안 생성`은 검사 종류별 템플릿을 사용한다. 자유 진단문이 아니라 결과 설명 초안으로 제한한다.
  3. 완료 시 차트의 오더 행에는 `결과 입력됨`, `AI 소견 초안 있음`, `수의사 확인 필요` 상태가 보인다.
  4. 수의사가 차트에서 원본 결과와 AI 초안을 같이 보고 승인하거나 수정한다.

F · Ambient audio scribe 데모 기획 P0 demo · P3 production

실제 제품에서는 법적 문제가 크지만, 데모에서는 가장 강한 기능 서사다. synthetic consent와 mock transcript로 보여준다.

데모실제 녹음 저장 없이 준비된 mock transcript로 `동의 → 녹음 → 초안 → 승인` 흐름을 보여준다.
운영실제품은 동의, 보관, 암호화, 삭제, 접근권한, 음성 오류 책임, 고지문이 모두 필요하다.
  1. 접수 또는 차트 시작 시 `AI 녹음 안내/보호자 동의` 상태를 표시한다. 동의, 거부, 나중에 묻기 상태가 필요하다.
  2. 진료 화면 상단에 작은 recorder bar를 둔다: 시작, 일시중지, 재개, 민감구간 제외, 보호자 질문 marker.
  3. 진료 종료 후 transcript를 바로 차트에 넣지 않고 SOAP/HPI 초안과 보호자 안내문 후보로 변환한다.
  4. 수의사는 transcript 근거 문장과 AI 초안을 나란히 보고 section별로 승인한다.
  5. 데모 문구는 “실제 녹음/실데이터 아님, synthetic transcript 기반”으로 제한한다.

AI 없이 먼저 구현할 항목

차트 마감 체크
  • SOAP section empty check
  • 미확인 결과, 미완료 오더 표시
  • 마감 전 blocking/warning rule
수납/오더 무결성
  • order snapshot과 invoice candidate 비교
  • service catalog price 기준 재계산
  • 수납 후보 누락 rule alert
입원 daily 현황
  • AI 요약보다 병동 board template 먼저
  • 오늘 확인 필요 date/time 표시
  • 투약, 처치, 바이탈 due 상태
입원 daily note는 나쁘지 않지만, 초기에는 AI가 아니라 “오늘 확인해야 할 항목을 놓치지 않게 보여주는 입원 현황판”이 더 정확하다. AI 요약은 입원 데이터가 durable하게 쌓인 뒤 붙이는 편이 좋다.
