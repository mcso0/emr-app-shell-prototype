DEN-349 Candidate Promotion Confirmation Policy Report

DEN-349 records the approved billing timing: chart Order 청구 creates billing candidates, billing workspace review shows 수납 후보, 청구 확정 accepts those candidates as the guardian-facing invoice amount basis, and 수납 완료 changes payment state only.

제품 타이밍

  • Order 청구: chart user requests billing review for selected billable orders.
  • Billing workspace review: billing/front desk verifies candidate rows and amount context.
  • 청구 확정: candidate rows become the confirmed invoice amount basis and the invoice can move to issued.
  • 수납 완료: payment state changes against the already confirmed invoice amount.

현재 DB/RPC Fit

  • clair_sync_billing_invoice_candidates already creates or refreshes invoice_lines when billing candidates are synced.
  • clair_save_billing_invoice_lines can edit existing line quantities and set the invoice to issued, but cannot create lines from candidate IDs.
  • Therefore the current model supports "candidate-backed draft invoice lines confirmed at 청구 확정".
  • It does not strictly support "physical invoice line creation happens only at 청구 확정" without a DB/RPC migration.

Recommendation

MVP recommendation: keep candidate-backed draft invoice lines and make 청구 확정 the point where those lines become financially confirmed.

  • This matches current candidate sync and invoice-line confirmation RPCs.
  • It avoids a larger candidate table split before representative review.
  • UI copy must keep 수납 후보 distinct from issued/paid state until 청구 확정.
  • If stricter semantics are required, request approval for a migration that separates candidate storage from invoice line creation.

Approval Gate

  • No production deploy was performed.
  • No remote Supabase migration push was performed.
  • No real data import was performed.
  • No remote RLS replay was performed.
  • Remote DB/RPC migration should wait for explicit approval after choosing between candidate-backed draft lines and strict candidate-to-line promotion.
