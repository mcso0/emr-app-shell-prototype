DEN-289 / 2026-05-26 / Security Review

Order Platform 권한·테넌트·Snapshot 보안 리뷰

병원관리 Order Catalog, 차트 오더 확정, fulfillment handoff, billing candidate sync의 권한 경계와 데이터 신뢰 경계를 검토했다. 이번 작업은 보안 리뷰만 수행했으며, 앱 코드 수정이나 remote Supabase 적용은 하지 않았다.

Status: Human Review Code fixes: Not applied Remote DB/RLS/Deploy: Not run

비개발자용 요약

오더 플랫폼은 병원별 가격과 오더명을 다루기 때문에, 화면에서 숨기는 수준이 아니라 서버가 반드시 권한과 금액을 검증해야 한다. 현재 기본 구조는 대체로 맞지만, 수납 후보 API 한 곳에서 외부 요청이 보낸 금액 snapshot을 내부 서버 snapshot처럼 받아들일 수 있는 지점이 발견됐다. 실제 병원 운영 전에 이 부분은 별도 구현 이슈로 막아야 한다.

검토 범위

  • service_catalog:view/manage 권한 경계
  • 차트 오더 확정, fulfillment 상태 변경, billing 후보 동기화 권한
  • workspaceId 기반 catalog/order/work item 격리
  • catalog mutation 감사 로그 coverage
  • fulfillment sourceSnapshot 최소 정보 원칙
  • billing amount와 client-submitted amount 신뢰 경계
  • STRIDE 기준 위협 모델링

주요 Findings

등급 Finding 근거 권장 조치
P1
High confidence		 Public billing candidate API가 client-submitted orderSnapshots를 받을 수 있다. InvoiceCandidateSyncInput에 orderSnapshots가 포함되어 있고, route가 request body를 그대로 cast한다. Mock gateway는 snapshot의 priceKrw, lineTotalSnapshot, billingName을 후보 금액/표시에 사용한다. public API input과 trusted internal sync input을 분리한다. 외부 PATCH route는 orderSnapshots를 무시하거나 제거하고, chart/fulfillment 서버 내부 경로만 snapshot sync를 호출하게 한다.
P1
High confidence		 Supabase session route에서 차트 확정이 live catalog와 live invoice candidate gateway를 사용하지 않는다. chart order action route는 Supabase chart/audit/fulfillment gateway만 넘긴다. saveChartOrderAction은 catalog와 invoice candidate gateway를 받지 않으면 mock gateway로 fallback한다. live order catalog gateway와 live invoice candidate gateway를 route에 연결하고, Supabase session에서 mock fallback이 섞이지 않는 regression을 추가한다.
P2
High confidence		 treatment fulfillment 권한이 별도 권한이 아니라 dispensing 권한으로 처리된다. permissionForQueue는 lab/imaging만 분기하고, 나머지는 dispensing:view/complete를 반환한다. phase-1 정책으로 treatment가 dispensing 권한을 공유하는지 명시하거나, treatment:view/complete 권한을 별도 정의하는 후속 이슈를 만든다.
P2
Medium confidence		 catalog create/update/use-stop mutation에는 mutation audit event emission이 없다. mutateOrderCatalogItem은 service_catalog:manage 권한과 gateway mutation은 수행하지만, emitLiveMutationAuditEvent를 호출하지 않는다. catalog mutation 전후 값, actor, request id, workspaceId를 audit event로 남기고, route에서 Supabase audit gateway를 연결한다.

확인된 안전 장치

  • 병원관리 catalog 읽기와 chart search는 service_catalog:view, mutation은 service_catalog:manage를 요구한다.
  • 차트 확정 core는 client가 보낸 가격/청구명을 신뢰하지 않고, 서버가 active workspace catalog를 다시 조회해 applied snapshot을 만든다.
  • fulfillment source snapshot은 오더 표시명, 청구/라우팅/가격 snapshot, 지시사항, 환자/보호자 표시명 중심이며 raw SOAP, provider payload, token, secret pattern은 발견하지 못했다.
  • lab/imaging completion은 바로 billing candidate로 가지 않고 담당 수의사 review gate로 보류된다.
  • focused server regression 30개가 통과했다.
