DEN-305 Order Platform Staging Replay Closeout

DEN-302부터 DEN-305까지의 rework는 병원관리 Order Catalog 저장 실패에서 시작해 차트 후보 검색, draft 추가, 확정, fulfillment/billing readback까지 staging에서 실제 DB mutation으로 다시 검증하는 범위였다.

결론

Staging preview에서 synthetic Supabase 세션으로 Order Catalog 생성/수정/사용 중지, chart search, chart draft insert, order confirm, confirmed snapshot 보존, fulfillment queue 생성, billing candidate 생성/읽기를 통과했다.

주요 변경

영역 변경 내용
Hospital Admin Order Catalog API가 Supabase workspace membership/permission adapter, live catalog gateway, live audit gateway를 사용하도록 연결됐다. 신규 오더 drawer는 비어 있는 입력, 필수값 저장 비활성화, 저장 확인 모달, 성공 toast, 생성 row 선택 상태를 갖도록 정리됐다.
Chart Draft catalog 후보를 chart draft에 추가할 때 UUID order id와 catalog snapshot metadata를 함께 보내고, Supabase RPC가 없는 orders row를 encounter-scoped draft order로 생성하도록 보강했다.
Chart Confirm live confirmation 응답과 readback이 confirmed snapshot을 billingName, priceKrw, lineTotalSnapshot 형태로 유지하도록 정규화했다.
Fulfillment/Billing Supabase 세션 기반 chart/billing/fulfillment route에 DB permission adapter를 연결해, UI/API가 같은 workspace membership 기준으로 read/write 되도록 했다.

주의 사항

Staging에는 synthetic test order/catalog rows가 생성됐다. production DB, production deploy, real data import, remote production RLS replay는 수행하지 않았다. Vercel preview 배포는 HEAD commit author가 팀 권한을 가진 계정이어야 해서, 배포 unblock용 빈 commit을 하나 추가했다.

대표 검수 포인트

  • 병원관리 > Order 관리에서 새 임상병리 오더를 만들고 저장되는지 확인
  • 저장된 오더가 테이블에서 선택/활성 상태로 보이는지 확인

  • 후보를 draft로 추가하고 확정했을 때 실패 toast 없이 확정되는지 확인
  • 확정 후 fulfillment/billing 흐름이 이어지는지 확인
