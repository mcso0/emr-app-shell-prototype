Billing Component Reuse Implementation Plan Report

DEN-359 audited the current billing screen code and created the implementation plan for DEN-360 through DEN-364. The goal is to avoid a broad one-shot rewrite and let each follow-up issue own a clear slice of the guardian-centered billing checkout screen.

현재 코드 상태

  • src/features/billing/module.tsx is 2,296 lines and contains fetch helpers, data hook, queue, header, guardian groups, combine panel, invoice table, payment summary, and financial dialogs.
  • src/features/billing/data.ts owns mock/domain selectors for queue rows, guardian groups, and detail hydration.
  • src/features/billing/store.ts owns selected invoice, combined invoice IDs, payment method, and line edit state.
  • Candidate readback behavior from DEN-348 is concentrated around candidate merge helpers and must be preserved during UI reshaping.
