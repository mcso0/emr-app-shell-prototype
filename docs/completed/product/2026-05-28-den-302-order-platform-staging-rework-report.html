DEN-302 Order Platform staging 저장 흐름 복구 리포트

일자: 2026-05-28

Linear: DEN-302 / DEN-303 / DEN-304 / DEN-305, DEN-290 rework hub

병원관리 Order 관리에서 새 Order가 화면에만 생기고 staging DB에 저장되지 않는 문제를 우선 복구했다. Supabase 세션에서는 mock gateway가 아니라 live Order Catalog gateway와 DB permission adapter를 사용하도록 바꿨고, staging DB에는 catalog 검색, mutation audit, fulfillment queue, Order Catalog RLS/write 정책을 적용했다.

제품 변경

  • 병원관리 Order Catalog API가 Supabase 세션에서 live DB gateway로 listAdminCatalog, create, update, pause를 처리한다.
  • 새 Order 드로어는 임상병리 오더 추가처럼 목적이 보이는 제목으로 열리고, 표준 Order명, 원내 Order명, 청구서명, 판매금액은 빈 입력과 placeholder로 시작한다.
  • 필수값이 비어 있으면 저장 버튼이 비활성화되고, 저장 전 확인 모달을 거친다. 등록 성공 후 토스트와 상태 메시지를 보여주고, 등록된 Order가 선택된 상태로 남는다.
  • 새 Order 생성 드로어에서는 사용 중지 액션을 숨겼고, 기존 Order 상세에서는 유지했다.
