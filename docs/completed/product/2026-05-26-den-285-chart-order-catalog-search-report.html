DEN-285 / 2026-05-26 / Chart Order Selection

차트 Order 검색을 병원별 Catalog에 연결한 보고서

진료/차트 화면의 + Order가 더 이상 임시 안내만 보여주지 않고, 현재 병원의 active workspace catalog를 검색한다. 사용자는 병원관리에서 관리되는 오더 후보를 선택해 차트의 draft order row에 추가할 수 있다.

Status: Human Review Snapshot persistence: DEN-286 Remote DB: Not applied

무엇이 바뀌었나

  • 차트 + Order와 테이블 하단 + Order 추가하기가 workspace catalog 검색 drawer를 연다.
  • /api/workspaces/{workspaceId}/hospital-admin/order-catalog?mode=chart-search를 호출해 active catalog rows와 active order sets만 읽는다.
  • 검색어는 Order명, 청구서명, source preset id, category를 대상으로 적용된다.
  • 환자 종에 맞는 후보만 화면에 보여준다. 예를 들어 환자가 dog/cat이면 해당 대상이 포함된 후보를 우선 표시한다.
  • 중지된 catalog row는 chart-search route에서 제외되어 신규 차트 오더 후보로 나오지 않는다.
  • 후보를 추가하면 display name, billing name, instruction 후보, price 후보가 차트 draft row에 채워진다.
  • 기존 차트 오더 필터 테스트가 새 공통 filter builder 동작에 맞도록 안정화됐다.

왜 중요한가

이제 차트에서 선택하는 오더의 출처가 CLAiR 고정 샘플이 아니라 병원별로 관리되는 catalog가 된다. 병원관리에서 이름, 청구명, 금액, 사용여부를 조정한 값이 미래 차트 선택 후보에 반영되는 흐름이 생겼다.

보안 및 데이터 경계

  • chart search는 기존 catalog API route와 actor headers를 통과한다.
  • 중지된 오더 제외는 UI 표시 조건만이 아니라 chart-search 결과 자체에서 보장된다.
  • 차트 draft에 금액 후보를 표시하지만, 최종 청구 금액 신뢰 경계는 후속 confirmation snapshot/server boundary에서 처리해야 한다.
  • remote Supabase 적용, 원격 RLS replay, production deploy, 실데이터 import는 수행하지 않았다.

제외한 것

  • 확정 시점의 immutable applied snapshot 저장은 DEN-286 범위다.
  • order set을 개별 오더로 확장해 저장하는 정책은 별도 후속 범위다.
  • fulfillment routing, lab/imaging review gate, billing candidate sync 연결은 후속 issue 범위다.
  • 실제 DB migration 적용, remote Supabase 검증, RLS replay는 하지 않았다.
