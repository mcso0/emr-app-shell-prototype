DEN-282 / 2026-05-25 / Preset & Workspace Catalog

Workspace 오더 카탈로그 프리셋 초기화 구현 보고서

CLAiR 기본 오더 프리셋을 병원별 오더 카탈로그로 안전하게 복사하고, 이후 프리셋 업데이트 시 병원이 수정한 값은 덮어쓰지 않는 local-first 경계를 구현했다.

Status: Human Review Remote DB: Not applied

무엇이 바뀌었나

  • 오더 카탈로그 row에 프리셋 출처, 최초 import version, 마지막 자동 병합 version, 커스터마이즈 상태, merge 상태를 표현할 수 있게 했다.
  • CLAiR system preset을 workspace catalog row로 만드는 순수 초기화 함수를 추가했다.
  • 초기화는 같은 preset을 여러 번 실행해도 중복 row를 만들지 않는다.
  • 프리셋이 새 버전으로 바뀌면 병원이 수정하지 않은 row만 자동 업데이트한다.
  • 병원이 수정한 row는 값을 보존하고 update_available 상태로 남긴다.
  • Sales Demo fixture id는 기존처럼 deterministic하게 유지했다.

왜 중요한가

병원마다 오더 이름, 청구명, 가격을 다르게 운영할 수 있어야 한다. 이번 경계가 있어야 CLAiR가 기본 프리셋을 계속 개선해도 병원의 기존 운영값을 임의로 덮어쓰지 않고, 차트·청구 스냅샷 안정성도 후속 이슈에서 연결할 수 있다.

제외한 것

  • remote Supabase migration 적용, 원격 RLS replay, production deploy는 하지 않았다.
  • 실데이터 import와 CSV import 실행은 하지 않았다.
  • 오더 상세 UI CRUD 연결은 후속 DEN-284 범위로 남겼다.
