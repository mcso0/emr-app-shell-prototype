현재 Linear 프로젝트:
- CLAiR EMR Billing Data Model & RPC Hardening
- Project URL: https://linear.app/deny-93/project/clair-emr-billing-data-model-and-rpc-hardening-ac0037c18691

프로젝트 목표:
- 보호자 중심 수납 UX에서 확정된 수납이력, 합산 checkout, 완료/취소 합산 제외, 상태 전환, 결제 배분 요구를 DB/RPC 계약과 검증 가능한 migration 계획으로 정리한다.

중요 배경:
- 차트 `Order 청구`는 이미 수납 요청이다.
- 수납이력 날짜 기준은 “수납으로 오더가 넘어온 일자”가 되어야 한다.
- 수납 화면에서는 완료/취소 건도 선택해서 세부 내역을 볼 수 있어야 한다.
- 단, 완료/취소 건은 현재 수납 요약 금액에 합산되면 안 된다.
- 완료 -> 대기 / 미납 / 취소, 취소 -> 대기 / 미납 / 완료 상태 전환은 실사용 DB에서는 audited RPC가 필요할 수 있다.
- 여러 환자/여러 청구서를 한 보호자 checkout으로 묶으려면 checkout session과 payment allocation이 필요하다.

주의:
- production deploy 금지
- 실데이터 import 금지
- remote Supabase migration push 금지

- 기존 dirty worktree가 많으니 관련 파일만 건드리고 unrelated 변경 revert 금지

3. 부족한 DB/RPC 항목을 DEN-371~DEN-381과 연결해서 정리해줘.
4. 비개발자도 이해할 수 있는 짧은 HTML 결과 보고서를 남기고 Linear를 Human Review로 넘겨줘.
