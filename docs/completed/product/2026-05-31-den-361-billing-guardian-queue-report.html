Billing Guardian Queue Report

DEN-361 changes the billing side-panel queue from the older 대기 / 미납 / 종료 wording to a guardian-centered work queue: 수납대기 / 미납 / 완료. The left queue now explains who should pay, which patient the bill belongs to, how many billable order lines are included, how much is due, and when the request was last created or issued.

큐 상태 기준

Same-day payable items are 수납대기, not 미납.

  • 수납대기: payable draft/issued invoices that are not terminal and do not have an unpaid reason/state.
  • 미납: invoices with an explicit unpaid/failed payment state or unpaid reason.
  • 완료: paid, refunded, or voided invoices.
  • This keeps old issued rows from being misread as overdue before DEN-366 adds richer unpaid semantics.

변경 내용

  • Updated side-panel group labels to 수납대기, 미납, and 완료.
  • Added reason-backed unpaid classification in src/features/billing/data.ts.
  • Queue rows now lead with guardian name and explicit billing state badge.
  • Rows show patient chip, billable order-line count, payable/unpaid amount, invoice number, encounter number, and request/update time.
  • Billing header waiting/unpaid summary now uses the same queue classification so issued without unpaid reason remains waiting.
  • Existing invoice selection, candidate readback, row action menu, and payment panel behavior were preserved.
