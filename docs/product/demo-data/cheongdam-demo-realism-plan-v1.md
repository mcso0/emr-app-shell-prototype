# 청담 시연 데이터 현실화 계획 v1

이 문서는 승욱이 검토하고 결정하기 위한 초안이다. 모든 환자, 보호자, 수치, 처방은 가상이다. 임상 수치와 용량은 일반적인 소동물 진료 범위를 참고해 작성했다. 수의학적 정확성은 아직 검토받지 않았다.

## 1. 목적과 원칙

- **목적:** 청담 워크스페이스를 "6개월째 운영 중인 병원"처럼 보이게 한다. 시연에서 어느 화면을 열어도 실제 진료 기록처럼 보여야 한다.
- **범위:** `workspace-clair-cheongdam` 하나만 다룬다.
- **만드는 방식:** 과거 진료는 앱의 실제 처리 함수로 재생한다(접수 → 차트 → 오더 → 수행 → 수납). 그 뒤 기록 시각만 과거로 옮긴다. 2026-11-28에 한 내원으로 검증했다.
- **원칙 1:** 화면에 "합성", "검증용", "테스트" 같은 문구가 보이지 않게 한다.
- **원칙 2:** 환자마다 시간 순서가 맞는 이야기를 갖는다. 수치는 진단과 치료 경과에 맞게 변한다.
- **원칙 3:** 실제 사람, 실제 병원, 실제 환자 정보는 쓰지 않는다.

### 3.2 오더 카탈로그

정비 범위는 A안으로 확정했다(8장 결정 1).

- **A안 (확정): 일괄 규칙 + 핵심 항목 수작업**
  - 전체 항목에 일괄 적용: 테스트 문구 제거, 가격 100원 단위 정리, 수납 기준 입력(회당 청구, 과세 구분).
  - 시연에 쓰는 핵심 항목 약 70개는 이름, 가격, 기본 지시 문구를 직접 다듬는다.
- **B안 (채택 안 함): 핵심 항목만 남기기**
  - 시연에 쓰는 약 100개만 활성으로 두고 나머지는 비활성으로 돌린다. 화면은 깔끔하지만 "오더가 많은 병원" 느낌은 줄어든다.

| 아리 | 노르웨이 숲, 8세 | 털 관리(D-130), 노령묘 건강검진(D-30) |

- 내원 합계: 대표 환자 약 55건 + 일반 환자 약 30건 = **약 85건**
- 6개월간 수납 합계는 약 1,300만 원 수준이다. 실제 1차 병원 매출보다 훨씬 작다. "병원 전체 매출"을 보여주려면 일반 환자를 더 늘려야 한다(8장 결정 5).

## 6. 시연 당일 화면 구성

과거 기록만 있으면 운영 중인 병원처럼 보이지 않는다. 시연일(D) 화면을 이렇게 채운다.

| 구분 | 구성 |
|---|---|
| 예약 | 오전 4건, 오후 5건. 수의사 6명에게 분산 |
| 접수 대기 | 2마리 (예: 두부 재진, 신규 내원) |
| 진료 중 | 2마리 (예: 레오 정기 추적, 콩이 귀 재진) |
| 검사·영상 진행 | 혈액검사 대기 1, 초음파 진행 1 |
| 처치·조제 | 조제 대기 1, 처치 진행 1 |
| 수납 대기 | 1마리 |
| 오늘 완료 | 3마리 |
| 다가오는 예약 | 향후 2주에 12건 (재진, 접종, 수술) |
| 알림 | 오늘 업무에서 자연스럽게 생긴 알림만 남긴다 |

- 날짜는 모두 시연일 기준 상대값으로 관리한다.
- 시연 전에 "오늘 상태"만 다시 만드는 재설정 스크립트를 둔다. 과거 기록은 그대로 둔다.

## 7. 기술 검증 상태

| 항목 | 상태 |
|---|---|
| 접수 → 차트 → 진단 → 서명 | 운영 DB에서 재생 검증됨 |
| 진찰·검사·영상·처치 오더와 수행 | 검증됨 |
| 수납 완료 | 검증됨. 단, 수납 기준과 부가세 정책이 설정돼 있어야 한다 |
| 조제 | 미검증. 약품 목록 정비 후 시험 |
| 입원, 수술, 예약, 오더 세트 | 미검증 |
| 과거 날짜로 옮기기 | 한 내원으로 검증됨(18개 테이블 31행). 내원 안의 단계별 시간 간격과 청구서 번호의 날짜는 추가 설계가 필요하다 |
| 이미지 첨부 | 운영 DB에 반영됨 (15장). 운영 화면의 검색 카드와 차트에서 확인됨 |
| 테스트 데이터 삭제 | 스크립트 준비됨. 미실행 |
