# 총괄 지시사항 — PRD

이 문서는 2026-11-01까지의 논의와 **최종 HTML 시안 v45**를 정리한 제품 기획이다. 확정한 화면 결정과 이번에 보완한 제품 제안을 구분한다. **이 문서 자체가 원격 DB 변경·배포 권한을 부여하지 않는다.** 별도 승인된 로컬 구현과 검증은 PR-012에 기록한다. 기존 경구제 기록의 당시 적용 범위는 보존한다.

- 구현 조사와 단계별 계획: [총괄 지시사항 구현 계획](../../../engineering/architecture/overall-instructions-implementation-plan.md)
- 이후 사용자가 로컬 구현을 승인했다. 작성·저장·수행 확인·알림의 로컬 구현과 합성 검증은 [PR-012](../../../work/clinical-fulfillment/CLINICAL-FULFILLMENT-PR-012-overall-instructions.md)에 기록한다. 실제 차트 진입점과 수행 경로를 연결했고, DB 마이그레이션은 격리된 합성 환경에서 검증했다. 원격 적용·배포의 최신 결과는 [PR #1033](https://github.com/mcso0/emr-app-shell-prototype/pull/1033)에 기록한다. 병원 사용자 수용 검증은 별도다.
- 화면과 상태별 세부 규칙: [총괄 지시사항 상세 기획](../../../design/screens/chart/specs/overall-instructions.md)
- 리뷰 대상: [v45 시안](https://spare-thumbnail-consultation-circles.trycloudflare.com/?open=1&v=45&instructions=saved)
- 시안은 합성 데이터로 동작한다. `적용`은 브라우저 메모리만 바꾸며, 새로고침하면 초기 상태로 돌아간다.
- 공유 링크는 임시다. URL의 `v=45`는 캐시 구분값이며 독립된 불변 버전을 보장하지 않는다. 문서 작성 시점의 파일 지문은 상세 기획에 기록했다.

## 1. 문서의 판단 기준

| 구분 | 의미 |
| --- | --- |
| UI 확정 | 사용자가 대화에서 명시적으로 선택했고 최종 시안에 반영한 화면·상호작용 |
| 정책 확정 | 사용자가 명시적으로 승인한 제품 규칙. 앱 구현·DB 변경·배포 승인은 별도 |
| 시안 확인 | 현재 HTML에서 관찰한 동작. 서버 저장이나 실제 앱 동작의 증거는 아님 |
| 제품 권장안 | 이번 문서에서 적용 이후 흐름과 제품 구현 조건을 구체화한 제안 |
| 결정 필요 | 원안에서도 제안이었거나 최종 시안만으로 임상·권한 정책을 확정할 수 없는 항목 |

화면 시안의 수용은 수행 상태 전환, 권한 변경, 알림 전송이나 데이터 이전의 승인을 뜻하지 않는다.

## 2. Goal — 목적

수의사가 현재 차트의 공통 지시를 한곳에서 작성·수정하고, 수행자가 자신의 오더에 해당하는 현재 지시와 과거 지시를 구분해서 확인하게 한다.

사용자는 다음 질문에 답할 수 있어야 한다.

- 이 지시는 어느 차트와 어느 오더 분류에 적용되는가?
- 내가 방금 적용한 내용이 저장되었는가?
- 이전 내용과 무엇이 달라졌고, 누가 언제 바꿨는가?
- 수행 화면이 보여 주는 내용은 최신 지시인가, 요청·완료 당시 지시인가?

## 3. Users — 사용자

| 사용자 | 필요한 행동 | 제한 |
| --- | --- | --- |
| 작성 가능한 수의사 | 전체·분류별 지시 작성, 수정, 삭제, 이력 조회 | 기존 chart:update 권한과 서버의 차트·오더 상태 조건을 유지 |
| 조제·처치·검사 등 수행 담당자 | 자기 작업의 지시와 변경 전후 내용 확인 | 차트 전체 편집 권한을 새로 부여하지 않음 |
| 조회 권한 사용자 | 현재 지시와 이력 조회 | 추가·삭제·적용 불가 |

현재 경구제 API의 `chart:view`·`chart:update`와 수의사 전용 제품 조건이 같은지는 별도 확인한다. 이 문서로 정식 권한 정책을 바꾸지 않는다.

## 4. Scope — 범위

### 포함

- Plan/Order의 단일 `총괄 지시사항` 진입점.
- 전체 오더 지시와 분류별 지시의 추가·작성·삭제·일괄 적용.
- 적용 성공, 실패, 충돌, 결과 미확인 상태와 재진입 흐름.
- 작성자·시각과 변경 전후 이력 조회.
- 실제 수행 화면에 전달해야 할 정보와 검증 조건.
- 기존 `경구제 전체 지시`를 `조제 지시`로 통합하는 요구사항과 과거 기록 보존.

### 제외

- 세트 공통 지시와 개별 오더 지시의 편집 위치 변경.
- 용량·횟수·투여 경로 등 구조화된 오더 값 변경.
- 수행 완료·담당자·수행 결과·청구·수납 상태의 자동 변경.
- 임상적 문구 해석, 상충 지시의 자동 판단, AI 지시 생성.
- 실환자 데이터 검증, 외부 알림 실제 발송, 원격 DB 변경, 앱 구현·출시.

## 5. 지시 범위

| 범위 | 적용 대상 | 작성 위치 |
| --- | --- | --- |
| 전체 오더 지시 | 같은 병원/workspace의 현재 차트에 속한 유효 확정 오더 | 총괄 지시사항 |
| 분류별 지시 | 같은 차트에서 해당 분류에 속한 유효 확정 오더 | 총괄 지시사항 |
| 세트 공통 지시 | 해당 세트의 구성 오더 | 기존 위치 유지 |
| 개별 오더 지시 | 오더 하나 또는 세트의 특정 구성 오더 | 기존 위치 유지 |
| 조제 지시 | 현재 차트의 모든 조제 분류 오더 | 총괄 지시사항의 조제 지시 입력란 |
| 처치 지시 | 현재 차트의 모든 처치 분류 오더 | 총괄 지시사항의 처치 지시 입력란 |

- **정책 확정 D-01 (2026-11-01): 같은 차트에서 이후 확정되는 오더에도 최신 지시를 자동 적용한다.** 전체 지시는 모든 분류에, 분류별 지시는 해당 분류에만 적용한다. 미확정 오더는 확정되는 시점부터 적용한다.
- 같은 환자라도 다른 차트에는 자동 상속하지 않는다.
- 이후 오더에 최신 지시를 적용해도 기존 작업의 요청·완료 당시 지시 기록은 덮어쓰지 않는다.
- 표의 현재 분류 필터와 체크한 행은 총괄 지시 범위를 바꾸지 않는다.
- 분류 후보는 `진료·임상·영상·원외검사·조제·처치·입원·기타`다. 최종 판정은 확정 오더의 분류로 한다. 수행 모듈명으로 대신 판정하지 않는다.
- 세트의 자식이 서로 다른 분류라면 자식별 분류를 적용한다.
- `전체 → 분류 → 세트 → 개별`은 표시 순서다. 뒤의 문구가 앞의 문구를 자동 무효화하지 않는다.
- `system_exam` 등 차트 안에서 처리하는 유형을 분류·대상 계산에서 빠뜨리지 않는다. 실제 분류 매핑은 구현 전 결정 항목이다.

## 6. UI 확정 사항

| ID | 확정 내용 |
| --- | --- |
| UI-01 | 저장된 지시가 없으면 가운데 정렬한 범위 선택 화면으로 시작한다. 아이콘 박스를 유지한다. 전체 오더와 분류를 고른 뒤 해당 입력란을 연다. 전체 지시 작성은 필수가 아니다. |
| UI-02 | 입력란 아래에 전체 폭의 점선 `+ 지시 추가` 영역을 둔다. 배경은 투명하고 글자색은 옅게 한다. 오른쪽 화살표는 없다. 누르면 버튼과 같은 폭·좌우 정렬의 메뉴를 연다. |
| UI-03 | 확정 오더가 있는 분류 중 아직 추가하지 않은 분류만 선택할 수 있다. 삭제한 전체 지시도 재추가할 수 있다. 선택 후 메뉴를 닫고 새 입력란에 포커스를 둔다. 다른 입력은 유지한다. |
| UI-04 | 전체·분류 입력란 모두 삭제할 수 있다. 저장된 본문 삭제는 적용 전까지 `삭제 예정`이며 개별 되돌리기를 제공한다. 입력란과 삭제 예정이 모두 없어지면 범위 선택 화면으로 돌아간다. |
| UI-05 | 불필요한 오더 개수·상태 라벨·반복 설명·환자 정보를 다이얼로그 안에 추가하지 않는다. |
| UI-06 | 제목은 `총괄 지시사항`, ×는 우측 상단. 제목 아래 설명과 헤더 하단 보더는 없다. 입력 섹션 위 여백은 4px다. |
| UI-07 | 푸터 왼쪽은 `변경 이력` 고스트 버튼. 오른쪽은 아웃라인 `취소`와 주요 `적용` 버튼. 세로 디바이더는 없다. 범위 선택 첫 화면에서는 오른쪽 버튼을 숨긴다. |
| UI-08 | 데스크톱 다이얼로그는 560×560px. 추가·삭제·빈 상태에서도 외곽 크기를 유지하고 본문만 스크롤한다. 작은 화면에서는 뷰포트 안으로 크기를 제한한다. |
| UI-09 | 변경 이력 버튼은 항상 표시하고 이력이 없으면 비활성화한다. 현재 본문을 모두 삭제해도 과거 이력이 있으면 활성화한다. |
| UI-10 | 작성자·시각과 높이 조절 손잡이를 입력란 하단 한 줄에 배치한다. 최대 5,000자이며 4,500자부터 글자 수를 표시한다. |
| UI-11 | 삭제 예정은 중립 색상·삭제 아이콘·되돌리기로 표시한다. 입력란·추가 영역의 좌우 끝을 제목과 푸터 버튼에 맞춘다. |
| UI-12 | 이력은 날짜·시각 다음 작성자 순서다. 내부 버전 번호를 노출하지 않고 최초·변경·삭제·재작성을 구분한다. |
| UI-13 | 이력 전후는 데스크톱 좌우, 모바일 위아래로 비교한다. 날짜는 `2026. 10. 31 10:15` 형식이다. |
| UI-14 | 첫 화면의 범위 선택·취소 등 보조 버튼은 아웃라인이다. 실제 CLAiR 컴포넌트·토큰을 재사용한다. 저장 테스트 영역은 숨기고 제품 화면에 포함하지 않는다. |


## 7. Requirements — 제품 동작

### R-01. 진입과 편집 가능 여부

유효 확정 오더가 없으면 신규 작성 진입을 막는다. 조회 중·조회 실패를 오더 없음과 구분한다. 서버도 적용 시 확정 오더, 차트 상태, 권한을 다시 검사해야 한다.

읽기 권한만 있는 사용자와 서명된 차트는 조회 전용으로 처리하는 기존 경계를 유지한다.

**정책 확정 D-02 (2026-11-01): 현재 차트의 모든 오더가 완료되면 총괄 지시사항을 조회 전용으로 전환한다.** 현재 지시와 변경 이력은 볼 수 있지만, 일반 추가·수정·삭제·적용은 허용하지 않는다. 완료 당시 지시 기록은 보존한다. 정정이 필요하면 기존 정정 절차를 따르며, 이 결정으로 새로운 정정 권한이나 절차를 만들지 않는다.

**정책 확정 D-03 (2026-11-01): 현재 차트의 모든 오더가 취소되면 새 지시 작성과 일반 수정은 막고, 이전 지시와 변경 이력의 조회는 유지한다.** 조회 전용 상태에서는 추가·삭제·적용도 허용하지 않는다. 오더 취소를 이유로 기존 지시나 요청·완료 당시 기록을 삭제하지 않는다.

### R-02. 초안과 적용

여러 범위를 수정한 뒤 `적용` 한 번으로 묶어서 저장한다. 원자적 저장, 즉 **전부 반영하거나 전부 실패**하는 방식을 제품 권장안으로 삼는다. 같은 내용으로 불필요한 이력을 만들지 않는다. 실패·충돌 때 작성 중 내용을 자동 교체하지 않는다.

전체 오더 지시를 먼저 작성해야 하는 제한은 없다. 필드별 최대 5,000자를 기준으로 하며, 공백만 있는 본문은 유효한 지시로 보지 않는다. 빈 내용과 삭제의 처리 차이는 상세 기획에 명시한다.

### R-03. 적용 이후 — 제품 권장 흐름

1. 변경·권한·내용을 검사한다. 저장할 변경이 없으면 적용을 비활성화한다.
2. 적용 중에는 중복 제출과 초안 변경을 막고 `적용 중…`을 표시한다.
3. 서버가 모든 변경의 저장 성공과 최신 버전을 반환하면 해당 차트의 현재 지시 상태를 갱신한다.
4. 다이얼로그를 닫고 원래 Plan/Order 문맥으로 돌아간다. 분류 필터·선택한 오더·표 스크롤은 유지한다.
5. 진입 버튼으로 키보드 포커스를 돌려주고 성공 토스트를 한 번 표시한다.
6. 같은 차트의 연결 화면은 관련 지시를 갱신한다. 실패한 화면을 최신 상태인 것처럼 표시하지 않는다.
7. 다시 열면 서버에서 확인된 최신 내용·작성자·시각·이력을 보여 준다. 변경 전 초안이나 삭제 전 본문을 되살리지 않는다.

성공 토스트 권장 문구는 **`지시사항을 적용했습니다.`**다. 삭제만 적용한 경우에도 같은 성공 원칙을 사용한다. 오더 개수·내부 버전·`(시안)`은 실제 제품 토스트에 넣지 않는다. 이 문구는 이번 문서의 제안이며 HTML v45의 문구를 변경하지 않았다.

**토스트는 저장 완료 알림이다.** 작업 요청, 수행 완료, 담당자의 읽음·확인, 알림 수신 성공을 뜻하지 않는다. 저장 성공 뒤 자동으로 수행 화면을 열거나 작업을 시작하지 않는다.

### R-04. 실패·충돌·결과 미확인

| 결과 | 사용자에게 보이는 상태 | 다음 행동 |
| --- | --- | --- |
| 저장 실패가 확정됨 | 다이얼로그 유지, 입력·삭제 예정 유지, 인라인 오류 | 원인 해결 후 같은 변경을 재시도 |
| 다른 사용자의 변경과 충돌 | 내 초안과 서버 최신 내용 비교, 적용 잠금 | 범위별 선택·검토 후 최신 기준 버전으로 재적용 |
| 서버 저장 여부를 알 수 없음 | 성공도 실패도 단정하지 않는 `적용 결과를 확인하지 못했습니다.` | 요청 결과 확인 후 성공으로 정리하거나 재시도 |
| 저장은 성공했지만 다른 화면 갱신이 실패함 | 저장 성공은 유지, 해당 화면에는 최신화 실패 안내 | 지시 다시 조회. 저장을 반복하지 않음 |
| 적용 직전 권한 상실·차트 잠김·대상 소멸 | 적용 차단과 원인 안내 | 허용되는 조회/복구 행동만 제공. 민감한 초안을 다른 병원·차트에 노출하지 않음 |

불확실한 결과에 무조건 `적용하지 못했습니다`라고 표시하면 중복 이력과 중복 알림을 만들 수 있다. 같은 요청 식별자로 결과를 확인하고 재시도해도 효과가 중복되지 않게 설계한다.

### R-05. 이력과 과거 기록

현재 지시, 변경 이력, 요청·완료 당시 지시, 담당자의 명시적 확인 기록은 다른 정보다. 과거 기록은 최신 문구로 덮어쓰지 않는다. 삭제 역시 이전 내용과 행위자·시각을 보존한다. 기록이 없는 과거 작업에는 `당시 지시 기록 없음`을 표시한다.

### R-06. 수행 화면으로 전달

전체 지시 변경은 해당 차트의 영향을 받는 진행 작업에, 분류 지시 변경은 그 분류의 진행 작업에만 반영한다. 다른 차트·병원·분류에 새 변경 표시를 퍼뜨리지 않는다.

조제·처치의 지시서와 임상·영상의 수행 화면은 읽기 경로가 다르다. 각 실제 경로에서 현재 지시, 변경 전후, 과거 기록의 연결을 확인해야 한다. 진료·입원·기타·원외검사는 실제 지원 수준과 수행 위치를 먼저 확인한다.

**정책 확정 D-04 (2026-11-01): 변경된 최신 지시가 있는 작업은 담당자가 해당 버전을 명시적으로 확인한 뒤 시작·완료한다.** 같은 버전을 이미 확인했다면 반복해서 묻지 않고, 새 변경이 생기면 다시 확인한다. 기존 수행 내용·완료 기록은 지우지 않는다.

페이지 진입 시 자동 팝업이나 별도 상단 안내 줄을 추가하지 않는다. 기존 지시사항 Info bar의 제목 옆에 `변경됨`을 표시하고, 제목 줄 오른쪽에는 `변경 내용 확인`, 맨 오른쪽에는 기존 ×를 둔다. 기존 변경 이력 버튼이 그 자리에 있으면 미확인 변경이 있을 때만 그 버튼의 이름과 동작을 전환한다. 비교 다이얼로그의 `최신 지시 확인`으로 확인을 기록하며, 미확인 상태에서 시작·완료를 누르면 같은 비교 다이얼로그를 연다.

×는 Info bar를 잠시 숨길 뿐 확인 처리하지 않는다. 다시 볼 수 있는 경로를 유지하고 새 변경이 생기면 다시 표시한다. 확인 후에는 `변경됨` 표시를 해제하고 일반 변경 이력 조회로 돌아간다. 별도 앱 내 알림은 아래 확정 정책 D-05를 따른다. **이 확정 흐름은 문서에 반영했으며 HTML v45와 실제 앱에는 아직 구현하지 않았다.**

수행자의 확인 흐름은 **페이지 진입 시 화면 안에서 안내 → 변경 전후 비교와 명시적 확인 → 미확인 시작·완료 시 같은 확인 다이얼로그 제공**의 세 단계다. 페이지를 둘러보는 것만으로 자동 팝업을 띄우지 않고, 실제 수행 행동 전에 최신 버전을 확인하게 한다. 여기서 상단 안내는 기존 Info bar의 `변경됨` 표시와 `변경 내용 확인` 버튼을 뜻하며 별도 배너나 설명 줄을 추가하지 않는다.

**정책 확정 D-05 (2026-11-01): 영향받는 미완료 작업의 담당자에게 기존 앱 내 알림을 보낸다.** 같은 담당자가 같은 차트의 여러 작업을 맡고 있어도 한 번의 적용당 알림 1건으로 묶는다. 관계없는 분류와 이미 완료된 작업에는 보내지 않는다. 알림을 누르면 해당 작업으로 이동한다. 알림을 열거나 읽음 처리한 사실은 최신 지시를 명시적으로 확인한 기록과 별개다.

알림은 저장 성공이 확정된 변경에만 연결하고 재시도로 중복 생성하지 않는다. 이번 승인은 앱 내 알림에 한정하며 외부 메시지·이메일·문자 발송 승인이 아니다. 미배정 작업의 수신자, 배정 변경 시점과 여러 대상 작업 중 이동할 작업 선택은 구현 준비에서 세부 규칙을 정한다. 이 결정으로 실제 알림을 보내거나 앱을 수정하지 않는다.

### R-07. 기존 경구제 전체 지시를 조제 지시로 통합

**정책 확정 D-06 (2026-11-01): 기존 `경구제 전체 지시` 기능을 총괄 지시사항의 `조제 지시`로 통합한다.** 조제 지시는 현재 차트의 모든 조제 오더에, 처치 지시는 모든 처치 오더에 전달한다. 적용 대상은 오더 분류로 판정한다. 새 조제 지시를 경구 투여(PO) 오더만의 지시로 제한하지 않는다.

새 화면에는 `기존 경구제 지시`라는 별도 영역이나 `조제 지시로 복사하여 검토` 단계를 두지 않는다. 앞서 제안한 별도 PO 범위 유지·초안 복사 방식은 이 결정으로 대체한다. v45에 남아 있는 기존 지시 조회·복사 UI는 확정 기획과의 차이로 기록한다.

기존 내용·변경 이력과 요청·완료 당시 기록은 보존한다. 통합 후의 현재 조제 지시 범위와 과거 기록 당시의 범위를 구분하며, 과거 기록을 모든 조제 오더에 적용됐던 것처럼 소급 변경하지 않는다. 실제 저장 구조와 데이터 이전 절차는 구현 계획에서 정한다. 이후 승인된 로컬 구현은 수의사가 새로 적용하기 전까지 기존 PO 범위를 유지한다. 원격 데이터 이전은 수행하지 않았다.

정량적인 작업 시간·오류 감소·임상 효과는 아직 측정하지 않았다. 로컬 구현·합성 검증은 병원 사용자 검증을 대신하지 않는다.

UI, 저장·이력, 수행 화면 연결, 동시성·권한 검증을 나누어 계획하되, 사용자에게 저장 성공을 보장하려면 필요한 서버 구현을 생략하지 않는다.

## 2026-11-01 후속 정책 확정

- 기존 경구제 문구는 원래 PO 적용 범위를 유지한다. 수의사가 조제 지시로 새로 적용한 시점부터 조제 전체에 전달한다. 과거 기록의 적용 범위는 바꾸지 않는다.
- 완료·취소가 섞여도 진행할 확정 오더가 없으면 조회 전용이다. 새 미완료 오더가 확정되면 기존 권한·차트 상태 조건 아래 편집을 다시 허용한다.
- 수행 확인은 사용자·차트·해당 지시 버전 기준으로 재사용한다. 다른 사용자 확인으로 대체하지 않는다. 기존 요청자의 완료 권한은 유지한다.

## 로컬 구현 기록

로컬 구현은 작성 화면, 다범위 저장·삭제·이력, 차트 이동 시 초안 보호, 수행 전 명시적 확인, 요청·완료 당시 스냅샷, 앱 내 변경 알림을 포함한다. 최초 지시와 삭제 변경도 확인 대상이다. 같은 사용자의 해당 차트·버전 확인만 재사용한다. 확정과 동시에 완료되는 오더는 확정 전에 저장된 오더 기준으로 확인한다.

알림은 기존 활성 개별 담당자와 세트 주 담당자에게 전달한다. 미배정 작업에는 임의의 수신자를 만들지 않는다. 한 적용의 같은 수신자는 중복하지 않고, 해당 작업의 운영 날짜와 선택 ID로 이동한다. 알림 읽음은 수행 확인을 대신하지 않는다. 검증 범위와 원격 적용 전 조건은 PR-012를 따른다.
