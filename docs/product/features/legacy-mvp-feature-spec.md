## 1. Product Context

### One-line Definition

동물병원 전용 EMR SaaS 서비스

### MVP Goal

중대형 동물병원의 기본 진료 흐름인 보호자/환자 등록, 접수, 진료, SOAP 차트, 처방, 업무 오더, 오더 수행, 기본 수납을 하나의 encounter 중심 워크플로우로 연결합니다. MVP는 병원 운영의 가장 빈번한 일상 업무를 안정적으로 처리하고, 이후 장비 연동, 입원, 메시징, 운영 분석, 마이그레이션을 확장할 수 있는 데이터 구조와 권한 기반을 마련하는 데 집중합니다.

### Target Users

- 수의사
- 간호사
- 데스크 직원
- 병원 관리자
- 시스템 관리자

### Supported Devices

- Web: MVP의 주 사용 환경
- Mobile: 조회와 간단한 상태 확인 중심으로 후속 최적화

---

## 2. MVP Scope

### Included in MVP

- 보호자와 환자 기본 정보 등록 및 조회
- 개인정보 수집/이용 동의 기록
- 예약, 접수, 대기열, 담당 수의사 배정
- encounter 중심 진료 흐름 관리
- SOAP 차트 작성, 저장, 수정, 과거 차트 조회
- 진단명, 처방, 처방 변경 이력 관리
- 조제, 처치, 임상병리 검사, 영상 검사 오더 생성
- 간호사용 오더 큐, 오더 상태 변경, 수행 기록
- 검사/영상 결과의 수동 입력 및 파일 첨부
- 진료/오더 항목과 수가 및 가격 변경 이력 관리
- 기본 수납 항목 생성, 할인, 결제 상태, 환불 요청/확정 관리
- 메시지 템플릿과 발송 이력 기반
- 직원 계정, 역할, 기본 권한 관리
- 감사 로그와 민감 데이터 접근 이력

### Deferred After MVP

- 검사/영상 장비 자동 연동
- DICOM/HL7/API 기반 장비 인터페이스
- 입원 병동 대시보드와 입원/퇴원 상세 관리
- 카카오 알림톡 provider 자동 연동, 템플릿 승인/버전 관리
- 고급 운영 분석, 수익 분석, 재방문율 분석
- 기존 EMR 데이터 마이그레이션 도구
- AI 모델 학습용 데이터 파이프라인
- 약물 상호작용, 알레르기, 마약류 자동 경고
- 모바일 전용 UX 고도화

### MVP Success Criteria

- 접수부터 수납까지 한 환자의 내원 흐름을 끊김 없이 완료할 수 있다.
- 수의사는 환자 차트, 처방, 오더를 encounter 안에서 작성하고 조회할 수 있다.
- 간호사는 본인 또는 팀에 할당된 오더를 확인하고 상태를 변경할 수 있다.
- 병원 관리자는 최소 권한 기반으로 직원 접근 범위를 관리할 수 있다.
- 주요 변경 이력은 감사 로그로 남는다.

## 3. Feature List

### 3.1 보호자 및 환자 관리

> **Priority**: High | **Progress**: To Do | **Roles**: 데스크 직원, 수의사, 간호사, 병원 관리자 | **Devices**: Web

보호자와 환자의 기본 정보를 등록하고, 진료 접수와 차트 작성에서 공통으로 참조할 수 있는 기본 마스터 데이터를 제공합니다.

**Acceptance Criteria:**

1. 데스크 직원은 보호자 이름, 연락처, 주소, 메모를 등록하고 수정할 수 있어야 한다.
2. 데스크 직원은 환자 이름, 환자번호, 종, 품종, 성별, 생년월일 또는 추정 나이, 체중, 특이사항을 등록할 수 있어야 한다.
3. 한 보호자에게 여러 환자를 연결할 수 있어야 한다.
4. 환자 상세 화면에서 보호자 정보, 최근 내원, 최근 처방, 주요 메모를 확인할 수 있어야 한다.
5. 환자 또는 보호자 정보 변경 시 변경자와 변경 시각이 기록되어야 한다.
6. 개인정보 수집/이용 동의 여부, 동의 시각, 동의 문서 파일을 기록할 수 있어야 한다.
7. 환자 주의사항은 내부 직원용 잠금 메모로 관리하며 보호자-facing 화면이나 문서에는 기본 노출하지 않아야 한다.

#### 3.1.1 보호자 정보 관리

보호자 기본 정보 등록, 조회, 수정, 비활성화를 지원합니다.

#### 3.1.2 환자 정보 관리

환자 기본 정보와 진료에 필요한 주요 특이사항을 관리합니다. 내부 시스템 ID와 병원 직원이 보는 환자번호를 분리하고, 물림/할큄/예민함 같은 핸들링 주의사항은 기본 잠금 메모로 관리합니다.

#### 3.1.3 보호자-환자 관계 관리

보호자와 환자의 관계를 연결하고, 다중 보호자 또는 다중 환자 케이스를 확장 가능하도록 설계합니다.

---

### 3.2 접수, 예약 및 대기열 관리

> **Priority**: High | **Progress**: To Do | **Roles**: 데스크 직원, 수의사, 병원 관리자 | **Devices**: Web

예약 또는 현장 접수로 내원 건을 생성하고, 대기-진료중-진료완료-수납대기 상태를 관리합니다.

**Acceptance Criteria:**

1. 데스크 직원은 예약 일시, 내원 목적, 담당 수의사, 환자 정보를 입력해 예약을 생성할 수 있어야 한다.
2. 데스크 직원은 예약 건을 접수 처리하여 encounter를 생성할 수 있어야 한다.
3. 현장 방문 환자는 예약 없이 바로 접수하고 encounter를 생성할 수 있어야 한다.
4. 대기열은 환자명, 보호자명, 담당 수의사, 접수 시각, 상태를 표시해야 한다.
5. 환자 상태는 대기, 진료중, 진료완료, 수납대기, 완료, 취소 중 하나로 변경할 수 있어야 한다.
6. 상태 변경 이력은 변경자, 변경 시각과 함께 기록되어야 한다.
7. 예약 후 내원하지 않은 건은 노쇼 상태로 남기고 보호자/환자 이력에서 확인할 수 있어야 한다.

#### 3.2.1 예약 등록 및 변경

예약 생성, 수정, 취소, 노쇼 처리를 지원하되 MVP에서는 provider 연동 기반 자동 알림 발송을 포함하지 않습니다. 예약 가능 시간은 병원 영업시간/휴무일과 담당 수의사 스케줄을 기준으로 판단합니다.

#### 3.2.2 현장 접수

보호자/환자를 검색하거나 신규 등록한 뒤 바로 접수할 수 있습니다.

#### 3.2.3 진료 대기열

진료 상태별 환자 목록을 제공하고 담당 수의사 기준으로 필터링할 수 있습니다.

### 3.3 진료 Encounter 및 SOAP 차트

> **Priority**: High | **Progress**: To Do | **Roles**: 수의사 | **Devices**: Web

한 번의 내원 또는 진료 건을 encounter로 관리하고, SOAP 차트와 진단, 처방, 오더를 같은 맥락에서 작성합니다.

**Acceptance Criteria:**

1. 수의사는 대기열에서 환자를 선택해 encounter 진료 화면으로 진입할 수 있어야 한다.
2. 수의사는 Subjective, Objective, Assessment, Plan 필드를 구분해 SOAP 차트를 작성할 수 있어야 한다.
3. 차트는 저장, 수정, 임시 저장 상태를 지원해야 한다.
4. 과거 SOAP 차트는 환자 기준으로 시간순 조회할 수 있어야 한다.
5. 저장 후 24시간까지 수정 가능하며, 이후 차트 수정 시 수정 사유와 변경 이력이 기록되어야 한다.
6. encounter 화면에서 환자 기본 정보, 보호자 정보, 과거 이력, 현재 오더 상태를 함께 확인할 수 있어야 한다.

#### 3.3.1 Encounter 진료 화면

환자 컨텍스트, 진료 상태, SOAP 차트, 처방, 오더를 한 화면 흐름 안에서 제공합니다.

#### 3.3.2 SOAP 작성 및 저장

SOAP 필드를 구조화하고 임시 저장, 자동저장, 최종 저장, 수정 이력을 관리합니다.

#### 3.3.3 과거 진료 이력 조회

환자별 이전 encounter, SOAP 차트, 처방, 검사 결과, 오더 이력을 날짜순 타임라인과 항목별 필터로 조회합니다.

---

### 3.4 진단 및 처방 관리

> **Priority**: High | **Progress**: To Do | **Roles**: 수의사 | **Devices**: Web

수의사가 encounter 안에서 진단명과 약물 처방을 등록하고, 처방 변경 이력을 남길 수 있도록 지원합니다.

**Acceptance Criteria:**

1. 수의사는 진단명을 직접 입력하거나 등록된 진단명 목록에서 선택할 수 있어야 한다.
2. 수의사는 약물명, 용량, 용법, 투약 횟수, 투약 기간, 주의사항을 입력할 수 있어야 한다.
3. 처방은 작성 수의사 또는 진료 권한이 있는 수의사가 추가, 수정, 취소할 수 있어야 하며 수정/취소 시 사유를 기록해야 한다.
4. 처방 내역은 환자별 과거 처방 이력으로 조회할 수 있어야 한다.
5. 처방에서 조제 오더를 생성할 수 있어야 한다.

#### 3.4.1 진단명 입력

MVP에서는 직접 입력과 기본 검색을 지원하고, 자동 추천은 후속 범위로 둡니다.

#### 3.4.2 약물 처방 작성

약품명은 사전에서 선택하고 용량, 단위, 경로, 횟수, 일수, 수량, 복약 안내를 구조화합니다.

#### 3.4.3 처방 변경 이력

처방 추가, 수정, 취소 이력을 담당자와 시각 기준으로 남깁니다.

---

### 3.5 업무 오더 생성 및 관리

> **Priority**: High | **Progress**: To Do | **Roles**: 수의사, 간호사 | **Devices**: Web

수의사가 조제, 처치, 임상병리 검사, 영상 검사 오더를 생성하고, 간호사가 오더 큐에서 수행 상태를 관리합니다.

**Acceptance Criteria:**

1. 수의사는 encounter 안에서 조제, 처치, 임상병리 검사, 영상 검사 오더를 생성할 수 있어야 한다.
2. 오더는 대기, 진행중, 완료, 취소 상태를 가져야 한다.
3. 오더에는 우선순위, 담당자, 요청 메모, 생성자, 생성 시각이 기록되어야 한다.
4. 간호사는 오더 큐에서 타입, 상태, 우선순위, 담당자 기준으로 오더를 필터링할 수 있어야 한다.
5. 간호사는 오더 수행 결과와 메모를 기록하고 완료 처리할 수 있어야 한다.
6. 오더 변경과 취소는 변경 사유와 함께 이력으로 남아야 한다.
7. 오더 담당자는 직접 담당하기로 배정할 수 있고, 권한자는 담당자를 지정 또는 변경할 수 있어야 한다.
8. 검사/영상 오더는 수행 완료와 수의사 확인 상태를 분리해서 표시해야 한다.

#### 3.5.1 오더 생성

조제, 처치, 임상병리 검사, 영상 검사 오더 생성을 지원합니다.

#### 3.5.2 오더 큐

간호사용 업무 목록을 제공하고 상태별, 타입별, 우선순위별 필터링을 지원합니다.

#### 3.5.3 오더 수행 기록

오더 수행 시간, 담당자, 결과 메모, 완료 상태를 기록합니다.

#### 3.5.4 검사 및 영상 결과 수동 입력

MVP에서는 장비 자동 연동 대신 결과값 수동 입력, 첨부 파일 업로드, 판독 메모 입력을 지원합니다. 검사 담당자가 완료 처리하면 수의사의 차트 오더/처방 테이블에서 진행 상태와 결과를 확인할 수 있고, 수의사 확인 상태를 별도로 남깁니다.

---

### 3.6 기본 수납 관리

> **Priority**: High | **Progress**: To Do | **Roles**: 데스크 직원, 병원 관리자 | **Devices**: Web

진료, 처방, 오더에서 발생한 비용 항목을 encounter 기준으로 모아 기본 수납을 처리합니다.

**Acceptance Criteria:**

1. encounter에 연결된 진료 항목, 처방, 오더를 기준으로 청구 항목을 생성할 수 있어야 한다.
2. 데스크 직원은 청구 후보 항목의 금액, 수량, 할인 메모를 확인하고 최종 확정할 수 있어야 한다.
3. 결제 상태는 미수납, 청구확정, 수납완료, 환불요청, 환불완료 중 하나로 관리할 수 있어야 한다.
4. 결제 수단과 결제 시각, 담당자를 기록할 수 있어야 한다.
5. 수납 완료 시 encounter 상태를 완료로 변경할 수 있어야 한다.
6. 환불 확정은 병원 관리자 권한으로만 처리할 수 있어야 한다.

#### 3.6.1 청구 항목 생성

처방/오더에서 청구 후보 항목을 자동 생성하고, 진료 완료 후 수납 담당자가 최종 확정합니다.

#### 3.6.2 결제 상태 관리

MVP에서는 복잡한 회계, 세금, 정산, 부분 결제 없이 기본 결제 상태, 할인, 환불 기록에 집중합니다.

---

### 3.7 병원 설정, 직원 및 권한 관리

> **Priority**: High | **Progress**: To Do | **Roles**: 병원 관리자, 시스템 관리자 | **Devices**: Web

병원 운영에 필요한 기본 설정, 직원 계정, 역할 기반 접근 권한을 관리합니다.

**Acceptance Criteria:**

1. 병원 관리자는 병원명, 지점명, 연락처, 주소, 진료 시간을 설정할 수 있어야 한다.
2. 병원 관리자는 직원 계정을 생성하고 역할을 부여할 수 있어야 한다.
3. 역할은 수의사, 간호사, 데스크 직원, 병원 관리자, 시스템 관리자를 기본으로 제공해야 한다.
4. 병원 관리자는 진료/오더 항목과 기본 수가를 등록하고 수정할 수 있어야 한다.
5. 사용자는 본인 역할에 허용된 기능만 접근할 수 있어야 한다.
6. 민감 정보 조회, 차트 수정, 처방 취소, 오더 취소, 수납 변경은 감사 로그에 남아야 한다.
7. 메시지 템플릿과 발송 이력을 관리할 수 있어야 한다.

#### 3.7.1 병원 기본 설정

병원 프로필과 진료 시간 등 MVP 운영에 필요한 최소 설정을 제공합니다.

#### 3.7.2 직원 계정 관리

직원 등록, 역할 부여, 계정 활성/비활성 처리를 지원합니다.

#### 3.7.3 역할 기반 권한

MVP에서는 기본 역할별 권한 매트릭스를 제공하고, 세부 커스텀 권한은 후속 범위로 둡니다.

#### 3.7.4 감사 로그

환자 정보, 진료 기록, 처방, 오더, 수납 관련 주요 변경 이력을 기록합니다.

#### 3.7.5 진료 항목 및 기본 수가 설정

진료, 처치, 검사, 영상, 약품성 항목의 기본 이름, 카테고리, 가격과 가격 변경 이력을 관리합니다.

#### 3.7.6 메시지 템플릿 및 발송 이력

예약/접수/차례 안내와 진료 결과/복약 지도 등 메시지 템플릿과 발송 이력을 관리합니다. 실제 카카오 알림톡 provider 연동, 템플릿 승인 상태, 버전 관리는 후속 범위로 둡니다.

## 5. MVP Data and Workflow Notes

### Encounter 중심 데이터 연결

MVP의 핵심 업무 단위는 `encounter`입니다. 예약, 접수, SOAP 차트, 진단, 처방, 오더, 수납은 모두 encounter를 기준으로 연결합니다.

### 오더 수명주기

공통 오더 상태는 `대기 -> 진행중 -> 완료`이며, 예외적으로 `취소` 상태를 지원합니다. 취소와 수정에는 사유 기록이 필요합니다.

### 메시지 발송 정책

예약 안내, 접수 완료, 진료 차례 안내는 자동 또는 담당자 즉시 발송을 허용합니다. 진료 결과, 복약 지도, 수술 후 관리처럼 의료 내용이 포함된 메시지는 수의사 확인 후 발송합니다.

### 장비 연동 정책

MVP에서는 장비 자동 연동을 구현하지 않습니다. 임상병리 검사와 영상 검사는 오더 생성, 수행 상태 관리, 결과 수동 입력, 파일 첨부만 지원합니다.

### 보안 및 감사 로그

민감한 의료 정보와 개인정보를 다루므로 MVP부터 역할 기반 접근 제어와 감사 로그를 포함합니다.

## 2026-05-02 MVP Feature Realignment

### PR 0 Documentation Baseline

- PRD, Feature Spec, User Flow, DB 구조 문서, MVP gap/backlog를 현재 수집한 화면 흐름 기준으로 갱신한다.
- 공통화 후보는 `docs/archive/ui-notes/reusable-component-candidates.md`, 승인/정보 필요 항목은 `docs/work/open-questions.md`, 화면 레퍼런스는 `docs/design/reference-screen-index.md`에 둔다.

### PR 1 Domain Baseline

- `encounter` 중심 도메인 연결을 검수하고 환자-보호자 관계, consent, CS 이력, 최신 업무 바로가기, 검사/영상/수납 mock 연결을 보강한다.
- UI 변경은 포함하지 않는다.

### PR 2 Reception Closeout

- 접수/예약 사이드 패널을 `전체 / 접수 / 예약`으로 정리하고 숫자는 탭이 아니라 목록 헤더 개수로 표시한다.
- 캘린더는 24시간 표기, `08:00-20:00` 표시 범위, `09:00-19:00` 영업시간 강조, sticky header, 현재 시간선 위치 보정을 적용한다.
- 환자 정보바, 우측 사이드 패널, 별도 진료 대기열, 하단 스케줄 생성, 불필요한 접수 폼 바는 제거한다.
- 카드 클릭 시 접수/예약 상세 드로어로 진입할 수 있는 구조를 둔다.

### PR 3 Patient/Guardian Drawer

- 환자 정보, 보호자 정보, 보호자 연결 관리, CS 이력, 최신내역을 드로어 기반으로 제공한다.
- 읽기/수정 모드와 신규 환자 등록 모달/레이어를 mock 세션 상태로 처리한다.

### PR 4 Chart

- 진료(차트) 화면은 좌측 환자 과거 이력, 별도 진료 대기 사이드 패널, SOAP, Assessment, Assessment History, 하단 Order 영역으로 구성한다.
- 과거 이력 리스트는 조제 이력과 유사한 정보 밀도를 갖되 조제/처치 화면 자체는 수정하지 않는다.

### PR 5 Lab/Image

- 임상병리/계통 검사와 영상검사 화면을 구현한다.
- 검사 대기/완료, 결과 입력, 장비 수신 내역, 영상 판독, 종합소견, 첨부자료를 mock으로 연결한다.
- 장비/PACS 연동은 no-op으로 둔다.

### PR 6 Billing

- 수납 화면은 대기/미납/종료 목록, 보호자 기준 청구 묶음, 청구 항목 편집, 합산/해제, 결제 수단, 미납/수납 액션을 제공한다.

### Component Policy

- 프로젝트 기존 컴포넌트, foundation, token을 우선한다.
- 없는 패턴만 shadcn 또는 shadcn + 기존 컴포넌트 조합으로 만든다.
- 2개 이상 화면에서 반복되고 안정화된 패턴만 PR 이후 공통 컴포넌트로 추출한다.
