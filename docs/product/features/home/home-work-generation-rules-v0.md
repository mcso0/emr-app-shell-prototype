# Home Work Generation Rules v0

## Purpose

이 문서는 홈 화면의 `내 업무`에 어떤 항목을 올릴지 정의한다.

2026-07-05 note: this document remains the personal `내 업무` generation reference. For the hospital-wide `원내 현황` operations board, common status contract, work type generation table, and DB/API read-model direction, use `home-operations-work-status-contract-v0.md`.

홈의 `내 업무`는 사용자가 볼 수 있는 모든 정보가 아니라, 사용자에게 요청되었거나 사용자가 담당자로 지정된 action이다.

> 내 업무 = 나에게 요청되었거나 내가 담당자로 지정된 업무

업무의 시작은 환자 내원과 데스크 접수다. 이후 진료 흐름에서 발생하는 assignment, order, request, status transition이 각 역할의 홈 업무를 만든다.

## Event To Work Pipeline

```text
환자 내원/예약
→ 데스크 접수
→ 담당자/담당 role 지정
→ 진료, 검사, 조제/처치, 수납, 입원 request 발생
→ 사용자별 Task / Signal / Flow Issue 분류
→ 홈 내 업무 또는 notification으로 노출
→ 원본 업무 화면으로 진입
```

## Work Item Common Shape

홈 업무 카드는 최소한 다음 정보를 가진다.

| 필드 | 설명 |
|---|---|
| title | 업무 제목 |
| patientContext | 환자, 보호자, encounter 맥락 |
| source | 업무 발생 원인 또는 요청자 |
| requestedAt | 요청 시각 |
| dueAt | 마감 또는 확인 기준 시각 |
| priority | normal, high, urgent 등 업무 우선순위 |
| recommendedNextAction | 사용자가 다음에 할 일 |
| entryTarget | 진입할 원본 업무 화면 |
| completionRule | 홈 업무에서 사라지거나 완료되는 기준 |

홈은 업무를 최종 처리하지 않는다. 홈은 관련 업무 화면으로 이동시키는 entry surface다. 홈에서 제공하는 action은 `열기` 또는 `확인하러 가기` 정도로 제한한다.

## Priority Rule v0

정렬 기준:

1. 명시적으로 긴급 요청된 업무
2. Overdue 업무
3. 오늘 마감 또는 예정 시간 임박
4. 내가 담당자로 지정된 업무
5. 다른 직원이 요청한 업무

기본 노출은 상위 5-7개로 제한한다. 나머지는 필터 또는 전체 보기에서 확인한다.

## Assignment And Claim Rule v0

업무는 개인에게 직접 배정될 수도 있고, 특정 role queue에만 배정된 상태로 생성될 수도 있다.

Definitions:

| 상태 | 의미 | 홈 노출 |
|---|---|---|
| Assigned to user | 특정 담당자에게 배정됨 | 해당 사용자 `내 업무`에 표시 |
| Unassigned role work | 담당자는 없지만 담당 role이 정해짐 | 해당 role을 가진 모든 사용자 `내 업무`에 표시 |
| Claimed | 사용자가 업무 담당하기를 선택함 | claim한 사용자 `내 업무`에만 표시 |

Rules:

- 업무가 생성되었지만 assignee가 없고 담당 role만 있는 경우, 해당 role에 속한 모든 사용자에게 `내 업무`로 보여준다.
- 사용자가 원본 업무 화면에서 `업무 담당하기` 또는 claim을 하면 그 업무는 claim한 사용자의 개인 업무가 된다.
- Claim된 업무는 같은 role의 다른 사용자 `내 업무` 목록에서는 더 이상 보이지 않는다.
- Claim된 업무는 원본 group work list에는 계속 보인다.
- 원본 group work list에서는 담당자 상태를 함께 보여준다. 예: `미배정`, `박지현 처리중`, `완료`.
- Claim은 홈에서 하지 않는다. Claim은 원본 업무 흐름에서 담당자를 확정하는 assignment action이다.

Example:

```text
콩이 CBC 검사 요청 생성
assigneeUser = 없음
assigneeRole = 임상병리검사 담당

→ 임상병리검사 담당자 A/B/C의 홈 `내 업무`에 표시

담당자 B가 업무 담당하기
→ B의 홈에는 계속 표시
→ A/C의 홈 `내 업무`에서는 사라짐
→ 임상병리검사 group 업무 목록에는 `B 처리중`으로 유지
```

## Work Lifecycle And Removal Rule v0

홈 업무는 원본 workflow의 상태를 반영한다. 홈은 업무를 시작하도록 안내하지만, 담당자 확정, 완료, 취소, 보류 같은 상태 변경은 원본 업무 화면에서 처리한다.

Lifecycle:

```text
request/order/assignment 생성
→ 홈 내 업무에 노출
→ 사용자가 홈에서 원본 업무 화면 열기
→ 원본 업무 화면에서 claim, 진행, 완료, 취소, 보류, 담당자 변경
→ 홈 내 업무에서 유지, 제거, 또는 다른 사용자에게 이동
```

Home action policy:

| Action | 홈 허용 여부 | 처리 위치 |
|---|---|---|
| 열기 | 허용 | 홈 |
| 확인하러 가기 | 허용 | 홈 |
| 담당하기/claim | 비허용 | 원본 업무 화면 |
| 완료 처리 | 비허용 | 원본 업무 화면 |
| 취소/보류 | 비허용 | 원본 업무 화면 |
| 문자 발송/수납 완료/검사 확정 | 비허용 | 원본 업무 화면 |

Removal rules:

| 상황 | 홈 처리 |
|---|---|
| 원본 업무가 완료됨 | 해당 사용자의 `내 업무`에서 제거 |
| 원본 업무가 취소/보류됨 | `내 업무`에서 제거하거나 보류 상태로 약화 |
| 미배정 role 업무를 다른 사용자가 claim | 현재 사용자 `내 업무`에서 제거 |
| 사용자가 직접 claim | claim한 사용자 `내 업무`에 유지 |
| 담당자가 변경됨 | 이전 담당자 `내 업무`에서 제거, 새 담당자 `내 업무`에 표시 |
| 원본 workflow에서 재요청 발생 | 새 요청 업무로 생성 |

Area examples:

| 업무 | 홈에서 사라지는 기준 |
|---|---|
| 진료 대기 배정 | 진료 시작, 담당의 변경, 접수 취소 |
| 대기 안내 필요 | 보호자 안내 완료, 진료 시작, 귀가/취소 |
| 검사 요청 | 검사 진행/완료, 담당자 변경, 검사 취소 |
| 검사 결과 확인 | 수의사 확인 완료, 후속 오더 생성, 결과 invalid 처리 |
| 조제 요청 | 조제 완료, 보류/문의, 오더 취소 |
| 처치 요청 | 처치 완료, 일정 변경, 보류/문의 |
| 수납 요청 | 수납 시작/완료, 담당자 인계, 미수/보류 전환 |
| 입원 등록 요청 | 입원 등록 완료, 요청 취소 |

Principle:

> 홈은 업무 상태를 바꾸는 곳이 아니라, 원본 업무로 이동하는 곳이다.

## Area Rules

### Desk

데스크 업무는 접수, 대기, 보호자 응대, 서류 확인, 수납 연결에서 발생한다.

| 이벤트 | 발생 조건 | 내 업무 대상 | 우선순위 | 추천 다음 행동 | 진입 화면 | 완료 기준 |
|---|---|---|---|---|---|---|
| 예약 도착 확인 | 예약 시간이 임박했거나 지났지만 접수되지 않음 | 데스크 | normal/high | 도착 여부를 확인하고 접수 처리 | 예약/접수 | 접수 완료 또는 예약 상태 변경 |
| 현장 접수 생성 | 보호자/환자가 방문했지만 접수 form 미완료 | 데스크 | normal | 접수 정보를 입력하고 담당의/목적을 지정 | 예약/접수 | 접수 완료 |
| 서류 미완료 | 동의서, 문진표, 수술/입원 관련 서류 누락 | 데스크 | normal/high | 보호자에게 서류 완료 요청 | 접수/환자 | 서류 완료 또는 보류 처리 |
| 대기 30분 초과 | 접수 후 대기 30분 이상 | 데스크 | high | 보호자에게 예상 대기 안내 | 예약/접수 대기실 | 보호자 안내 완료, 진료 시작, 취소/귀가 |
| 수납 연결 필요 | 진료 완료 후 수납 요청이 생성됨 | 데스크 또는 수납 담당 | normal/high | 보호자를 수납 흐름으로 안내 | 수납 | 수납 진행 또는 담당자 인계 |

대기 지연은 단계형으로 escalation한다. 상세 기준은 `home-command-entry-planning.md`의 Waiting Delay Escalation을 따른다.

### Attending Veterinarian

진료 수의사의 내 업무는 담당의 지정 또는 다른 역할의 요청/재요청에서 발생한다.

| 이벤트 | 발생 조건 | 내 업무 대상 | 우선순위 | 추천 다음 행동 | 진입 화면 | 완료 기준 |
|---|---|---|---|---|---|---|
| 진료 대기 배정 | 내가 담당의로 지정된 접수/대기 환자 발생 | 담당 수의사 | normal/high | 환자 맥락을 확인하고 진료 시작 | 진료/차트 | 진료 시작 또는 담당의 변경 |
| 차트 작성 미완료 | 진료가 시작됐지만 SOAP/Assessment/Plan이 미완성 | 담당 수의사 | normal/high | 차트를 확인하고 기록을 마무리 | 진료/차트 | 작성 완료 또는 보류 처리 |
| 검사 결과 확인 | 검사 담당자가 결과 입력 후 완료 처리 | 담당 수의사 | normal/high | 결과를 확인하고 차트/보호자 설명에 반영 | 임상병리/영상검사 | 결과 확인 처리 또는 후속 오더 생성 |
| 검사/처치 재확인 결과 도착 | 내가 요청한 재확인/재검/처치 확인 결과가 완료됨 | 요청 수의사 | high | 재확인 결과를 보고 다음 처치를 결정 | 원본 검사/처치 화면 | 확인 완료 또는 추가 요청 |
| 대기 45분 초과 개입 | 담당 대기열에서 45분 이상 지연 발생 | 담당 수의사 | signal/high 조건부 | 진료 순서 조정 또는 데스크 전달 메시지 준비 | 진료 대기열 | 진료 시작, 순서 조정, 안내 메시지 작성 |

검사 수치만으로 홈 업무를 자동 생성하지 않는다. 임상 판단은 수의사가 하며, 시스템은 결과지에서 비정상 수치를 인지하기 쉽게 돕는다.

### Dispensing And Treatment Technician

조제/처치 업무는 수의사의 오더, 재요청, overdue 상태에서 발생한다.

| 이벤트 | 발생 조건 | 내 업무 대상 | 우선순위 | 추천 다음 행동 | 진입 화면 | 완료 기준 |
|---|---|---|---|---|---|---|
| 조제 요청 | 수의사가 처방/조제 오더를 확정 또는 요청 | 조제 담당 | normal/high | 처방 내용을 확인하고 조제 준비 | 조제/처치 | 조제 완료 또는 보류/문의 |
| 처치 요청 | 수의사가 처치 오더를 요청 | 처치 담당 | normal/high | 처치 내용을 확인하고 환자 상태를 준비 | 조제/처치 | 처치 완료 또는 보류/문의 |
| 조제/처치 재요청 | 수의사가 수정, 재확인, 재처치를 요청 | 조제/처치 담당 | high | 요청 사유를 확인하고 빠르게 재처리 | 조제/처치 | 재요청 완료 또는 수의사에게 문의 |
| 처치 overdue | 예정된 처치 시간이 지남 | 처치 담당 | high | 지연 사유를 확인하고 처치 가능 여부 판단 | 조제/처치 | 처치 완료, 보류, 일정 변경 |
| 투약/처치 변경 확인 | 수의사가 기존 오더 변경을 요청 | 조제/처치 담당 | high | 변경 내용을 확인하고 기존 준비 상태를 조정 | 조제/처치 | 변경 반영 또는 확인 완료 |

시스템은 투약/처치 판단을 대신하지 않는다. overdue, 요청, 재요청, 변경 요청 같은 workflow event가 홈 업무를 만든다.

### Lab And Imaging

임상병리/영상검사 업무는 진료 수의사의 검사 오더, 재요청, 결과 입력/완료에서 발생한다.

| 이벤트 | 발생 조건 | 내 업무 대상 | 우선순위 | 추천 다음 행동 | 진입 화면 | 완료 기준 |
|---|---|---|---|---|---|---|
| 검사 요청 | 진료 수의사가 임상병리 또는 영상검사를 요청 | 검사 담당 | normal/high | 검사 오더와 환자 맥락을 확인 | 임상병리/영상검사 | 검사 진행 또는 보류/문의 |
| 검사 결과 입력 필요 | 장비 연동 없음 또는 결과 수기 입력 필요 | 검사 담당 | normal/high | 결과를 입력하고 완료 처리 | 임상병리/영상검사 | 결과 입력 완료 |
| 검사 완료 처리 | 검사 담당자가 결과 입력 후 완료 | 담당 수의사 | normal/high | 결과를 확인하고 진료 판단에 반영 | 임상병리/영상검사 또는 차트 | 결과 확인 완료 |
| 긴급 전달 표시 | 검사 담당자가 긴급 확인 필요로 명시 | 담당 수의사 | urgent | 결과를 즉시 확인하고 후속 조치 판단 | 임상병리/영상검사 | 확인 완료 또는 후속 오더 |
| 재확인 요청 | 수의사가 결과 이상 또는 불일치로 재확인을 요청 | 검사 담당 | high | 검체, 장비, 입력값을 확인 | 임상병리/영상검사 | 재확인 완료 |
| 재검 요청 | 수의사가 재검을 요청 | 검사 담당 | high | 재검 가능 여부와 환자 준비 상태 확인 | 임상병리/영상검사 | 재검 완료 또는 보류/문의 |

장비와 EMR이 연결되지 않은 병원도 전제로 한다. 긴급 상황에서는 전화, 카톡, 구두 전달이 먼저 일어날 수 있으며, EMR은 외부 전달 사실과 후속 업무를 기록한다.

### Billing

수납 업무는 진료 완료, 중간 정산, 미수 또는 보류 상태에서 발생한다.

| 이벤트 | 발생 조건 | 내 업무 대상 | 우선순위 | 추천 다음 행동 | 진입 화면 | 완료 기준 |
|---|---|---|---|---|---|---|
| 수납 요청 | chart `Order 청구` 또는 진료 완료 후 수납대기 건이 생성됨 | 수납 담당 또는 데스크 | normal/high | 청구 항목과 보호자 정보를 확인 | 수납 | 수납 진행 또는 담당자 인계 |
| 중간 정산 요청 | 입원/수술/장기 진료 중 중간 정산이 필요함 | 수납 담당 | high | 현재 청구 항목과 보호자 안내 필요 여부 확인 | 수납 | 중간 정산 완료 또는 보류 |
| 수납대기 항목 확인 필요 | 차트에서 청구 요청된 항목이 수납대기에 있음 | 수납 담당 | normal/high | 보호자 기준으로 결제할 항목 묶음 확인 | 수납 | 수납 진행, 보류, 미납 처리 |
| 수납 대기 지연 | 수납 요청 후 기준 시간 이상 진행 없음 | 수납 담당 | high | 보호자 대기 상태와 청구 상태 확인 | 수납 | 수납 진행, 보류, 미수 전환 |
| 미수 처리 필요 | 결제 보류 또는 미납 상태 발생 | 수납 담당 | high | 미수 사유와 후속 안내를 확인 | 수납 | 미수 등록, 결제 완료, 담당자 인계 |

매출, 방문자 수, 전체 미수 KPI는 홈 기본 화면이 아니라 병원관리 메뉴에서 다룬다.

### Inpatient

입원 업무는 수의사의 입원 요청, 입원 중 케어 일정, 퇴원 관리에서 발생한다.

| 이벤트 | 발생 조건 | 내 업무 대상 | 우선순위 | 추천 다음 행동 | 진입 화면 | 완료 기준 |
|---|---|---|---|---|---|---|
| 입원 등록 요청 | 수의사가 입원을 요청 | 입원 담당 | high | 입원장 등록과 보호자 안내 상태 확인 | 입원 | 입원 등록 완료 또는 보류 |
| 입원 케어 예정 | 입원 환자에게 예정된 케어/투약/바이탈 확인 시간 도래 | 입원 담당 | normal/high | 케어 항목과 환자 상태 확인 | 입원 | 케어 완료 또는 보류/문의 |
| 입원 케어 overdue | 예정 케어 시간이 지남 | 입원 담당 | high | 지연 사유와 환자 상태 확인 | 입원 | 케어 완료, 일정 변경, 수의사 문의 |
| 수의사 재확인 요청 | 입원 중 상태 변화나 처치 후 수의사가 재확인을 요청 | 입원 담당 | high | 요청 사유와 확인 항목을 확인 | 입원 | 확인 완료 또는 수의사에게 회신 |
| 퇴원 관리 필요 | 퇴원 예정 또는 퇴원 체크리스트 미완료 | 입원 담당 또는 데스크 | normal/high | 퇴원 안내, 처방, 수납 연결 상태 확인 | 입원/수납 | 퇴원 체크 완료 |

## Notification Boundary

모든 notification이 홈 업무가 되지는 않는다.

Current notification implementation contract: `docs/product/features/notifications/global-notification-center-v0-contract.md`.

| 분류 | 홈 내 업무 | Notification |
|---|---|---|
| 나에게 요청된 action | 표시 | 표시 가능 |
| 내가 담당자로 지정된 action | 표시 | 표시 가능 |
| 참고용 상태 변화 | 기본 비표시 | 표시 가능 |
| 시스템 공지 | 비표시 | 표시 |
| 운영관리 공지 | 기본 비표시 | 표시 또는 병원관리 메뉴 |
| 병원 흐름 병목 | compact summary 또는 flow lens | 표시 가능 |

## Empty State Rule

내 업무가 없는 상태는 정상 상태다.

내 업무가 비어 있을 때 병원 전체 정보를 억지로 끌어와 채우지 않는다. 대신 사용자 역할/책임에 맞는 compact 업무 시작 런처를 보여준다.

Examples:

| 사용자/업무 책임 | Empty launcher |
|---|---|
| 데스크 | 예약/접수 열기, 현장 접수, 수납 대기 보기 |
| 진료 수의사 | 진료 대기열, 내 차트, 검사 결과 확인 |
| 조제/처치 테크니션 | 조제/처치 큐, 검사 대기, 입원 케어 |
| 검사 담당 | 검사 대기열, 결과 입력, 재확인 요청 |
| 수납 담당 | 수납 대기, 미수 목록, 중간 정산 |
| 입원 담당 | 입원장, 입원 등록 대기, 퇴원 체크리스트 |
