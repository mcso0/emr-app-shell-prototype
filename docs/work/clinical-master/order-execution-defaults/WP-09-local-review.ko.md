# 오더 기본값 전체 작업 중간 점검

2026-09-07 기준, WP-01B부터 WP-09까지 남아 있던 구현과 세 병원 통합 DB 검증을 마쳤다. 적용 대상, 검사 데모 설정, 약품을 합성 데모에서 선택하는 경로와 기존 비청구 검사 묶음 예외는 승인받았다. 실제 서버 적용과 배포는 아직 하지 않았다. 현재는 이번 변경만 분리해 PR과 배포 검사를 준비한다.

원본 522개를 모두 대조했다. 조제 항목 51개는 명시한 제품으로 대체하고 새 항목 53개를 추가해 게시 후보는 524개가 됐다. 이전 51개는 삭제하지 않고 앞으로의 선택만 중단할 계획이다. 과거 처방과 병원별 수정값은 보존한다.

병원관리와 차트는 저장된 데이터를 읽는다. 다른 병원의 응답이 늦게 도착하거나 조회가 실패해도 예전 목록을 성공한 결과처럼 보여주지 않는다. 기본값은 항목별 상속·수정·초기화·충돌 해결을 지원한다.

조제 127개, 처치 111개, 영상 30개, 입원·상담·기타·계통검사 136개의 정의를 연결했다. 계획과 실제 수행을 나누고 수행자·수행시간·수정 사유를 별도로 기록한다. 입원은 병원에 등록된 위치를 선택하며 기존 처치 업무 흐름을 사용한다.

검사 원본 86개는 개별 실행 오더 90개와 중첩 구성 35개로 정리했다. 결과 프로필 24개, 병원별 정상범위 버전, 판별, 재검사와 과거 결과 보존을 연결했다. 합성 기능검증용 구간이며 임상 정상범위가 아니다. 실제 장비 연동도 없다.

최근 계약 테스트 203개, 게시 API 호환 테스트 35개, 후보·설정·보고서 테스트 93개를 통과했다. 배포용 작업 폴더에서 타입·문서·비밀정보 검사와 빌드도 통과했다. 앞서 화면 테스트 14개와 별도 검사 화면 2개를 확인했다. 화면 테스트는 모의 API를 사용했으며 실제 로그인한 배포 환경 검증과는 다르다. 최종 문구와 문서 정리가 끝나면 정확한 배포 후보로 필수 검사를 다시 실행한다.

연결된 원격 DB는 조회만 했다. clair-demo, workspace-clair-cheongdam, workspace-clinical-master-pilot-v1에는 원본 마스터가 각각 522개 연결돼 있다. 이 세 곳을 적용 대상으로 승인받았고 clair-foreign-demo는 변경하지 않는다. 수동 검사 프로필, 부모 항목만 청구, 재검 기본 비청구도 승인됐으며 재검 화면의 비청구 기본값은 검증했다.

기존 약품 108개는 제품 프로필의 버전까지 맞춰야 한다. DB는 임상 미검증 약품의 active 상태를 금지한다. 보호 규칙을 유지하면서 합성 데모에서 선택·확정하는 기존 경로는 있지만 DB 상태는 pending_activation이다. 새 합성 프로필과 카탈로그 연결을 함께 바꾸는 좁은 이행 작업도 필요하다. 과거 프로필과 임상 리뷰를 수정하거나 임상 승인을 새 정의에 재사용하지 않는다.

파일럿 병원의 metabolic 검사 묶음 하나는 기존부터 가격이 없고 비청구다. 이 한 건은 비청구를 유지하고 나머지 89건은 부모 가격을 유지하기로 승인받았다. 같은 병원의 기존 초진 상담도 가격과 비청구 상태를 보존한다. 이미 승인한 대상과 정책을 다시 묻는 단계는 아니다.

새 항목 53개에는 종류별 합성 데모 가격을 정했다. 조제 19개는 건당 7,000~45,000원, 개별 검사 34개는 5,000~20,000원이다. 알약·용량별 단가나 실제 병원 견적이 아니며, 검사 묶음 가격을 개별 검사 가격의 합계로 바꾸지도 않는다. 기존 항목 가격은 손대지 않는다.

통합 검증에서는 기존 검사 69개씩, 총 207개의 ID를 먼저 고정했다. 갱신 검토 항목이 없어 15개가 이전 버전에 남던 문제를 수정했다. 같은 고정 목록에만 검토 항목을 만들고 기존 승인 함수로 갱신한다. 검사 연결, 과거 결과, 기존 알림과 읽음 상태, 다른 병원의 자료를 보존하는 검사도 통과했다. 정상 반영, 중간 실패, 재실행을 시험한 뒤 모두 되돌렸으며 실제 원격 DB에 남긴 변경은 없다.

기존 프리셋 471개의 ID와 이력을 보존하는 후보 변환 테스트를 통과했다. 과거 차트 확정 재시도가 수행 이력을 새로 만들지 않도록 수정했다. 통합 검증 뒤 최신 main에서 이번 변경만 분리해 PR Preview와 배포 검사를 준비한다. 정확한 후보의 운영 배포 승인을 받은 뒤 DB·앱을 함께 반영하고 병원별 실제 로그인 검증을 진행한다. 그 전에는 전체 작업이나 배포를 완료로 표시하지 않는다.
