# CBC 구조 조사 결과

## 지금 확인된 결론

현재 구조를 전부 다시 만들 필요는 없다. 개별 검사 정의, 단위, 버전, 확정 시점의 복사본은 이미 있다. 다만 장비·동물종별 정상범위와 판별 규칙을 연결하는 구조는 완성되지 않았다. 후보 데이터만 넣어서는 작동하지 않는다.

이번에는 로컬 코드와 연결된 스테이징 DB를 읽기 전용으로 확인했다. 앱, 마스터, 워크스페이스 데이터는 변경하지 않았다. 환자 정보와 실제 검사 결과도 조회하지 않았다.

## DB에서 직접 확인한 내용

| 확인 대상 | 현재 상태 |
| --- | --- |
| 마스터 | 오더 522개, 검사 결과 정의 73개, 검사 패널 19개 |
| CBC 구성 | 마스터와 청담점 모두 WBC·HCT·PLT 3개만 연결 |
| RBC·HGB | 결과 정의는 있으나 단독 요청용 마스터 오더 연결은 없음 |
| 청담점의 CBC 관련 오더 6개 | 활성 상태. 검사명·검체·채취 안내 기본값은 저장돼 있음 |
| 정상범위와 판별 | 현재 DB 규칙이 정상범위를 비우고 판별을 미판정으로 고정 |
| 병원 수정값 | 확인한 6개 오더에 가격·활성 상태 수정 이력이 있음 |

검사 결과 정의 73개와 조사 대상 오더 86개는 서로 다른 수치다. 하나의 검사 오더가 여러 결과 정의를 포함할 수 있다.

## 가장 중요한 세 가지 차이

### 결과 항목과 결과 프로필

WBC라는 검사 항목과 단위는 저장할 수 있다. 하지만 어떤 장비·동물종의 정상범위를 사용할지 정하고 그 버전을 결과에 고정하는 기능은 추가해야 한다.

원격 DB의 생성 함수는 정상범위를 비워 두고 저장 함수는 판별을 미판정으로 만든다. 검증 함수는 다른 값이 들어오면 거부한다. 화면만 고치거나 JSON에 범위를 추가하는 것으로는 해결되지 않는다.

### 검사 패널과 중첩 세트

현재 검사 패널은 하위 검사 결과 항목만 포함한다. 별도로 일반 오더 세트에는 하위 세트 한 단계가 허용된다.

CBC → 항목 그룹 → 개별 오더는 일반 세트의 허용 깊이에 맞지만, 종합검진 → CBC → 항목 그룹 → 개별 오더는 제한을 넘는다. 더구나 현재 CBC 마스터는 일반 세트가 아니라 오더다. 기존 ID를 유지하면서 세트 구성과 연결하는 변경이 필요하다.

### 병원 수정값과 마스터 갱신

수정 이력과 기본값을 저장하는 기반은 있다. 그러나 확인한 기본값 동기화 함수는 병원이 전혀 수정하지 않은 오더를 대상으로 기본값 전체를 복사한다. 가격만 수정한 오더에서도 다른 기본값을 안전하게 갱신하려면 필드별 상속을 구현해야 한다.

## 병원관리와 차트에서 고칠 부분

두 화면은 이미 워크스페이스 오더를 읽는다. 각각 별도의 마스터를 검색하는 구조는 아니다.

읽기에 실패해도 성공한 빈 목록으로 바꾸는 경로가 남아 있다. 기존 형식의 기본값을 대신 읽는 경로도 있다. 병원관리에는 연결된 검사 항목과 프로필 요약을 보여주는 부분이 부족하다.

검사 화면에는 빈 입력을 0으로 해석할 수 있는 코드도 있다. 정상범위를 연결할 때 빈 값·0·입력 오류를 구분하고, 화면과 서버가 같은 판별 결과를 사용하도록 함께 수정한다.

이 내용은 코드와 DB 조사 결과다. 과거 브라우저에서 발생한 상황을 이번에 직접 재현한 것은 아니다.

## 후보 ID는 어떻게 처리하나

CBC 후보 26개를 원격 마스터와 대조했다. 기존 오더 ID 5개와 결과 정의 ID 7개는 유지한다. 새 오더 후보 21개와 새 결과 정의 후보 19개는 현재 같은 키로 등록돼 있지 않다.

RBC·HGB는 기존 결과 정의에 새 단독 오더를 연결한다. 망상적혈구 비율의 기존 ID를 절대수 항목으로 바꾸지 않는다. 소수 자릿수가 달라지는 항목은 새 버전을 만들고 과거 결과는 그대로 둔다.

후보 키가 비어 있다는 사실은 적용 승인이 아니다. 실제 반영 직전에 중복·의미·버전을 다시 확인한다.

## 다음 작업 순서

| 순서 | 작업 | 완료하면 확인할 것 |

| 2 | CBC 세트·결과 프로필 저장 계약 | 기존 ID를 보존하며 장비·동물종별 규칙과 세트 관계를 저장 |
| 3 | WP-02와 CBC 워크스페이스 연결 | 병원 수정값을 지키면서 미수정 필드를 갱신 |
| 4 | CBC 차트·검사 결과 연결 | 선택한 프로필, 정상범위와 판별이 저장·새로고침 후에도 일치 |
| 5 | WBC 단독 재검과 청구 분리 | 원래 결과는 보존하고 새 요청은 빈 결과로 시작 |
| 6 | 나머지 검사군 확대 | 검증한 구조를 다른 임상병리 검사에도 적용 |

한 번에 전부 구현하지 않는다. 다음은 1번만 진행한다. CBC가 끝까지 작동하는 것을 확인한 뒤 다른 검사군으로 넓힌다.

## 적용할 때 지킬 경계

기존 검사 결과에 새 정상범위를 덮어씌우지 않는다. 새 결과는 새 계약을 사용하고 과거 결과는 당시 계약으로 읽는다. 장애가 나도 새 결과와 이력을 지우는 방식으로 되돌리지 않는다.

계산에 필요한 보조 측정값은 추가 오더나 청구로 몰래 만들지 않는다. 부분 재검 가격과 상위·하위 청구 방식은 구현 전에 별도로 정한다. 실제 장비 연결 없이 수동 입력·연동 안 됨을 표시하는 원칙은 유지한다.

새 프로필은 명시적으로 저장·선택한다. 임의의 다른 장비 값으로 대체하지 않으며 합성 마스터 오더에 임상 검수 대기 상태를 만들지 않는다.

## 검증 범위와 남은 확인

이번 산출물 검사는 원격 조회 근거, 후보 ID 대조와 파일 해시, 보고서 링크·화면을 대상으로 한다. 실제 저장 동작, 사용자 권한별 DB 접근, 배포된 앱 화면 검증은 다음 구현 단계에서 진행한다.

산출물·보고서 테스트 3개는 통과했다. 데스크톱·모바일 화면도 확인했다. 전체 문서 검사는 기존의 다른 문서에 있는 깨진 링크 1건 때문에 실패했다. 이번 작업에서 그 문서는 변경하지 않았다. 앱·DB 구현이 끝났다는 의미로 이 조사 완료 상태를 사용하지 않는다.
