# WP-00·WP-01A 중간 검토 보고서

## 결론

현재 조사 기준 오더 522건은 오더와 프리셋 JSON이 존재하는 단계까지는 와 있다. 그렇다고 전부 차트에서 바로 확정할 수 있는 상태는 아니다. WP-00 감사 결과, 522건 모두 차단 상태였다. 공통 원인은 기존 `synthetic_unreviewed`가 사용 가능 여부와 합성 데이터 출처, 임상 검증 여부를 한 필드에 섞어 둔 데 있다. 사용자가 정한 프로토타입 정책과 맞지 않는 구조다.

이번 작업에서 상태를 `active`·`synthetic_research_informed`·`not_clinically_validated`의 세 축으로 나누는 계약을 확정했다. 별도의 `검수 대기`나 `검수 완료` 상태는 만들지 않는다. 병원관리와 차트가 저장되지 않은 오더나 필드값을 임의로 보충하는 fallback도 어떤 경우든 허용하지 않는다.

WP-01A에서는 522건 전부에 대한 비적용 후보 레코드를 만들었다. 내용 기준으로 161건은 제품 검토가 가능한 후보, 26건은 합성 가정을 명시한 검토 가능 후보, 335건은 추가 설계나 근거가 필요한 차단 후보다. 실제 앱에 적용 가능한 오더 수를 뜻하는 것은 아니다. 모든 후보는 `non_applied_candidate`이며 앱·기존 fixture·DB·Supabase·Airtable·워크스페이스에 반영하지 않았다.

## 이번 단계에서 확정한 기준

오더 기본값은 이름이나 메모가 아니다. 수의사, 테크니션, 검사자, 조제 담당자가 업무를 수행하는 데 필요한 재사용 조건과 절차다. 마스터에는 공통 기준을 두고 병원별 설정은 워크스페이스 사본에서 수정한다. 차트에서는 환자별 계획값을 조정해 확정한다. 실제 조제량·투여량·측정값·판독·소견은 별도 결과 기록에 남긴다.

필드 소유권은 다음과 같이 구분했다.

- 마스터 기본값: 오더 종류마다 반복해서 쓰는 방법, 단위, 공식, 범위, 절차, 지시사항
- 워크스페이스 값: 병원별 장비, 검사기관, 병동·케이지, 병원 정책과 로컬 수정값
- 차트 계획값: 체중, 적응증, 환자 상태를 반영해 이번 처방이나 처치에서 정한 값
- 실제값·결과값: 실제 조제·투여·검사·촬영·판독·처치가 끝난 뒤 기록하는 값

환자마다 값이 달라진다는 이유로 마스터 필드를 비워 두지는 않는다. 마스터에 계산 기준, 공식, 단위, 필수 입력값, 허용 범위, 반올림 규칙, 조정 사유를 둬야 한다. 반대로 실제 시행량이나 정상 소견을 마스터에서 미리 채우는 것도 금지한다.

### 조제

조제 마스터에는 제품·성분·제형·함량과 계산 구조가 있어야 한다. 환자별 처방과 실제 조제·투여 기록은 분리한다. [수의사법 시행규칙 제11조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900458957)는 처방전에 약품명, 용량, 용법, 일수, 수량 등을 적도록 한다. [HL7 MedicationRequest](https://hl7.org/fhir/medicationrequest.html)와 [MedicationAdministration](https://hl7.org/fhir/medicationadministration.html)은 요청과 실제 투여를 별도 자원으로 구분한다.

제품이 확인된 108건은 [영국 VMD 제품 정보](https://www.vmd.defra.gov.uk/ProductInformationDatabase/)를 근거로 현재 값을 후보에 유지했다. 한국 허가나 임상 승인을 대신하는 자료는 아니다. 108건 중 2건은 `dose × 일일 횟수 × durationDays`로 계산한 이론 총량과 저장 총량이 다르다. 제품·도구별 반올림 근거가 없으므로 자동 보정하지 않고 차단했다.

51개 조제 오더는 조제 대상을 계산 가능한 수준으로 식별할 정보가 부족하다. 이 중 14건은 `경구제 조제`, `안약 조제`처럼 약물 성분이 없는 조제 업무·제형명이고, 37건은 `아목시실린 경구제 조제`처럼 성분명은 있지만 함량·농도·구체적인 제형 또는 제품 근거가 없다. 다른 약의 값을 복사하거나 그럴듯한 용량을 만들면 다시 fallback이 된다. 이 오더들은 제품 또는 성분·함량·제형 단위로 재정의하고, 재정의 전까지 차트 사용을 차단한다. 계산은 승인된 입력을 변환하는 역할만 맡는다. [UC Davis VetPDA](https://www.vetmed.ucdavis.edu/computing/vetpda)와 [UCUM](https://ucum.org/ucum)을 참고해 입력, 단위, 계산 전 값, 반올림 후 값, 조정 사유를 함께 보존하는 규칙을 잡았다.

### 처치

현재 111건은 `administeredAmount`를 차트 확정 전 필수값처럼 취급한다. 실제 시행량을 계획값과 섞은 구조다. [HL7 ServiceRequest](https://hl7.org/fhir/servicerequest.html)와 [Procedure](https://hl7.org/fhir/procedure-definitions.html), [수의사법 시행규칙 제13조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900458968)를 근거로 계획과 실제 기록을 분리해야 한다.

마스터에는 방법, 계획량 기준과 단위, 부위 정책, 횟수, 일정, 준비 절차를 둔다. 차트에서는 환자별 계획량과 부위를 정한다. 수행 뒤에는 실제량·실제부위·시행자·시각·결과를 별도로 기록한다. 수액처럼 환자 상태에 따라 재평가가 필요한 항목에는 하나의 범용 수치 기본값을 만들지 않는다.

### 임상검사

검체 종류만 채웠다고 검사 오더가 완성되지는 않는다. [ASVCP QALS](https://www.asvcp.org/page/QALS_Guidelines)와 [Cornell 혈액검사 안내](https://www.vet.cornell.edu/animal-health-diagnostic-center/testing/testing-protocols-interpretations/hematology)를 근거로 검체 용기, 항응고제, 최소량, 채취, 전처리, 보관, 운송, 지연 조건을 검사별로 관리해야 한다.

패널과 분석항목도 분리해 버전 관리한다. 결과값은 단위, 정밀도, 측정범위, 검사법, 분석기와 함께 저장한다. 기준범위는 종, 품종, 연령, 성별, 검체, 검사법, 분석기 조건을 가진 별도 버전 엔터티다. [ASVCP 기준간격 지침](https://www.asvcp.org/resource/resmgr/QALS/Other_Publications/RI_Guidelines_For_ASVCP_webs.pdf)에 따르면 외부 제조사 범위를 곧바로 병원 검증 완료 값으로 표시할 수 없다. 프로토타입에 쓴다면 `provisional` 성격을 분명히 해야 한다.

### 영상과 나머지 카테고리

영상은 촬영 요청, 획득, 품질 확인, 판독을 분리한다. [DICOM 수의 해부부위·투사방향 코드](https://dicom.nema.org/medical/dicom/final/cp922_ft2.pdf)와 [ACVR·ECVDI 영상보고 합의문](https://pmc.ncbi.nlm.nih.gov/articles/PMC11649853/)을 근거로 모달리티, 부위, 뷰, 촬영 장수, 임상 질문, 진정·조영 정책을 구조화했다. 모든 부위에 적용할 단일 뷰 수나 범용 조영제 용량은 만들지 않았다.

입원에는 반복 모니터링, 간호, 식이, 악화 기준, 인계와 담당 역할이 필요하다. 병동·케이지는 마스터 문자열이 아니라 현재 워크스페이스의 실제 자원에서 고른다. 계통검사는 검사 범위·계통·방법·부위·좌우를 마스터와 계획에 두고 정상·비정상 소견은 실제 결과에 기록한다. 기타 39건은 증명서, 응급, 소모품을 하나의 일반 메모로 묶지 말고 하위 유형별 산출물과 완료 조건을 정의해야 한다.

## 확정된 제품 결정

1. **확정(2026-09-04)** — 프로토타입 상태는 `active`·`synthetic_research_informed`·`not_clinically_validated`로 분리하고 별도 검수 상태를 만들지 않는다.
2. **확정(2026-09-04)** — 조제 대상을 계산 가능한 수준으로 식별할 정보가 부족한 51건은 임의 수치로 채우지 않는다. 제품 또는 성분·함량·제형 단위의 독립 마스터 오더로 재정의하고, 재정의 전까지 차트 사용을 차단한다.
3. **확정(2026-09-04)** — VMD 기반 조제 후보 106건은 실제 임상 업무에 사용하지 않는 합성 프로토타입 데이터로 한정해 다음 설계 단계에 사용한다. 한국 허가 또는 임상 검증을 받은 값으로 표현하지 않으며, 총량 계산이 불일치하는 2건은 계속 차단한다.
4. **확정(2026-09-04)** — 진료차트의 `Plan/Order`에서 확정한 환자별 작업 지시와 조제·처치·검사·영상 화면에서 업무 수행 후 입력하는 실제 시행량·측정값·촬영 정보·판독을 별도 데이터로 저장한다. 두 기록은 연결하되 서로 덮어쓰지 않는다.
5. **확정(2026-09-04)** — 계통검사 12건에는 안정적인 영속 마스터 ID를 부여한다. 검사 구조와 기본 세부 계약이 같으면 개·고양이 공통으로 등록하고, 종에 따른 차이가 명확할 때만 별도 오더로 분리한다. 정상·비정상 소견은 마스터 기본값이 아니라 실제 검사 결과에 기록한다.
6. **확정(2026-09-04)** — `phase1a2.fallback.path.lab` 분류 키를 가진 `합성 기초 혈액검사`는 WP-01B에서 생성 목적과 사용 경로를 확인한다. 독립적으로 필요한 실제 오더라면 정상 임상검사 분류로 이동하고 부족한 세부값을 완성하며, 화면을 임시로 채우기 위한 오더라면 비활성화하거나 제거한다. 어떤 경우에도 다른 fallback 오더로 대체하지 않는다.

## 다음 스텝

WP-01B 하위 계획서와 저장 경로 코드 감사를 마쳤다. 아직 앱 동작이나 데이터베이스 데이터는 바꾸지 않았다.

병원관리와 차트는 같은 API 주소로 들어가지만 서버 안에서는 서로 다른 데이터베이스 함수를 호출한다. 병원관리는 현재 워크스페이스의 전체 오더를 읽는다. 차트는 사용 중인 오더와 유효한 오더 세트만 읽은 뒤 환자 종과 카테고리로 다시 거른다. 의도된 차이지만 두 결과가 같은 영속 오더 ID와 값에서 출발한다는 보장이 필요하다.

문제는 코드에서 확인됐다. 병원관리 조회 함수가 실패하면 별도의 테이블 조회로 우회하며 그 조회나 차트 조회가 실패해도 빈 목록을 성공으로 돌려준다. 데모 헤더 모드에서는 하드코딩된 오더와 오더 세트가 병원 오더 API의 데이터가 될 수 있다. 조제 값이 비어 있을 때 병원관리 화면이 1정, PO, SID, 1일, 실온 같은 값을 만들어 표시하는 경로도 있다. 차트와 검증 코드에는 저장되지 않은 스키마 기본값을 대신 쓰는 경로가 남아 있다. 잘못된 행은 오류 없이 목록에서 빠질 수 있다. 병원관리의 일부 하위 분류는 저장된 분류 ID가 아니라 이름에 포함된 단어로 정한다.

조제와 처치 탭이 나뉘어 있다는 사실은 이번 문제의 근본 원인이 아니다. 탭은 이미 가져온 오더를 나중에 거르는 장치다. 특정 탭에서 안 보이는 이유는 설명할 수 있어도 전체 탭에서 사라지거나 기본값이 서로 다르게 보이는 문제까지 설명하지는 못한다.

구현은 다섯 조각으로 나눈다. 먼저 조회 오류를 빈 목록으로 바꾸는 우회 경로와 런타임 가라 오더를 없앤다. 병원관리와 차트가 같은 영속 기본값 해석기를 쓰도록 맞추고 임의 필드값도 제거한다. 그다음 저장된 분류와 핵심 세부값만 병원관리 표에 표시한다. 차트 검색 후보와 새 초안이 같은 오더 ID와 값을 쓰는지도 추적한다. 마지막으로 빈 목록, 오류, 권한 거부, 수정 후 재조회, 사용 중지와 재활성화, 워크스페이스 전환을 브라우저에서 검증한다.

WP-01B 구현이 통과하면 WP-02로 넘어간다. 마스터 기본값을 워크스페이스에 복사하고 병원에서 수정한 필드는 보존한다. 수정하지 않은 필드만 새 마스터 버전으로 갱신한다.
