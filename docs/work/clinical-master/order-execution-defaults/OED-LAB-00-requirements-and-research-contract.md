# OED-LAB-00: 임상병리 요구사항 및 조사 계약

## 이 문서의 목적

현재 522개 마스터 오더 가운데 임상병리 검사는 86개다. 기존 후보 데이터는
검체, 검사명, 채취 조건처럼 차트에 표시할 기본 필드만 다뤘다. 검사 세트 안의
하위 검사 오더, 결과 입력 방식, 단위, 판별 규칙, 정상범위는 완성하지 못했다.

이 문서에 임상병리 검사 86건을 다시 조사할 기준을 모아 둔다. 먼저 각 검사의
업무 구조와 필요한 데이터를 확정한 뒤 로컬 저장 구조와 원격 DB가 그 구조를
수용하는지 조사한다. 조사 단계에서는 앱, 마스터, 워크스페이스, Supabase,
Airtable 데이터를 변경하지 않는다.

## 트랙 이름과 진행 순서

`OED-LAB`은 전체 작업의 다섯 번째 단계를 뜻하지 않는다. 임상병리 검사만
추적하는 별도 작업 계열이다. 이전 `WP-05A`와 `WP-05B` 표기는 상위 계획에서
임상병리가 배치된 카테고리 순번이었지만 실제 진행 순서로 오해하기 쉬워 더 이상
사용하지 않는다.

| 작업 | 상태 | 역할 |
| --- | --- | --- |
| `OED-LAB-00` | `active` | 지금까지 확정한 요구사항과 조사 계약 |
| `OED-LAB-01` | `done` | 임상병리 86건의 외부 전체 구조 조사와 비적용 산출물 완료 |
| `OED-LAB-02` | `done · 비적용 후보` | CBC 정밀 조사·후보 데이터·로컬 기능 검증 완료 |
| `OED-LAB-03` | `done · 조사만 완료` | 로컬·원격 구조 대조, 26개 후보 ID 확인, 변경·이행 계획 작성 |

표의 상태는 이 문서 트랙의 진행 위치다. 마스터 오더의 활성, 검수 또는 임상
검증 상태로 복사하지 않는다.

현재 다음 구현은 기존 **WP-01B — 병원관리·차트 데이터 일치와 fallback 제거**다.
[LAB-03 조사 및 전환 계획](./artifacts/oed-lab-03/audit-and-transition-plan.md)에
원격 근거와 이후 CBC 단계별 완료기준을 기록했다. 조사 완료는 앱·DB 반영을
뜻하지 않는다.

## 확정된 제품 요구사항

### 검사 세트와 개별 검사 오더

검사는 하나 이상의 하위 검사 오더를 묶은 검사 세트로 정의한다.
검사 종류가 달라도 `세트 → 최종 하위 검사 오더`라는 기본 관계는 유지한다.
다만 최종 하위 오더의 결과 형식은 검사마다 다를 수 있다.

예를 들어 CBC 검사 세트에는 WBC, RBC, HCT, PLT 같은 하위 검사 오더가
포함된다. 각 하위 검사 오더는 단순한 결과 입력칸이 아니다. 단독으로 검색하고
요청하거나 재검을 요청할 수 있는 안정적인 오더 ID와 업무 이력을 가진다.

```text
CBC 검사 세트
├─ WBC 개별 검사 오더
├─ RBC 개별 검사 오더
├─ HCT 개별 검사 오더
└─ PLT 개별 검사 오더
```

### 세트의 세트

상위 세트는 다른 검사 세트와 개별 검사 오더를 함께 포함할 수 있다.
`종합 검진 → 혈액 검사·요검사 → 최종 하위 검사 오더`처럼 단계가 늘어날 수
있다. 어떤 상위 세트를 선택하더라도 실행 시점에는 최종 하위 검사 오더를
확정적으로 찾을 수 있어야 한다.

```text
종합 검진 세트
├─ CBC 검사 세트
│  ├─ WBC
│  └─ RBC
├─ 혈청화학 검사 세트
│  ├─ ALT
│  └─ AST
└─ 요검사 세트
   ├─ 요비중
   └─ 요단백
```

세트 관계에는 순환 참조가 없어야 한다. 여러 경로에서 같은 하위 오더가
포함될 때 중복 요청을 허용할지 합칠지도 명시해야 한다.

### 하위 검사 오더의 결과 정의

각 하위 검사 오더는 검사 성격에 맞는 결과 계약을 가진다.

- 결과 입력 유형: 수치, 코드, 음성·양성, 등급, 선택값, 서술, 복합 결과,
  이미지 또는 첨부
- 단위: 필수, 선택 또는 해당 없음
- 판별값: 미달, 정상, 초과, 음성, 양성, 검출, 미검출, 등급, 임계값 또는
  검사별 판독 용어
- 정상범위: 수치 범위, 기대 코드, 해석 규칙 또는 해당 없음
- 적용 조건: 동물종과 필요한 경우 품종, 연령, 성별, 생리 상태
- 검사 조건: 검체, 채취·전처리, 검사법, 분석 장비, 외부 검사기관
- 업무 결과: 결과값, 판별, 소견, 첨부, 수행자, 수행 시각, 검토자

정상범위가 없는 검사는 `누락`으로 남기지 않고 `해당 없음`의 근거를 기록한다.
범위가 있는 검사는 단순 문자열 하나가 아니라 조건, 단위, 하한·상한, 경계
포함 여부, 출처와 버전을 함께 저장한다.

### 장비 연동과 결과 프로필 분리

검사 장비와 시스템을 직접 연결하지 않아도 장비별 결과 입력과 판별은 지원해야
한다. 장비 등록과 결과 프로필, 결과 자동 수신은 서로 다른 책임이다. 현재
프로토타입은 결과 자동 수신을 구현하지 않는다. 워크스페이스가 사용하는 장비와
결과 프로필을 명시적으로 등록하고 직원이 결과를 직접 입력한다.

화면에는 수행 장비, `수동 입력`, `연동 안 됨`을 함께 표시한다. 사용자가
결과값을 입력하면 선택된 장비 프로필의 단위, 정상범위와 판별 규칙으로
미달·정상·초과 등을 계산한다. 실제 연동이 없는 장비를 `연동됨`으로 표시하지
않는다.

```text
검사 오더
→ 워크스페이스 수행 장비 또는 수행 프로필 선택
→ 장비별 단위·정상범위·판별 규칙 표시
→ 직원이 결과를 수동 입력
→ 판별값 계산
→ 결과와 적용 프로필 버전을 함께 저장
```

### 마스터와 워크스페이스의 장비 책임

마스터에는 장비와 무관한 검사 정의, 검사 세트 구성, 장비 종류, 대표 모델별
결과 프로필과 호환 관계를 둔다. 결과 프로필에는 제조사·모델, 검사법, 지원 검사
항목, 동물종, 검체, 단위, 정상범위, 소수점, 측정 가능 범위, 판별 규칙, 근거
문서와 버전을 기록한다.

워크스페이스는 실제로 사용하는 장비를 등록하고 장비의 사용 상태, 결과 입력
방식, 연동 상태, 담당 검사, 기본 수행 장비와 적용할 결과 프로필을 정한다.
병원이 수정한 프로필 값은 워크스페이스 값으로 보존한다.

병원이 명시적으로 지정한 기본 장비는 차트에서 미리 선택할 수 있다. 기본
장비가 없거나 여러 장비 중 하나를 결정할 수 없으면 결과 입력 전에 수행 장비나
결과 프로필을 선택해야 한다. 다른 장비의 값이나 화면용 목업값으로 대신하지
않는다. 외부 검사실과 수기 검사도 임의 fallback이 아니라 별도의 수행 프로필로
관리한다.

검사 결과에는 사용 장비, 입력 방식, 결과 프로필 버전과 당시 적용한
단위·정상범위·판별 규칙을 스냅샷으로 보존한다. 이후 장비나 프로필이 바뀌어도
과거 결과의 판별 근거는 변하지 않아야 한다.

### 특정 항목 재검

검사 세트를 다시 요청하지 않고 하위 검사 오더 하나만 재요청할 수 있어야 한다.
CBC 결과에서 WBC만 다시 확인해야 한다면 새 WBC 오더를 만든다. 기존 결과는
수정하거나 덮어쓰지 않는다.

새 재검 오더에는 다음 연결을 보존한다.

- 최초 검사 오더와 상위 검사 세트
- 직전 검사 시도와 결과
- 재검 사유
- 새 검체가 필요한지 여부
- 요청자, 수행자, 요청·수행 시각
- 적용한 결과 정의와 정상범위 버전
- 재검 비용과 청구 처리 결과

## 현재 저장 구조에서 확인한 사실

현재 로컬 마스터 fixture에는 검사 패널 18개, 개별 검사 정의 72개, 패널-검사
연결 120개, 검사 오더 프로파일 85개가 있다. CBC 기본 패널은 WBC, HCT, PLT
세 항목을 연결한다.

이 구조만으로는 이번 요구사항 전체를 처리하지 못한다.

- `master.lab_panel_items`는 패널을 `lab_test` 결과 정의와 연결한다. 하위 항목을
  독립 `order`로 연결하지 않는다.
- `master.lab_order_profiles`의 오더 하나는 검사 하나 또는 패널 하나만 가리킨다.
- 검사 패널 안에 다른 검사 패널을 넣을 수 없다.
- 워크스페이스의 일반 오더 세트는 중첩 세트를 지원하지만 임상병리 마스터
  패널과 같은 계약으로 연결되어 있지 않다.
- 결과 행에는 단위, 정상범위 문자열과 제한된 판별값을 저장할 수 있지만
  마스터 정상범위와 판별 규칙의 출처·조건·버전 구조가 없다.
- 실행용 오더 후보에서는 패널 관계가 `testPanel` 문자열로 축소된다.

현재 구조만으로는 `종합 검진 → CBC → WBC` 계층, 하위 WBC의 독립
요청·재검, 조건별 정상범위의 일관된 적용을 보장할 수 없다.

## 조사 범위

### 1. 임상병리 검사 86건 전수 목록 고정

WP-00에서 고정한 522개 오더 중 `clinical_lab` 86건의 ID, 이름, 종 적용 범위,
현재 검사·패널 연결과 실행 기본값을 다시 추출한다. 현재 72개 검사 정의와
18개 패널, 120개 패널 연결을 함께 대조해 중복, 누락과 이름만 다른 동일 검사를
찾는다.

### 2. 검사 유형 분류

각 검사와 최종 하위 오더를 수치형, 정성형, 코드형, 등급형, 선택형, 서술형,
복합 결과형, 이미지·첨부형으로 분류한다. 기존 유형에 맞지 않는 검사는 별도
유형으로 기록하며 억지로 수치형이나 서술형에 넣지 않는다.

### 3. 세트와 하위 오더 조사

각 검사에 필요한 최종 하위 오더를 조사한다. 세트 구성, 필수·선택 항목,
표시 순서, 단독 요청 가능 여부, 재검 가능 여부를 기록한다. 종합검진처럼 여러
검사 세트를 포함하는 상위 구성을 별도로 찾는다.

### 4. 장비와 수행 방식 조사

임상병리 검사 86건을 원내 장비 검사, 수기 검사, 외부 검사실 의뢰로 먼저
분류한다. 장비 검사는 필요한 장비 종류와 대표 모델을 찾고, 세트와 최종 하위
검사 오더별로 지원 여부를 연결한다. 검사 세트 하나가 여러 장비나 수기 판독을
함께 요구할 수 있으며 장비 하나가 여러 검사 세트를 지원할 수도 있다.

대표 장비별로 다음 항목을 조사한다.

- 지원 검사 세트와 최종 하위 검사 항목
- 결과 유형, 단위, 소수점과 측정 가능 범위
- 동물종별 정상범위와 판별 규칙
- 검체, 전처리와 검사법
- 장비 오류, 범위 초과와 판정 불가 표시
- 제조사 문서의 버전과 출처

장비 목록과 프로필 값은 제조사의 공식 검사 메뉴, 사용 설명서와 기준범위
문서를 우선한다. 세트 구성과 수기·외부 검사실 검사는 수의과대학 검사실과
수의임상병리 전문단체 자료로 교차 확인한다. 패널 계층과 결과 용어는 LOINC와
HL7 FHIR, 단위는 UCUM을 구조 참고자료로 사용한다. 검색 결과 요약, 일반 블로그,
판매처 설명은 단독 근거로 쓰지 않는다.

시중의 모든 장비를 전수 조사하지는 않는다. 프로토타입에서 필요한 검사 유형을
대표할 모델을 선정하되 `프로토타입 장비 설정`, `수동 입력`, `연동 안 됨`을
분명히 표시한다. 실제 병원이 해당 장비를 보유하거나 시스템과 연동했다는 주장은
하지 않는다.

공개 자료에서 특정 장비의 결과값이나 정상범위를 충분히 찾지 못해도 기능 검증을
중단하지 않는다. 상용 장비 이름에 임의 값을 붙이지 않고 `CLAiR 프로토타입
혈구분석기`처럼 명시적인 데모 장비 프로필을 만든다. 데모 프로필도 마스터에
버전과 생성 규칙을 갖춘 기본값으로 저장하며 런타임 fallback으로 만들지 않는다.

### 5. 결과 정의와 정상범위 조사

각 최종 하위 오더의 입력 유형, 단위, 판별 용어, 정상범위 정책과 적용 조건을
조사한다. 자료는 규제기관, 수의학 전문단체, 대학 검사실, 표준기관과 검사 장비
제조사 문서를 우선한다. Deep Research를 사용해 주장별 출처와 한계를 원장에
남긴다.

제휴 병원 자료가 없으므로 실제 병원 검증값이라고 표현하지 않는다. 모든 후보는
`active`와 `not_clinically_validated`를 유지하고, 데이터 출처는 다음 두 종류 중
하나로 기록한다.

- `synthetic_research_informed`: 공개 자료를 참고해 만든 합성값
- `synthetic_functional_fixture`: 정확한 공개 값을 찾지 못했을 때 기능 검증을
  위해 생성 규칙으로 만든 합성값

별도의 `검수 대기` 상태는 만들지 않는다. 정확한 임상값을 찾지 못했다는 이유만으로
결과 입력이나 판별 기능을 차단하지도 않는다. 대신 해당 검사 유형에서 필요한
정상·미달·초과, 양성·음성, 등급, 판정 불가 같은 화면과 업무 상태를 모두 확인할
수 있도록 서로 모순되지 않는 값을 만든다.

기능용 합성값에는 생성 규칙, 단위, 범위와 판별 조건을 기록한다. 실제 장비,
외부 검사실 또는 임상 검증값으로 오해할 이름이나 설명은 붙이지 않는다. 다른
검사나 화면 목업의 값을 실행 중에 가져오는 fallback은 허용하지 않는다.

### 6. 재검과 세트 확장 규칙 조사

세트를 차트에서 요청할 때 최종 하위 오더를 언제 생성할지, 상위·하위 관계를
어떤 ID로 보존할지 정의한다. 일부 항목 재검은 새 오더와 새 결과 시도를 만들고
이전 결과를 그대로 보존해야 한다. 중복 하위 오더, 검체 공유, 재채취, 부분 취소,
부분 완료와 청구 정책도 조사 대상에 포함한다.

### 7. 로컬·원격 구조 감사

검사 내용과 목표 계약을 먼저 정한 뒤 현재 구조와 비교한다.

- 로컬 migration과 마스터 publisher·adopter
- 마스터 검사, 패널, 패널 항목, 오더 프로파일
- 워크스페이스 오더와 중첩 오더 세트
- 차트 세트 확장과 확정 스냅샷
- 검사 작업 큐, 결과지, 결과 행과 재요청 이력
- 장비 코드 매핑과 워크스페이스 정상범위 override
- 원격 Supabase의 실제 테이블, 함수, 행 수와 관계
- fixture·목업·fallback이 실제 데이터처럼 보이는 경로

원격 감사는 읽기 전용으로 수행한다. 원격 migration 적용, 데이터 수정, 마스터
배포, 워크스페이스 채택은 별도 구현 계획과 승인 범위에서 다룬다.

## 조사 산출물

OED-LAB-00이 정의하는 조사 산출물은 다음과 같다.

1. 임상병리 검사 86건 고정 목록과 현재 관계 감사
2. 검사 세트·하위 오더 계층 후보
3. 하위 오더별 결과 정의 후보
4. 검사별 수행 방식과 장비 종류·대표 모델 연결표
5. 대표 장비와 CLAiR 데모 장비별 결과 프로필 후보
6. 연구 참고형·기능 검증형 합성값 구분과 출처·생성 규칙 원장
7. 정상·미달·초과, 양성·음성 등 판별 분기를 확인할 결과 예시
8. 단독 요청·부분 재검·세트 확장 업무 규칙
9. 현재 로컬·원격 DB와 목표 구조의 차이표
10. 기존 ID 보존, 신규 ID, 변환과 backfill 계획
11. 마스터 → 워크스페이스 → 차트 → 검사 결과 흐름 구현계획

후보 JSON은 실제 앱에서 import하지 않는 `non_applied_candidate`로 만든다.

## 완료 기준

- 임상병리 검사 86건 모두가 하나의 조사 결과를 가진다.
- 모든 검사 세트는 최종 하위 오더까지 순환 없이 펼쳐진다.
- 모든 최종 하위 오더에 안정적인 ID와 단독 요청·재검 정책이 있다.
- 임상병리 검사 86건 모두가 원내 장비, 수기 또는 외부 검사실 수행 방식으로
  분류된다.
- 장비 검사는 필요한 장비 종류, 대표 모델 또는 명시적인 CLAiR 데모 장비,
  지원 세트·하위 항목과 결과 프로필이 연결된다.
- 각 하위 오더에 필요한 결과 유형, 단위 정책, 판별 규칙, 정상범위 정책, 검체와
  검사법·장비 조건이 완성되고 `synthetic_research_informed` 또는
  `synthetic_functional_fixture`로 분류된다.
- 수치형 결과는 정상·미달·초과를, 정성형 결과는 해당 검사에 필요한 양성·음성,
  등급 또는 판정 불가 상태를 기능적으로 확인할 수 있다.
- 프로토타입 화면과 데이터 계약이 `사용 장비`, `수동 입력`, `연동 안 됨`을
  구분하며 자동 수신이나 실제 병원 보유 장비를 주장하지 않는다.
- 워크스페이스가 지정하지 않은 장비나 프로필로 자동 대체하지 않는다.
- 정상범위가 없는 검사도 그 이유와 결과 판독 방법이 기록된다.
- 중복 항목, 검체 공유, 부분 완료·취소·재검과 청구 정책의 미결정 사항이 드러난다.
- 현재 마스터·워크스페이스·차트·검사 결과·재요청 구조와 목표 구조의 차이가
  테이블과 필드 수준으로 정리된다.
- 현재 ID를 유지할 항목, 새 ID가 필요한 항목과 backfill 대상이 구분된다.
- 조사 후보는 앱, 마스터, 로컬·원격 DB에 적용되지 않는다.
- fallback 값이나 가라 오더가 생성되지 않는다.

- 마스터·워크스페이스 데이터 수정
- Airtable 또는 Supabase 쓰기
- 합성 후보를 임상 검증값으로 표현하는 일
- 실제 장비 인터페이스, 장비 통신 프로토콜 또는 결과 자동 수신 구현
- 실제 병원의 장비 보유·연동 상태를 확인하지 않고 등록하는 일
- 기능용 합성값을 실제 상용 장비값이나 임상 검증값으로 표현하는 일
